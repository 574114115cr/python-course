## 三、代码块铁律（违反任何一条都会让生成脚本出错）

1. **所有 ``` 围栏必须顶格写**，前面不能有空格。列表里要嵌代码时，把代码块移出列表单独成段。
2. **围栏必须成对**。写完自查：全文 ``` 出现次数必须是偶数。
3. 语言标注：Python 代码用 ` ```python `；Shell/终端命令用 ` ```bash `；
   运行结果、目录树、ASCII 图用 ` ```text `（或无标注裸围栏）。
4. **每个 Python 代码块都必须是合法、可运行的 Python 3.12 代码**。
   不允许出现只写一半的片段、伪代码、`...` 省略号代替函数体。
   需要省略时用注释 `# ……` 说明，并保证剩下的部分仍能跑。
5. 故意写错的示例必须在该块内第一行加注释标记：
   `# INTENTIONALLY-BROKEN 演示用：……`
6. 文件读写示例会真实产生文件，**统一在代码里用 `Path("data")` 或显式的临时文件名**，
   并在注释里提醒「跑完可以删掉」。不要写死绝对路径。

## 五、写作风格（对齐阶段 1 已有讲义）

- 简体中文，口语化但不水；像一位有经验的学长在讲，不像教科书
- **每个抽象概念都配一个生活化类比**（例：变量是贴标签的盒子、类是模具、实例是饼干）
- 多用表格做对比（例：r/w/a 三种模式的行为差异）、多用 ASCII 图讲结构
- 难点用 `★` 标注，并在正文里说明「这里为什么难」「卡住正常吗」
- 代码注释要充分，注释解释「为什么」而不是重复代码
- **不要编造教材里没有的 API 或章节内容**。以提供给你们的章节大纲为准；
  大纲之外的必要补充（如 Python 3.12 的变化）要标注「教材未涉及，补充说明」。
- 讲 Django / Pygame 时，每一步都要说清「这个文件是干什么的」「改了它会影响什么」，
  因为这两个框架对新手最大的困惑是「我不知道我改的东西在哪生效」。
