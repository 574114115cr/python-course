## 二、核心知识点讲解

### 2.1 函数：给一段代码起个名字

没有函数时，计算 BMI 的代码要在不同地方重复写三遍：

```python
bmi1 = 70 / 1.75 ** 2
bmi2 = 80 / 1.80 ** 2
bmi3 = 60 / 1.65 ** 2
```

函数把它打包成一个"有名字的积木"：

```python
def calculate_bmi(weight, height):
    """根据体重和身高计算 BMI。"""
    return weight / height ** 2


print(calculate_bmi(70, 1.75))   # 22.86
print(calculate_bmi(80, 1.80))   # 24.69
```

生活化类比：函数就像**「饺子机」**——你把原料（参数）放进去，按下按钮（调用），机器产出饺子（返回值）。同一台机器可以反复使用，产出多少饺子取决于你这次放了多少原料。你不需要知道机器内部怎么运作，只需要会用。

三条语法铁律：
```python
def 函数名(参数):
    """文档字符串"""
    函数体
    return 结果
```

1. `def` 和函数名之间**有空格**（`def 函数名`，不是 `def函数名`）
2. 括号后面**必须有冒号**
3. 函数体**必须缩进**

### 2.2 return：把结果"递出窗口"

`return` 做两件事：
1. **立刻结束函数**（后面的代码不再执行）
2. **把一个值交回给调用者**

**有 return 和没 return 的本质区别**：

```python
def with_return():
    return 42

def without_return():
    pass              # 什么都不返回


print(with_return())       # 42
print(without_return())    # None  ← 默认就是 None
```

生活化类比：`return` 相当于**柜台的取货窗口**。函数内部的员工在窗口后面干活，做好的东西从窗口递给你。没有窗口（没有 return），你伸手只能拿到一个空的窗口（None）。

**两条极重要的规则**：

① `return` 之后的代码永远不执行：
```python
def check():
    return "早退了"
    print("这句话永远不会打印")      # 死代码
    return "第二个 return 也不可达"
```

② 一个函数**可以有多个 return**，但**只会走一个**：
```python
def classify(n):
    if n > 0:
        return "正数"      # 命中就返回，函数结束
    elif n < 0:
        return "负数"
    return "零"            # 兜底分支
```
> 注意最后那个 `return "零"` 要**缩进在函数体层级**（和 `if` 平齐），而不是缩进在 `elif` 里面。

### 2.3 三种参数写法

```python
def describe(name, age=18, *hobbies, **extras):
    """三种参数写法的演示。"""
    print(f"姓名：{name}")
    print(f"年龄：{age}")
    print(f"爱好：{hobbies}")
    print(f"其他：{extras}")


describe("小明")                        # 年龄用默认值 18，hobbies 为空
describe("小红", 25)                    # 位置传参：第二个参数是年龄
describe("小刚", age=30)                # 关键字传参：明确指定年龄
describe("小丽", 22, "读书", "游泳")       # 多余的位置参数进 *hobbies
describe("小强", 20, "篮球", city="杭州")   # 多余关键字参数进 **extras
```

**Python 的强制规则：有默认值的参数必须放在没有默认值的参数后面。**

```python
# INTENTIONALLY-BROKEN 演示：必填参数放在默认参数后面，Python 直接拒绝
def bad(a=1, b):      # SyntaxError: non-default argument 'b' follows default argument
    pass
```
原因是调用时 Python 无法确定 `bad(2)` 里的 2 该给 a 还是 b。规则简单：**必填参数在前，选填参数在后。**

### 2.4 ★ 参数传递的副本语义（本单元最重要的概念）

这是零基础学习者最容易掉坑的地方，必须彻底搞懂。

**Python 传递参数时，传递的永远是"指向数据的地址"。** 而函数内部对参数做的操作，分为两类：

| 参数类型 | 函数内部做什么 | 影响到原变量吗 |
|---|---|---|
| **整数、字符串、布尔、浮点数**（不可变类型） | 修改参数 = 造一份新的给参数 | **不影响** |
| **列表、字典**（可变类型） | 修改参数 = 改同一份数据 | **会影响！** |

看代码：

```python
# ===== 情况1：传整数，不影响原变量 =====
def add_one(n):
    n = n + 1        # 只是让参数 n 指向了一个新的整数
    print(f"函数内 n = {n}")      # 11


age = 10
add_one(age)
print(f"函数外 age = {age}")      # 10  ← 没变

# ===== 情况2：传列表，会影响原列表 =====
def add_item(items):
    items.append("新元素")    # 直接改的是同一份列表
    print(f"函数内 items = {items}")


fruits = ["苹果", "香蕉"]
add_item(fruits)
print(f"函数外 fruits = {fruits}")  # ['苹果', '香蕉', '新元素']  ← 变了！
```

**生活化类比（务必记住这个）：**

> 函数就像一个**公共厨房**。你把食材递进去：
> - 递进去**一瓶牛奶**（整数、字符串这类不可变数据）——厨房里的人往瓶子上贴了新标签自己用，**你的那瓶没动**。
> - 递进去**一整盘菜**（列表、字典这类可变数据）——厨房里的人**直接吃了你的菜**，还往盘子里加了料，**你的盘子内容就变了**。

**三种正确的应对方式**（按推荐程度排序）：

```python
# 方案 1：函数内自己造副本（推荐，最简单）
def safe_append_1(items):
    items = items[:]    # 先复制一份，只改副本
    items.append("新元素")
    return items

# 方案 2：调用时传副本
result = safe_append_1(fruits[:])     # 调用方负责给副本

# 方案 3：用不可变类型替代可变类型
def safe_append_3(items):
    return items + ["新元素"]          # + 号产生新列表，原列表不动
```

**判断原则**：如果一个函数**接收列表或字典**，并且它可能修改这个参数，那么这个函数有一个"副作用"——调用者需要知道这件事。所以有两种设计取向：

- **有意修改**：用 `modify()` 这样的名字明确表达"我会改它"，比如单元 9 里写文件。
- **无意修改**：函数内部造副本，或者干脆不要这个参数。

### 2.5 作用域：谁能看见谁

```python
name = "全局变量"


def show():
    local_name = "局部变量"
    print(name)                # 能看全局的
    print(local_name)          # 能看自己的


show()
print(local_name)      # NameError: name 'local_name' is not defined
```

规则很简单：
- 函数内定义的变量是**局部变量**，只在函数内可见，函数结束就消失。
- 函数可以**读取**全局变量，但**不推荐修改**全局变量。
- 函数内如果要给一个名字赋值，Python 就认为它是局部的（不会去改全局的那个）。

```python
count = 0

def broken():
    count = 100        # 这是新建了一个局部 count，全局的那个不受影响
    print(count)       # 100

def works():
    global count       # 声明"我要用全局的那个"
    count = 100


broken()
print(count)       # 0  ← 全局没被改
works()
print(count)       # 100 ← 这次真改了
```

**最佳实践：不要用 `global`。** 需要修改全局状态时，把数据传进去、把结果返回出来：

```python
def add_to_total(amount, current_total):
    """返回新的总额，而不是修改外部变量。"""
    return current_total + amount


total = 100
total = add_to_total(50, total)     # 显式地接住返回值
print(total)       # 150
```

### 2.6 函数是"一等公民"

Python 的函数可以：
- **赋给变量**：`double = lambda x: x * 2`（`lambda` 就是"一次性小函数"）
- **当参数传给别的函数**：`sorted(scores, key=scores.get)`
- **放进列表**：`operations = [加, 减, 乘]`
- **当返回值返回**：`def get_adder(): return 加`

```python
def add(a, b):
    return a + b


# 函数赋给变量
operation = add
print(operation(3, 4))    # 7

# lambda：一个参数的小函数，写法极简
square = lambda x: x ** 2
print(square(5))         # 25

# 函数放进列表，根据需要选
operations = [lambda a, b: a + b, lambda a, b: a - b, lambda a, b: a * b]
print([op(10, 3) for op in operations])    # [13, 7, 30]
```

这个特性的价值在单元 11 的投票分析器里会充分体现——你可以把"加票"和"投票"两个函数分别交给两个不同的类。

### 2.7 把函数存进模块（教材 8.6）

函数越写越多，一个 `.py` 文件迟早会到几百行：定义、调用、测试混在一起，改一处要滚半天。教材 8.6 的解法是**按用途拆文件**——一个 `.py` 文件就是一个**模块**，模块名就是文件名去掉 `.py`。

**最小的模块就是两个文件。**

```python
# （片段）pizza.py —— 函数放在这里，文件名就是模块名
def make_pizza(size, *toppings):
    """概述要制作的披萨。"""
    print(f"\n制作 {size} 寸披萨，配料：")
    for t in toppings:
        print(f"  - {t}")


if __name__ == "__main__":
    make_pizza(12, "蘑菇", "青椒")     # 只有直接运行 pizza.py 才执行
```

```python
# （片段）main.py —— 与 pizza.py 放在同一目录
import pizza                        # ① 导入整个模块
from pizza import make_pizza        # ② 只导入函数
from pizza import make_pizza as mp  # ③ 导入并起别名
import pizza as p                   # ④ 给模块起别名

pizza.make_pizza(16, "芝士")          # ① 用「模块名.函数名」调用
make_pizza(12, "蘑菇")               # ② 直接调用
mp(9, "榴莲")                        # ③ 用别名调用
p.make_pizza(6, "玉米")               # ④ 别名也能点出函数
```

四种写法没有优劣，区别只在**调用时写多长**和**名字冲突的风险**：

| 写法 | 调用时要写 | 适合场景 |
|---|---|---|
| `import pizza` | `pizza.make_pizza()` | 模块名短、函数多，一眼看出函数来自哪 |
| `from pizza import make_pizza` | `make_pizza()` | 只用一两个函数，代码更短 |
| `from pizza import make_pizza as mp` | `mp()` | 函数名太长，或与本地函数重名 |
| `from pizza import *` | `make_pizza()` | **不推荐**：导入了什么看不出来，容易覆盖同名变量 |

**`if __name__ == "__main__":` 到底在防什么？** 每个模块都有一个内置变量 `__name__`：

- 直接运行这个文件时，`__name__` 的值是 `"__main__"`；
- 被别的文件 `import` 时，`__name__` 的值是模块名 `"pizza"`。

所以把「只有自己运行时才该做的事」（打印演示、跑一遍自测）放进这个判断里，别人 import 你的函数时就不会被那些 `print` 打扰。**模块顶层不要写会造成副作用的代码**（打印、`input()`、删文件），这是 Python 模块的基本礼貌。

```python
# （片段）两种结果对照
# 直接运行：      python pizza.py   → __name__ == "__main__" → 打印演示
# 被别人导入：    import pizza      → __name__ == "pizza"    → 只拿到函数，不打印
```

> **要点**
> - 模块名不能和标准库重名：自己写一个 `random.py`，`import random` 就会导入你自己那个，标准库彻底用不了。
> - 同目录才能直接 `import`；跨目录要靠包（带 `__init__.py` 的文件夹）或 `sys.path`，本课程不展开。
> - 导入是**执行一次**模块顶层代码，之后再用不会重复执行——这也是为什么顶层别写副作用。
> - 模块里的函数照样要遵守 2.1～2.6 的规则：参数、返回值、作用域都不变。

### 示例 2：return 与 None

```python
# return_demo.py —— return 的三个要点

# 有 return 和没 return 的差别
def with_return():
    return 42


def without_return():
    print("我执行了，但我什么都不返回")


print("with_return() 返回：", with_return())      # 42
print("without_return() 返回：", without_return())  # None

# return 之后立刻结束函数
def early_exit():
    return "这是第一个 return 的结果"
    print("这行永远不会执行")            # 死代码
    return "这行也永远不会执行"


print(early_exit())        # 这是第一个 return 的结果

# 一个函数可以有多个 return，但只会走一个
def classify_number(n):
    """判断正数、负数或零。"""
    if n > 0:
        return "正数"
    elif n < 0:
        return "负数"
    return "零"      # 注意：这行缩进和 if 平齐，不在 elif 里面


for value in [5, -3, 0]:
    print(f"{value} 是 {classify_number(value)}")

# 返回多个值：其实返回的是一个元组
def min_and_max(numbers):
    """返回最小值和最大值。"""
    return min(numbers), max(numbers)


smallest, largest = min_and_max([3, 9, 2, 7])
print(f"最小 {smallest}，最大 {largest}")

# 返回字典：适合"多个名字的东西"
def get_user():
    """返回用户信息的字典。"""
    return {"name": "小明", "age": 18}


user = get_user()
print(f"{user['name']}今年 {user['age']} 岁")

# 无 return 的隐式 None（容易踩坑）
def side_effect_only(numbers):
    """只打印不返回。"""
    for n in numbers:
        print(n)


result = side_effect_only([1, 2, 3])
print("返回值是：", result)      # None —— 所以别拿它参与运算
```

### 示例 3：三种参数写法

```python
# parameters.py —— 位置参数、关键字参数、默认参数

# 1）位置参数：按顺序对应
def describe_pet(animal_type, pet_name):
    """位置参数：调用时的顺序必须和定义时一致。"""
    return f"这是一只{animal_type}，名字叫{pet_name}"


print(describe_pet("狗", "旺财"))       # 狗 / 旺财
print(describe_pet("猫", "咪咪"))       # 猫 / 咪咪
# print(describe_pet("旺财", "狗"))    # 参数顺序错了，含义就全错了

# 2）关键字参数：按名字对应，顺序可以变
print(describe_pet(pet_name="旺财", animal_type="狗"))   # 顺序变了但结果正确

# 3）默认参数：可以不填，用默认值
def make_pizza(size=12, with_cheese=True):
    """默认参数：有默认值的参数必须写在最后。"""
    info = f"{size} 英寸披萨"
    if with_cheese:
        info += "，加芝士"
    else:
        info += "，不加芝士"
    return info


print(make_pizza())                          # 12 英寸披萨，加芝士
print(make_pizza(16))                         # 16 英寸披萨，加芝士
print(make_pizza(16, False))                  # 16 英寸披萨，不加芝士
print(make_pizza(with_cheese=False))          # 12 英寸披萨，不加芝士（跳过第一个）

# 4）可变参数 *args：收集所有的位置参数
def sum_all(*numbers):
    """接收任意多个位置参数。"""
    return sum(numbers)


print(sum_all(1, 2, 3))           # 6
print(sum_all(1, 2, 3, 4, 5))     # 15
print(sum_all())                  # 0

# 5）可变参数 **kwargs：收集所有的关键字参数
def build_profile(**info):
    """接收任意多个关键字参数，打包成字典。"""
    return info


print(build_profile(name="小明", age=18, city="杭州"))
print(build_profile())             # {}

# 6）四种参数混合使用（顺序有强制规定）
def full_demo(a, b=2, *args, **kwargs):
    """必填参数 -> 默认参数 -> *args -> **kwargs，顺序不能乱。"""
    print(f"a={a}")
    print(f"b={b}")
    print(f"args={args}")
    print(f"kwargs={kwargs}")


full_demo(1, 3, 5, 7, name="x", age=1)
# 错误示范：必填参数放在默认参数后面会报 SyntaxError
# def wrong(a=1, b):    # SyntaxError
#     pass
```

### 示例 4：★ 参数传递的副本语义

```python
# copy_semantics.py —— 函数里修改参数，到底影响不影响原数据

# ===== 情况1：传整数 -> 不影响原变量 =====
def add_one(n):
    n = n + 1         # 只是让参数 n 指向了一个新整数
    print(f"  函数内 n = {n}")


age = 10
add_one(age)
print(f"  函数外 age = {age}\n")     # 10  没变

# ===== 情况2：传字符串 -> 不影响 =====
def shout(word):
    word = word.upper()   # 返回了新字符串，参数指向了它
    print(f"  函数内 word = {word}")


name = "tom"
shout(name)
print(f"  函数外 name = {name}\n")   # tom  没变

# ===== 情况3：传列表 -> 会影响原列表！=====
def add_item(items):
    items.append("新元素")     # 直接改的是同一份列表
    print(f"  函数内 items = {items}")


fruits = ["苹果", "香蕉"]
add_item(fruits)
print(f"  函数外 fruits = {fruits}\n")   # ['苹果', '香蕉', '新元素']  变了！

# ===== 情况4：传字典 -> 同样会影响 =====
```

### 示例 7：默认参数的可变对象陷阱

```python
# mutable_default.py —— 默认参数不要用可变对象（重要坑）

# ===== 错误写法：默认参数用了列表 =====
def add_task(task, todo=[]):      # 注意这个 []
    """危险！默认列表只创建一次，所有调用共享它。"""
    todo.append(task)
    return todo


print(add_task("买菜"))     # ['买菜']
print(add_task("做饭"))     # ['买菜', '做饭']  <- 上次的"买菜"还在！
print(add_task("睡觉"))     # ['买菜', '做饭', '睡觉']

# 原因：默认参数在函数**定义时**只求值一次，
# 之后每次调用都用那同一份列表对象。

# ===== 正确写法1：用 None 作为默认值 =====
def add_task(task, todo=None):
    """默认值为 None，每次调用时再创建新列表。"""
    if todo is None:
        todo = []# 每次都新建一个，互不影响
    todo.append(task)
    return todo


print()
print(add_task("买菜"))     # ['买菜']
print(add_task("做饭"))     # ['做饭']  干净了

# ===== 正确写法2：用不可变类型 =====
def add_tag(tag, tags=()):        # 元组不可变，安全
    return tags + (tag,)


print()
print(add_tag("a"))     # ('a',)
print(add_tag("b"))     # ('b',)  独立

# ===== 默认参数还有另一个用途：让函数"记住"状态 =====
# 这是少数"用可变默认值"是合理的场景
def make_counter(start=0):
    """返回一个能计数的函数，记住上次的结果。"""
    return start


# 更实用的闭包写法
def make_adder(n):
    """返回一个"加了 n 的函数"。"""
    def adder(x):
        return x + n

    return adder


add_5 = make_adder(5)
print()
print("add_5(10) =", add_5(10))      # 15

print("add_10(10) =", add_10(10))    # 20  两者互不影响
```

### 示例 8：`__name__` 的两种身份

把下面这段存成 `module_demo.py` 直接运行，会看到 `__name__` 是 `"__main__"`；如果被别的文件 `import module_demo`，`__name__` 就变成 `"module_demo"`，`if` 里面的三行不会执行。

```python
# module_demo.py —— 直接运行时才跑自测
def area(w, h):
    """矩形面积。"""
    return w * h


def average(nums):
    """平均值；空列表返回 None，而不是 ZeroDivisionError。"""
    return sum(nums) / len(nums) if nums else None


print("__name__ =", __name__)          # 直接运行 → __main__

if __name__ == "__main__":
    print("面积  ", area(3, 4))
    print("平均  ", average([80, 90, 100]))
    print("空列表", average([]))
```

运行结果：

```text
__name__ = __main__
面积   12
平均   90.0
空列表 None
```

把它当模块用的时候，调用方只要写：

```python
# （片段）另一个文件里
import module_demo

print(module_demo.area(5, 6))          # 30
print(module_demo.average([]))         # None
# 上面那三行 print 不会再出现，__name__ 是 "module_demo"
```

这个模式的实际好处是：**同一个文件既能当脚本跑，又能当库被导入**，而且「跑起来会打印东西」和「被导入时安静」这两件事不用维护两份代码。单元 10 的 pytest 也会用同一种思路——测试文件被 pytest 收集，而不是被直接运行。

```python
# longest_word.py —— 找出最长单词

def longest_word_loop(words):
    """用普通循环找最长单词，长度相同返回第一个。"""
    if not words:               # 空列表要提前处理
        return ""

    longest = words[0]          # 假设第 0 个最长
    for word in words:
        if len(word) > len(longest):     # 严格大于，所以同长度保留先来的
            longest = word
    return longest


def longest_word_max(words):
    """用内置 max 找最长单词。"""
    if not words:
        return ""
    return max(words, key=len)


# 测试
words = ["apple", "banana", "watermelon", "kiwi"]
print("输入：", words)
print("循环版：", longest_word_loop(words))     # watermelon
print("max 版：", longest_word_max(words))      # watermelon
print("两者一致：", longest_word_loop(words) == longest_word_max(words))

# 边界情况：长度相同时都应返回第一个
tie = ["apple", "mango", "pear"]              # mango 和 pear 都是 5 个字母
print()
print("并列时循环版：", longest_word_loop(tie))    # mango
print("并列时 max 版：", longest_word_max(tie))     # mango
# max 也返回第一个，这是 Python 的稳定行为

print()

def all_longest_words(words):
    """返回所有达到最长长度的单词。"""

        return []
    max_len = max(len(w) for w in words)
    return [w for w in words if len(w) == max_len]
```

```python
# timer_decorator.py —— 用"函数返回函数"实现计时器

import time


def make_timer(func):
    """把一个函数包成"会自动打印耗时"的版本。"""
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)      # 真正干活
        end = time.time()
        print(f"  [{func.__name__}] 耗时 {end - start:.6f} 秒")
        return result                      # 别忘了把结果传出去
    return wrapper


# 被包装的函数：故意做点耗时的活
def slow_sum(n):
    """累加 1 到 n 的和，n 大一点才有感。"""
    total = 0
    for i in range(1, n + 1):
        total += i
    return total


def quick_answer():
    """一个几乎不耗时的函数。"""
    return 42


# ===== 使用 =====
timed_slow_sum = make_timer(slow_sum)
timed_answer = make_timer(quick_answer)

print("调用被包装的慢函数：")

print("  返回值：", result1)

        return result
    return wrapper
```

## 六、常见错误清单（务必逐条自查）

> 以下 6 类是写函数时最高频的错误。每一条都给出「症状 → 原因 → 修法」。

### 错误 1：忘记写冒号，或缩进错误

```python
# INTENTIONALLY-BROKEN 演示 5 种错误写法，请逐个修复
def greet(name)      # 错误 1a：括号后面漏了冒号
    print(name)


def greet2(name):
print(name)           # 错误 1b：函数体没有缩进


def greet3(name):
    print(name)       # 错误 1c：缩进用了 Tab 而不是 4 个空格
print("这里是函数外的代码")  # 错误 1d：函数体提前结束了，缩进不一致


def greet4(name):
    print(name)
        print("多缩进了")   # 错误 1e：同一块内缩进不一致 -> IndentationError
```

**症状**：`SyntaxError: expected ':'` / `IndentationError: expected an indented block`
**原因**：`def` 行末必须有 `:`；函数体所有行必须用**一致的 4 个空格**缩进。
**修法**：VS Code 里按 Tab 会自动插入 4 空格，不要混用 Tab。报错信息里的 `^` 会指到出问题的位置。

### 错误 2：★ 函数修改列表，会改到原列表

```python
def add_item(items):
    items.append("新元素")      # 这一行直接改掉了调用方的列表


fruits = ["苹果"]
add_item(fruits)
print(fruits)      # ['苹果', '新元素']  ← 原数据被污染了
```

**症状**：函数返回后，原列表莫名其妙多了东西；或者多个函数调用之间数据互相串味。
**原因**：列表是**可变对象**，Python 传的是"地址"，函数里改的就是原件。
**修法**（三选一）：
```python
# 修法1：函数内造副本（推荐）
def add_item(items):
    items = items[:]        # 先复制
    items.append("新元素")
    return items

# 修法2：调用时传副本
add_item(fruits[:])

# 修法3：用 + 产生新列表
def add_item(items):
    return items + ["新元素"]
```

### 错误 3：默认参数用了可变对象

```python
# INTENTIONALLY-BROKEN 演示这个隐蔽的 bug（能运行，但结果错误）
def add_task(task, todo=[]):     # 错误：默认值是列表！
    todo.append(task)
    return todo


print(add_task("买菜"))     # ['买菜']
print(add_task("做饭"))     # ['买菜', '做饭']  ← 上次的"买菜"莫名出现！
print(add_task("睡觉"))     # ['买菜', '做饭', '睡觉']
```

**症状**：单独调用正常，反复调用时结果里出现了前面调用的数据。
**原因**：默认参数在**函数定义时**只求值一次，那个列表被所有调用共享。
**修法**：
```python
def add_task(task, todo=None):     # 默认值用 None
    if todo is None:
        todo = []                 # 每次调用时新建
    todo.append(task)
    return todo
```

### 错误 4：忘记 return，函数等于白写

```python
# INTENTIONALLY-BROKEN 演示：以为改了列表就有返回值
def add_score(scores):
    scores.append(100)      # 列表确实被改了，但函数本身返回 None


result = add_score([1, 2, 3])
print(result)      # None
print(result + 1)  # TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'
```

**症状**：`TypeError: 'NoneType' object is not subscriptable` 或者结果莫名是 `None`。
**原因**：没有 `return` 的函数默认返回 `None`。修改外部数据 ≠ 返回新结果。
**修法**：明确写出 `return`。如果函数只是"做事"不改返回值（比如写文件、打印），就把 `def f():` 写成 `def f():` 并在文档里说明它没有返回值。

### 错误 5：参数顺序或数量不对

```python
def make_pizza(size=12, with_cheese=True):
    """有默认值的参数必须写在没有默认值的参数后面。"""
    return f"{size} 英寸，芝士={with_cheese}"


# INTENTIONALLY-BROKEN 演示 3 类调用错误
print(make_pizza(16, False))       # 合法：16 英寸，芝士=False
print(make_pizza(False))           # 陷阱：False 被当成了 size！
# print(make_pizza(16, 18, 20))    # 错误：Too many positional arguments
# print(make_pizza(size=16, cheese=True))   # 错误：参数名写错，应为 with_cheese

# 报错信息里有个高频拼写错误：cheese 不是 with_cheese
# TypeError: make_pizza() got an unexpected keyword argument 'cheese'
```

**症状**：`TypeError: got an unexpected keyword argument` 或结果莫名其妙。
**原因**：位置参数按顺序匹配；关键字参数按名字匹配；参数个数或名字不对。
**修法**：多个参数时**优先用关键字参数**，比如 `make_pizza(size=16, with_cheese=False)`，顺序和意图一目了然，也不用担心位置搞混。

### 错误 6：局部变量遮蔽全局变量

```python
count = 0


def reset_counter():
    count = 100       # 错误：这是新建了一个局部变量，全局 count 没变
    print(count)      # 打印 100


reset_counter()
print(count)      # 0  ← 你以为改了，其实没改
```

**症状**：函数里改了变量，函数外"莫名其妙"没变；或者函数里想读全局值却报 `NameError`。
**原因**：函数内只要出现赋值，Python 就认定这个名字是**局部**的，不会去读全局的那个。
**修法**（推荐第一种）：
```python
# 修法1（最佳）：把数据传进去，把结果返回出来
def add_to_count(current, amount):
    return current + amount


count = add_to_count(count, 100)
print(count)      # 100

# 修法2：确实需要改全局时用 global（官方不推荐）
def reset_counter():
    global count
    count = 100
```

## 七、本单元验收自测

**1. 简答题**：
```python
def modify(n):
    n = 10
    return n


x = 5
result = modify(x)
print(x, result)
```
输出什么？为什么？
> **要点**：输出 `5 10`。整数是**不可变类型**，函数内的 `n = 10` 只是让参数 `n` 指向了一个新的整数 10，原始数据 5 毫发无损。`return` 返回的 10 和外部的 `x = 5` 是两个完全无关的值。

**2. 简答题**：
```python
def add_item(items):
    items.append("新")


data = []
add_item(data)
print(data)
```
输出什么？如果希望 `data` 保持为空，应该怎么改？
> **要点**：输出 `['新']`。列表是可变对象，Python 传递的是指向列表的地址，函数内的 `append` 修改的就是 `data` 指向的那一份数据。要让 `data` 保持为空，两种改法：① 函数内先造副本 `items = items[:]` 再 append；② 或者干脆改用 `return items + ["新"]` 的纯函数写法。

**3. 判断题**：`def f(a, b=2): return a + b` 这行代码可以写成 `def f(b=2, a)` 吗？
> **要点**：不可以，会报 `SyntaxError: non-default argument 'a' follows default argument`。Python 要求有默认值的参数必须排在没有默认值的参数之后，否则调用时无法判断 `f(5)` 里的 5 是给 `a` 还是 `b`。

**4. 简答题**：`return` 语句有哪些作用？如果函数里没有写 `return`，调用它会得到什么？
> **要点**：`return` 有两个作用——① 立刻结束函数，后面的代码不再执行；② 把一个值交回调用者。没有写 `return` 的函数，调用结果是 `None`（Python 默认隐式返回 None）。这个坑很隐蔽：函数里明明修改了列表，但 `result = func(lst)` 拿到的却是 `None`。

**5. 简答题**：下面这个函数为什么第二次调用时结果里会多出第一次的"买菜"？
```python
def add_task(task, todo=[]):
    todo.append(task)
    return todo
```
> **要点**：因为默认参数 `[]` 是在**函数定义时**只求值一次，那个列表对象被后续所有调用共享。所以第二次调用时，`todo` 里已经有了第一次放进去的"买菜"。正确写法是 `def add_task(task, todo=None):`，然后在函数体里写 `if todo is None: todo = []`，让每次调用都创建一个新列表。
