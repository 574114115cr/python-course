## 二、核心知识点讲解

### 2.1 三个项目的工程流程回顾

三个项目长得完全不同（游戏、可视化脚本、Web 应用），但流程是同一条：

```text
① 读需求         搞清楚"要解决什么问题"，不是"要写什么函数"
      ↓
② 自己先拆解    ★ 别急着抄。列出：需要哪些数据、哪些模块、哪些类
      ↓            拿不准的地方先记下来，别边写边想
③ 查官方文档    只查你卡住的那一个点，不要通读整本文档
      ↓
④ 编码           一次只实现一个功能，跑通了再做下一个
      ↓
⑤ git 提交       每完成一个能跑的功能就提交一次，说明写清做了什么
      ↓
⑥ 写 README      别人（或三个月后的你）怎么把这个项目跑起来
      ↓
⑦ 重构           功能对了之后代码还乱，就拆文件、抽函数、补注释
```

★ **为什么这条流程比「跟着敲完」重要 10 倍**：跟着敲完，你得到的是**一个能跑的程序**；走完这条流程，你得到的是**一个能被接手、能被部署、能被修改的程序**。举个场景：三个月后你忘了当初为什么把 `while True` 改成 `while running`。走完 ⑤⑥，git 提交说明会告诉你「为了加暂停功能，把事件循环改成可中断的」；只跟着敲，400 行代码摆在那儿你只能重读一遍。**项目不是一次性的代码，是一份持续被修改的资产。**

| 步骤 | 常见翻车 | 正确做法 |
|---|---|---|
| ① 读需求 | 一上手就写代码，写完发现做的不是题目要的 | 用一句话写出「输入是什么、输出是什么」 |
| ② 自己先拆解 | 跳过这步直接抄，抄完不知道每行为什么这么写 | 先列数据来源 / 模块清单 / 类清单 |
| ③ 查文档 | 通读官方文档前三章，越读越乱 | 只查卡住的那一个 API：搜函数名 → 看参数 → 跑最小例子 |
| ④ 编码 | 一次写 300 行再调试 | 一次一个功能，跑通了再往下 |
| ⑤ git 提交 | 一次提交 800 行，说明写「update」 | 小步提交，说明写成「Added pause on P key」 |
| ⑥ 写 README | 只写项目简介，不写怎么跑 | 必含三段：这是什么 / 怎么装依赖 / 怎么运行 |
| ⑦ 重构 | 跳过这步，代码能跑但没人敢改 | 见 2.3 节的两条硬标准 |

### 2.2 三个项目的技术地图

这张表回答的是：**我这两个阶段到底学到了什么、这些东西各自解决了什么问题。**

| | 项目 1：外星人入侵 | 项目 2：数据可视化 | 项目 3：学习笔记（Django） |
|---|---|---|---|
| **核心技术** | Pygame 事件循环 + 精灵编组 `Group` | matplotlib + Plotly + requests | Django 的 MVT + ORM + 认证 |
| **关键 API** | `pygame.event.get()`、`pygame.sprite.Group()` | `matplotlib.pyplot`、`plotly.graph_objects` | `startproject`、`Model`、`makemigrations`、`LoginView` |
| **数据结构** | 类继承链（`Ship`/`Alien`/`Bullet` ← `Sprite`）+ 编组 | 字典套列表、列表套字典（地震数据） | 模型实例、查询集 `QuerySet` |
| **数据来源** | 无（数据在代码里） | CSV（sitka_weather）+ GeoJSON（USGS 地震） | SQLite → PostgreSQL（Platform.sh 云上） |
| **第三方依赖** | `pygame` | `matplotlib`、`plotly`、`requests` | `django`、`django-bootstrap5`、`platformshconfig`、`gunicorn`、`psycopg2` |
| **测试与部署** | 测纯逻辑函数；本地跑，不用部署 | 测数据处理函数；本地产图，不用部署 | 测视图与模型；**必须部署**：Platform.sh + 三个 yaml + 双环境配置 |

```text
项目 1 练的是「事件驱动」：  程序不按顺序跑，而是"等事件 → 处理 → 再等"
项目 2 练的是「数据流动」：  数据从哪来 → 清洗 → 变形 → 可视化 → 讲结论
项目 3 练的是「工程交付」：  有状态、有并发用户、有安全要求、要 7×24 在线
```

★ 读陌生代码时这张表就是「地图」：先猜项目属于哪一类，再去找对应的那一行技术。看代码里有 `pygame.event.get()` 就知道是事件驱动；看到 `class Model` 就知道是 Django。**先分类，再细读，效率差十倍。**

### 2.3 阶段 1 → 阶段 2 的能力跃迁

| 维度 | 阶段 1 | 阶段 2 |
|---|---|---|
| 代码规模 | 单文件几十到几百行 | 多文件、几百到上千行 |
| 文件数 | 1 个 `.py` | 目录 + 多模块 + 配置 + 模板 |
| 依赖 | 只有标准库 | 第三方库（pygame / matplotlib / Django） |
| 依赖管理 | 不用管 | `requirements.txt` 必须锁版本 |
| 数据存放 | JSON / CSV 文件 | SQLite → PostgreSQL，带迁移 |
| 别人能跑吗 | 给你代码你也许能跑 | 有 README 和 requirements，别人 5 分钟跑起来 |

**标准一：单文件不超过 300 行。** 超了按「谁在调用它」拆：

```text
alien_invasion.py  400 行  →拆成↓
├── settings.py            所有常量（颜色、数量、速度）
├── ship.py                Ship 类
├── alien.py               Alien 类
├── bullet.py              Bullet 类
├── game_functions.py      update() / check_keydown() / fire_bullet() 等纯逻辑
└── main() 留在 alien_invasion.py 里，只负责"组装"
```

拆完有个**意外的好处**：`game_functions.py` 里全是纯逻辑、不碰 pygame 屏幕，**这些函数能直接写 pytest 测试了**（测的时候根本不用开窗口）。这就是「逻辑与 I/O 分离」的实际收益。

**标准二：配置与逻辑分离。** 判据很简单：**代码里出现一个"魔法数字"或"魔法字符串"，就应该考虑搬到配置文件里。**

```python
# 反面：逻辑和配置糊在一起
def create_ship():
    return Ship(57, 63, pygame.image.load("images/ship.bmp"), 5)
    #                      ↑多少   ↑多少        ↑路径           ↑速度
    #                     改一次要动函数体，改坏了不知道是谁的锅

# 正面：配置抽到 settings.py，逻辑文件只管用
from settings import SHIP_START_X, SHIP_START_Y, SHIP_IMAGE, SHIP_SPEED

def create_ship():
    return Ship(SHIP_START_X, SHIP_START_Y, pygame.image.load(SHIP_IMAGE), SHIP_SPEED)
```

Django 侧更彻底：`ll_project/settings.py` 是纯配置，`models.py` / `views.py` 是纯逻辑。单元 20 追加 Platform.sh 配置时，**逻辑一行都没动**——这就是分离带来的安全感。

### 2.4 常见工程问题速查

这一节是「查手册」性质的，卡住时回来翻。

**问题一：依赖怎么锁？** 在虚拟环境里执行 `pip freeze > requirements.txt`，别人拿到项目后 `pip install -r requirements.txt` 重建环境。三条纪律：① **只在虚拟环境里 `pip freeze`**，否则会把系统全局的包也冻进去；② **必须带 `==` 版本号**，不带就是「装最新版」，半年后可能装到不兼容的大版本；③ **间接依赖也留着**（asgiref、sqlparse 是 Django 带进来的）。

**问题二：密钥怎么不提交？** 一行口令：**密钥只从环境变量读，永远不写进代码。**

```python
import os
# 正确：代码里没有密钥本身，值从环境变量来
SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]

# 错误：密钥躺在代码里，推到公开仓库谁都能拿到
SECRET_KEY = "django-insecure-9f8a7b6c5d4e3f2a1b0c9d8e7f6a5b4c"
```

配套三步：① `.gitignore` 忽略 `.env`、`settings_local.py`；② 仓库里放 `.env.example`，**只写键名不写值**；③ 密钥已经推出去了怎么办？**立刻去平台后台重置旧密钥**——删记录没用，旧值已在别人的克隆里。Django 的 `SECRET_KEY` 泄露，攻击者能伪造 `sessionid` cookie 冒充任意用户。

**问题三：数据库怎么备份？** SQLite 就是一个文件，`sqlite3 db.sqlite3 .backup backup.db` 或直接复制走就是备份；PostgreSQL 用 `pg_dump > backup.sql` 导出、`psql < backup.sql` 恢复。Django 侧更省事：`manage.py dumpdata > data.json` / `loaddata data.json`。三个要点：① **备份要定期**；② **异地存一份**，同一台机器上的副本在磁盘坏掉时一起没；③ **定期演练恢复**，没验证过的备份等于没有备份。

**问题四：怎么读一个没写过的项目？** 五步，顺序别乱：

```text
第 1 步  看目录树          哪些是入口？哪些是配置？哪些是测试？
第 2 步  读 README         它自称解决什么问题？怎么跑？
第 3 步  读依赖清单        requirements.txt 告诉你用了什么库
第 4 步  找入口再往外读    main.py / manage.py → 调用的函数 → 函数定义
第 5 步  grep 搜关键字     搜函数名/类名，找到全部使用点
```

第 5 步的具体命令（在项目根目录执行）：

```bash
grep -rn "def update" --include="*.py" .      # 找函数在哪定义、哪被调用
grep -rn "Group()" --include="*.py" .        # 找精灵编组在哪用
grep -rn "SECRET_KEY" --include="*.py" .     # 找密钥相关代码
grep -rn "class .*Model" --include="*.py" .  # 找 Django 模型
```

**为什么顺序重要**：从头读到尾是新手读代码最慢的方式——你会同时看到常量、工具函数、类、业务逻辑，全都混在一起。先建「地图」再进细节，才不会迷路。示例 5 会给一个能把前四步自动做掉的脚本。

### 2.5 关卡 2 的五条硬指标

先讲「为什么是这五条」，第八节再展开验收细则。五条分别对应五种能力：

| # | 指标 | 考的是 |
|---|---|---|
| 1 | 三个项目全部跑通、推到公开仓库，各有 README + requirements.txt | **可交付**：别人拿到能跑起来 |
| 2 | 「学习笔记」已部署上线，公网可访问，错误页已定制 | **能上线**：处理过真实环境的坑 |
| 3 | 能用自己的函数写出 pytest 测试并跑过（不是抄教材的） | **可验证**：不靠肉眼保证质量 |
| 4 | 接手一个没写过的 500 行 Python 项目，能读懂结构并定位一个 bug | **可阅读**：能维护别人的代码 |
| 5 | 能说清每个项目「解决了什么问题、还能怎么扩展」 | **有判断力**：知道东西值不值、往哪走 |

★ **为什么第 5 条也算硬指标**：前四条「做过」就能证明，只有第 5 条考「想清楚」。有人照抄教程做出三个项目然后寸步难行，也有人做出三个项目且清楚下一步加什么。**区别不在做过多少，在有没有判断。** 面试和实际工作里后者才真正值钱。

常见状态与补法：项目能跑但没推仓库 → 练习 21-1；推了但没 README → 必含「是什么 / 怎么装 / 怎么跑」三段；「学习笔记」只在本地跑 → 回单元 20；测试全是抄教材的 → 练习 21-2；看别人的代码就慌 → 按 2.4 五步 + 示例 5 练；说不出能怎么扩展 → 每个项目写三句「未来想法」。

### 2.6 下一步方向选择

阶段 2 到此结束，接下来不必全都学。**选一条主攻，其余当备用。**

| 想深挖 | 先学什么 | 为什么先学它 |
|---|---|---|
| **Web 后端** | Django REST Framework（把「学习笔记」的数据变成 JSON API），再看点前端基础 | 你已有 MVT + ORM + 认证的底子，加一层「给程序调用的接口」是最自然的延伸 |
| **数据分析** | pandas（读 CSV、处理缺失值、分组聚合）、numpy，再把项目 2 的图升级成交互式的 | 项目 2 用了 matplotlib，但数据清洗靠手写循环，pandas 几行就能搞定 |
| **自动化与爬虫** | `requests` 进阶（会话、超时、重试）、`beautifulsoup4`、`schedule`；**先读目标站点的 `robots.txt`** | 本质是「让程序替你重复做取数+处理」；`requests` 项目 2 已用过，起点不低 |
| **测试与工程化** | pytest 的 fixture / 参数化进阶、`unittest.mock` 打桩、`black` 格式化、`ruff` 检查、CI（GitHub Actions 跑测试） | 关卡 2 第 3、4 条就靠这条撑起来；也是「会写代码」和「会交付软件」的分界线 |

**怎么选**：① 做项目时最常卡在哪一步？卡在数据处理 → 数据方向。② 想让别人用我的东西吗？想 → Web 方向。③ 受不了「不知道别人代码在干什么」的时刻吗？受不了 → 先攻工程化。**共同的第一步**：不管选哪条，先把三个项目里**你最想改的那个**改到你自己满意。

## 三、可运行代码示例

本单元的例子全部只用标准库（`ast`、`pathlib`、`logging`），**不需要装 pygame / Django / matplotlib**，任何机器上直接跑。写文件的例子都写在 `data/` 目录下，跑完整个删掉。

### 示例 1：项目目录体检脚本（project_doctor.py）

对应 2.4 的「工程件齐全」检查。放在项目根目录跑一遍，就知道缺什么。

```python
# project_doctor.py —— 检查一个项目该有的工程件是否齐全
# 用法：python project_doctor.py [项目根目录，默认为当前目录]
import sys
from pathlib import Path

REQUIRED = ["README.md", "requirements.txt", ".gitignore"]
IGNORE_KEYWORDS = ["__pycache__", "venv", "db.sqlite3"]
SECRET_NAMES = ["SECRET_KEY", "PASSWORD", "API_KEY", "TOKEN"]
SKIP_DIRS = {".git", "__pycache__", "venv", ".venv", "env", "node_modules"}
FILE_LIMIT = 300


def read_text(path):
    """读文件；不存在或编码不对就返回空字符串。"""
    try:
        return path.read_text(encoding="utf-8")
    except (UnicodeDecodeError, OSError):
        return ""


def check_requirements(root):
    """依赖清单有没有锁版本。返回 None 表示通过。"""
    path = root / "requirements.txt"
    if not path.exists():
        return "requirements.txt 不存在"
    unpinned = [ln.strip() for ln in read_text(path).splitlines()
                if ln.strip() and not ln.strip().startswith("#")
                and "==" not in ln]
    return f"有 {len(unpinned)} 个依赖没锁版本，例如：{unpinned[:3]}" if unpinned else None


def check_gitignore(root):
    """.gitignore 有没有覆盖关键条目。"""
    path = root / ".gitignore"
    if not path.exists():
        return ".gitignore 不存在"
    missing = [k for k in IGNORE_KEYWORDS if k not in read_text(path)]
    return f".gitignore 缺少：{missing}" if missing else None


def report(root):
    """跑完全部检查并打印报告，返回问题总数。"""
    files = [p for p in root.rglob("*.py")
             if not any(part in SKIP_DIRS for part in p.parts)]
    problems = 0
    print(f"体检对象：{root.resolve()}\n【必备工程件】")
    for name in REQUIRED:
        ok = (root / name).exists()
        print(f"  [{'OK' if ok else '缺'}] {name}")
        problems += 0 if ok else 1

    print("\n【内容检查】")
    for label, result in [("依赖清单", check_requirements(root)),
                          ("忽略清单", check_gitignore(root))]:
        print(f"  [{'OK' if result is None else '问题'}] {label}"
              + ("检查通过" if result is None else f"：{result}"))
        problems += 0 if result is None else 1

    print(f"\n【代码扫描】（共 {len(files)} 个 .py 文件）")
    # 扫硬编码密钥：排除从环境变量读的、名单字面量、没赋值的行
    secrets = []
    for path in files:
        for lineno, line in enumerate(read_text(path).splitlines(), 1):
            if not any(k in line for k in SECRET_NAMES):
                continue
            if "os.environ" in line or "getenv" in line:
                continue
            if "=" not in line or "[" in line or "{" in line:
                continue
            if len(line.split("=", 1)[1].strip()) > 8:
                secrets.append(f"{path}:{lineno}")
    long_files = [f"{p}（{len(read_text(p).splitlines())} 行）" for p in files
                  if len(read_text(p).splitlines()) > FILE_LIMIT]
    for label, found in [("硬编码密钥检查", secrets),
                         (f"{FILE_LIMIT} 行检查", long_files)]:
        print(f"  [{'OK' if not found else '问题'}] {label}"
              + ("" if not found else f"：{found}"))
        problems += len(found)

    print()
    print(f"共发现 {problems} 个必须修的问题。" if problems
          else "体检通过：工程件齐全，可以推仓库 / 部署了。")
    return problems


if __name__ == "__main__":
    report(Path(sys.argv[1]) if len(sys.argv) > 1 else Path("."))
```

### 示例 2：requirements.txt 自动生成（make_requirements.py）

思路：扫项目里所有 `import` 语句，把「Python 自带的」剔掉，剩下的就是第三方依赖。

```python
# make_requirements.py —— 扫描 import 语句，列出项目用到的第三方包
# 用法：python make_requirements.py [项目根目录]
# 局限：它只猜「需要哪些包」，版本号要用 pip freeze 补上
import ast
import sys
import sysconfig
from pathlib import Path

# import 名和 PyPI 包名不一致的映射（最常踩的几个）
ALIASES = {"PIL": "Pillow", "cv2": "opencv-python",
           "sklearn": "scikit-learn", "bs4": "beautifulsoup4",
           "yaml": "PyYAML", "django_bootstrap5": "django-bootstrap5"}
INDIRECT = {"setuptools", "pip", "wheel"}
SKIP_DIRS = {".git", "__pycache__", "venv", ".venv", "env",
             "node_modules", "data", "tests"}


def known_names():
    """标准库 + 内置模块 + 已知别名，都是"不用写进 requirements"的。"""
    stdlib = Path(sysconfig.get_paths()["stdlib"])
    names = {p.stem for p in stdlib.glob("*.py")} | set(sys.builtin_module_names)
    names |= {p.name for p in stdlib.glob("*")
              if p.is_dir() and (p / "__init__.py").exists()}
    return names | set(ALIASES) | INDIRECT


def collect_imports(root, known):
    """遍历所有 .py 文件，返回 {顶层模块名: [出现位置]}（已滤掉标准库和本地模块）。"""
    found = {}
    for path in sorted(root.rglob("*.py")):
        if any(part in SKIP_DIRS for part in path.parts):
            continue
        try:
            tree = ast.parse(path.read_text(encoding="utf-8"))
        except (UnicodeDecodeError, SyntaxError):
            continue
        for node in ast.walk(tree):
            if isinstance(node, ast.Import):
                names = [x.name.split(".")[0] for x in node.names]
            elif isinstance(node, ast.ImportFrom):
                # level > 0 是相对导入，属项目内部模块，不算依赖
                names = ([node.module.split(".")[0]]
                         if node.level == 0 and node.module else [])
            else:
                names = []
            for name in names:
                found.setdefault(name, []).append(str(path))
    return {n: p for n, p in found.items() if n not in known
            and not (root / f"{n}.py").exists()
            and not (root / n / "__init__.py").exists()}


def main():
    root = Path(sys.argv[1]) if len(sys.argv) > 1 else Path(".")
    imports = collect_imports(root, known_names())
    print(f"在 {root.resolve()} 中发现 {len(imports)} 个第三方依赖：")
    for name in sorted(imports):
        print(f"  {ALIASES.get(name, name):<22} ← {', '.join(imports[name][:2])}")
    print("\n下一步：在虚拟环境里执行 pip freeze，核对版本号后写成")
    print("        包名==版本号  的形式写进 requirements.txt。")


if __name__ == "__main__":
    main()
```

### 示例 3：代码规模与圈复杂度提示（code_metrics.py）

对应 2.3 节的「单文件不超 300 行」。用 `ast` 静态统计，**不导入你的项目**，所以不会有副作用。

```python
# code_metrics.py —— 统计文件行数、函数长度和圈复杂度近似值
# 用法：python code_metrics.py [项目根目录]
# 只用标准库，不会导入你的项目代码
import ast
import sys
from pathlib import Path

SKIP_DIRS = {".git", "__pycache__", "venv", ".venv", "env", "node_modules", "data"}
FILE_LIMIT, FUNC_LIMIT, COMPLEXITY_LIMIT = 300, 50, 8
BRANCH_NODES = (ast.If, ast.IfExp, ast.While, ast.For, ast.AsyncFor,
                ast.ExceptHandler, ast.With, ast.AsyncWith, ast.Assert,
                ast.comprehension)


def count_decisions(node):
    """数一遍「会改变控制流」的节点数量，作为圈复杂度的近似。"""
    total = 0
    for child in ast.walk(node):
        if isinstance(child, BRANCH_NODES):
            total += 1
        elif isinstance(child, ast.BoolOp):
            total += max(0, len(child.values) - 1)   # a and b：每多一项 +1
        elif isinstance(child, ast.Match):
            total += len(child.cases)
    return total


def analyze_source(source, filename):
    """解析一个文件，返回 {文件, 总行数, 函数列表}（按复杂度降序）。"""
    result = {"文件": filename, "总行数": len(source.splitlines()), "函数": []}
    try:
        tree = ast.parse(source)
    except SyntaxError as error:
        result["错误"] = str(error)
        return result
    for node in ast.walk(tree):
        if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)):
            start = node.lineno
            length = getattr(node, "end_lineno", start) - start + 1
            result["函数"].append({
                "名字": node.name, "行号": start, "长度": length,
                "复杂度": count_decisions(node) + 1})   # 圈复杂度 = 决策点 + 1
    result["函数"].sort(key=lambda f: f["复杂度"], reverse=True)
    return result


def report(root):
    """扫描并打印报告，返回值得重构的处数。"""
    reports = []
    for path in sorted(root.rglob("*.py")):
        if any(part in SKIP_DIRS for part in path.parts):
            continue
        try:
            reports.append(analyze_source(path.read_text(encoding="utf-8"),
                                          str(path)))
        except UnicodeDecodeError:
            continue
    if not reports:
        print(f"{root} 下没找到 .py 文件")
        return 0
    print(f"共 {len(reports)} 个文件、{sum(r['总行数'] for r in reports)} 行、"
          f"{sum(len(r['函数']) for r in reports)} 个函数\n")
    problems = 0
    print(f"【超过 {FILE_LIMIT} 行的文件（建议拆分）】")
    big = [r for r in reports if r["总行数"] > FILE_LIMIT]
    for r in sorted(big, key=lambda x: x["总行数"], reverse=True):
        print(f"  {r['文件']}：{r['总行数']} 行")
    if not big:
        print("  无")
    problems += len(big)

    print("\n【复杂度最高的 5 个函数】")
    all_funcs = [(r["文件"], f) for r in reports for f in r["函数"]]
    for filename, func in sorted(all_funcs, key=lambda x: x[1]["复杂度"],
                                 reverse=True)[:5]:
        flag = (" ← 超标" if func["复杂度"] > COMPLEXITY_LIMIT else "") \
               + (" ← 太长" if func["长度"] > FUNC_LIMIT else "")
        print(f"  复杂度{func['复杂度']:>3}  {func['长度']:>4} 行  "
              f"{func['名字']}()  ({filename}:{func['行号']}){flag}")
        if flag:
            problems += 1
    print(f"\n共 {problems} 处值得重构。先挑「复杂度最高」的那个函数下手。"
          if problems else "\n全部在阈值以内，规模控制得不错。")
    return problems


if __name__ == "__main__":
    report(Path(sys.argv[1]) if len(sys.argv) > 1 else Path("."))
```

### 示例 4：统一日志配置模板（logging_setup.py）

三个项目都缺一个东西：**出问题时能回头查**。`print` 只适合调试，正式项目要写日志。这个模板可以直接抄进任何项目。

```python
# logging_setup.py —— 项目通用的日志配置模板
# 用法：from logging_setup import setup_logging
import logging
import logging.handlers
from pathlib import Path

LOG_FORMAT = "%(asctime)s | %(levelname)-7s | %(name)-12s | %(message)s"
DATE_FORMAT = "%Y-%m-%d %H:%M:%S"


def setup_logging(name="my_project", level="INFO", log_file="data/app.log"):
    """配置并返回一个 logger。

    装两个 handler：① RotatingFileHandler 写文件，单文件超 1MB 就轮换、最多留 3 份，
    防止日志把磁盘写满；② StreamHandler 让终端也能看到，方便开发。
    """
    logger = logging.getLogger(name)
    logger.handlers.clear()      # 重复调用时先清空，否则日志会打印好几遍
    logger.setLevel(getattr(logging, level.upper(), logging.INFO))
    logger.propagate = False     # 不冒泡到 root，避免重复输出
    formatter = logging.Formatter(LOG_FORMAT, datefmt=DATE_FORMAT)

    path = Path(log_file)
    path.parent.mkdir(parents=True, exist_ok=True)
    for handler in (logging.handlers.RotatingFileHandler(
                        path, maxBytes=1_000_000, backupCount=3,
                        encoding="utf-8"),
                    logging.StreamHandler()):
        handler.setFormatter(formatter)
        logger.addHandler(handler)
    return logger


def main():
    """最小可跑演示：建 logger → 记三条不同级别的日志。"""
    logger = setup_logging(name="demo", log_file="data/app.log")
    logger.info("程序启动")
    logger.warning("这是一条警告：磁盘占用偏高")
    logger.error("这是一条错误：连不上数据库")
    logger.info("程序正常结束，日志已写入 data/app.log")
    # 跑完可以删掉 data/ 目录


if __name__ == "__main__":
    main()
```

### 示例 5：陌生项目结构速读（explorer.py）

把 2.4 节的第 2–4 步做成一个脚本：标出每个文件的角色、读依赖清单、给出建议阅读顺序。

```python
# explorer.py —— 30 秒速读一个陌生项目
# 用法：python explorer.py [项目根目录]
import sys
from pathlib import Path

SKIP_DIRS = {".git", "__pycache__", "venv", ".venv", "env", "node_modules",
             ".idea", ".vscode", "static", "migrations"}
TEXT_SUFFIXES = {".py", ".txt", ".md", ".cfg", ".toml", ".yaml", ".yml",
                 ".json", ".ini", ".env"}
ENTRY_MARKERS = ('if __name__ == "__main__"', "def main(")
READ_ORDER = ["项目说明", "依赖清单", "★ 程序入口", "★ Django 入口",
              "配置文件", "业务逻辑", "测试"]


def read_text(path):
    """读文件；编码不对就返回空字符串。"""
    try:
        return path.read_text(encoding="utf-8")
    except (UnicodeDecodeError, OSError):
        return ""


def guess_role(path, source):
    """根据文件名和内容猜这个文件的角色。"""
    name = path.name
    if name == "manage.py":
        return "★ Django 入口"
    if name in ("settings.py", "config.py", ".env"):
        return "配置文件"
    if name == "requirements.txt":
        return "依赖清单"
    if name.startswith("test_") or "tests" in path.parts:
        return "测试"
    if name.lower().startswith("readme"):
        return "项目说明"
    if any(m in source for m in ENTRY_MARKERS):
        return "★ 程序入口"
    return "业务逻辑" if "def " in source or "class " in source else "数据/其他"


def scan_files(root):
    """★ 第 2–4 步：所有源码文件按角色归类，并打印依赖清单。"""
    print("\n【文件角色】")
    roles = {}
    for path in sorted(root.rglob("*")):
        if not path.is_file() or path.suffix not in TEXT_SUFFIXES:
            continue
        if any(part in SKIP_DIRS for part in path.parts):
            continue
        rel = str(path.relative_to(root)).replace("\\", "/")
        if rel == "requirements.txt":
            continue                      # 依赖清单单独打印
        roles.setdefault(guess_role(path, read_text(path)), []).append(rel)
    for role in sorted(roles):
        print(f"\n{role}：")
        for name in roles[role][:8]:
            print(f"    {name}")

    print("\n【依赖清单】")
    lines = [ln.strip() for ln in read_text(root / "requirements.txt").splitlines()]
    print("\n".join(f"  {ln}" for ln in lines if ln and not ln.startswith("#"))
          or "  没有 requirements.txt —— 这本身就是一个工程问题")
    return roles


def main():
    root = Path(sys.argv[1]) if len(sys.argv) > 1 else Path("data/unknown_project")
    if not root.exists():
        print(f"目录不存在：{root}（可以先随便传一个已有目录试试）")
        return
    print(f"速读目标：{root.resolve()}\n")
    roles = scan_files(root)
    print("\n【建议阅读顺序】")
    for role in READ_ORDER:
        if role in roles:
            print(f"  {role}：{roles[role][0]}")


if __name__ == "__main__":
    main()
```

**关于「行数反而变多了」**：从 412 行变成 486 行，但分布从「一个巨型文件」变成「6 个都小于 300 行的文件」，最长函数从 168 行降到 38 行。**行数增加是拆分的正常成本**（每个新文件要写 import 和模块文档字符串），换来的是：① 任何一个文件都能一口气读完；② `game_functions.py` 里的纯逻辑能直接写测试；③ 改 `settings.py` 的常量不会碰到游戏逻辑。拆分后 `alien_invasion.py` 只剩组装职责（约 80 行）：`run_game()` 里只有「创建窗口 → 建三个编组 → while 循环里查事件、调 `update_*` 函数、`draw()` 绘制、`pygame.display.flip()`」这一串骨架，所有细节都委托给了 `game_functions` 里的纯逻辑函数。**判断标准是：入口文件里如果出现了具体的碰撞坐标、速度数值，说明拆分没做干净。**

### 参考答案 21-4（陌生项目定位 bug 的完整过程）

定位 bug 的标准动作。假设读到一个这样的小游戏片段：

```python
# buggy_code.py —— INTENTIONALLY-BROKEN 演示用：4 处 bug，请自己发现
import pygame


def check_keydown(event, ship, bullets):
    """处理按键。"""
    if event.key == pygame.K_q:
        sys.exit()                      # bug 1：用了 sys.exit() 但没 import sys
    elif event.key == pygame.K_SPACE:
        bullets.add(Bullet(ship))       # bug 2：Bullet 类没定义、也没导入
    elif event.key == pygame.K_RIGHT:
        ship.moving_right = False       # bug 3：按右键反而停下，应该 = True


def update_aliens(aliens):
    """让整个舰队横向移动。"""
    for alien in aliens.sprites():
        alien.x += 1
    if len(aliens) == 0:
        game_active = False            # bug 4：只是定义了函数内的局部变量
```

**定位过程（这四步就是关卡 2 第 4 条的答案）**：

| 步骤 | 做法 | 对上面代码的发现 |
|---|---|---|
| ① 分类 | 看 import 和目录：用了 pygame，属于「事件驱动的图形程序」 | 搜 `if __name__` 找到入口 `run_game()` |
| ② 静态看 | 从入口往下追三层：`run_game` → `check_keydown` / `update_aliens` | 找到两个可疑函数 |
| ③ 读报错 | 看 traceback 的**最后一行**（异常类型）和**第一行 File "…", line N** | `NameError: name 'sys' is not defined`（bug 1）→ 定位到具体行 |
| ④ 判断是不是 bug | 对着「代码想表达的意思」逐行对照 | bug 2/3/4 静态就能看出来 |

**修复要点**：bug 1、2 补上 `import sys` 和 `from bullet import Bullet`；bug 3 把 `ship.moving_right = False` 改成 `True`；bug 4 把 `update_aliens` 改成接收一个 `game_state` 字典参数，写 `game_state["active"] = False`，让状态改动作用到调用方可见的对象上。

★ bug 4 最值得记住：`game_active = False` 只在函数内创建了一个**局部变量**，函数一返回就没了，调用方的状态一点没变。这和阶段 1 里 `self.count = count` 是同一个家族的问题——**赋值只是给一个名字绑定对象，能不能影响别人，取决于这个名字的作用域。**

## 六、常见错误清单（务必逐条自查）

### 错误 1：★ 没有 .gitignore 就 `git add .`，虚拟环境和数据库进了仓库

**现象**：`git push` 传了 400MB。**原因**：没有 `.gitignore`，`git add .` 把一切都加进去了。**修复**：补写 `.gitignore`，再 `git rm -r --cached ll_env` 把已跟踪文件撤出索引（只删索引，不删本地文件），然后提交。

### 错误 2：`pip freeze` 在全局环境执行，清单长到没法看

**现象**：requirements.txt 有 80 行，大部分是本项目没用到的包。**原因**：没建虚拟环境就 `pip freeze`，冻的是全局环境。**修复**：`python -m venv venv` → 激活 → 只装项目需要的包 → `pip freeze > requirements.txt`。

### 错误 3：★ 测试全是抄教材的，自己一条没写

**现象**：关卡 2 第 3 条过不了。**原因**：`test_game_functions.py` 里全是照抄的用例，没有一条针对你自己写的代码。**修复**：挑 3 个自己的纯逻辑函数，各写 2 条断言具体数值的测试（练习 21-2）。**判断标准**：关掉讲义后还能写出来，才算真的会。

### 错误 4：把 SECRET_KEY 硬编码在 settings.py 里，还推上了公开仓库

**现象**：仓库公开后被人 issue 提醒。**原因**：`SECRET_KEY = "django-insecure-…"` 直接写在代码里。**修复**：改成 `os.environ["DJANGO_SECRET_KEY"]`，**立刻去平台后台重置旧密钥**（删记录没用，克隆里已经有了），把 `.env` 加进 `.gitignore`、提交 `.env.example` 说明要配哪些变量。

### 错误 5：代码里全是魔法数字，改一个参数要翻 8 个文件

**现象**：「敌人快一点」这个需求改了半小时。**原因**：`alien.rect.top += 1` 这种数字散落在各处。**修复**：按 2.3 标准二抽到 `settings.py`，用有名字的常量替换；改完再搜一遍那个数字，确认没有漏网。

### 错误 6：所有代码堆在一个文件里，两千行

**现象**：想加个功能要读 500 行才敢动手；pytest 一导入就把 pygame 窗口开起来了。**原因**：没拆文件（2.3 标准一）。**修复**：按「谁调用它」拆，**先把纯逻辑挑出来——这一步顺带就解决了测试要开窗口的问题**。

## 七、本单元验收自测

**1. 判断题**：跟着教材把三个项目完整敲了一遍，就算「具备独立做项目的能力」了。
> **要点**：**错误**，也是最需要警惕的自我感觉。跟着敲得到的是**能跑的代码**；独立做项目需要的是**能交付、能维护、能被接手**的工程——判断标准就是关卡 2 那五条。三个项目敲完但一条硬指标没过，只能算「完成了教材」。

**2. 简答题**：为什么 `requirements.txt` 里每个依赖都要写 `==` 版本号？什么时候可以不写？
> **要点**：因为部署环境是一台全新的机器，只能靠清单重建；不带版本号就是「装最新版」，大版本升级可能带不兼容改动，半年后重建环境直接启动失败。可以不写的情况只有一种：**这个包只在你本地开发环境用**（如 `platformshconfig`、本地 `gunicorn`），但即使这种也建议写清，注释说明理由。

**3. 改错题**：下面这段想把「最高分」从 JSON 文件读出来，错在哪里？该怎么改？

```python
# high_score_buggy.py —— INTENTIONALLY-BROKEN 演示用：改错题
import json

HIGH_SCORE_FILE = "data/high_score.json"


def load_high_score():
    with open(HIGH_SCORE_FILE) as f:      # 第一次运行时文件还不存在，会直接崩
        return json.load(f)["score"]
```

> **要点**：三个问题。① **没处理文件不存在**：第一次运行 `FileNotFoundError` 直接崩，游戏开不了；修法是 `try/except FileNotFoundError` 返回默认值 0。② **没指定 `encoding="utf-8"`**：Windows 默认按 GBK 打开，含中文时抛 `UnicodeDecodeError`。③ **路径硬编码**：按 2.3 标准二应放进 `settings.py`。建议另补 `except json.JSONDecodeError` 处理文件被写坏的情况。

**4. 简答题**：接手一个 500 行的陌生项目，你的前三步分别做什么？为什么不能从头读到尾？
> **要点**：① **画目录树 + 标文件角色**（入口 / 配置 / 测试 / 业务逻辑 / 数据），`python explorer.py 项目路径` 可自动完成；② **读 README 和 requirements.txt**，知道它解决什么问题、用了什么库；③ **从入口往下追三层调用关系**（`__main__` → `main()` → 它调用的函数 → 被调用函数的定义）。从头读到尾会把常量、工具函数、类、业务逻辑混着看，读完记不住也拼不出全貌——**先建地图再进细节，是读代码的第一原则**。

**5. 简答题**：`print()` 和 `logging` 有什么区别？为什么正式项目要用后者？
> **要点**：`print` 无条件打到标准输出，没有时间戳、没有级别、不能按级别开关、不能按文件分类、出错后不留痕。`logging` 有级别（DEBUG/INFO/WARNING/ERROR）、有格式（时间+级别+模块+内容）、可同时输出到终端和文件（`RotatingFileHandler` 自动轮换防写满磁盘）。用 logging 的真正价值是：**出问题时能回头查「那一刻发生了什么」**。模板见示例 4。
