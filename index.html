这门课要解决什么

不是「学完语法」，是「能独立写出一个别人能接手、能长期改的程序」。

能独立完成并上线一个 Django Web 应用。
会写测试、会用 Git、管好依赖、读得懂 500 行别人的项目。

实操必须压过讲解。讲得多不等于学得多，跑出输出才算。

零基础教学三原则

  • 讲完 10 分钟内必须敲一次代码。报错是教材，不要擦掉。练习顺序：照抄 → 改需求 → 自己写。
  • 单元 3、6、7、8 允许放慢 50%。这四章是分水岭，课时可加、练习翻倍。允许落后，不允许跳过。
  • 每个单元都要有可跑的产出物。一个能跑的小程序 + 一次 git 提交，正反馈才撑得住三周。

六处最容易卡住的地方

第 4–7 章语法陡增、缩进错多 → 动手练重做，同题写三遍
第 8 章 函数不知该拆几个 → 先抄 3 例，再改需求
第 9 章 类最劝退 → 慢 2 周，造学生/购物车/账户三例
第 10 章 文件乱码/找不到 → 全程 pathlib + with + utf-8
第 11 章 测试不会测 → 单元 0 就建虚拟环境，只测小函数
学不下去战线太长 → 降难度做 20 行小程序，两天内见效

零基础的三种假信号

下面这三句话，出现任意一条就等于没学会：

  • 「我好像看懂了」
  • 「跟着敲一遍没问题」
  • 「这段逻辑很清楚」

真信号只有一个：不看讲义，从空文件开始敲出来。
