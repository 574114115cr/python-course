一、学习目标

完成本单元后，你应该能够：

  1. 在自己的电脑上安装 Python 3.12 或更高版本，并在终端里用 python --version 验证成功。
  2. 安装并配置 VS Code + Python 扩展，能用「运行」按钮或快捷键执行一个 .py 文件。
  3. 独立创建一个项目目录，写出并运行人生第一个 hello.py，并能读懂最简单的报错信息。
  4. 用 git init / add / commit / log 建立自己的第一个版本仓库，并配置好 .gitignore。
  5. 说清「终端 / 编辑器 / 解释器」三者的区别，知道自己的代码最终由谁执行。

二、核心知识点讲解

2.1 Python 解释器：写的是"食材"，跑的是"厨师"

Python 是一门解释型语言。你写的 .py 文件只是纯文本（叫"源代码"），机器本身并不认识它。真正把文本变成机器能执行的动作，需要一个叫 Python 解释器 的程序来完成。

生活化类比：你写了一张菜谱（.py 文件），但菜谱不会自己变成菜。必须有厨师（解释器）照着做，才能端上桌（输出结果）。所以"运行 Python 代码"这件事，物理上必然是：某台机器上的某个解释器程序，读取你的文本文件，逐行执行。

理解这一点，你就明白了为什么安装 Python 是第一步——没有厨师，菜谱就是废纸。

2.2 终端（命令行）：和解释器对话的窗口

终端（Windows 上叫 PowerShell 或命令提示符，macOS/Linux 上叫 Terminal）是一个可以输入文字的地方。你在里面输入 python hello.py，回车，解释器就会去读取并执行那个文件。

初学者最常见的困惑是"我怎么确认自己装好了？"——标准动作是打开终端，输入：

终端命令python --version

如果屏幕回你一行 Python 3.12.x，说明解释器已经装好并且在 PATH 里能找到。如果报 'python' 不是内部或外部命令，几乎一定是安装时没有勾选 "Add Python to PATH"。这个勾选项的作用，就是告诉 Windows"以后我在任何目录里敲 python，都去那个安装位置找它"。

另外两个你会立刻用到的命令：

  • cd 文件夹名 —— 进入某个目录（change directory）
  • dir（Windows）或 ls（macOS/Linux）—— 列出当前目录里有什么

2.3 VS Code + Python 扩展：写代码的写字板

编辑器不是解释器，它只是"写字板"。VS Code 负责让你写代码更舒服：语法高亮（关键字变色）、自动缩进、括号补全、侧边栏文件树。

装上微软官方的 Python 扩展（Python by Microsoft）之后，VS Code 额外获得：

  • 右上角的 ▶ 播放按钮，一键运行当前文件
  • 智能提示：打了一半的函数名，会自动补全并显示参数说明
  • 错误提示：你在当前文件还没运行之前，就能看到红波浪线告诉你哪里写错了

记住这个分工：编辑器负责"写"，解释器负责"跑"，终端负责"把两者连起来"。

2.4 第一个报错：报错是你的朋友

几乎每个人第一天都会遇到这个：

故意写错 · 先跑一遍看报错print("Hello, Python!"   # ← 结尾少了一个右括号
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪

运行后会得到：

报错信息  File "hello.py", line 1
    print("Hello, Python!"
                                ^
SyntaxError: '(' was never closed

读报错只需看三行信息：

  • File "hello.py", line 1 —— 哪个文件、第几行
  • 那行代码 + 一个 ^ 箭头 —— 箭头指着的就是问题所在
  • SyntaxError: '(' was never closed —— 人类语言的错误原因

中文意思是：语法错误：左括号对应的右括号从来没被写出来。

对应教材附录 C 的排错思路：先看行号 → 再看箭头 → 最后读错误类型。

2.5 Git：给代码拍快照

Git 是一个版本控制系统，作用是给你的代码拍快照。写崩了可以回到任何一个快照。

四个必须先掌握的指令：

指令 生活化含义
git init 在这个文件夹里放一个"快照仓库"，从此开始记录
git status 现在有哪些改动？哪些已经收进仓库了？
git add 文件名 挑几件改动放进"待提交篮子"
git commit -m "说明" 给这批改动盖章存档，写清这次干了什么
git log 翻看历史存档记录

.gitignore 则是一份"永远别记录这些"的清单，比如虚拟环境、缓存、__pycache__。它不是 Python 特有的，GitHub 官方提供了各语言模板，Python 项目里常见的几行是：

.gitignore__pycache__/
*.pyc
.venv/

2.6 建议的目录结构

从第一天起就养成"一个项目一个文件夹"的习惯，单元 10 开始你会立刻感谢自己：

目录结构my_project/
├── .gitignore
├── README.md
├── venv/              ← 虚拟环境（可随时删掉重建，不要手动改）
├── main.py            ← 主程序入口
├── data/
│   └── sample.txt     ← 数据文件放这里
└── tests/
    └── test_main.py   ← 测试代码放这里（单元 10 会用）

示例 2：先写后跑的顺序演示（体会"从上到下"）

Python# order_demo.py —— Python 严格从上往下逐行执行

print("第一步：准备开始")     # 第 1 行最先打印

name = "小明"                # 第 3 行：把"小明"这个名字存进变量 name
print("第二步：变量已赋值，name =", name)   # 第 4 行：这里才能用 name

print("第三步：程序结束")     # 最后一行

注意：如果把 print("第二步...", name) 挪到 name = "小明" 之前，程序就会报 NameError: name 'name' is not defined。

示例 3：用变量做一次简单计算

Python# calc_demo.py —— 认识变量赋值和基本运算

# 变量名 = 值，等号叫"赋值号"，把右边的东西交给左边的名字
price = 35.5        # 一个小数：单价 35.5 元
count = 3           # 一个整数：买了 3 个
total = price * count   # * 是乘法

print("单价：", price, "元")
print("数量：", count, "个")
print("总价：", total, "元")

# 变量可以被重新赋值，像一个可以反复贴标签的盒子
total = total - 5   # 抹掉零头，给 5 元优惠
print("优惠后总价：", total, "元")

示例 4：认识 print 的分隔符与注释

Python# print_demo.py —— print 的三个实用参数

# sep 指定"用什么把多个值隔开"
print("苹果", "香蕉", "橘子", sep="、")
# 输出：苹果、香蕉、橘子

# end 指定"这一行结束之后接什么"
print("正在加载", end="...")
print("完成")
# 输出：正在加载...完成（中间没有换行）

# 注释的三种写法
# 1）井号写在代码后面，前面要有两个空格才符合 PEP8
x = 1  # 这是行尾注释

# 2）单独成行的注释
# 这一整行都是说明文字

# 3）用三引号写"文档字符串"，常放在文件或函数开头
"""
这是模块级文档字符串。
说明这个文件是干什么的。
"""

示例 5：用 f-string 把变量嵌进文字里

Python# fstring_demo.py —— 格式化字符串，最常用的"拼句子"方式

name = "小红"
score = 92.567

# 普通做法：靠逗号隔开，输出会有多余空格
print("同学", name, "成绩", score)

# f-string 做法：大写 f 前缀，花括号里直接写变量名
print(f"同学{name}成绩{score}")

# 想控制小数位数，就在花括号里写 :.2f（保留两位小数）
print(f"同学{name}成绩{score:.2f}")

# 字符串里的对齐和补零也能做
num = 7
print(f"编号：{num:03d}")      # 03d 表示至少 3 位，不够前面补零 → 007
print(f"右对齐：{'hi':>8}|")     # >8 表示靠右，占 8 个字符宽度
print(f"左对齐：{'hi':<8}|")     # <8 表示靠左
print(f"居中对齐：{'hi':^8}|")  # ^8 表示居中

示例 6：初识类型与打印类型

Python# type_demo.py —— 认识 Python 的基本数据类型

print(type(name), name)       # <class 'str'> 小明

# 类比：type() 告诉你容器是什么，变量里装的是内容

五、参考答案

参考答案 0-1

终端里的输出随安装版本不同而不同，关键是确认版本号 ≥ 3.12，形如：

示例$ python --version
Python 3.12.4

$ python -c "print('命令行直接执行')"
命令行直接执行

-c 的意思是 command：把后面引号里的那一段直接当作程序执行，不写文件、不留 .py。 它最适合「只验证一句话」的场景——比如确认装对了、确认某个库能导入：

示例$ python -c "import sys; print(sys.version_info[:2])"
(3, 12)

三条自查： - 如果是 Python 3.11.x 或更低 → 本课程要求 3.12+（removeprefix、更好的错误信息都用得上），先升级。 - 如果报 'python' 不是内部或外部命令 → 装的时候没勾「Add Python to PATH」，重装或手动加环境变量。 - 如果输出的是 Python 2.7 → 你机器上有两套 Python，用 python3 --version 确认，后面统一用 python3。

六、本单元验收自测

1. 判断题：print("Hi") 这行代码能直接双击 .py 文件就看到输出吗？

要点：不能。双击是用操作系统默认方式打开文本文件，不是执行。要看到输出必须用解释器运行：在 VS Code 里点 ▶，或在终端里输入 python 文件名.py。

2. 简答题：终端提示 'python' 不是内部或外部命令，最可能的原因是什么？该怎么解决？

要点：安装 Python 时没有勾选 "Add Python to PATH"，系统不知道去哪儿找解释器。解决办法：重新运行安装包 → 勾选该选项 → 或手动把 Python 安装目录加进系统环境变量 PATH，然后重开终端。

3. 判断题：git commit -m "更新" 和 git add file.py 可以交换顺序吗？

要点：不可以。add 是"把改动放进暂存区"，commit 是"把暂存区里的内容存档"。必须先 add 再 commit，否则 commit 会提示 nothing to commit（因为暂存区是空的）。

4. 简答题：这段代码会输出什么？为什么？

Pythonprint("A")
x = 10
print("B")

要点：输出两行 A、B。因为 Python 从上往下逐行执行：x = 10 本身不产生任何输出，只有两个 print() 会打印东西。（如果把 print("B") 改成 print(x) 并挪到赋值之前，就会报 NameError——这正是"先赋值后使用"的意义。）

5. 简答题：.gitignore 是干什么的？如果没有它，提交可能出现什么问题？

要点：它是一份"永远不要记录"的清单，通常放虚拟环境（venv/）、Python 缓存（__pycache__/、*.pyc）等。缺少它时，虚拟环境里成千上万个文件会被一起提交，仓库体积暴涨、提交记录被噪音淹没，且不同电脑的缓存文件会造成大量无意义差异。

七、常见错误清单（务必逐条自查）

错误 1：'python' 不是内部或外部命令

症状：终端里敲 python --version 报这一句，但明明装过了。 原因：安装时没勾「Add Python to PATH」，系统找不到解释器。 改法：重新运行安装包选 Modify 勾上 PATH，或手动把 ...\Python312\ 与 ...\Scripts\ 加进环境变量，然后重开终端（旧窗口不会刷新 PATH）。

错误 2：按 3.12 的教程写，removeprefix 却报 AttributeError

症状：str 没有 removeprefix。 原因：装的是 3.8/3.9，这个方法是 3.9 才有的（match 语法是 3.10）。 改法：python --version 确认版本；低于 3.12 就升级——本课程按 3.12 写，前面的单元还能凑合，到单元 8 之后会到处踩坑。

错误 3：pip install requests 成功，import requests 却 ModuleNotFoundError

症状：装完导不进来。 原因：机器上有两个 Python，pip 属于另一个，VS Code 用的又是第三个。 改法：一律用 python -m pip install 包名（跟着当前解释器走）；VS Code 里 Ctrl+Shift+P → Python: Select Interpreter 选同一个解释器。

错误 4：改了代码，运行结果没变

症状：明明保存了，输出还是旧的。 原因：跑的是另一个文件（同目录下有同名 .py），或终端里跑的是缓存的 .pyc。 改法：看 VS Code 标题栏的文件名与路径；终端里用 python 完整路径/文件名.py，或先 cd 到文件所在目录。

错误 5：git checkout 之后代码没了

症状：想撤销修改，结果改的内容被覆盖。 原因：git checkout -- 文件 是「用最近一次提交覆盖工作区」，不是「撤销上一次 checkout」。 改法：先 git status 看清改了什么；只想临时回退就先 git stash（可 git stash pop 找回），别直接 checkout。
