关键词：pytest 安装、assert 断言、测试函数命名 test_*、测试类 Test*、-v 详细输出、-k 按名字筛选、@pytest.mark.parametrize、测试与被测代码分离

一、学习目标

完成本单元后，你应该能够：

  1. 用 pip install pytest 装好 pytest，并用 pytest --version 验证。
  2. 写出一个合格的测试函数：文件命名 test_*.py、函数命名 test_*、用 assert 断言结果。
  3. 区分正常用例和边界用例，会为除零、负数、空输入这类情况设计测试。
  4. 用 pytest -v 查看详细结果、用 pytest -k "关键词" 只跑相关测试，并读懂 FAILURE 报告定位问题。
  5. 用 @pytest.mark.parametrize 为同一个测试准备多组输入，理解它如何减少重复代码。

二、核心知识点讲解

2.1 为什么需要测试：Bug 有两种

类型 含义 危害
语法错误（Syntax Error） Python 读不懂你的代码 立即报错，跑不起来，很明显
逻辑错误（Logic Error） 代码能跑，但结果不对 悄无声息，可能几个月后才被发现，最危险

逻辑错误是测试唯一能对付的东西。 语法错误在第一次运行时就会暴露，根本不需要测试。

Python# 一个语法完全正确、但逻辑错误的函数
def calculate_average(numbers):
    """求平均值 —— 这个实现有 bug。"""
    return sum(numbers)      # 忘了除以个数！

print(calculate_average([80, 90, 100]))   # 270，不是 90

程序跑得通，不报任何错。如果你没有测试，这个 bug 可能一直留到有人拿它算工资的那天。

2.2 自动化测试的价值

手动测试：改一次代码 → 手动跑一遍所有功能 → 累。 自动化测试：改一次代码 → 跑一条命令 pytest → 几秒内告诉你所有测试是否通过。

生活化类比： - 手动测试像每次装修完都亲自去每个房间检查一遍门锁、水电——可靠但极慢。 - 自动化测试像装一套传感器系统，装修完按下按钮，所有房间的检测报告十几秒内全出来。

项目越大、代码改得越频繁，自动化的收益越明显。

2.3 三条硬性命名规则

pytest 靠命名约定自动发现测试，规则错了测试就"根本不被执行"：

对象 命名规则 例子
文件 test_*.py test_calculator.py
函数 test_* test_add()
类 Test*（且类里不能有 __init__） TestCalculator
类里的方法 test_* test_divide()

最高频的坑：文件名或函数名少写了 test_，pytest 静默地不跑它——不报错，但也不执行。如果你发现"pytest 说 0 passed"，第一件事就是检查命名。

Python# 下面这个类有 __init__ 是错的
class TestBad:
    def __init__(self):
        self.value = 0    # pytest 报错：不能有 __init__，测试类只用来分组


# 正确：测试类只用来把测试函数归类，不做初始化
class TestGood:
    def test_something(self):
        assert True

2.4 assert：用代码描述"应该是什么"

assert 的意思是"断言"。写法是：assert 表达式，表达式为假就报错。

Pythondef test_add():
    assert 1 + 1 == 2          # 通过：条件为真，测试通过

def test_add_wrong():
    assert 1 + 1 == 3          # 失败：AssertionError

关键在于 assert 里要写"实际结果 == 预期结果"，而不是只写实际结果：

Python# 不推荐：只测了"返回了一个东西"，测不出返回值对不对
def test_bad(result):
    assert result is not None

# 推荐：明确写出期望值
def test_good():
    assert add(2, 3) == 5

断言消息：可以给 assert 加一句说明，失败时这条消息会显示出来。这在测试复杂逻辑时非常有用：

Pythonassert actual == expected, f"期望 {expected}，实际得到 {actual}"

2.5 测试与被测代码必须分离

不要把测试代码写在被测文件里。 正确做法是两个文件：

目录结构project/
├── calculator.py       ← 被测代码（纯粹的函数定义）
└── test_calculator.py  ← 测试代码（只有测试）

这样做的好处： 1. 测试可以独立运行、独立删除（删掉测试不影响程序运行）。 2. 被测代码保持干净，没有"为了测试而加的怪代码"。 3. 一目了然哪些是测试哪些是功能。

2.6 测试用例的设计：正常 + 边界

一个好的测试不只测"正常情况"，更重要的是测"极端情况"。

类别 例子
正常用例 divide(10, 2) == 5
边界用例 divide(10, 1)、divide(1, 10)
异常用例 divide(10, 0) —— 除零会怎样？
类型用例 add("a", "b") —— 字符串能加吗？
空值用例 average([]) —— 空列表会怎样？
负数用例 factorial(-1) —— 负数怎么处理？

除零、负数、空输入这三类是最容易藏 bug 的地方，也是面试和实际工作里最常被要求测试的点。本单元的练习会重点覆盖。

2.7 parametrize：一次测很多组数据

如果同一个测试要跑 6 组数据，逐个写函数太浪费：

Python# 不推荐：6 个几乎一样的函数
def test_divide_1(): assert divide(10, 2) == 5
def test_divide_2(): assert divide(20, 4) == 5
# ...

用参数化装饰器，一行搞定：

Pythonimport pytest

@pytest.mark.parametrize("a,b,expected", [
    (10, 2, 5),
    (20, 4, 5),
    (-10, 2, -5),
    (7, 1, 7),
])
def test_divide(a, b, expected):
    assert divide(a, b) == expected

pytest 会自动把这个测试展开成 4 个独立的测试，任何一个失败都会单独报告。

2.8 运行 pytest 的常用命令

终端命令pytest                      # 运行当前目录所有测试
pytest -v                   # 详细模式：显示每个测试名和 PASSED/FAILED
pytest -vv                  # 更详细
pytest -q                   # 安静模式：只显示汇总
pytest test_calculator.py   # 只运行指定文件
pytest -k "divide"          # 只运行名字里含 "divide" 的测试
pytest -x                   # 第一个失败就停止
pytest --tb=short           # 缩短错误堆栈的显示

-v 是你用得最多的一个参数，因为它会告诉你哪个测试失败了、哪个通过了。

示例 4：测试类

Python# test_bank.py —— 测试类：把相关测试归类

import pytest


class BankAccount:
    """被测的银行账户类。"""
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance
        self.history = []

    def deposit(self, amount):
        """存款。"""
        if amount <= 0:
            raise ValueError("存款金额必须大于 0")
        self.balance += amount
        self.history.append(f"存款 {amount}")
        return self.balance

    def withdraw(self, amount):
        """取款。"""
        if amount > self.balance:
            raise ValueError("余额不足")
        self.balance -= amount
        self.history.append(f"取款 {amount}")
        return self.balance


class TestBankAccountDeposit:
    """测试类：只用来分组，不能有 __init__。"""

    def test_deposit_increases_balance(self):
        """存款后余额增加。"""
        account = BankAccount("小明", 100)
        account.deposit(50)
        assert account.balance == 150

    def test_deposit_returns_new_balance(self):
        """存款方法返回新的余额。"""
        account = BankAccount("小明", 100)
        result = account.deposit(50)
        assert result == 150

    def test_deposit_zero_raises(self):
        """存 0 元应该报错。"""
        account = BankAccount("小明", 100)
        with pytest.raises(ValueError):
            account.deposit(0)

    def test_deposit_negative_raises(self):
        """存负数应该报错。"""
        account = BankAccount("小明", 100)
        with pytest.raises(ValueError):
            account.deposit(-50)

    def test_history_records_transaction(self):
        """交易记录应该被保存。"""
        account = BankAccount("小明", 100)
        account.deposit(50)
        assert len(account.history) == 1
        assert "存款 50" in account.history[0]


class TestBankAccountWithdraw:
    """另一组测试，同样针对 BankAccount。"""

    def test_withdraw_reduces_balance(self):
        account = BankAccount("小明", 100)
        account.withdraw(30)
        assert account.balance == 70

    def test_withdraw_all_succeeds(self):
        """取光全部余额应该允许。"""
        account = BankAccount("小明", 100)
        account.withdraw(100)
        assert account.balance == 0

    def test_withdraw_too_much_raises(self):
        """取超额应该报错。"""
        account = BankAccount("小明", 100)
        with pytest.raises(ValueError):
            account.withdraw(150)

示例 5：参数化测试

Python# test_parametrize.py —— 用 parametrize 减少重复代码

import pytest


def is_prime(n):
    """判断 n 是否为素数。"""
    if n < 2:
        return False
    for i in range(2, int(n ** 0.5) + 1):
        if n % i == 0:
            return False
    return True


# ===== 不用 parametrize：写 4 个几乎一样的函数 =====
def test_prime_2():
    assert is_prime(2) is True


def test_prime_4():
    assert is_prime(4) is False


def test_prime_17():
    assert is_prime(17) is True


def test_prime_1():
    assert is_prime(1) is False


# ===== 用 parametrize：等价但更紧凑 =====
@pytest.mark.parametrize("n", [2, 3, 5, 7, 11, 13])
def test_is_prime_true(n):
    """这些数都是素数。"""
    assert is_prime(n) is True


@pytest.mark.parametrize("n", [0, 1, 4, 6, 9, 15, 100])
def test_is_prime_false(n):
    """这些数都不是素数。"""
    assert is_prime(n) is False


# ===== 多参数：一次测多组组合 =====
def divide(a, b):
    """返回 a 除以 b。"""
    return a / b


@pytest.mark.parametrize("a,b,expected", [
    (10, 2, 5.0),
    (9, 3, 3.0),
    (7, 1, 7.0),
    (-10, 2, -5.0),
    (0, 5, 0.0),
])
def test_divide(a, b, expected):
    """多组数据共用一个测试函数。"""
    assert divide(a, b) == expected


# ===== 参数化 + 异常测试 =====
@pytest.mark.parametrize("b", [0, -0.0])
def test_divide_by_zero(b):
    """除以 0 应该报错。"""
    with pytest.raises(ZeroDivisionError):
        divide(10, b)

示例 6：测试夹具（简单版）

Python# test_fixture.py —— 用 setup_method 准备测试数据

import pytest


class ShoppingCart:
    """被测的购物车。"""
    def __init__(self):
        self.items = []

    def add(self, name, price):
        self.items.append({"name": name, "price": price})

    def remove(self, name):
        self.items = [item for item in self.items if item["name"] != name]

    def total(self):
        return sum(item["price"] for item in self.items)

    def count(self):
        return len(self.items)


class TestShoppingCart:
    """用 setup_method 为每个测试准备一个全新的购物车。"""

    def setup_method(self):
        """pytest 会在每个测试函数之前自动调用这个方法。"""
        self.cart = ShoppingCart()
        self.cart.add("苹果", 5.0)
        self.cart.add("香蕉", 3.0)

    def test_cart_is_empty_before_add(self):
        """测试：初始购物车是空的。"""
        empty = ShoppingCart()
        assert empty.count() == 0
        assert empty.total() == 0.0

    def test_setup_added_two_items(self):
        """测试：setup_method 确实准备好数据了。"""
        assert self.cart.count() == 2
        assert self.cart.total() == 8.0

    def test_add_item(self):
        self.cart.add("橙子", 4.0)
        assert self.cart.count() == 3
        assert self.cart.total() == 12.0

    def test_remove_item(self):
        self.cart.remove("苹果")
        assert self.cart.count() == 1
        assert self.cart.total() == 3.0

    def test_remove_nonexistent(self):
        """删除不存在的商品不应该报错，也不应该改变购物车。"""
        self.cart.remove("西瓜")
        assert self.cart.count() == 2

四、动手练习

def count_words(text):
    """返回文本中的单词数，以空格分隔。"""
    if not text.strip():
        return 0
    return len(text.split())


def reverse(text):
    """返回反转后的字符串。"""
    return text[::-1]


def is_palindrome(text):
    """判断是否回文（忽略大小写、空格和常见标点）。"""
    # 清洗：只保留字母和数字，统一小写
    cleaned = "".join(
        char.lower()
        for char in text
        if char.isalnum()
    )
    return cleaned == cleaned[::-1]

def divide(a, b):
    """返回 a 除以 b 的结果。

    除数为 0 时会抛出 ZeroDivisionError。
    """
    return a / b


def divide_safe(a, b, default=0.0):
    """安全除法：除数为 0 时返回默认值。"""
    try:
        return a / b
    except ZeroDivisionError:
        return default

class Book:
    """一本书。"""
    def __init__(self, title, price, available=True):
        self.title = title
        self.price = price
        self.available = available

    def borrow(self):
        """借出图书。已被借出时抛出 ValueError。"""
        if not self.available:
            raise ValueError(f"《{self.title}》已被借出，无法再次借出")
        self.available = False
        return self

    def return_book(self):
        """归还图书。"""
        self.available = True
        return self

    def apply_discount(self, rate):
        """打折，rate 是 0-1 之间的折扣率。"""
        if not 0 <= rate <= 1:
            raise ValueError("折扣率必须在 0 到 1 之间")
        self.price = self.price * rate
        return self.price

class ShoppingCart:
    """购物车。"""
    def __init__(self):
        self.items = []

    def add(self, name, price):
        """添加商品。price 必须大于 0。"""
        if price <= 0:
            raise ValueError("价格必须大于 0")
        self.items.append({"name": name, "price": price})
        return self

    def remove(self, name):
        """移除指定商品。商品不存在时不报错，返回是否真的移除了。"""
        original = len(self.items)
        self.items = [item for item in self.items if item["name"] != name]
        return len(self.items) < original

    def total(self):
        """返回总价。"""
        return sum(item["price"] for item in self.items)

    def count(self):
        """返回商品件数。"""
        return len(self.items)

    def clear(self):
        """清空购物车。"""
        self.items = []
        return self

def analyze_votes(votes):
    """分析投票结果。

    参数:
        votes: 候选人名字组成的列表

    返回:
        {
            "winner": 票数最多的候选人名字；平票或无票时为 None,
            "total": 总票数,
            "counts": {候选人: 票数},
            "tied": 是否平票,
        }
    """
    # 统计票数
    counts = {}
    for name in votes:
        counts[name] = counts.get(name, 0) + 1

    total = len(votes)

    # 空列表的边界情况
    if not counts:
        return {
            "winner": None,
            "total": 0,
            "counts": {},
            "tied": False,
        }

    # 找出最高票数
    highest_count = max(counts.values())

    # 找出所有达到最高票数的候选人
    leaders = [name for name, count in counts.items() if count == highest_count]

    # 只有一个人领先才有winner，否则是平票
    winner = leaders[0] if len(leaders) == 1 else None

    return {
        "winner": winner,
        "total": total,
        "counts": counts,
        "tied": len(leaders) > 1,
    }

七、本单元验收自测

1. 简答题：下面这个测试为什么不会被 pytest 执行？

Python# test_calc.py
def check_add(a, b):
    assert a + b == 5

要点：因为函数名不以 test_ 开头。pytest 按命名约定自动发现测试，函数必须命名成 test_* 才会被收集。如果命名不对，pytest 会显示 collected 0 items——不报错，但什么都不跑，这是最容易浪费时间的问题之一。改名为 test_add 即可。

2. 简答题：为什么测试文件应该单独放在 test_calculator.py，而不是直接写在 calculator.py 里？

要点：三个理由：① 测试代码可以被独立运行、独立删除，不会影响程序正常运行；② 被测代码保持"纯粹"，不用为了配合测试而加入奇怪的辅助代码；③ 一看文件名就能分清哪些是功能、哪些是测试。标准结构是两个文件并列：calculator.py 放函数定义，test_calculator.py 放测试。

3. 判断题：用 assert 写测试时，写 assert result is not None 就够了，不需要知道 result 具体等于多少。

要点：错误。这是一种"弱断言"，很多错误的实现也能通过它（比如函数返回 "abc"、返回 0、返回 False）。正确的做法是明确写出期望值：assert add(2, 3) == 5。测试的价值在于能区分"正确的实现"和"错误的实现"，只断言非空几乎做不到这一点。

4. 简答题：测试除法函数时，除了 divide(10, 2) == 5 这种正常情况，还必须测哪些边界情况？用什么语法写？

要点：至少要测：① 除零 divide(10, 0) —— 这是最重要的，必须用 with pytest.raises(ZeroDivisionError): 断言它抛异常；② 除以 1 divide(7, 1) == 7；③ 负数相除 divide(-10, 2) == -5；④ 除不尽 divide(10, 3) 的小数结果（用 pytest.approx 比较）；⑤ 如果函数要求整数输入，还要测小数输入。核心是异常路径也必须被测试——正常路径通常能工作，bug 都藏在异常路径里。

5. 简答题：pytest -v 输出 3 passed、1 failed，-k "divide"、-x 这两个参数分别有什么用？

要点：-v（verbose）用详细模式显示每个测试的名字和 PASSED/FAILED 状态，方便定位是哪一条失败了。-k "divide" 是按测试名字筛选，只运行名字里含 divide 的测试，在测试文件变多后能大幅缩短反馈时间。-x 是遇到第一个失败就停止（fail-fast），适合"CI 里快速发现问题"的场景。加上 pytest test_bank.py::TestBook::test_borrow 这样的完整路径，可以精确运行单个测试。

八、常见错误清单（务必逐条自查）

错误 1：pytest 报 no tests ran

症状：明明写了测试，一条都没跑。 原因：文件名不是 test_*.py，或函数名不是 test_ 开头。 改法：文件 test_xxx.py、函数 def test_xxx():；pytest -q --collect-only 先看有没有被收集到。

错误 2：断言写反

症状：代码明明有 bug，测试却绿了。 原因：assert 结果 == 3 里条件为真才通过；写成 assert 结果 != 3 就是反的。 改法：写完故意改坏一行实现，确认测试变红——不会红的就是无效测试。

错误 3：浮点数直接用 ==

症状：0.1 + 0.2 == 0.3 是 False。 原因：二进制浮点有精度误差。 改法：math.isclose(a, b) 或 abs(a-b) < 1e-9；金额用 Decimal。

错误 4：测试之间互相依赖

症状：单独跑通过，一起跑失败（或反过来）。 原因：共用了全局变量/同一个文件，执行顺序变了结果就变。 改法：每个测试自己准备数据（fixture 里创建临时目录），不依赖别的测试留下的状态。

错误 5：只测「正常路径」

症状：覆盖率挺高，但用户一输入空值就崩。 原因：只测了理想输入，没测边界与非法值。 改法：每个函数至少三条：正常、边界（空/0/最大）、非法（类型错/负数）——用 pytest.raises 测异常。
