2.3 阶段 1 → 阶段 2 的能力跃迁

维度 阶段 1 阶段 2
代码规模 单文件几十到几百行 多文件、几百到上千行
文件数 1 个 .py 目录 + 多模块 + 配置 + 模板
依赖 只有标准库 第三方库（pygame / matplotlib / Django）
依赖管理 不用管 requirements.txt 必须锁版本
数据存放 JSON / CSV 文件 SQLite → PostgreSQL，带迁移
别人能跑吗 给你代码你也许能跑 有 README 和 requirements，别人 5 分钟跑起来

标准一：单文件不超过 300 行。 超了按「谁在调用它」拆：

示例alien_invasion.py  400 行  →拆成↓
├── settings.py            所有常量（颜色、数量、速度）
├── ship.py                Ship 类
├── alien.py               Alien 类
├── bullet.py              Bullet 类
├── game_functions.py      update() / check_keydown() / fire_bullet() 等纯逻辑
└── main() 留在 alien_invasion.py 里，只负责"组装"

拆完有个意外的好处：game_functions.py 里全是纯逻辑、不碰 pygame 屏幕，这些函数能直接写 pytest 测试了（测的时候根本不用开窗口）。这就是「逻辑与 I/O 分离」的实际收益。

标准二：配置与逻辑分离。 判据很简单：代码里出现一个"魔法数字"或"魔法字符串"，就应该考虑搬到配置文件里。

2.4 常见工程问题速查

这一节是「查手册」性质的，卡住时回来翻。

问题一：依赖怎么锁？ 在虚拟环境里执行 pip freeze > requirements.txt，别人拿到项目后 pip install -r requirements.txt 重建环境。三条纪律：① 只在虚拟环境里 pip freeze，否则会把系统全局的包也冻进去；② 必须带 == 版本号，不带就是「装最新版」，半年后可能装到不兼容的大版本；③ 间接依赖也留着（asgiref、sqlparse 是 Django 带进来的）。

问题二：密钥怎么不提交？ 一行口令：密钥只从环境变量读，永远不写进代码。

Pythonimport os
# 正确：代码里没有密钥本身，值从环境变量来
SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]

# 错误：密钥躺在代码里，推到公开仓库谁都能拿到
SECRET_KEY = "django-insecure-9f8a7b6c5d4e3f2a1b0c9d8e7f6a5b4c"

配套三步：① .gitignore 忽略 .env、settings_local.py；② 仓库里放 .env.example，只写键名不写值；③ 密钥已经推出去了怎么办？立刻去平台后台重置旧密钥——删记录没用，旧值已在别人的克隆里。Django 的 SECRET_KEY 泄露，攻击者能伪造 sessionid cookie 冒充任意用户。

问题三：数据库怎么备份？ SQLite 就是一个文件，sqlite3 db.sqlite3 .backup backup.db 或直接复制走就是备份；PostgreSQL 用 pg_dump > backup.sql 导出、psql < backup.sql 恢复。Django 侧更省事：manage.py dumpdata > data.json / loaddata data.json。三个要点：① 备份要定期；② 异地存一份，同一台机器上的副本在磁盘坏掉时一起没；③ 定期演练恢复，没验证过的备份等于没有备份。

问题四：怎么读一个没写过的项目？ 五步，顺序别乱：

示例第 1 步  看目录树          哪些是入口？哪些是配置？哪些是测试？
第 2 步  读 README         它自称解决什么问题？怎么跑？
第 3 步  读依赖清单        requirements.txt 告诉你用了什么库
第 4 步  找入口再往外读    main.py / manage.py → 调用的函数 → 函数定义
第 5 步  grep 搜关键字     搜函数名/类名，找到全部使用点

第 5 步的具体命令（在项目根目录执行）：

终端命令grep -rn "def update" --include="*.py" .      # 找函数在哪定义、哪被调用
grep -rn "Group()" --include="*.py" .        # 找精灵编组在哪用
grep -rn "SECRET_KEY" --include="*.py" .     # 找密钥相关代码
grep -rn "class .*Model" --include="*.py" .  # 找 Django 模型

为什么顺序重要：从头读到尾是新手读代码最慢的方式——你会同时看到常量、工具函数、类、业务逻辑，全都混在一起。先建「地图」再进细节，才不会迷路。示例 5 会给一个能把前四步自动做掉的脚本。
