一、学习目标

完成本单元后，你应该能够：

  1. 用一句话说清 API 是什么，说得出「餐厅服务员」这个类比里调用方和服务端各自的职责。
  2. 用 requests.get(url, headers=..., timeout=...) 发出请求，读懂响应对象上的 status_code、text、headers、json()。
  3. 根据 status_code 判断成败：说清 200 / 403 / 404 / 429 / 500 各自意味着什么，写出「检查状态码 + try/except」的固定套路。
  4. 调用 GitHub search API（带 Accept: application/vnd.github+json 头），从 response_dict["items"] 里提取 name、stargazers_count、html_url、description、owner.login。
  5. 用 response.headers["X-RateLimit-Remaining"] 查剩余配额，说清「未认证每小时 60 次」，知道超限返回 403。
  6. 用 px.bar、hover_data、color_discrete_map 定制条形图，并用 custom_data + hovertemplate 做出可单击的链接。
  7. 走通 Hacker News 的「两段式调用」：先取 topstories.json 拿 id 列表，再对每个 id 取 item/{id}.json 拿详情。

二、核心知识点讲解

2.1 API 是什么：餐厅服务员的类比

上一单元数据是下载文件得到的。这一单元换个思路——不下载文件，直接对着服务方要数据，这个「服务方」就是 API。

先捋一遍教材 17.1 的背景：Git 是给代码拍快照的版本控制系统；GitHub 是托管 Git 仓库的网站；一个项目文件夹叫仓库（repo）；别人给你项目点的赞叫星标（star），star 数是「热门程度」的粗略度量。而 API 就是 GitHub 提供的「服务员」——你报菜名，它端出 JSON。

API（Application Programming Interface，应用程序编程接口） 是一种约定：服务方公开一组「网址 + 参数 + 返回格式」，你按约定发请求，它按约定回数据，你不必知道它怎么实现。

★ 生活化类比：餐厅服务员。

示例你（调用方）                服务员（API）              厨房（服务器）
   │ 念菜名 ──────────────────▶  │  走进厨房、和厨师商量、   │
   │ "我要宫保鸡丁"（= URL+参数）  │                        │
   │  ◀────────────────────────── │                        │
   │  一盘菜，或一句"卖完了"       │                        │
   ▼
吃（= 你处理返回的数据）

这个类比精确在三处：① 你不需要进厨房，也不必知道宫保鸡丁先爆香还是先下肉——服务方可以随时换做法，只要端出来的还是那道菜，这就是「接口稳定、实现可变」；② 菜单公开、厨房私密——文档告诉你能点什么，服务器代码不必看；③ 服务员会拒绝你——「今天卖完了」「菜不在菜单上」对应程序里的 403 / 404，★ 要有被拒绝的心理准备。

本单元只碰教材涉及的三个接口：GitHub search API（返回仓库搜索结果）、Hacker News API（返回 id 列表与帖子详情）、以及单元 16 用过的 USGS 地震 GeoJSON。

2.2 requests.get() 与响应对象：先看 status_code ★

requests 是 Python 里发 HTTP 请求最常用的第三方库（单元 9 讲过「标准库不够用就装第三方库」）。核心只有一个函数 requests.get(url)，它返回一个 Response 响应对象——像快递包裹：拆之前先看面单（status_code）确认送对了没，再拆箱取货。对象上有四个你会反复用的东西：status_code（int，状态码，判断成败的第一道关卡）、text（str，响应体原始字符串）、headers（字典，大小写不敏感，能看到剩余配额）、json()（方法，把 JSON 响应体转成 Python 字典）。

status_code 必须先看，200 和 403 后面接的操作完全不同：

状态码 含义 你该做什么
200 成功 OK 放心用 response.json()
403 禁止 Forbidden 多半是速率限制超了或需要认证，别死循环重试
404 没找到 网址或资源 ID 写错了
429 / 500 请求过多 / 服务器出错 等一会儿再来，别重试轰炸

★ 关键：不要先写 response.json() 再想成功失败。 403 时响应体也是合法 JSON（GitHub 返回一段解释原因的 JSON），.json() 照样成功——但内容是错误信息。顺序：先 status_code，再 .json()。

取数函数三个要点一个都不能省：① try/except 包住 requests.get()——网络请求永远可能失败；② 检查 status_code；③ 失败要打印，不要静默跳过——静默跳过会画出「少了 30 个仓库」的图，你还以为它成功了。失败的请求要留下痕迹。（完整可运行版本见示例 3 的 get_json。）

2.3 .json()：把响应体变成字典 ★

这是 API 调用最关键的一步：把 JSON 文本解析成 Python 的字典和列表，从此你就能用单元 5 的字典取值、单元 7 的函数来处理它。下面这份「已经拿在手上」的响应字典（真实项目里来自 response.json()）长这样：

示例response_dict（字典）
├── total_count: 4350000         ← 总命中数，不是结果条数！
├── incomplete_results: False
└── items: [ ... ]               ← ★ 真正的结果在这里，是个列表
    ├── [0]  ← 每个元素又是一个字典（一个仓库）
    │   ├── name / stargazers_count / html_url / description
    │   │                              ↑ ★ 这个字段可能是 None！
    │   └── owner: { "login": "vinta" }  ← 字典套字典
    ├── [1] ...
    └── [N] ...

取值路线就是一层层剥：response_dict["items"][0]["owner"]["login"] → vinta。★ 难在嵌套的方括号，四对括号很容易写错。技巧：拆成中间变量一层层剥。
