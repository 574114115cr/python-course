  • ★ 多文件项目的组织原则：单文件不超过 300 行；配置与逻辑分离；一个文件只管一件事。

◆ 课堂实操（40 分钟，全程不许看答案）

  1. 装上 django-bootstrap5 并渲染表单
  2. 故意把 jumbotron 类去掉看效果

一、学习目标

完成本单元后，你应该能够：

  1. 用 django-bootstrap5 把 Django 表单变成 Bootstrap 风格，并说清 {% load %} 和 {% bootstrap_form %} 各自在干什么。
  2. 独立改造 base.html 和各页面模板，讲清每个模板文件的职责、改了它会影响哪些页面。
  3. 说清 .platform.app.yaml、.platform/routes.yaml、.platform/services.yaml 三个配置文件各自负责什么。
  4. 解释「同一份 settings.py 怎么知道自己在本地还是在云上」，以及 platformshconfig 扮演的角色。
  5. 独立完成一次完整部署：写 requirements.txt → git 提交 → platform create → platform push → 线上验证。
  6. 避开 ALLOWED_HOSTS、collectstatic、DEBUG 这三个最高频的部署坑，并按检查清单逐项自查。

二、核心知识点讲解

2.1 django-bootstrap5：一行代码让表单变漂亮（对应教材 20.1）

先回忆「学习笔记」的登录页面现在长什么样：光秃秃的输入框、光秃秃的按钮，像 1998 年的网页。原因很简单——Django 只负责把表单渲染成合法的 HTML，好不好看它一概不管：{{ form.as_p }} 渲染出的控件上没有任何 CSS 类，浏览器就用默认样式显示。生活化类比：Django 是裁缝，只保证衣服合身；好不好看是造型师的事，django-bootstrap5 就是那位造型师。

第 3 版教材用的是 django-bootstrap5（注意：不是第 2 版的 django-bootstrap4，Bootstrap 4 到 5 是不小的升级，库名也跟着换了）。用法分三步，一步都不能少：

终端命令# 1. 安装（在虚拟环境里）
(ll_env)learning_log$ pip install django-bootstrap5

Python# 2. settings.py 的 INSTALLED_APPS 里注册（不注册，模板标签不生效）
INSTALLED_APPS = [
    'learning_logs',
    'accounts',
    'django_bootstrap5',      # ← 加这一行
    # ……（Django 自带的应用略）
]

HTML{% load django_bootstrap5 %}

<form action="{% url 'login' %}" method="post">
    {% csrf_token %}
    {% bootstrap_form form %}
    <button name="submit" class="btn btn-primary">登录</button>
</form>

两行模板标签的分工一定要分清：

  • {% load django_bootstrap5 %}：把工具包拿到这个模板里。不 load 就用 bootstrap_form，Django 会报 Invalid block tag——就像工具落在家里，活儿没法干。它只负责加载，不改变任何输出。
  • {% bootstrap_form form %}：一键美颜。它内部遍历表单的每个字段，给它们包上 Bootstrap 需要的 div 和 form-control 等类名。输出的还是同一个表单，但浏览器一渲染就有了圆角、间距、聚焦高亮。

★ 这里对新手最难的是：模板标签不是 Python 函数。你没法在 {% bootstrap_form %} 里写 if、传变量、或者 print 它看看结构。Django 模板语言是故意设计得「不会写代码」的，复杂逻辑必须提到视图函数里做好、用上下文传进来。想搞清楚它到底输出了什么，老办法：浏览器里右键「查看网页源代码」。

2.2 改造「学习笔记」的界面（对应教材 20.1 各小节）

讲 Django 项目，每动一个文件都要先说清：这个文件是干什么的、改了它会影响什么。这是新手在框架里最大的迷茫——「我不知道我改的东西在哪生效」。

先建静态文件目录。静态文件指 CSS、JavaScript、图片这类「不需要服务器计算、原样发给浏览器」的文件：

示例learning_log/                  ← 项目根目录（manage.py 所在处）
├── ll_project/                ← 项目配置包（settings.py、urls.py 在这）
├── learning_logs/             ← 应用：主题和条目
│   ├── templates/learning_logs/   ← 这个应用专用模板
│   ├── static/css/styles.css      ← ★ 新建：我们自己写的样式
│   └── views.py
├── accounts/                  ← 应用：用户账户
├── templates/                 ← 项目级模板（404/500 放这，2.8 节用）
├── manage.py
└── db.sqlite3                 ← 本地开发数据库（不能传上云！）

各文件的职责和影响范围：

文件 干什么用 改了它影响什么
static/css/styles.css 补 Bootstrap 没有的样式（如 .jumbotron） 引入了这个 CSS 的页面（base.html 引了就全站）
templates/learning_logs/base.html 全站骨架：导航条 + 内容占位区 所有页面，改坏了全站 500
templates/registration/login.html 登录页 只有登录页
templates/learning_logs/index.html 主页 只有主页
templates/learning_logs/topics.html 主题列表页 只有该页

base.html 是「继承树」的根：其他模板都 {% extends %} 它，所以 Bootstrap 的 CSS 链接写在 base.html 里，一次引入全站生效。导航条部分长这样：

HTML<nav class="navbar navbar-expand-md bg-body-tertiary mb-4 border">
  <div class="container-fluid">
    <a class="navbar-brand" href="{% url 'learning_logs:index' %}">学习笔记</a>
    <ul class="navbar-nav me-auto">
      <li class="nav-item"><a class="nav-link" href="{% url 'learning_logs:topics' %}">主题</a></li>
    </ul>
    <ul class="navbar-nav ms-auto">
      {% if user.is_authenticated %}
        <li class="nav-item"><span class="navbar-text">你好，{{ user.username }}。</span></li>
        <li class="nav-item">
          <form action="{% url 'logout' %}" method="post">
            {% csrf_token %}
            <button class="btn nav-link" type="submit">退出</button>
          </form>
        </li>
      {% else %}
        <li class="nav-item"><a class="nav-link" href="{% url 'login' %}">登录</a></li>
      {% endif %}
    </ul>
  </div>
</nav>

<main class="container">
  {% block page_header %}{% endblock page_header %}
  {% block content %}{% endblock content %}
</main>

注意 {% if user.is_authenticated %}：登录和未登录的人看到不同导航，这个判断用的是 Django 自动塞进每个模板的 user 对象，视图里什么都不用做。

jumbotron：教材给主页用了一个居中的大卡片当「门面」。这里有个版本细节——jumbotron 是 Bootstrap 4 时代的组件名，Bootstrap 5 已经把它删掉了（补充说明，教材未涉及），所以第 3 版的做法是在 static/css/styles.css 里自己写一个 .jumbotron 类，把当年的效果补回来：

css.jumbotron {
    padding: 2rem 1rem;
    margin-bottom: 2rem;
    background-color: #e9ecef;
    border-radius: 0.3rem;
}

登录页的表单用 {% bootstrap_form form %} 美颜，主题列表页用 Bootstrap 列表组（list-group）逐行列出主题。这些改动的共同点是：只动模板和 CSS，不动任何 Python 代码——这就是「样式」和「逻辑」分离的好处。
