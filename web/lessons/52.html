一、学习目标

完成本单元后，你应该能够：

  1. 用 pip install pytest 装好 pytest，并用 pytest --version 验证。
  2. 写出一个合格的测试函数：文件命名 test_*.py、函数命名 test_*、用 assert 断言结果。
  3. 区分正常用例和边界用例，会为除零、负数、空输入这类情况设计测试。
  4. 用 pytest -v 查看详细结果、用 pytest -k "关键词" 只跑相关测试，并读懂 FAILURE 报告定位问题。
  5. 用 @pytest.mark.parametrize 为同一个测试准备多组输入，理解它如何减少重复代码。

二、核心知识点讲解

2.1 为什么需要测试：Bug 有两种

类型 含义 危害
语法错误（Syntax Error） Python 读不懂你的代码 立即报错，跑不起来，很明显
逻辑错误（Logic Error） 代码能跑，但结果不对 悄无声息，可能几个月后才被发现，最危险

逻辑错误是测试唯一能对付的东西。 语法错误在第一次运行时就会暴露，根本不需要测试。

Python# 一个语法完全正确、但逻辑错误的函数
def calculate_average(numbers):
    """求平均值 —— 这个实现有 bug。"""
    return sum(numbers)      # 忘了除以个数！

print(calculate_average([80, 90, 100]))   # 270，不是 90

程序跑得通，不报任何错。如果你没有测试，这个 bug 可能一直留到有人拿它算工资的那天。

2.2 自动化测试的价值

手动测试：改一次代码 → 手动跑一遍所有功能 → 累。 自动化测试：改一次代码 → 跑一条命令 pytest → 几秒内告诉你所有测试是否通过。

生活化类比： - 手动测试像每次装修完都亲自去每个房间检查一遍门锁、水电——可靠但极慢。 - 自动化测试像装一套传感器系统，装修完按下按钮，所有房间的检测报告十几秒内全出来。

项目越大、代码改得越频繁，自动化的收益越明显。

2.3 三条硬性命名规则

pytest 靠命名约定自动发现测试，规则错了测试就"根本不被执行"：

对象 命名规则 例子
文件 test_*.py test_calculator.py
函数 test_* test_add()
类 Test*（且类里不能有 __init__） TestCalculator
类里的方法 test_* test_divide()

最高频的坑：文件名或函数名少写了 test_，pytest 静默地不跑它——不报错，但也不执行。如果你发现"pytest 说 0 passed"，第一件事就是检查命名。

Python# 下面这个类有 __init__ 是错的
class TestBad:
    def __init__(self):
        self.value = 0    # pytest 报错：不能有 __init__，测试类只用来分组


# 正确：测试类只用来把测试函数归类，不做初始化
class TestGood:
    def test_something(self):
        assert True
