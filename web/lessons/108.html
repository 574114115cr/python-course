◆ 复盘（10 分钟）｜上一节：第 107 节 · 部署上线、错误页与实战

  • ★ 阶段 2 的终点不是「学完了 20 章」，而是「能独立交付一个别人能用的东西」。
  • 下一步四个方向：深 Web（Django REST / 前端）、深数据（pandas / numpy）、深自动化与爬虫、深测试与工程化。
  • 每个方向都是「先有项目、再学框架」，不要反过来先啃框架。

◆ 课堂实操（40 分钟，全程不许看答案）

  1. 用七步流程复盘自己这三个项目各走了哪几步
  2. 给一个需求现场拆成步骤清单

一、学习目标

完成本单元后，你应该能够：

  1. 完整复述做项目的七步工程流程，并解释它为什么比「跟着敲一遍」重要得多。
  2. 画出三个项目的技术地图：每个项目用了什么技术、解决了什么问题。
  3. 说清阶段 1 → 阶段 2 的能力跃迁，并用「单文件不超 300 行、配置与逻辑分离」检查自己的代码。
  4. 独立处理四个高频工程问题：依赖锁定、密钥不入库、数据库备份、读懂一个陌生项目。
  5. 用自己的函数写出 pytest 测试并跑通，并给三个项目补齐 README、requirements.txt、.gitignore。
  6. 对照关卡 2 五条硬指标逐条自测，明确说出自己还差哪一条、接下来补什么。

二、核心知识点讲解

2.1 三个项目的工程流程回顾

三个项目长得完全不同（游戏、可视化脚本、Web 应用），但流程是同一条：

示例① 读需求         搞清楚"要解决什么问题"，不是"要写什么函数"
      ↓
② 自己先拆解    ★ 别急着抄。列出：需要哪些数据、哪些模块、哪些类
      ↓            拿不准的地方先记下来，别边写边想
③ 查官方文档    只查你卡住的那一个点，不要通读整本文档
      ↓
④ 编码           一次只实现一个功能，跑通了再做下一个
      ↓
⑤ git 提交       每完成一个能跑的功能就提交一次，说明写清做了什么
      ↓
⑥ 写 README      别人（或三个月后的你）怎么把这个项目跑起来
      ↓
⑦ 重构           功能对了之后代码还乱，就拆文件、抽函数、补注释

★ 为什么这条流程比「跟着敲完」重要 10 倍：跟着敲完，你得到的是一个能跑的程序；走完这条流程，你得到的是一个能被接手、能被部署、能被修改的程序。举个场景：三个月后你忘了当初为什么把 while True 改成 while running。走完 ⑤⑥，git 提交说明会告诉你「为了加暂停功能，把事件循环改成可中断的」；只跟着敲，400 行代码摆在那儿你只能重读一遍。项目不是一次性的代码，是一份持续被修改的资产。

步骤 常见翻车 正确做法
① 读需求 一上手就写代码，写完发现做的不是题目要的 用一句话写出「输入是什么、输出是什么」
② 自己先拆解 跳过这步直接抄，抄完不知道每行为什么这么写 先列数据来源 / 模块清单 / 类清单
③ 查文档 通读官方文档前三章，越读越乱 只查卡住的那一个 API：搜函数名 → 看参数 → 跑最小例子
④ 编码 一次写 300 行再调试 一次一个功能，跑通了再往下
⑤ git 提交 一次提交 800 行，说明写「update」 小步提交，说明写成「Added pause on P key」
⑥ 写 README 只写项目简介，不写怎么跑 必含三段：这是什么 / 怎么装依赖 / 怎么运行
⑦ 重构 跳过这步，代码能跑但没人敢改 见 2.3 节的两条硬标准

第 ⑤ 步「git 提交」有个隐藏要求：说明要写给人看。三个月后你要靠这些说明回忆「当时为什么改」，update 这种说明等于没写。可以把规则写成函数，提交前跑一遍：

Python# 提交说明检查：一条好的 commit 说明能救三个月后的你
import re

BAD_WORDS = {"update", "fix", "改", "修改", "提交", "wip", "test", "111"}


def check_message(message):
    """返回问题列表；空列表表示这条说明合格。"""
    problems = []
    if len(message) < 10:
        problems.append("太短：说清「做了什么」，至少 10 个字")
    if message.strip().lower() in BAD_WORDS:
        problems.append("没有信息量：update / fix / 修改 等于没写")
    if not re.match(r"^[A-Z\u4e00-\u9fa5]", message):
        problems.append("首字母建议大写（或直接中文）")
    if not re.search(r"[A-Za-z\u4e00-\u9fa5]{3,}", message):
        problems.append("看不到实词")
    return problems


SAMPLES = [
    "update",
    "Added pause on P key, main loop is now interruptible",
    "修改",
    "Fix 403 when ALLOWED_HOSTS missing .platformsh.site",
    "把外星人下压速度抽到 settings.py",
]

for message in SAMPLES:
    problems = check_message(message)
    flag = "OK  " if not problems else "问题"
    print(f"[{flag}] {message}")
    for item in problems:
        print(f"        - {item}")

实跑结果是 3 条合格、2 条不合格：update 被抓出三个问题（太短、没信息量、首字母小写），修改 被抓出两个。判据不是「字多」，而是「看说明能不能重建当时的意图」——Added pause on P key, main loop is now interruptible 只比 update 长一点，但它回答了「改了哪、为什么改」。

2.2 三个项目的技术地图

这张表回答的是：我这两个阶段到底学到了什么、这些东西各自解决了什么问题。

项目 1：外星人入侵 项目 2：数据可视化 项目 3：学习笔记（Django）
核心技术 Pygame 事件循环 + 精灵编组 Group matplotlib + Plotly + requests Django 的 MVT + ORM + 认证
关键 API pygame.event.get()、pygame.sprite.Group() matplotlib.pyplot、plotly.graph_objects startproject、Model、makemigrations、LoginView
数据结构 类继承链（Ship/Alien/Bullet ← Sprite）+ 编组 字典套列表、列表套字典（地震数据） 模型实例、查询集 QuerySet
数据来源 无（数据在代码里） CSV（sitka_weather）+ GeoJSON（USGS 地震） SQLite → PostgreSQL（Platform.sh 云上）
第三方依赖 pygame matplotlib、plotly、requests django、django-bootstrap5、platformshconfig、gunicorn、psycopg2
测试与部署 测纯逻辑函数；本地跑，不用部署 测数据处理函数；本地产图，不用部署 测视图与模型；必须部署：Platform.sh + 三个 yaml + 双环境配置 
示例项目 1 练的是「事件驱动」：  程序不按顺序跑，而是"等事件 → 处理 → 再等"
项目 2 练的是「数据流动」：  数据从哪来 → 清洗 → 变形 → 可视化 → 讲结论
项目 3 练的是「工程交付」：  有状态、有并发用户、有安全要求、要 7×24 在线

★ 读陌生代码时这张表就是「地图」：先猜项目属于哪一类，再去找对应的那一行技术。看代码里有 pygame.event.get() 就知道是事件驱动；看到 class Model 就知道是 Django。先分类，再细读，效率差十倍。

分类这件事本身可以用代码做——扫一遍 import 和关键调用，命中哪一行就说明是哪种项目：

Python# 先分类再细读：看到这几个特征就知道是哪种项目
CORE_TECH = [
    ("pygame.event.get(", "事件驱动（游戏）", "Unit 12–14"),
    ("fig, ax = plt.subplots(", "数据可视化", "Unit 15–16"),
    ("requests.get(", "数据获取 / API", "Unit 16–17"),
    ("urlpatterns = [", "Web 应用（Django）", "Unit 18–20"),
]


def classify(sources):
    """sources 是 {文件名: 全文}；返回 (项目类型, [(类型, 单元, 文件列表)])。"""
    hits = []
    for keyword, kind, where in CORE_TECH:
        files = [name for name, text in sources.items() if keyword in text]
        if files:
            hits.append((kind, where, files))
    return (hits[0][0] if hits else "纯脚本 / 数据处理"), hits


GAME = {
    "alien_invasion.py": "while True:\n    for event in pygame.event.get():\n        pass\n",
    "settings.py": "SHIP_SPEED = 1.5\n",
}
kind, hits = classify(GAME)
print(f"项目类型：{kind}")
for name, where, files in hits:
    print(f"  证据：{name}（{where}）出现在 {files}")

print("\n换成 Django 项目：")
kind, hits = classify({"ll_project/urls.py": "urlpatterns = [path('', views.index)]"})
print(f"  项目类型：{kind}；证据 {[h[0] for h in hits]}")

print("\n★ 先分类的价值：知道是「事件驱动」就先找主循环，")
print("   知道是「Web」就先找 urls.py —— 能少读 80% 无关代码。")

GAME 里那份代码只命中 pygame.event.get(，所以直接判成「事件驱动」并指出证据文件；换成 urlpatterns = [ 就判成 Web。注意 hits[0][0] 取的是第一个命中——如果一个项目同时命中两类（比如 Django 里也发了 requests），说明它横跨两行，值得先读哪一半就得你自己判断。
