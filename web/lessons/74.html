四、动手练习

基础档

练习 13-1【编组基本功】

不打开窗口，用 pygame.sprite 完成以下流程并打印结果：创建一个 Group，放入 5 个自制精灵；调用 group.update() 让它们全部右移 100 像素；再造一个 3 成员的「子弹」编组，与前者 groupcollide()；最后 empty()。

验收点：每一步打印成员数；能说出 groupcollide() 返回值的结构（键是谁、值是谁）。

练习 13-2【复现并修复「漏删」bug】

用列表模拟子弹（每个元素是 {"id": i, "y": ...}，y <= 0 表示已飞出屏幕），故意让多个「已消失」的子弹相邻：先直接遍历列表并 remove()，数一数剩下的；再用 copy() 修复，再数一次。

验收点：错误写法至少漏删 1 个；正确写法全部删净。并用一句话回答：这和阶段 1「遍历字典时不能删键」为什么是同一个坑？

练习 13-3【边缘检测】

不用 Pygame 窗口，实现 check_edges() 的逻辑（用假 rect：宽 60、屏宽 800），验证三种情况：x = 0 → True；x = 740 → True；x = 370 → False。

验收点：三种情况判断正确；能解释为什么边界判断用 >= 和 <= 而不是 ==。

进阶档

练习 13-4【舰队密度可调】

在示例 6 的 _create_fleet() 里改计算，让每行外星人少 1 个、行数少 1 行（提示：把 number_aliens_x 和 number_rows 各减 1 是最直接的做法，但更好的做法是从「可用空间」上减去一个身位）。打印修改前后的两组数字。

验收点：打印出修改前后的 number_aliens_x 和 number_rows；能说清少一个外星人对游戏难度的影响。

练习 13-5【三条命的完整流程】

用示例 5 的 GameStats，再写一个小类模拟 _ship_hit() 的逻辑（被撞 → 减命 → 清空 → 重建 → 复位；没命了 → game_active = False）。连续撞 4 次，打印每次之后的状态。

验收点：ships_left 从 3 递减到 0；第 3 次被撞后 game_active 变 False；第 4 次撞击不再改变任何状态。

练习 13-6【子弹越打越快，结束时有简报】

在示例 6 的基础上做两个增强（都可以用不打开窗口的小程序验证）：

  • 每击落一个外星人，bullet_speed 增加 0.5，但不超过 6.0；
  • 游戏结束时打印「本局击落 X 个外星人、坚持了 Y 帧、剩余 Z 条命」。

验收点：速度封顶 6.0；击落数用 len(collisions) 累加得到；三个数字与模拟过程一致。

Python# group_basic.py —— 编组基本功（无需显示器）
import os

os.environ["SDL_VIDEODRIVER"] = "dummy"

import pygame
from pygame.sprite import Group, Sprite, groupcollide

pygame.init()


class Block(Sprite):
    def __init__(self, color, x, y):
        super().__init__()
        self.image = pygame.Surface((40, 40))
        self.image.fill(color)
        self.rect = self.image.get_rect(topleft=(x, y))
        self.vx = 0

    def update(self):
        self.rect.x += self.vx


aliens = Group()
for i in range(5):
    aliens.add(Block((200, 60, 60), 100 + i * 90, 100))
print("① 加入 5 个外星人：", len(aliens))

for alien in aliens:
    alien.vx = 100
aliens.update()
print("② 全员右移 100 后，第一个的 x：", aliens.sprites()[0].rect.x)

# 3 颗子弹，故意和外星人重叠
bullets = Group()
for i in range(3):
    bullets.add(Block((60, 60, 200), 120 + i * 90, 100))

collisions = groupcollide(bullets, aliens, True, True)
print("③ 碰撞字典的键（被撞掉的外星人）：")
for key, value in collisions.items():
    print("   ", key, "被", len(value), "颗子弹命中")
print("   碰撞后外星人剩：", len(aliens), "，子弹剩：", len(bullets))

bullets.empty()
aliens.empty()
print("④ empty() 之后：", len(bullets), len(aliens))

Python# iteration_bug.py —— 复现"边遍历边删除"的漏删 bug


def make_bullets():
    """y <= 0 表示已飞出屏幕；故意让多个消失的子弹相邻。"""
    return [{"id": i, "y": y}
            for i, y in enumerate([100, -5, -5, 80, 60, -5, -5, -5, 40])]


# 错误写法：直接遍历并删除
bullets = make_bullets()
print("删除前：", [b["y"] for b in bullets])
for bullet in bullets:
    if bullet["y"] <= 0:
        bullets.remove(bullet)
print("错误写法删除后：", [b["y"] for b in bullets])
print("还剩几个 -5：", sum(1 for b in bullets if b["y"] <= 0))

# 正确写法：遍历副本
bullets = make_bullets()
for bullet in bullets.copy():
    if bullet["y"] <= 0:
        bullets.remove(bullet)
print("正确写法删除后：", [b["y"] for b in bullets])

print("结论：迭代器按序号走，删除会让后面的元素往前补位、被跳过；"
      "这和阶段 1 遍历字典时不能删键是同一个坑。")

运行结果：

示例删除前： [100, -5, -5, 80, 60, -5, -5, -5, 40]
错误写法删除后： [100, -5, 80, 60, -5, 40]
还剩几个 -5： 2
正确写法删除后： [100, 80, 60, 40]
结论：迭代器按序号走，删除会让后面的元素往前补位、被跳过；这和阶段 1 遍历字典时不能删键是同一个坑。

Python# edge_check.py —— 边缘检测逻辑（无需 pygame）


class FakeRect:
    """模拟 pygame.Rect 的 x / right / left。"""

    def __init__(self, x, width):
        self.x = float(x)
        self.width = width

    @property
    def right(self):
        return self.x + self.width

    @property
    def left(self):
        return self.x


class Alien:
    def __init__(self, x):
        self.rect = FakeRect(x, 60)      # 外星人宽 60

    def check_edges(self, screen_width=800):
        screen_rect = FakeRect(0, screen_width)
        return (self.rect.right >= screen_rect.right) or (self.rect.left <= 0)


for x, expect in [(0, True), (740, True), (370, False), (741, True)]:
    result = Alien(x).check_edges()
    print(f"x={x:>3} → check_edges={result}（期望 {expect}）",
          "PASS" if result == expect else "FAIL")

print("解释：用 >= 和 <= 是因为'刚好贴上边缘'也算到边；"
      "速度大于 1 时可能一步跨过精确坐标，用 == 会漏判。")

运行结果：

示例x=  0 → check_edges=True（期望 True）PASS
x=740 → check_edges=True（期望 True）PASS
x=370 → check_edges=False（期望 False）PASS
x=741 → check_edges=True（期望 True）PASS
解释：用 >= 和 <= 是因为'刚好贴上边缘'也算到边；速度大于 1 时可能一步跨过精确坐标，用 == 会漏判。

六、本单元验收自测

1. 判断题：子弹列表可以用 self.bullets.pop() 直接删除，因为它就是个普通列表。

要点：错误。self.bullets 不是 list 而是 pygame.sprite.Group（编组）。Group 的 pop() 接受的是精灵对象不是下标，删完也不自动维护内部列表。要删子弹必须走 self.bullets.remove(bullet) 或 self.bullets.empty()。这题专门考「编组和列表不是一回事」——阶段 1 学列表时形成的直觉在这里会骗人。

2. 简答题：为什么删除子弹的代码要写 for bullet in self.bullets.copy():，而不是 for bullet in self.bullets:？

要点：因为在遍历过程中删除元素会漏删。遍历 self.bullets 时拿到的是一个「正在被遍历的列表」的快照式访问，一旦你在循环体里删元素，遍历指针会错位——后面的子弹被跳过，明明还在屏幕上也消失了。.copy() 先复制一份快照，遍历副本、删除原件，两边互不干扰。这和阶段 1「遍历字典时不能删键」是同一条红线，只是这次的对象换成了编组。

3. 简答题：groupcollide(self.bullets, self.aliens, True, True) 后面两个 True 分别是什么意思？改成 False 会怎样？

要点：第一个 True 是 kill_bullets——命中的子弹会被移除；第二个 True 是 kill_aliens——命中的外星人会被移除。都改成 False 的话，碰撞依然会被检测到并返回列表，但什么都不删，于是同一个外星人在原地反复被同一颗子弹判定命中、反复加分。这是新手最常见的「打不死外星人」bug 根因。

4. 判断题：检测边缘时可以写 if self.rect.left == 0:，和教材用的 >= / <= 效果完全一样。

要点：错误，只在一种情况下碰巧一样。舰队的移动步长由 aliens_speed 决定，一旦速度大于 1，rect.left 可能一步跨过 0 变成负数，== 就永远匹配不上，舰队会飞出屏幕外再也不掉头。教材用 >= / <= 是为了「越过或刚好贴上边缘」都能抓住。这个 bug 的表现是「玩着玩着整队消失」，很难查，所以要一开始就写对。

5. 简答题：Alien.check_edges() 里为什么要拿任意一个外星人来判断，而不是所有外星人？

要点：因为整支舰队是同速同向整体移动的。同一时刻所有外星人的 x 坐标差值固定，谁先到边缘一定是左端或右端那个。所以只要拿一个代表（教材里取 self.aliens.sprites()[0]，靠 Group 按加入顺序排序保证它是最左的）就够了。对每个人都调一次方法是 O(n) 的无用功，而且一旦有外星人被击落，代表就换人了，反而更乱。

6. 改错题：下面这段代码有什么问题？运行后飞船会怎样？

Pythondef _update_bullets(self):
    self.bullets.update()
    for bullet in self.bullets.copy():
        bullet.update()
        if bullet.rect.top <= 0:
            self.bullets.remove(bullet)
        if pygame.sprite.groupcollide(self.bullets, self.aliens, True, True):
            self._create_fleet()
            self.settings.aliens_speed *= 1.1

要点：检查了碰撞，却没把子弹挪出循环。命中判定已经把子弹和外星人移出编组了，但 for 仍在遍历这份快照。此时 bullet 对象虽然已不在 self.bullets 里，循环体却还会继续对它调 bullet.update()。更要命的是 self._create_fleet() 在每次碰撞时都会执行——如果同一颗子弹在同一帧击落多个外星人，或者子弹数量多，就会连续重建舰队。正确写法见正文：拿到碰撞列表后先判断 if collisions:，只在确实命中时才重建舰队并加速。
