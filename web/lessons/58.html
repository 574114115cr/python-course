2.3 一个完整项目的骨架

不管是哪个项目，结构都长这样：

Python# main.py —— 项目骨架

# 1）导入
import json
import os

# 2）常量配置
DATA_FILE = "data.json"

# 3）数据模型（类）
class Item:
    """一条数据。"""
    def __init__(self, title, value=0):
        self.title = title
        self.value = value

    def __str__(self):
        return f"{self.title} ({self.value})"


# 4）业务逻辑（函数）—— 核心逻辑必须是纯函数，方便测试
def add_items(items, new_items):
    """合并两个列表，返回新列表。"""
    return items + new_items


def summarize(items):
    """统计数据，返回字典。"""
    if not items:
        return {"count": 0, "total": 0, "max": None}
    values = [item.value for item in items]
    return {
        "count": len(items),
        "total": sum(values),
        "max": max(values),
    }


# 5）持久化层
def load_data(filename=DATA_FILE):
    """从文件加载，失败时返回空列表而不是崩溃。"""
    try:
        with open(filename, "r", encoding="utf-8") as f:
            data = json.load(f)
        return [Item(d["title"], d["value"]) for d in data]
    except FileNotFoundError:
        return []
    except json.JSONDecodeError:
        return []


def save_data(items, filename=DATA_FILE):
    """保存到文件。"""
    with open(filename, "w", encoding="utf-8") as f:
        json.dump(
            [{"title": i.title, "value": i.value} for i in items],
            f,
            ensure_ascii=False,
            indent=2,
        )


# 6）用户交互层
def main():
    """程序入口。"""
    items = load_data()
    print(f"已加载 {len(items)} 条数据")

    while True:
        print("\n1. 查看统计  2. 添加数据  3. 保存退出")
        choice = input("请选择：")

        if choice == "1":
            stats = summarize(items)
            for key, value in stats.items():
                print(f"  {key}: {value}")
        elif choice == "2":
            try:
                title = input("标题：")
                value = int(input("数值："))
                items.append(Item(title, value))
                print(f"已添加：{items[-1]}")
            except ValueError:
                print("数值必须是整数")
        elif choice == "3":
            save_data(items)
            print("已保存，再见！")
            break
        else:
            print("无效选项")


# 7）入口保护：只有直接运行这个文件时才执行 main
if __name__ == "__main__":
    main()

这个骨架的四个设计要点（每个都是阶段 1 的知识点）：

  1. 核心逻辑与 I/O 分离：add_items 和 summarize 不碰文件、不碰 input，所以能直接写单元测试；只有 load_data/save_data/main 负责 I/O。
  2. 类负责承载状态，函数负责处理逻辑：Item 只管存数据，summarize 只管算统计。
  3. 加载失败降级而不是崩溃：except FileNotFoundError: return []，让程序第一次运行时也能正常开始。
  4. if __name__ == "__main__"：让文件既能当模块被导入（测试用），又能当脚本直接运行。这是 Python 的标准惯例。

2.4 排错思路（最实用的一节）

遇到报错时，按这个顺序查，不要乱试：

代码第1 步：读报错的最后一行
        异常类型名告诉你"哪一类问题"
        IndentationError  → 缩进
        NameError         → 名字拼错/没用过
        SyntaxError       → 语法（漏冒号、括号不匹配）
        TypeError         → 类型不对（str 和 int 加在一起）
        ValueError        → 类型对但值不合法
        IndexError        → 越界
        KeyError          → 字典里没这个键
        AttributeError    → 对象没这个方法/属性
        ZeroDivisionError → 除以 0
        FileNotFoundError → 文件不存在
        ModuleNotFoundError → import 的模块找不到

第 2 步：看报错中间的行号和箭头 ^
        定位到出问题的**具体那一行**

第 3 步：把这一行逐段拆开看
        括号配对了吗？冒号写了吗？缩进对了吗？
        变量名和上面定义的一致吗？

第 4 步：往上找"这个名字定义了吗"
        NameError 90% 是这里出了问题

第 5 步：print 出来看中间值
        在出错行**之前**插一行 print，观察变量到底是什么

三个最高频报错的快速定位：

① IndentationError

故意写错 · 先跑一遍看报错def greet(name)
    print(name)        # 少冒号
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪
报错信息  File "x.py", line 2
    print(name)
IndentationError: expected an indented block

查两处：def 行末有没有冒号；函数体的缩进是不是 4 个空格。

② NameError

故意写错 · 先跑一遍看报错print(total)          # 先用了，还没定义
total = 100
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪
报错信息NameError: name 'total' is not defined

查一处：这个名字定义了吗？定义在使用之后了吗？大小写拼错了吗？（Total 和 total 是两个名字）

③ TypeError

报错信息TypeError: can only concatenate str (not "int") to str

查一处：input() 的结果要用 int() / float() 转；或者两个操作数类型不匹配。

2.4.1 调试三件套：从 print 到断点

读报错只能定位到"哪一行炸了"，但很多 bug 不报错——结果不对。这类问题靠 print 和调试器。

第一件：print 要看得出东西

Python# 坏写法：看不出哪个值是什么
print(a, b, c)

# 好写法 1：带上名字
print("a =", a, "b =", b, "c =", c)

# 好写法 2（Python 3.8+，最省事）：f-string 的等号调试语法
print(f"{a=} {b=} {c=}")          # 直接输出 a=1 b=2 c=3

# 好写法 3：看不见的字符要现形（字符串里的空格、\n 最容易骗人）
s = "hello \n"
print(s)            # 看起来就是 hello
print(repr(s))      # 'hello \n'  ← 真正的样子

repr() 是调试字符串的神器：它会把换行、制表符、首尾空格全显示出来。 判断"两个字符串为什么不相等"时，第一件事就是 print(repr(a), repr(b))。

第二件：breakpoint() 让程序停在半路

Pythondef calc(items):
    total = 0
    for it in items:
        total += it
    breakpoint()          # ← 程序会停在这里，把命令行交给你
    return total / len(items)

print(calc([1, 2, 3]))

运行后你会看到一个 (Pdb) 提示符，此时可以：

输入 作用
total 看看这个变量现在是多少
items 看看列表内容
n 执行下一行（next）
c 继续跑完（continue）
q 退出
l 显示当前代码位置

这比 print 强的地方：不用改代码就能看任何变量，看完再决定往哪走。 （breakpoint() 是 Python 3.7+ 内置的，等价于 import pdb; pdb.set_trace()，不需要装任何东西。）

第三件：VS Code 的图形调试器

  1. 在行号左边点一下，出现红点 = 断点（想停在哪就点哪一行）
  2. 按 F5（或菜单「运行 → 启动调试」）
  3. 程序停在断点上：左侧「变量」面板直接显示当前所有变量的值
  4. 按 F10 单步执行一行，F11 进入函数内部，F5 继续

图形调试器适合看"循环跑了三轮之后变量变成什么样"——用 print 得插一堆输出，用调试器点三下就行。

2.4.2 二分法定位：找不到问题在哪时

程序 200 行跑出来结果不对，从头读一遍是最慢的办法。用二分法：

Pythondef pipeline(data):
    a = step1(data)
    print("step1 后:", a)      # ← 临时插一根探针
    b = step2(a)
    print("step2 后:", b)      # ← 再插一根
    c = step3(b)
    return c

看哪一步的输出第一次"不是你预期的样子"，问题就在这两步之间。 确认之后再删掉 print——不要留着，也不要用注释掉代码的方式找 bug（见错误 3）。

2.5 阶段 1 的能力边界

你现在能做到的： - 写一个几十到几百行的单文件程序 - 用类和函数组织代码 - 让程序读写 JSON / CSV 文件 - 处理常见的用户输入错误 - 给自己的代码写 pytest 测试 - 用 Git 管理代码版本

你现在还做不到的（这些留给阶段 2 的项目篇）： - 导入第三方库（requests、pandas 等）—— 阶段 2 会教 - 搭建多文件、多模块的项目架构 - 图形界面（tkinter / PyQt） - 网络编程、数据库 - 打包成可以分发的程序

这些"做不到"完全正常。 阶段 1 的目标不是成为高手，而是掌握足以开始造东西的基础。就像学完游泳的基本动作，现在还游不快，但你已经能下水了。

2.6 卡住了怎么办：求助的正确姿势（教材附录 C）

这一节解决的是"报错看不懂、搜也搜不到、身边没人可问"。 自己能解决 80% 的问题、剩下的 20% 知道怎么问，才算真的能脱离课本自学。

2.6.1 求助前先做完这三件事

直接问人，对方也要花 10 分钟才能搞懂你的状况——大部分提问被冷落，是因为提问的人自己没先做这三步：

  1. 把报错的最后一行原样复制下来（不是凭记忆复述，是复制）
  2. 把问题压到最小：删代码删到"再删就不报错了"为止（下面 2.6.3 讲怎么做）
  3. 自己先试过至少两种改法，并把试过什么写进问题里

完成这三步，你会发现大概有三分之一的问题不用问就已经解决了——因为在压最小的过程中你自己看见了原因。

2.6.2 怎么搜：90% 的报错别人早就遇到过

搜索的关键是搜索词要用机器生成的原文，不要用你的描述：

不要这样搜 要这样搜
Python 字典报错 KeyError: 'name'
我的循环不执行 for loop doesn't run python list
字符串加数字失败 TypeError: can only concatenate str (not "int") to str

三条技巧：

  1. 只搜报错的最后一行。前面几行是调用栈，里面有你的文件名和行号，搜了也搜不到。
  2. 把你的变量名换掉。KeyError: 'user_name_2024' 搜不到东西，改成 KeyError 通用形式再搜，或者只取异常类型名。
  3. 加上版本和平台。同一个问题在 Python 3.8 和 3.12 下解法可能不同，Windows 和 macOS 的路径问题更是两回事。搜的时候带上 python 3.12 windows。
  4. 搜不到就换成英文搜。中文技术内容的覆盖面比英文小一个数量级，把报错原文贴进搜索引擎（英文原文不需要你翻译）。

判断搜索结果靠不靠谱：看发布日期（5 年前的答案可能已过时）、看有没有解释原因（只给代码不给解释的答案，照抄容易埋雷）、看是不是同一个 Python 版本。

2.6.3 最小可复现（MRE）：让问题从 200 行变成 5 行

"最小可复现示例"是把问题精简到别人复制过去就能跑、就能看到你的报错。它既是求助的利器，也是自己找 bug 的最强手段。

假设你有这么一段报错的代码：

Pythonimport json

def load_users(path):
    with open(path) as f:
        return json.load(f)

def active_names(users):
    return [u["name"] for u in users if u["active"]]

users = load_users("data/users.json")
print(active_names(users))
# KeyError: 'active'

压成 MRE 的过程：

Python# 第 1 刀：文件读取跟这个错无关，直接用字面量替代
users = [{"name": "a", "active": True}, {"name": "b"}]

# 第 2 刀：函数也可以去掉，循环直接写
for u in users:
    print(u["active"])        # 第二项没有 active 键 → 报错

5 行，谁都能看懂。 而答案往往在这一步自己就浮出来了：原来是数据里有的字典缺了 active 键。 修法也就清楚了：把 u["active"] 改成 u.get("active", False)。

做 MRE 的三刀：去掉跟报错无关的文件读写和网络请求 → 去掉无关的函数包装 → 把大列表缩到两三个元素。

2.6.4 提问模板：照着填，回复率翻倍

代码【环境】Windows 11 / Python 3.12.4 / VS Code
【想做什么】从 users.json 读出用户，打印所有活跃用户的名字
【我写的代码】（贴能直接跑的最小版本，不要贴 200 行原文）
【期望结果】打印 a
【实际结果】KeyError: 'active'
【完整报错】（从 Traceback 到最后一字，全部复制，用代码块包起来）
【我试过的】1. 检查过 JSON 文件格式 2. 试过 u.get('active')，但不知道这样对不对

四个最容易犯的错：

  • 不贴完整报错，只说"报错了"——对方只能猜
  • 贴一整屏截图——文字代码别人没法复制运行，请用代码块贴文字
  • 贴 300 行原始代码——没人有时间读，请先做 MRE
  • 把报错翻译成中文再问——搜索和他人检索都依赖原文，请保留英文原文

2.6.5 去哪问

渠道 适合什么 注意
搜索引擎 所有报错，尤其是常见错误 用报错原文最后一行

2.6.6 AI 时代怎么求助才不被带偏

问 AI 是现在最快的方式，但它会自信地编造不存在的函数。三条用法纪律：

  1. 给完整上下文：贴报错原文 + 相关代码 + 你想达成的目标，别只问"为什么报错"。
  2. 要求解释，而不是只给代码：问"这行为什么报错、原理是什么"，比"帮我改"学到的多。
  3. 它给的代码一定要自己跑一遍。编造的 API 一跑就 AttributeError，跑一遍就知道真假。
  4. 它给的解释要能用自己的话复述。复述不出来 = 你没懂，继续追问"为什么"。

AI 是加速器，不是裁判。代码跑得通才是唯一的裁判。
