2.3 request.user：每个请求自带的「当前用户」

Django 给每一个请求都挂上一个 user 对象，视图里直接用 request.user：已登录时是真实的 User 对象（带 username、id）；未登录时是 AnonymousUser——注意不是 None，所以视图里放心写 request.user，不会 AttributeError，只是 is_authenticated 为 False。

模板里同样有一个现成的 user 变量可用（不用在 context 里传）：

HTML{% if user.is_authenticated %}
  Hello, {{ user.username }}.
{% else %}
  <a href="{% url 'accounts:login' %}">Log in</a>
{% endif %}

这就是导航栏「已登录显示问候语、未登录显示登录链接」的实现——同一个变量，两种身份，模板自己判断。

「不是 None」这一点值得亲手验证一次，因为它决定了你后面所有视图函数的写法：

Python# request.user 的替身：登录与未登录，差别只在 is_authenticated
class AnonymousUser:
    """Django 里未登录时 request.user 就是这个对象——不是 None。"""

    username = ""
    pk = None

    def __str__(self):
        return "AnonymousUser"

    @property
    def is_authenticated(self):
        return False


class User:
    def __init__(self, username, pk):
        self.username = username
        self.pk = pk

    def __str__(self):
        return self.username

    @property
    def is_authenticated(self):
        return True


def nav_text(user):
    """视图或模板里唯一该用的判断：is_authenticated。"""
    if user.is_authenticated:
        return f"你好，{user.username}。"
    return "登录"


for user in (User("alice", 1), AnonymousUser()):
    print(f"{str(user):<14}is_authenticated={user.is_authenticated!s:<6}"
          f"pk={user.pk!r:<6}导航显示：{nav_text(user)}")

print("\n未登录时 username 是空串、pk 是 None，但对象永远存在——")
print("所以 request.user.username 不会 AttributeError，只是显示空字符串。")
print("视图里要拿「当前用户的主题」：Topic.objects.filter(owner=request.user)")
print("未登录还这么查，owner 会匹配到一个 AnonymousUser，结果恒为空集。")

实跑输出里 alice 那行是 is_authenticated=True pk=1，AnonymousUser 那行是 is_authenticated=False pk=None——pk 可以是 None，但 request.user 这个对象本身永远存在。所以判断登录状态永远写 if request.user.is_authenticated:，不要写 if request.user is not None:（那个条件永远为真）。

2.4 登录、注销、注册三件套

登录和注销不用自己写视图——Django 自带的用户身份验证系统（django.contrib.auth）全包了。在 accounts/urls.py 里包含默认 URL：

Python# accounts/urls.py —— 默认 URL 白拿 login / logout，register 用自己的视图
from django.urls import path, include

from . import views

app_name = "accounts"

urlpatterns = [
    # 包含默认的身份验证 URL
    path("", include("django.contrib.auth.urls")),
    # 注册页面（自己写）
    path("register/", views.register, name="register"),
]

但视图白送，模板要自己提供：默认登录视图只去 registration/login.html 找模板，位置放错就 TemplateDoesNotExist。注销请求必须以 POST 方式提交（防止攻击者伪造注销请求），所以在 base.html 里放一个只有提交按钮的小表单。

settings.py 末尾要交代三件事：

Python# ll_project/settings.py（末尾）
LOGIN_REDIRECT_URL = "learning_logs:index"   # 登录成功：去主页
LOGOUT_REDIRECT_URL = "learning_logs:index"  # 注销之后：回主页
LOGIN_URL = "accounts:login"                 # 被门禁拦下时：送到登录页

注册页面 Django 不提供，得自己写——但表单可以用现成的 UserCreationForm，它自带用户名合法性检查、两次密码一致性校验，保存时只存密码的哈希值（绝不存明文，教材专门强调过）。流程和 new_topic 一样：GET 显示空表单，POST 处理提交；验证通过后 form.save() 返回新用户对象，用 login(request, new_user) 让其自动登录，再重定向到主页。完整代码见示例 7。
