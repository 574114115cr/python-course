六、本单元验收自测

1. 判断题：print("Hi") 这行代码能直接双击 .py 文件就看到输出吗？

要点：不能。双击是用操作系统默认方式打开文本文件，不是执行。要看到输出必须用解释器运行：在 VS Code 里点 ▶，或在终端里输入 python 文件名.py。

2. 简答题：终端提示 'python' 不是内部或外部命令，最可能的原因是什么？该怎么解决？

要点：安装 Python 时没有勾选 "Add Python to PATH"，系统不知道去哪儿找解释器。解决办法：重新运行安装包 → 勾选该选项 → 或手动把 Python 安装目录加进系统环境变量 PATH，然后重开终端。

3. 判断题：git commit -m "更新" 和 git add file.py 可以交换顺序吗？

要点：不可以。add 是"把改动放进暂存区"，commit 是"把暂存区里的内容存档"。必须先 add 再 commit，否则 commit 会提示 nothing to commit（因为暂存区是空的）。

4. 简答题：这段代码会输出什么？为什么？

Pythonprint("A")
x = 10
print("B")

要点：输出两行 A、B。因为 Python 从上往下逐行执行：x = 10 本身不产生任何输出，只有两个 print() 会打印东西。（如果把 print("B") 改成 print(x) 并挪到赋值之前，就会报 NameError——这正是"先赋值后使用"的意义。）

5. 简答题：.gitignore 是干什么的？如果没有它，提交可能出现什么问题？

要点：它是一份"永远不要记录"的清单，通常放虚拟环境（venv/）、Python 缓存（__pycache__/、*.pyc）等。缺少它时，虚拟环境里成千上万个文件会被一起提交，仓库体积暴涨、提交记录被噪音淹没，且不同电脑的缓存文件会造成大量无意义差异。

七、常见错误清单（务必逐条自查）

错误 1：'python' 不是内部或外部命令

症状：终端里敲 python --version 报这一句，但明明装过了。 原因：安装时没勾「Add Python to PATH」，系统找不到解释器。 改法：重新运行安装包选 Modify 勾上 PATH，或手动把 ...\Python312\ 与 ...\Scripts\ 加进环境变量，然后重开终端（旧窗口不会刷新 PATH）。

错误 2：按 3.12 的教程写，removeprefix 却报 AttributeError

症状：str 没有 removeprefix。 原因：装的是 3.8/3.9，这个方法是 3.9 才有的（match 语法是 3.10）。 改法：python --version 确认版本；低于 3.12 就升级——本课程按 3.12 写，前面的单元还能凑合，到单元 8 之后会到处踩坑。

错误 3：pip install requests 成功，import requests 却 ModuleNotFoundError

症状：装完导不进来。 原因：机器上有两个 Python，pip 属于另一个，VS Code 用的又是第三个。 改法：一律用 python -m pip install 包名（跟着当前解释器走）；VS Code 里 Ctrl+Shift+P → Python: Select Interpreter 选同一个解释器。

错误 4：改了代码，运行结果没变

症状：明明保存了，输出还是旧的。 原因：跑的是另一个文件（同目录下有同名 .py），或终端里跑的是缓存的 .pyc。 改法：看 VS Code 标题栏的文件名与路径；终端里用 python 完整路径/文件名.py，或先 cd 到文件所在目录。

错误 5：git checkout 之后代码没了

症状：想撤销修改，结果改的内容被覆盖。 原因：git checkout -- 文件 是「用最近一次提交覆盖工作区」，不是「撤销上一次 checkout」。 改法：先 git status 看清改了什么；只想临时回退就先 git stash（可 git stash pop 找回），别直接 checkout。
