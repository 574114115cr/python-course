2.5 ★ 校正绘图：给坐标轴留边距

这是新手最高频的坑，值得单独一节。默认坐标轴范围贴着数据：x 轴从最小值到最大值。但点本身有「直径」——s=100 的点不是没有面积的一个点，而画布边框会切掉越界部分，于是两端点被削掉一小块，看着像「数据缺了一头」。

解决办法是手动指定范围：ax.axis([0, 1100, 0, 1_100_000])，四个数顺序是 [xmin, xmax, ymin, ymax]。为什么写 1100 和 1 100 000 这种「多出来的数」？因为数据最大值正好是它们，再留一点余量，点才不被切。110 万写作 1_100_000（下划线只分组）。

示例没校正                  校正之后（四周加了余量）
┌──────────────┐      ┌──────────────┐
│◐   ○ ○ ○   ◑ │  →   │  ◐ ○ ○ ○ ◑  │
│ ◐ ○ ○ ○ ○ ◑  │      │  ○ ○ ○ ○ ○ ○  │
└──────────────┘      └──────────────┘
 ↑ 贴边的点被削掉了      ↑ 点完整，四周留白

ax.axis([...]) 这名字很怪——它既设范围又管外观。等价写法是 ax.set_xlim() + ax.set_ylim()，更直白。关键是要知道为什么要手动设范围；更稳的做法是用 max(数据) * 1.05 算余量，数据换了也不用改代码（见示例 3）。余量是算出来的，不是猜的：

Python# 余量交给函数算：换数据不用改代码
def axis_range(values, margin=0.05):
    """返回 [xmin, xmax, ymin, ymax]，四周各留 margin 比例的余量。"""
    low, high = min(values), max(values)
    pad = high * margin
    return [0, high + pad, 0, high + pad]


x_values = [1, 2, 3, 4, 5]
y_values = [1, 8, 27, 64, 125]
print("数据最大值：", max(y_values))
print("写死的范围：", [0, 1100, 0, 1_100_000], "（教材的例子，换数据就废）")
print("算出来的范围：", axis_range(y_values), "-> ax.axis(...) 直接用")
print("再换一组数据：", axis_range([10, 4400, 250]))
print("\n为什么要有余量：s=100 的点有直径，贴边的点会被画布切掉一半。")

这段的实跑输出：数据最大值 125 时范围是 [0, 131.25, 0, 131.25]；换成 [10, 4400, 250] 后自动变成 [0, 4620.0, 0, 4620.0]。你只改了数据，代码一个字没动。

定制刻度标记。 默认刻度由 matplotlib 自选，大数字上会变成 1.0e6 科学计数法，或标签挤成一团。set_xticks() 是「刻度放在这些位置」，set_xticklabels() 是「这些位置显示什么」（见示例 3）。

★ set_xticks 与 set_xticklabels 必须配套调用。 只调后者，标签会被硬贴在默认刻度上，位置不够就叠。

★ 自动保存绘图用 fig.savefig()，推荐写全两个参数：dpi=200 让线更细腻，bbox_inches="tight" 表示「按有内容区域裁剪」，不写就带大片白边。

2.6 随机游走：RandomWalk 类

随机游走是最简单的随机模型：一只小虫每次随机往一个方向走一步，走一千步得到一条弯曲路径。它是布朗运动、股票涨跌、扩散的数学原型。教材把它做成一个类，这个设计比代码更值得学——「一只虫」是一个对象，x、y 是属性，「走一步」是方法（类见示例 4）：

Pythonclass RandomWalk:
    def __init__(self, num_points=5000):
        self.num_points = num_points          # 属性：走多少步
        self.x_values = [0]                   # 属性：从原点出发
        self.y_values = [0]

    def fill_walk(self):
        while len(self.x_values) < self.num_points:
            x_step = random.choice([-1, 0, 1])
            y_step = random.choice([-1, 0, 1])
            if x_step == 0 and y_step == 0:
                continue                      # ★ 拒绝原地不动
            self.x_values.append(self.x_values[-1] + x_step)
            self.y_values.append(self.y_values[-1] + y_step)

★ 这里最容易错：为什么要「拒绝原地不动」？ 若允许 x 和 y 同时不变，这轮什么也没发生。四种组合里「不动」占 1/4，5000 步里约 1250 步原地踏步。这违反了随机游走「每一步都要真的移动」的定义。 正确写法是两个同时为 0 才重来——所以用 and，不是 or。

random.choice(seq) 是「从序列里随机挑一个」，兄弟还有 random.randint(a, b)（含两端）、random.random()（0~1）。 ★ random.seed(42) 是这一章最有工程价值的一行。 随机性是编程里的「double 难度 bug 源」：跑一遍正常、再跑一遍崩，而你复现不出来。写上种子后随机序列完全可复现，bug 能稳定复现、修好、再验证。调试随机程序第一件事就是加种子。

模拟多次随机游走就是循环创建多个对象（完整代码见示例 4），有三点值得说：alpha=0.1 让 500 条半透明路径叠在一起、经过次数多的区域自然变深（不透明会糊成一坨纯黑）；edgecolors="none" 是点太多时不要描边；c=[i] * len(...) 配 cmap=plt.cm.Blues 让**「第几次游走」变成深浅**（c 必须和点一样长）。

2.7 Plotly 掷骰子：Die 类

前面全是 matplotlib，从这里换成 Plotly，因为掷骰子的本质是「大量样本的分布」，Plotly 的 bar 一行出图还自带交互。选库看需求，不看时髦程度——要把这张图印进 PDF 的话，matplotlib 一样能画。

终端命令pip install plotly kaleido      # kaleido 只在导出 PNG/SVG 时需要

kaleido 是 Plotly 静态导出的引擎，教材存 HTML 用不到它；本讲义统一用 fig.write_html()。

Die 类的设计：骰子是「能被掷的对象」，该有的是——面数（属性）、记住每次结果（属性）、掷一次（方法）：

Pythonimport random

class Die:
    """一枚 n 面骰子。"""

    def __init__(self, num_sides=6):
        self.num_sides = num_sides
        self.results = []              # 存每一次掷出的点数

    def roll(self):
        result = random.randint(1, self.num_sides)   # 含两端
        self.results.append(result)

★ results.count(value) 是本节的关键一招。 想知道「1 点出现了多少次」，最笨是手写循环去数；list 自带 count()，一行返回出现次数（见示例 5）。统计完还要加 assert sum(frequencies) == len(die.results)：这不是装饰——分布类程序最容易出的 bug 是「某个类别被漏掉了」，而它不报错、只让你看到缺一列的图。

画分布图。 px.bar() 需要横纵两组数据；定制用 fig.update_layout()（改整体：标题、轴标题）和 fig.update_traces()（改柱子：颜色、描边）；还可以用 fig.add_hline() 画「理论平均线」，让读者一眼看出随机结果靠不靠谱。

★ 术语纠正：中文常把这种图叫「直方图」（histogram），但 px.bar() 画的是柱状图。真正的直方图（px.histogram）是把连续数值分箱——比如把身高分成 160~170、170~180 两堆。骰子点数是离散类别，所以用 bar。

同时掷两个骰子，建两个对象、掷同样多次后把结果相加（2 到 12 共 11 种），核心就一行列表推导：

Pythonimport random

random.seed(42)
rolls_1 = [random.randint(1, 6) for _ in range(1000)]   # 骰子 1 的 1000 次
rolls_2 = [random.randint(1, 6) for _ in range(1000)]   # 骰子 2 的 1000 次
sums = [a + b for a, b in zip(rolls_1, rolls_2)]       # zip 把两串配对
frequencies = [sums.count(v) for v in range(2, 13)]     # 2~12 共 11 种
print(dict(zip(range(2, 13), frequencies)))

zip(a, b) 把两条等长列表「拉链」起来，一次给你一对元素，for a, b in ... 再把这一对拆成两个名字。这个 zip + 解包 后面「两份数据逐行对照」都会用到，务必练熟。

同时掷两个面数不同的骰子，用 plotly.graph_objects 显式画两组柱子（见示例 5）。go.Figure() + add_trace() 比 px.bar() 啰嗦，但控制力强：能画多条配置的柱子、能命名、能设透明度。barmode="group" 是并排，"overlay" 是叠放（记得配 opacity）。

统计结论（比代码更重要）：每次掷骰子各点数等概率，所以单个骰子的分布是平的。两个骰子相加时，靠中间的点有更多组合方式凑出来（六面+六面凑 7 有 6 种组合，凑 2 只有 1 种），分布向中间隆起；面数越多分布越均匀（六面+二十面有 120 种组合，几乎平坦）。这就是「大数压倒小数」。

保存图形——两个库不一样：matplotlib 存静态图用 fig.savefig("x.png", bbox_inches="tight")；Plotly 存可交互网页用 fig.write_html("x.html")，需要静态图（且装了 kaleido）用 fig.write_image("x.png")。
