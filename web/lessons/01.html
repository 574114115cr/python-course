装好 Python 与 VS Code

知道解释器是什么，能新建并运行第一个脚本

10复盘 min
30讲解 min
40实操 min
20讲评 min

◆ 开课准备（10 分钟）｜这节课怎么上

  • 这节课 90 分钟怎么分：复盘 10 + 讲解 30 + 实操 40 + 讲评 20。实操环节全程不准看答案。
  • 先确认三件事：Python 装好了（终端敲 python --version 有版本号）、VS Code 能打开、能新建并保存 .py 文件。
  • 两条铁律：看懂 ≠ 会写，必须从空文件自己敲一遍；报错不是失败，它是唯一会告诉你哪里错了的东西。

◆ 课堂实操（40 分钟，全程不许看答案）

  1. 跟着敲：新建 hello.py 并运行
  2. 故意写错一次，观察报错长什么样
  3. 用终端直接运行 python hello.py

一、学习目标

完成本单元后，你应该能够：

  1. 在自己的电脑上安装 Python 3.12 或更高版本，并在终端里用 python --version 验证成功。
  2. 安装并配置 VS Code + Python 扩展，能用「运行」按钮或快捷键执行一个 .py 文件。
  3. 独立创建一个项目目录，写出并运行人生第一个 hello.py，并能读懂最简单的报错信息。
  4. 用 git init / add / commit / log 建立自己的第一个版本仓库，并配置好 .gitignore。
  5. 说清「终端 / 编辑器 / 解释器」三者的区别，知道自己的代码最终由谁执行。

二、核心知识点讲解

2.1 Python 解释器：写的是"食材"，跑的是"厨师"

Python 是一门解释型语言。你写的 .py 文件只是纯文本（叫"源代码"），机器本身并不认识它。真正把文本变成机器能执行的动作，需要一个叫 Python 解释器 的程序来完成。

生活化类比：你写了一张菜谱（.py 文件），但菜谱不会自己变成菜。必须有厨师（解释器）照着做，才能端上桌（输出结果）。所以"运行 Python 代码"这件事，物理上必然是：某台机器上的某个解释器程序，读取你的文本文件，逐行执行。

理解这一点，你就明白了为什么安装 Python 是第一步——没有厨师，菜谱就是废纸。

2.2 终端（命令行）：和解释器对话的窗口

终端（Windows 上叫 PowerShell 或命令提示符，macOS/Linux 上叫 Terminal）是一个可以输入文字的地方。你在里面输入 python hello.py，回车，解释器就会去读取并执行那个文件。

初学者最常见的困惑是"我怎么确认自己装好了？"——标准动作是打开终端，输入：

终端命令python --version

如果屏幕回你一行 Python 3.12.x，说明解释器已经装好并且在 PATH 里能找到。如果报 'python' 不是内部或外部命令，几乎一定是安装时没有勾选 "Add Python to PATH"。这个勾选项的作用，就是告诉 Windows"以后我在任何目录里敲 python，都去那个安装位置找它"。

另外两个你会立刻用到的命令：

  • cd 文件夹名 —— 进入某个目录（change directory）
  • dir（Windows）或 ls（macOS/Linux）—— 列出当前目录里有什么

2.3 VS Code + Python 扩展：写代码的写字板

编辑器不是解释器，它只是"写字板"。VS Code 负责让你写代码更舒服：语法高亮（关键字变色）、自动缩进、括号补全、侧边栏文件树。

装上微软官方的 Python 扩展（Python by Microsoft）之后，VS Code 额外获得：

  • 右上角的 ▶ 播放按钮，一键运行当前文件
  • 智能提示：打了一半的函数名，会自动补全并显示参数说明
  • 错误提示：你在当前文件还没运行之前，就能看到红波浪线告诉你哪里写错了

记住这个分工：编辑器负责"写"，解释器负责"跑"，终端负责"把两者连起来"。

◆ 课后作业

  1. 装好环境并跑通 hello.py

◆ 讲评（20 分钟）｜对照检查你刚写的代码

  • hello.py 能跑通吗？输出和你预期的一模一样吗？
  • 把 print 里的字符串引号删掉一个，看报错长什么样——里面有文件名和行号吗？
  • VS Code 里有没有红色波浪线？点开看它说什么，别当没看见。
  • 终端里再跑一次 python hello.py，和点「运行」按钮效果一样吗？
本节一句话总结今天只记一件事：.py 只是文本，解释器才是执行它的人。
