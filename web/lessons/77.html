2.5 动态难度：speedup_scale 与 score_scale

游戏太难了，而且永远那么难：高手 3 分钟通关，新手 30 秒去世。把 Settings 的设置拆成静态（整局不变：屏幕尺寸、ship_limit、两个成长系数）和动态（会变：三种速度、alien_points）两组，完整代码见示例 2。

  • speedup_scale = 1.1：每升一级，ship_speed / bullet_speed / alien_speed 都乘 1.1。
  • score_scale = 1.5：每升一级，alien_points 乘 1.5。
  • initialize_dynamic_settings()：取初始值，点 Play 重置时调用。
  • increase_speed()：往上加，清空一波外星人升级时调用。

为什么拆成两个方法？ 「取初始值」和「往上加」是两个不同时机。不拆的话，重置点要把每个初始值重复抄一遍，容易漏。★ 记住：一组初始值单独抽成一个方法，重置时调用它。

alien_points 为什么要 int()？ 50 * 1.5 = 75.0（float），再乘得 112.5。小数分显示出来很怪（「112.5 分」），int() 一刀切只留整数：int(112.5) = 112（截断不是四舍五入，游戏里无所谓）。

难度曲线：1.1 的指数增长「先温和后陡峭」——第 1 级速度 1.0、第 5 级约 1.46、第 10 级约 2.36；分值 50 → 75 → 112 → 168 → 252，越往后每级涨得越多。风险越高，回报越高，玩家才有动力冲更高等级。

2.6 余下的飞船数：Group + Ship 的复用

左上角显示「你还剩几条命」，教材的实现非常优雅——直接复用 Ship 类（完整演示见示例 5）：

Pythondef prep_ships(self):
    self.ships = Group()
    for ship_number in range(self.stats.ships_left):
        ship = Ship(self.ai_game)
        ship.rect.x = 10 + ship_number * ship.rect.width
        ship.rect.y = 10
        self.ships.add(ship)
  • Group() 是 Pygame 的精灵编组，像一艘航空母舰，把一堆 Sprite 装进去统一管理，self.ships.draw(self.screen) 一行画出所有小图标。
  • 每个小图标都是一个完整的 Ship 对象——有图片、有 rect、有速度，只是不更新位置，纯粹借它的「长相」。这就是复用：不为图标单独写类。
  • ship.rect.width 是图片宽度，用它当间距，图标之间刚好不重叠。

你已经见过 bullets = Group() 和 aliens = Group()——同一个工具，同一套用法；将来统一更新、检测碰撞（update()、groupcollide()）也都是现成的。★ prep_ships() 每次调用都 self.ships = Group() 重建编组：命数会变，旧编组里装着旧数量的图标，必须整个扔掉重来；往旧编组里增增减减才是真的乱。
