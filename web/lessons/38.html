六、常见错误清单（务必逐条自查）

以下 6 类是写函数时最高频的错误。每一条都给出「症状 → 原因 → 修法」。

错误 1：忘记写冒号，或缩进错误

故意写错 · 先跑一遍看报错def greet(name)      # 错误 1a：括号后面漏了冒号
    print(name)


def greet2(name):
print(name)           # 错误 1b：函数体没有缩进


def greet3(name):
    print(name)       # 错误 1c：缩进用了 Tab 而不是 4 个空格
print("这里是函数外的代码")  # 错误 1d：函数体提前结束了，缩进不一致


def greet4(name):
    print(name)
        print("多缩进了")   # 错误 1e：同一块内缩进不一致 -> IndentationError
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪

症状：SyntaxError: expected ':' / IndentationError: expected an indented block 原因：def 行末必须有 :；函数体所有行必须用一致的 4 个空格缩进。 修法：VS Code 里按 Tab 会自动插入 4 空格，不要混用 Tab。报错信息里的 ^ 会指到出问题的位置。

错误 2：★ 函数修改列表，会改到原列表

Pythondef add_item(items):
    items.append("新元素")      # 这一行直接改掉了调用方的列表


fruits = ["苹果"]
add_item(fruits)
print(fruits)      # ['苹果', '新元素']  ← 原数据被污染了

症状：函数返回后，原列表莫名其妙多了东西；或者多个函数调用之间数据互相串味。 原因：列表是可变对象，Python 传的是"地址"，函数里改的就是原件。 修法（三选一）：

Python# 修法1：函数内造副本（推荐）
def add_item(items):
    items = items[:]        # 先复制
    items.append("新元素")
    return items

# 修法2：调用时传副本
add_item(fruits[:])

# 修法3：用 + 产生新列表
def add_item(items):
    return items + ["新元素"]

错误 3：默认参数用了可变对象

故意写错 · 先跑一遍看报错def add_task(task, todo=[]):     # 错误：默认值是列表！
    todo.append(task)
    return todo


print(add_task("买菜"))     # ['买菜']
print(add_task("做饭"))     # ['买菜', '做饭']  ← 上次的"买菜"莫名出现！
print(add_task("睡觉"))     # ['买菜', '做饭', '睡觉']
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪

症状：单独调用正常，反复调用时结果里出现了前面调用的数据。 原因：默认参数在函数定义时只求值一次，那个列表被所有调用共享。 修法：

Pythondef add_task(task, todo=None):     # 默认值用 None
    if todo is None:
        todo = []                 # 每次调用时新建
    todo.append(task)
    return todo

错误 4：忘记 return，函数等于白写

故意写错 · 先跑一遍看报错def add_score(scores):
    scores.append(100)      # 列表确实被改了，但函数本身返回 None


result = add_score([1, 2, 3])
print(result)      # None
print(result + 1)  # TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪

症状：TypeError: 'NoneType' object is not subscriptable 或者结果莫名是 None。 原因：没有 return 的函数默认返回 None。修改外部数据 ≠ 返回新结果。 修法：明确写出 return。如果函数只是"做事"不改返回值（比如写文件、打印），就把 def f(): 写成 def f(): 并在文档里说明它没有返回值。

错误 5：参数顺序或数量不对

Pythondef make_pizza(size=12, with_cheese=True):
    """有默认值的参数必须写在没有默认值的参数后面。"""
    return f"{size} 英寸，芝士={with_cheese}"


# INTENTIONALLY-BROKEN 演示 3 类调用错误
print(make_pizza(16, False))       # 合法：16 英寸，芝士=False
print(make_pizza(False))           # 陷阱：False 被当成了 size！
# print(make_pizza(16, 18, 20))    # 错误：Too many positional arguments
# print(make_pizza(size=16, cheese=True))   # 错误：参数名写错，应为 with_cheese

# 报错信息里有个高频拼写错误：cheese 不是 with_cheese
# TypeError: make_pizza() got an unexpected keyword argument 'cheese'

症状：TypeError: got an unexpected keyword argument 或结果莫名其妙。 原因：位置参数按顺序匹配；关键字参数按名字匹配；参数个数或名字不对。 修法：多个参数时优先用关键字参数，比如 make_pizza(size=16, with_cheese=False)，顺序和意图一目了然，也不用担心位置搞混。

错误 6：局部变量遮蔽全局变量

Pythoncount = 0


def reset_counter():
    count = 100       # 错误：这是新建了一个局部变量，全局 count 没变
    print(count)      # 打印 100


reset_counter()
print(count)      # 0  ← 你以为改了，其实没改

症状：函数里改了变量，函数外"莫名其妙"没变；或者函数里想读全局值却报 NameError。 原因：函数内只要出现赋值，Python 就认定这个名字是局部的，不会去读全局的那个。 修法（推荐第一种）：

Python# 修法1（最佳）：把数据传进去，把结果返回出来
def add_to_count(current, amount):
    return current + amount


count = add_to_count(count, 100)
print(count)      # 100

# 修法2：确实需要改全局时用 global（官方不推荐）
def reset_counter():
    global count
    count = 100
