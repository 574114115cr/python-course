六、本单元验收自测

1. 简答题：下面代码输出什么？

Pythonfor i in range(1, 4):
    print(i * 2)
print("i =", i)

要点：先输出 2\n4\n6，再输出 i = 3。因为 range(1, 4) 是 1、2、3 三轮；循环结束后 i 仍保留最后一次的值 3。

2. 判断题：nums = [1, 2, 3, 4, 5, 6]，nums[1:5] 的结果是 [2, 3, 4, 5]。

要点：正确。左闭右开——包含索引 1（值 2），不包含索引 5（值 6），所以结果是 [2, 3, 4, 5]，长度为 5 - 1 = 4。

3. 简答题：t = (5) 和 t = (5,) 的类型分别是什么？

要点：type((5)) 是 <class 'int'>——它就是整数 5，括号只是数学上的分组符号，逗号才是元组的标志。type((5,)) 是 <class 'tuple'>——加了逗号才是长度为 1 的元组。

4. 判断题：字典的键可以用列表，因为列表也能"存多个数据"。

要点：错误。字典的键必须是不可变类型。列表可以 .append() 修改内容，一旦键被修改，Python 就再也定位不到对应的值了。元组不能修改，所以可以当键；元组的长度和内容一旦创建就固定，用它当键才安全。

5. 简答题：下面代码会输出什么？为什么没输出东西？

故意写错 · 先跑一遍看报错numbers = [1, 2, 3]
for number in numbers
    print(number)
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪

要点：会报 SyntaxError。for 语句末尾漏写了冒号 :。这和括号不匹配是同一类问题——Python 语法上读不下去，代码一行都不会被执行。修复方法：for number in numbers:。

七、常见错误清单（务必逐条自查）

错误 1：边 for 边 remove，元素漏删

症状：列表里 3 个 "x"，循环后还剩 1 个。 原因：删除会让后面的元素前移，而循环下标继续往后走，正好跳过下一个。 改法：while "x" in items: items.remove("x")，或倒序遍历 for i in reversed(range(len(items)))，或直接列表推导。

错误 2：切片越界却不报错

症状：nums[2:99] 没崩，但结果比预期短。 原因：切片是「容错」的，越界只截到末尾。 改法：这是特性不是 bug；要严格校验长度就自己 if len(nums) < 3: raise ValueError。

错误 3：for i in range(len(x)) 里 append

症状：循环次数比预期多，甚至死循环。 原因：range(len(x)) 在循环开始时就把长度算好了；若在循环里删除，下标与元素就错位。 改法：不要在遍历时改长度；需要新列表就新建 out = [] 再 out.append(...)。

错误 4：sorted(x, reverse=True) 与 x[::-1] 混用

症状：以为两者等价，结果顺序不同。 原因：sorted(reverse=True) 是按大小降序；[::-1] 只是把原顺序倒过来。 改法：要排序用 sorted()；只想倒序用 reversed(x) 或 x[::-1]。

错误 5：t[0] = 1 报 TypeError

症状：'tuple' object does not support item assignment。 原因：元组不可变，创建后不能改元素。 改法：要改就换成列表；确实要「改一个值」就重建：t = t[:1] + (9,) + t[2:]。
