基础档

练习 19-1【登录页与注销】 按教材 19.2.1 ~ 19.2.5 操作： 1. python manage.py startapp accounts，并注册进 INSTALLED_APPS 2. 项目 urls.py 加 path("accounts/", include("accounts.urls")) 3. accounts/urls.py 包含默认身份验证 URL 4. 在 accounts/templates/registration/ 下写 login.html（路径一个字都不能错） 5. settings 加 LOGIN_REDIRECT_URL 和 LOGOUT_REDIRECT_URL 6. base.html 加用户问候语和注销表单 验收点：未登录显示 Log in（Register 链接等练习 19-2 再加）；登录后显示 Hello, 用户名. 和 Log out 按钮；点注销回主页，问候语消失。

练习 19-2【注册页面】 按教材 19.2.6： 1. accounts/urls.py 加 register 路由 2. accounts/views.py 写 register()（用 UserCreationForm，注册成功自动登录） 3. 写 registration/register.html，base.html 加注册链接 验收点：注册成功后自动登录并跳主页；故意输入两个不一样的密码，能被拦下并显示错误。

练习 19-3【让每个用户只有自己的主题】 按教材 19.3.1 ~ 19.3.3： 1. 用 Django shell 查出现有用户的 ID 2. models.py 给 Topic 加 owner = models.ForeignKey(User, on_delete=models.CASCADE)，并导入 User 3. makemigrations 时选择「现在提供一次性默认值」，填入你查到的用户 ID，然后 migrate 4. 给 topics 视图加 @login_required，查询改成 filter(owner=request.user) 5. settings 加 LOGIN_URL 验收点：注册两个用户，分别登录，看到的主题列表完全不同；未登录点 Topics 被弹到登录页。

进阶档

练习 19-4【教材练习 19.3：重构 check_topic_owner()】 教材原题：views.py 里有两处核实「主题属于当前用户」的代码。请把这段检查提取成一个函数，在两处调用它。要求：函数名 check_topic_owner()，参数和返回值自己设计，行为与原来完全一致。

练习 19-5【教材练习 19.4：保护 new_entry】 教材原题：用户可以在 URL 中指定属于别人的主题 ID，从而往别人的主题里加条目。请在保存新条目之前，核实它所属的主题归属于当前用户；不属于则 raise Http404。

练习 19-6【纯 Python：带用户隔离的笔记本】 不借助 Django，写一个内存版「学习笔记」，把三道防线都实现： 1. 白名单表单：submit(topic_data) 只接受 text 键，用户塞进来的 owner 一律丢弃，归属由 current_user 决定 2. 门禁：list_topics() 要求先 login(username)，否则抛出一个 PermissionError 3. 数据隔离：list_topics() 只返回当前用户的主题；get_topic(topic_id) 查到不属于当前用户的主题时抛出 KeyError 4. 内置两个用户各两条主题，写测试代码演示：未登录被拦、A 看不到 B、恶意塞 owner 无效

Python# accounts/views.py —— 注册视图
from django.shortcuts import render, redirect
from django.contrib.auth import login
from django.contrib.auth.forms import UserCreationForm


def register(request):
    """注册新用户。"""
    if request.method != "POST":
        form = UserCreationForm()
    else:
        form = UserCreationForm(data=request.POST)
        if form.is_valid():
            new_user = form.save()
            # 让用户自动登录，再重定向到主页
            login(request, new_user)
            return redirect("learning_logs:index")

    context = {"form": form}
    return render(request, "registration/register.html", context)

Python# learning_logs/models.py —— Topic 增加 owner 外键
from django.db import models
from django.contrib.auth.models import User


class Topic(models.Model):
    """用户学习的主题"""

    text = models.CharField(max_length=200)
    date_added = models.DateTimeField(auto_now_add=True)
    owner = models.ForeignKey(User, on_delete=models.CASCADE)

    def __str__(self):
        return self.text


class Entry(models.Model):
    """学到的有关某个主题的具体知识"""

    topic = models.ForeignKey(Topic, on_delete=models.CASCADE)
    text = models.TextField()
    date_added = models.DateTimeField(auto_now_add=True)

    class Meta:
        verbose_name_plural = "entries"

    def __str__(self):
        return f"{self.text[:50]}..."

Python# learning_logs/views.py —— 提取 check_topic_owner()（教材练习 19.3）
from django.shortcuts import render, redirect
from django.contrib.auth.decorators import login_required
from django.http import Http404

from .models import Topic, Entry
from .forms import TopicForm, EntryForm


def check_topic_owner(topic, request):
    """确认主题属于当前登录用户，不属于则引发 404。"""
    if topic.owner != request.user:
        raise Http404


@login_required
def topic(request, topic_id):
    """显示单个主题及其所有条目。"""
    topic = Topic.objects.get(id=topic_id)
    check_topic_owner(topic, request)          # 第一处调用

    entries = topic.entry_set.order_by("-date_added")
    context = {"topic": topic, "entries": entries}
    return render(request, "learning_logs/topic.html", context)


@login_required
def edit_entry(request, entry_id):
    """编辑既有条目。"""
    entry = Entry.objects.get(id=entry_id)
    topic = entry.topic
    check_topic_owner(topic, request)          # 第二处调用

    if request.method != "POST":
        form = EntryForm(instance=entry)
    else:
        form = EntryForm(instance=entry, data=request.POST)
        if form.is_valid():
            form.save()
            return redirect("learning_logs:topic", topic_id=topic.id)

    context = {"entry": entry, "topic": topic, "form": form}
    return render(request, "learning_logs/edit_entry.html", context)

重构的好处：规则只有一份。将来想改规则（比如允许管理员看别人的主题），只动 check_topic_owner() 一处。

Python# learning_logs/views.py —— new_entry() 加归属检查（教材练习 19.4）
@login_required
def new_entry(request, topic_id):
    """在特定主题中添加新条目。"""
    topic = Topic.objects.get(id=topic_id)
    # 保存条目之前，先确认主题属于当前用户
    check_topic_owner(topic, request)

    if request.method != "POST":
        form = EntryForm()
    else:
        form = EntryForm(data=request.POST)
        if form.is_valid():
            new_entry = form.save(commit=False)
            new_entry.topic = topic
            new_entry.save()
            return redirect("learning_logs:topic", topic_id=topic_id)

    context = {"topic": topic, "form": form}
    return render(request, "learning_logs/new_entry.html", context)

攻击路径复现：不检查时，登录用户 A 后直接访问 /new_entry/1/（主题 1 属于用户 B），就能往 B 的主题里塞条目。一行检查，堵住这个洞。这类「改 URL 参数越权」的攻击在 Web 世界里极其常见，永远不要相信 URL 里的 ID。

Python# isolated_notebook.py —— 纯 Python 实现三道防线

# 内存「数据库」：{用户名: {主题ID: 主题文本}}
NOTEBOOK = {
    "eric": {1: "Python", 2: "Django"},
    "willie": {3: "私密日记"},
}

# 当前登录用户（None 表示未登录）
current_user = None

# 表单白名单：用户只能填 text，owner 一律由系统决定
FORM_FIELDS = ["text"]


def login(username):
    """登录：设置当前用户。"""
    global current_user
    if username not in NOTEBOOK:
        raise ValueError(f"用户 {username} 不存在")
    current_user = username


def logout():
    """注销。"""
    global current_user
    current_user = None


def check_login():
    """门禁：未登录就拒绝。"""
    if current_user is None:
        raise PermissionError("未登录，请先登录")


def submit_topic(submitted):
    """白名单表单：只接 text，归属由 current_user 决定。"""
    check_login()
    cleaned = {key: submitted[key] for key in FORM_FIELDS if key in submitted}
    # 用户塞的 owner 被丢弃；归属永远来自系统
    topic_id = max(
        tid for topics in NOTEBOOK.values() for tid in topics
    ) + 1
    NOTEBOOK[current_user][topic_id] = cleaned["text"]
    return topic_id


def list_topics():
    """数据隔离：只返回当前用户的主题。"""
    check_login()
    return dict(NOTEBOOK[current_user])       # 拷贝一份，防外部改动


def get_topic(topic_id):
    """详情层：查不到或不属于当前用户，一律 KeyError（相当于 404）。"""
    check_login()
    topics = NOTEBOOK[current_user]
    if topic_id not in topics:
        raise KeyError(f"主题 {topic_id} 不存在或不属于你")
    return topics[topic_id]


# ===== 演示：三道防线如何各自生效 =====
print("=== 防线一：白名单 ===")
login("eric")
malicious = {"text": "假装是别人的", "owner": "willie"}
new_id = submit_topic(malicious)
print(f"提交了 {malicious}")
print(f"实际存入：{{'text': {NOTEBOOK['eric'][new_id]!r}, 'owner': 'eric'}}")
print("=> 恶意塞的 owner=willie 被丢弃，归属由系统盖章")

print("\n=== 防线二：门禁 ===")
logout()
try:
    list_topics()
except PermissionError as error:
    print("未登录调用 list_topics() ->", error)

print("\n=== 防线三：数据隔离 ===")
login("eric")
print("eric 的主题：", list_topics())
try:
    get_topic(3)          # willie 的主题
except KeyError as error:
    print("eric 请求主题 3 ->", error)
login("willie")
print("willie 的主题：", list_topics())
print("willie 请求主题 3 ->", get_topic(3))

六、常见错误清单（务必逐条自查）

错误 1：★ 视图里用 .all()，忘了按用户过滤

症状：登录 A 账号，能看到 B 账号的全部主题和条目——数据裸奔，本单元最严重的事故。自查方法：搜索项目里所有 objects.all()，逐个问「这里该不该按 owner=request.user 过滤」。涉及用户私有数据的查询，一个都不能漏。

错误 2：★ fields 白名单里写了 owner

fields = ["text", "owner"] 等于把「归属」这一列的控制权交给用户——提交表单时塞个别人的用户 ID，数据就归了别人。归属信息只有一个合法来源：request.user，由系统在 save(commit=False) 之后盖章。表单白名单里永远不要出现 owner。

错误 3：忘了写 @login_required

未登录用户访问该视图时，request.user 是 AnonymousUser，filter(owner=AnonymousUser) 直接 500。装饰器就一行，漏写整个页面裸奔。建议：除了主页和注册页，其他视图全部加，加错了顶多严格一点，漏加了是事故。

错误 4：save(commit=False) 之后忘了 save()

new_topic = form.save(commit=False) 只是拿到一个没入库的实例；不补 owner、不调用 save()，数据就永远停在内存里。最阴险的是页面照常跳转、用户毫无察觉——静默丢数据。记住三段式是一个整体：commit=False → 补 owner → save()。

错误 5：登录模板放错位置

TemplateDoesNotExist at registration/login.html——默认登录视图只认 registration/login.html 这个路径，且要从某个 app 的 templates/ 目录下找。正确位置：accounts/templates/registration/login.html。差一个单词都不行，这是 Django 的约定，没有为什么，记住即可。

错误 6：edit_entry 只查了条目，没查主题归属

entry = Entry.objects.get(id=entry_id) 之后直接用，等于放任用户 A 通过 /edit_entry/别人的条目ID/ 编辑用户 B 的条目。Entry 自己没有 owner，归属要从 entry.topic.owner 往上追一层——这就是「双重保护」：既确认条目存在，也确认条目的主题属于当前用户。

七、本单元验收自测

1. 简答题：fields 白名单为什么不能包含 owner？用户提交恶意数据时会发生什么？

要点：fields 规定用户能填哪些列。如果包含 owner，用户提交表单时就能塞一个 owner=别人ID，这条数据就归属到别人名下，而所有者本人毫不知情——这是典型的越权。归属信息只有一个合法来源：request.user，由系统在 form.save(commit=False) 之后、save() 之前盖章。表单白名单里只放真正该由用户填写的字段（如 text）。

2. 简答题：三段式每一段在干什么？commit=False 为什么存在？

要点：form.is_valid() 让 Django 自动校验（必填、类型、长度）；form.save(commit=False) 创建实例但不落库，把最后修改的机会交给你；补上 new_topic.owner = request.user 这类只有系统知道的信息后，save() 才真正存入数据库。commit=False 的意义：用户填的表单里没有「归属谁」，而这是保存前最后一刻必须补上的系统信息。

3. 判断题：未登录用户访问带 @login_required 的视图，会看到 500 错误页。

要点：错误。未登录时 @login_required 会直接重定向到登录页（地址来自 settings.LOGIN_URL），根本不会运行视图代码，也就不会 500。如果忘了配 LOGIN_URL 或漏写装饰器，才可能看到难看的错误页。request.user 对未登录用户是 AnonymousUser（不是 None），所以视图里用 request.user 本身不会 AttributeError。

4. 简答题：为什么说数据隔离是「安全红线」？filter(owner=request.user) 和 .all() 的后果差别是什么？

要点：学习笔记存的是用户的私有数据，用户对应用有极大的信任。filter(owner=request.user) 在数据库层面只捞当前用户的主题——相当于按门牌号发钥匙；.all() 不管归属全捞——相当于把整栋楼的钥匙复印给每个客人，用户 A 能看到用户 B 的全部笔记，这是重大事故。隔离要做三层：列表页 filter、详情页查归属后 Http404、编辑页沿「条目 → 主题 → 用户」追两层。

5. 简答题：edit_entry 为什么要「双重保护」？new_entry 呢？

要点：Entry 没有自己的 owner 字段，归属从所属主题继承（只需把最高层数据关联用户）。所以编辑条目时，先取 entry.topic，再查 topic.owner != request.user——确认了条目所属的主题属于当前用户，才放行；否则 raise Http404。new_entry 同理：URL 里的 topic_id 可能指向别人的主题，保存前必须核实主题归属，否则用户能往别人的笔记里塞条目。永远不要相信 URL 里的 ID。

6. 改错题：下面的 register() 想实现「注册成功并自动登录」，有 2 处错误，找出来并改正。

故意写错 · 先跑一遍看报错def register(request):
    if request.method != "POST":
        form = UserCreationForm()
    else:
        form = UserCreationForm(data=request.POST)
        if form.is_valid():
            new_user = form.save()
            return redirect("learning_logs:index")
    context = {"form": form}
    return render("registration/register.html", context)
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪

要点：错误一，注册成功后少了 login(request, new_user)——用户注册完还是未登录状态，刷新任何受保护页面都会被弹去登录页，体验断裂；正确做法是 form.save() 拿到新用户对象后，调用 login(request, new_user) 为其创建有效会话，实现自动登录。错误二，render() 少了第一个实参 request——应为 render(request, "registration/register.html", context)，Django 的 render() 签名是 render(request, template_name, context)，没有 request 会直接 TypeError。
