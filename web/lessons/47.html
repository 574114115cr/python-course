一、学习目标

完成本单元后，你应该能够：

  1. 用 with open(...) as f: 安全地读写文件，并解释 with 语句的两大好处（自动关闭文件、异常时也能关闭）。

  3. 掌握四种读取方式（.read() / .readline() / .readlines() / for 遍历），并根据数据规模选择合适的一种。
  4. 用 try / except 捕获指定异常、处理用户输入错误，并能说出为什么不该用裸 except:。
  5. 用 json 模块读写结构化数据，用 csv 模块读写表格，并理解 JSON 与 Python 字典/列表的对应关系。

二、核心知识点讲解

2.1 为什么需要文件：变量活不过程序结束

Pythonname = "小明"
print(name)
# 程序结束后，name 就彻底消失了。关掉终端，什么都没留下。

变量只活在内存里，程序一结束就没了。要让数据留下来，就必须写到磁盘上。

生活化类比： - 变量 = 草稿纸上的字——写完一扔就没了。 - 文件 = 写在笔记本上的字——合上本子，明天还在。

2.2 open() 与三种模式

故意写错 · 先跑一遍看报错# 括号里的"文件路径"和"模式"是占位文字，真跑起来 open() 会报 ValueError: invalid mode
file_object = open("文件路径", "模式")
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪

最关键的就是模式，它决定了这个文件被打开后你打算干什么：

模式 名称 文件不存在时 文件已存在时
"r" read 读 报错 FileNotFoundError 从头读
"w" write 写 新建 清空！
"a" append 追加 新建 在末尾加

w 模式的陷阱必须重点记住：它不是"写进文件"，而是"把文件清空，然后从零开始写"。如果你只是想往文件末尾加内容却用了 w，原数据会被无声地抹掉：

Python# 大错特错！
with open("日志.txt", "w") as f:
    f.write("新增一行")     # 原文件里所有的旧内容都没了！

这也是为什么单元 0 强调要用 git——任何"数据没了"的事故，Git 都能救回来（如果提交过的话）。

Python 3 里 r 是默认模式，open("f.txt") 等于 open("f.txt", "r")。

2.3 with open(...)：不只是语法糖

Python# 先准备一个要读的文件（真实项目里这文件是别人给你的，或上一段代码写出来的）
with open("文件.txt", "w", encoding="utf-8") as f:
    f.write("第一行内容\n第二行内容\n")

with open("文件.txt", "r", encoding="utf-8") as f:
    content = f.read()
# 出了 with 块，文件自动关闭
print(content)

with 做了两件普通写法做不到的事：

① 自动关闭文件，而且保证一定会关。

Python# 先准备一个要读的文件
with open("文件.txt", "w", encoding="utf-8") as f:
    f.write("第一行内容\n")

# 普通写法：必须记得手动关
f = open("文件.txt", encoding="utf-8")
content = f.read()
f.close()       # 忘了这行，文件句柄就泄漏了

# with 写法：到块末尾自动关闭，就算中途报错也会关
with open("文件.txt", encoding="utf-8") as f:
    content = f.read()
print(content)

生活化类比：普通写法像"借了本书，记得自己还回去"，忘了还就一直占着。with 像"进了图书馆的借阅室，出门自动归还，无论你在里面待多久、发生了什么"。

② 出块后 f 变量本身失效。

故意写错 · 先跑一遍看报错with open("文件.txt", "w", encoding="utf-8") as f:
    f.write("第一行内容\n")

with open("文件.txt", encoding="utf-8") as f:
    content = f.read()
print(content)      # OK，content 还在
print(f.read())      # ValueError: I/O operation on closed file
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪

这个特性能预防一整类 bug：把 with 块的内容赋值给 f 的习惯是不良的，因为出了块就访问不到了。规范做法是在块内把内容读到一个变量里：

Pythonwith open("文件.txt", "w", encoding="utf-8") as f:
    f.write("第一行内容\n")

with open("文件.txt", encoding="utf-8") as f:
    content = f.read()      # 把内容存到 content
# 之后用 content，不用 f
print(content)
