单元 0'python' 不是内部或外部命令

症状：终端里敲 python --version 报这一句，但明明装过了。 原因：安装时没勾「Add Python to PATH」，系统找不到解释器。 改法：重新运行安装包选 Modify 勾上 PATH，或手动把 ...\Python312\ 与 ...\Scripts\ 加进环境变量，然后重开终端（旧窗口不会刷新 PATH）。

单元 0按 3.12 的教程写，`removeprefix` 却报 AttributeError

症状：str 没有 removeprefix。 原因：装的是 3.8/3.9，这个方法是 3.9 才有的（match 语法是 3.10）。 改法：python --version 确认版本；低于 3.12 就升级——本课程按 3.12 写，前面的单元还能凑合，到单元 8 之后会到处踩坑。

单元 0pip install requests` 成功，`import requests` 却 ModuleNotFoundError

症状：装完导不进来。 原因：机器上有两个 Python，pip 属于另一个，VS Code 用的又是第三个。 改法：一律用 python -m pip install 包名（跟着当前解释器走）；VS Code 里 Ctrl+Shift+P → Python: Select Interpreter 选同一个解释器。

单元 0改了代码，运行结果没变

症状：明明保存了，输出还是旧的。 原因：跑的是另一个文件（同目录下有同名 .py），或终端里跑的是缓存的 .pyc。 改法：看 VS Code 标题栏的文件名与路径；终端里用 python 完整路径/文件名.py，或先 cd 到文件所在目录。

单元 0git checkout` 之后代码没了

症状：想撤销修改，结果改的内容被覆盖。 原因：git checkout -- 文件 是「用最近一次提交覆盖工作区」，不是「撤销上一次 checkout」。 改法：先 git status 看清改了什么；只想临时回退就先 git stash（可 git stash pop 找回），别直接 checkout。

单元 0PowerShell 里 `activate` 报「禁止运行脚本」

症状：创建虚拟环境后执行 .\venv\Scripts\activate，红色报错说此系统上禁止运行脚本。 原因：Windows PowerShell 默认的执行策略（Restricted）不允许运行 .ps1 脚本，activate 正是这种脚本。 改法：二选一——① 换成 cmd 或 Git Bash 终端，执行 venv\Scripts\activate.bat；② 仍用 PowerShell 就以管理员身份执行一次 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned，然后重开终端。 （这不是 Python 的问题，是 Windows 的安全策略，放宽到 RemoteSigned 只影响当前用户。）

单元 0把自己的文件命名成 `python.py` / `random.py` / `string.py

症状：import random 之后行为怪异，或者报 AttributeError: module 'random' has no attribute 'xxx'。 原因：你的文件名和标准库同名，Python 会优先导入你这个文件，把真正的标准库挡住了。 改法：立刻改名（如 my_random_demo.py），并删掉同目录下生成的 __pycache__ 文件夹。 规则：文件名永远不要用标准库名、也不要用 test.py（会和测试工具抢名字）。

单元 0Windows 上打印中文报 `UnicodeEncodeError`，或者文件里读出来是乱码

症状：print("中文") 直接崩，或者读 CSV 时中文变成 \xc4\xe3 之类。 原因：Windows 控制台默认编码是 GBK，而文件用的是 UTF-8，两边对不上。 改法： 1. 终端里先执行 chcp 65001 切到 UTF-8（或在「设置 → 时间和语言 → 语言 → 管理语言设置」里勾上 Beta UTF-8）。 2. 读写文件永远显式写编码：open(path, encoding="utf-8")，这是根治办法，别依赖系统默认。 3. VS Code 右下角看到编码不是 UTF-8 时，点它 → 「通过编码保存」→ 选 UTF-8。

单元 1SyntaxError: unterminated string literal

症状：字符串那行报「未闭合」。 原因：引号不成对——常见是中文引号 “”，或字符串里本身有引号没转义。 改法：统一用英文 " '；字符串里要引号就用另一种，或 \"。

单元 1int("3.9")` 报 ValueError

症状：把用户输入转整数崩了。 原因：int() 只认整数字面量，"3.9" 是浮点写法。 改法：先 float("3.9") 再 int(...)（会截断成 3）；要四舍五入用 round()，别指望 int()。

单元 1bool("0")` 竟然是 `True

症状：以为 "0" 是假值。 原因：bool() 对字符串只看「空不空」，非空字符串一律为真。 改法：要判断「是不是数字 0」得先转换：int(s) == 0；或用 s in ("0", "") 这类显式判断。

单元 1if x = 1:` 语法错误

症状：SyntaxError: invalid syntax 指向等号。 原因：= 是赋值，== 才是比较。 改法：条件里一律 ==；想同时赋值用海象运算符 if (n := len(s)) > 3:（3.8+）。

单元 1变量名 `class` / `2myvar` 报错

症状：SyntaxError 或变量莫名其妙是别的东西。 原因：class 是关键字；标识符不能以数字开头。 改法：避开 Python 关键字（import keyword; print(keyword.kwlist) 可查），名字用 my_var 这种下划线风格。

单元 2IndexError: list index out of range

症状：cars[3] 崩了，列表明明有 3 个元素。 原因：下标从 0 开始，3 个元素的下标是 0/1/2。 改法：最后一项用 cars[-1]；要按下标循环就 range(len(cars))，别手写上限。

单元 2空列表上 `x[-1]` 也崩

症状：IndexError 出现在取最后一项时。 原因：空列表没有任何元素，-1 一样越界。 改法：先判 if cars:（空列表为假），或用 cars[-1] if cars else None。

单元 2cars = cars.sort()` 之后列表变成 None

症状：排序后再用就 TypeError: 'NoneType' object is not subscriptable。 原因：sort() 原地排序、返回 None；sorted() 才返回新列表。 改法：cars.sort() 单独一行；要保留原列表就 new = sorted(cars)。

单元 2b = a` 之后改 b，a 也变了

症状：明明只改了副本。 原因：b = a 只是给同一个列表起了个别名，不是复制。 改法：b = a.copy() 或 b = a[:]（浅复制）；列表里还套列表时要用 copy.deepcopy(a)。

单元 2cars.remove("bmw")` 只删掉一个

症状：列表里有两个 "bmw"，只少了一个。 原因：remove() 只删第一个匹配项，且没有返回值。 改法：要删干净用循环 while "bmw" in cars: cars.remove("bmw")，或列表推导 cars = [c for c in cars if c != "bmw"]。

单元 3边 `for` 边 `remove`，元素漏删

症状：列表里 3 个 "x"，循环后还剩 1 个。 原因：删除会让后面的元素前移，而循环下标继续往后走，正好跳过下一个。 改法：while "x" in items: items.remove("x")，或倒序遍历 for i in reversed(range(len(items)))，或直接列表推导。

单元 3切片越界却不报错

症状：nums[2:99] 没崩，但结果比预期短。 原因：切片是「容错」的，越界只截到末尾。 改法：这是特性不是 bug；要严格校验长度就自己 if len(nums) < 3: raise ValueError。

单元 3for i in range(len(x))` 里 `append

症状：循环次数比预期多，甚至死循环。 原因：range(len(x)) 在循环开始时就把长度算好了；若在循环里删除，下标与元素就错位。 改法：不要在遍历时改长度；需要新列表就新建 out = [] 再 out.append(...)。

单元 3sorted(x, reverse=True)` 与 `x[::-1]` 混用

症状：以为两者等价，结果顺序不同。 原因：sorted(reverse=True) 是按大小降序；[::-1] 只是把原顺序倒过来。 改法：要排序用 sorted()；只想倒序用 reversed(x) 或 x[::-1]。

单元 3t[0] = 1` 报 TypeError

症状：'tuple' object does not support item assignment。 原因：元组不可变，创建后不能改元素。 改法：要改就换成列表；确实要「改一个值」就重建：t = t[:1] + (9,) + t[2:]。

单元 4IndentationError: expected an indented block

症状：if 后面那行没缩进。 原因：Python 用缩进表示代码块，if/for/def 后面必须缩进一层。 改法：统一 4 个空格（不要混 Tab）；VS Code 里开 Render Whitespace 能看见空格与 Tab 的区别。

单元 4if x = 1:` 或 `elif` 写成 `else if

症状：SyntaxError。 原因：条件用 ==；Python 没有 else if，是 elif。 改法：if x == 1:；多分支写 if / elif / else。

单元 4if answer == "Yes"` 对 `"yes"` 不成立

症状：用户输入 yes 却走了 else。 原因：字符串比较区分大小写。 改法：比较前统一 answer.strip().lower()；需要更宽松就用 answer.lower() in ("y", "yes")。

单元 4elif` 顺序写反，永远进第一个分支

症状：分数 95 只拿到「及格」。 原因：if score > 60: ... elif score > 90: ...——90 分也满足 > 60，第一个分支就截住了。 改法：从窄到宽排：先 >= 90，再 >= 60，最后 else。

单元 4if items:` 判空却把 0 当成空

症状：数量是 0 时走了「没有数据」分支，但 0 是合法值。 原因：0、""、[]、None 在条件里都为假。 改法：要区分「没有」和「是 0」就显式判：if items is None:、if len(items) == 0:。

单元 5KeyError: 'name'

症状：取一个不存在的键就崩。 原因：d["name"] 在键缺失时抛异常（这是设计，不是 bug）。 改法：可能缺的键用 d.get("name", "默认值")；确实必须有就让它崩，但要在上层 try/except KeyError 给出可读提示。

单元 5遍历字典时增删键 → RuntimeError

症状：dictionary changed size during iteration。 原因：迭代器依赖内部结构，边遍历边改会让它失效。 改法：先取快照 for k in list(d):，再改 d；或先用推导式算出要删的键，循环外统一删。

单元 5拿列表当键 → TypeError: unhashable type

症状：d[[1, 2]] = "x" 报不可哈希。 原因：字典靠 hash 定位，键必须不可变。 改法：用元组 d[(1, 2)]，或把列表 tuple(lst) 转一下。

单元 5以为 `d.keys()` 是列表，能下标

症状：d.keys()[0] 报 'dict_keys' object is not subscriptable。 原因：keys()/values()/items() 返回的是视图，不是列表。 改法：要下标就 list(d.keys())[0]；只是遍历直接用 for k in d:。

单元 5嵌套字典层层 `[]`，中间缺一层就崩

症状：d["a"]["b"]["c"] 里 d["a"] 不存在时 KeyError。 改法：逐层 get：d.get("a", {}).get("b", {}).get("c")；层次深就写个小函数或用 defaultdict。

单元 6input()` 拿到的数字当数字用

症状：if age > 18: 报 TypeError: '>' not supported between 'str' and 'int'。 原因：input() 永远返回字符串，"18" > 18 不成立。 改法：age = int(input("年龄："))；不确定输入合法就先 try: age = int(s) except ValueError: 提示重输。

单元 6while` 忘了改条件，死循环

症状：程序卡住不动，CPU 占满。 原因：while i < 5: 里没写 i += 1，条件永远成立。 改法：循环体里必须有能让条件变假的语句；临时排查在循环里加 print(i)（Ctrl+C 停）。

单元 6while "x" in items: items.remove("x")` 写成 `if

症状：删了一个还剩俩。 原因：if 只判断一次；要删干净得反复判断。 改法：用 while ... in ...；或 items = [i for i in items if i != "x"]。

单元 6break` 只跳出最内层

症状：两层循环里 break 之后外层还在跑。 原因：break 只结束它所在的那一层。 改法：用标志位 done = True 让外层也退出，或把内层抽成函数 return。

单元 6while True:` 里没留退出路径

症状：必须强制关窗口。 原因：只写了 break 的条件永远不会满足（比如没处理「退出」关键字）。 改法：明确列出所有结束条件；while True 里至少有一条 break 与用户输入相关。

单元 7★ 函数修改列表，会改到原列表
Pythondef add_item(items):
    items.append("新元素")      # 这一行直接改掉了调用方的列表


fruits = ["苹果"]
add_item(fruits)
print(fruits)      # ['苹果', '新元素']  ← 原数据被污染了

症状：函数返回后，原列表莫名其妙多了东西；或者多个函数调用之间数据互相串味。 原因：列表是可变对象，Python 传的是"地址"，函数里改的就是原件。 修法（三选一）：

Python# 修法1：函数内造副本（推荐）
def add_item(items):
    items = items[:]        # 先复制
    items.append("新元素")
    return items

# 修法2：调用时传副本
add_item(fruits[:])

# 修法3：用 + 产生新列表
def add_item(items):
    return items + ["新元素"]
单元 7默认参数用了可变对象
故意写错 · 先跑一遍看报错def add_task(task, todo=[]):     # 错误：默认值是列表！
    todo.append(task)
    return todo


print(add_task("买菜"))     # ['买菜']
print(add_task("做饭"))     # ['买菜', '做饭']  ← 上次的"买菜"莫名出现！
print(add_task("睡觉"))     # ['买菜', '做饭', '睡觉']
这是故意写错的示例——先自己跑一遍看报错，再对照下面的解析弄清错在哪

症状：单独调用正常，反复调用时结果里出现了前面调用的数据。 原因：默认参数在函数定义时只求值一次，那个列表被所有调用共享。 修法：

Pythondef add_task(task, todo=None):     # 默认值用 None
    if todo is None:
        todo = []                 # 每次调用时新建
    todo.append(task)
    return todo

单元 7参数顺序或数量不对
Pythondef make_pizza(size=12, with_cheese=True):
    """有默认值的参数必须写在没有默认值的参数后面。"""
    return f"{size} 英寸，芝士={with_cheese}"


# INTENTIONALLY-BROKEN 演示 3 类调用错误
print(make_pizza(16, False))       # 合法：16 英寸，芝士=False
print(make_pizza(False))           # 陷阱：False 被当成了 size！
# print(make_pizza(16, 18, 20))    # 错误：Too many positional arguments
# print(make_pizza(size=16, cheese=True))   # 错误：参数名写错，应为 with_cheese

# 报错信息里有个高频拼写错误：cheese 不是 with_cheese

单元 15样式名写老版本，报 `ValueError: style 'seaborn' is not in available styles

matplotlib 0.13 之后 seaborn 系列加了版本后缀，写 "seaborn-v0_8" 而不是 "seaborn"；拿不准就先 print(plt.style.available) 看现装的。样式只是皮肤。

单元 15matplotlib.use("Agg")` 写在 `import matplotlib.pyplot` 之后

会报 RuntimeError: Cannot switch to Agg after importing pyplot，因为后端在导入 pyplot 时就定死了。顺序必须先 matplotlib.use、后 import pyplot。

单元 15忘了 `assert sum(frequencies) == len(results)

range(1, die.num_sides + 1) 少写 + 1，最后一个面的频次永远是 0，图上少一根柱子，程序一声不吭。凡「按类别统计」都该加这行断言。

单元 16★ 把 `coordinates[1]` 当成经度（经纬度写反）

GeoJSON 的坐标是 [经度, 纬度, 深度]。写成 lat = coordinates[0]、lon = coordinates[1]，程序不报错，但所有点跑到镜像位置。自检方法：纬度绝对值不应超过 90。每次写完 coordinates，默念「先 lon 后 lat」。

单元 16★ 硬编码列号 `row[4]

数据源一更新（列顺序变了、多了几列），程序要么 IndexError，要么安静地取错列。正确做法：先 enumerate 打印表头，按列名建字典 {name: index}，再取数。

单元 16strptime` 格式码和字符串不匹配

"2021-07-01" 配 "%Y/%m/%d"、"2021/7/1" 配 "%Y-%m-%d"（少前导零也麻烦），都会抛 ValueError: time data ... does not match format。排查方法：把字符串和格式码并排写在纸上，一个字符一个字符对。

单元 16把 `append` 写进 `try` 块

某天 TMAX 缺失时，int("") 抛异常，但异常前的 dates.append 已经执行，lows 也可能转换成功——三个列表错位，画图时报一个看不懂的错，或者更糟：画出一张安静的错图。记住：append 放 else，保证「要么三个都进，要么都不进」。

单元 16plt.show()` 在无图形界面的环境卡住

远程服务器、WSL、某些 IDE 里 plt.show() 会报错或让程序挂起。本讲义统一用 plt.savefig("图.png", dpi=150, bbox_inches="tight") 存文件，哪里都能跑。教材未涉及，补充说明。

单元 16细节两件套——样式名和 CSV 参数

plt.style.use("seaborn") 在新版 matplotlib 会报 ValueError，要写 "seaborn-v0_8"（样式只是皮肤，删掉也行）；写 CSV 忘加 newline="" 会在 Windows 上多出空行，忘加 encoding="utf-8" 中文可能变乱码。

单元 17不检查状态码就 `.json()

症状：JSONDecodeError，或者拿到 {"message": "rate limit"} 还在解析。 原因：4xx/5xx 的响应体不是你要的数据。 改法：先 if r.status_code != 200: 打印状态与响应前 200 字，再决定是否解析；或 r.raise_for_status()。

单元 17没设超时，程序一直挂着

症状：脚本卡住不动，也不报错。 原因：requests.get(url) 默认不超时（可能等几分钟）。 改法：requests.get(url, timeout=10)；批量抓取时循环里加 time.sleep(0.5)。

单元 17只取了第一页

症状：明明有 1000 条，只拿到 30 条。 原因：分页参数没处理。 改法：看响应里的 next/Link 头或 page 字段，循环取到没有下一页为止。

单元 17直接 `data["items"]` → 偶尔 KeyError

症状：平时正常，偶尔崩一次。 原因：接口在出错/限流时返回的字段不一样。 改法：data.get("items", [])；每个 item 也用 .get("name", "?")。

单元 17被 403/429 拦了还继续打

症状：越跑越慢，最后全 429。 原因：请求太密，触发限流。 改法：读 Retry-After 头、加 time.sleep 退避（1s→2s→4s）；带上 User-Agent，别裸奔。

单元 18★ 忘了激活虚拟环境

症状：ModuleNotFoundError: No module named 'django'；或者 Django 装是装上了，但换个终端就消失。诊断方法只有一个——看提示符前面有没有 (ll_env)。没有就重新激活：source ll_env/bin/activate（Windows 用 ll_env\Scripts\activate）。记住：每开一个新终端，就要重新激活一次。

单元 18★ 搞混 `learning_log/`、`ll_project/`、`learning_logs/

三个名字长得像，角色完全不同：learning_log/ 是你的工作目录（manage.py 在这），ll_project/ 是项目配置的家（settings.py、总 urls.py 在这），learning_logs/ 是干活的 app（models.py、views.py 在这）。改错文件是新手最贵的浪费——在 ll_project 里找 models.py 当然找不到，因为模型在 learning_logs 里。拿不准就 ls 看一眼。

单元 18改了 `models.py` 不迁移

加完字段直接刷新网页，报 OperationalError: no such table 或「no such column」。原因：只改了图纸没施工。记住三步曲一个都不能少：改 models.py → makemigrations → migrate。反过来也要警惕：makemigrations 之后忘了 migrate，同样是图纸没施工。

单元 18新 app 忘了在 `INSTALLED_APPS` 登记

症状：migrate 不给你的模型建表；管理网站里看不到模型；报 LookupError: No installed app with label 'xxx'。类比：新生不来注册学籍，学校花名册上就没这人，食堂不给他开饭。startapp 之后第一件事，就是去 settings.py 登记。

单元 18startproject` 末尾忘了写句点

django-admin startproject ll_project（没有 .）会多套一层目录，manage.py 被埋进子目录，部署时各种配置问题。教材特意用「注意」框强调：千万别忘了这个句点。真忘了也别慌——删掉刚生成的目录（保留 ll_env），带上句点重跑。

单元 18模板里 `{% url %}` 写错

NoReverseMatch: Reverse for 'index' not found——十有八九是漏了命名空间。正确写法是 {% url 'learning_logs:index' %}（app 名 + 冒号 + URL 模式名）。另外注意教材的提醒：模板里用对象的 topic.id 取 ID 值，视图里的形参叫 topic_id，两者别混。

单元 19★ 视图里用 `.all()`，忘了按用户过滤

症状：登录 A 账号，能看到 B 账号的全部主题和条目——数据裸奔，本单元最严重的事故。自查方法：搜索项目里所有 objects.all()，逐个问「这里该不该按 owner=request.user 过滤」。涉及用户私有数据的查询，一个都不能漏。

单元 19★ `fields` 白名单里写了 `owner

fields = ["text", "owner"] 等于把「归属」这一列的控制权交给用户——提交表单时塞个别人的用户 ID，数据就归了别人。归属信息只有一个合法来源：request.user，由系统在 save(commit=False) 之后盖章。表单白名单里永远不要出现 owner。

单元 19忘了写 `@login_required

未登录用户访问该视图时，request.user 是 AnonymousUser，filter(owner=AnonymousUser) 直接 500。装饰器就一行，漏写整个页面裸奔。建议：除了主页和注册页，其他视图全部加，加错了顶多严格一点，漏加了是事故。

单元 19save(commit=False)` 之后忘了 `save()

new_topic = form.save(commit=False) 只是拿到一个没入库的实例；不补 owner、不调用 save()，数据就永远停在内存里。最阴险的是页面照常跳转、用户毫无察觉——静默丢数据。记住三段式是一个整体：commit=False → 补 owner → save()。

单元 19登录模板放错位置

TemplateDoesNotExist at registration/login.html——默认登录视图只认 registration/login.html 这个路径，且要从某个 app 的 templates/ 目录下找。正确位置：accounts/templates/registration/login.html。差一个单词都不行，这是 Django 的约定，没有为什么，记住即可。

单元 19edit_entry` 只查了条目，没查主题归属

entry = Entry.objects.get(id=entry_id) 之后直接用，等于放任用户 A 通过 /edit_entry/别人的条目ID/ 编辑用户 B 的条目。Entry 自己没有 owner，归属要从 entry.topic.owner 往上追一层——这就是「双重保护」：既确认条目存在，也确认条目的主题属于当前用户。

单元 20★ ALLOWED_HOSTS 没加平台域名，线上 400

现象：部署成功、日志没报错，但一打开网址就是 400 Bad Request。原因：Django 校验每个请求的 Host 头，不在 ALLOWED_HOSTS 就直接 400，视图根本不执行。修复：settings.py 的 Platform.sh 段加 ALLOWED_HOSTS.append('.platformsh.site')，提交后重新 push。

单元 20忘了注册 django_bootstrap5，模板报 Invalid block tag

现象：页面 500，报 TemplateSyntaxError: Invalid block tag: 'bootstrap_form'。原因：{% load %} 只是「打开工具包」，包本身要在 INSTALLED_APPS 注册。修复：INSTALLED_APPS 加 'django_bootstrap5'。

单元 20DEBUG 关了却没收静态文件，白脸页面

现象：线上页面结构都在，但没有样式。原因：DEBUG = False 后 Django 不再代发静态文件；collectstatic 没跑，或 STATIC_ROOT 没设置。修复：build 钩子确保有 python manage.py collectstatic --noinput，云上段设置 STATIC_ROOT。

单元 20requirements.txt 漏了 gunicorn 或 psycopg2

现象：部署日志 ModuleNotFoundError: No module named 'gunicorn'，或连不上数据库。原因：本地用 runserver + SQLite，这两个包本地没装过，pip freeze 不会列出来。修复：建 requirements_remote.txt 写上两者，并在 build 钩子里 pip install -r requirements_remote.txt。

单元 20.gitignore 缺失，虚拟环境和本地数据库被推上云

现象：push 奇慢，仓库几百 MB；甚至线上用了你本地带数据的 SQLite 文件。原因：没有 .gitignore，git add . 把 ll_env/、__pycache__/、db.sqlite3 全提交了。修复：补写 .gitignore，用 git rm -r --cached 把已跟踪文件撤出索引，再提交。

单元 20新文件忘了 git add，推送后线上缺东西

现象：本地明明建了 templates/404.html，线上还是默认错误页。原因：git commit -am 只提交已跟踪文件的修改，新文件必须先 git add。修复：只要产生了新文件（包括 makemigrations 生成的迁移文件），先 git add . 再 commit。

单元 21★ 没有 .gitignore 就 `git add .`，虚拟环境和数据库进了仓库

现象：git push 传了 400MB。原因：没有 .gitignore，git add . 把一切都加进去了。修复：补写 .gitignore，再 git rm -r --cached ll_env 把已跟踪文件撤出索引（只删索引，不删本地文件），然后提交。

单元 21pip freeze` 在全局环境执行，清单长到没法看

现象：requirements.txt 有 80 行，大部分是本项目没用到的包。原因：没建虚拟环境就 pip freeze，冻的是全局环境。修复：python -m venv venv → 激活 → 只装项目需要的包 → pip freeze > requirements.txt。

单元 21★ 测试全是抄教材的，自己一条没写

现象：关卡 2 第 3 条过不了。原因：test_game_functions.py 里全是照抄的用例，没有一条针对你自己写的代码。修复：挑 3 个自己的纯逻辑函数，各写 2 条断言具体数值的测试（练习 21-2）。判断标准：关掉讲义后还能写出来，才算真的会。

单元 21把 SECRET_KEY 硬编码在 settings.py 里，还推上了公开仓库

现象：仓库公开后被人 issue 提醒。原因：SECRET_KEY = "django-insecure-…" 直接写在代码里。修复：改成 os.environ["DJANGO_SECRET_KEY"]，立刻去平台后台重置旧密钥（删记录没用，克隆里已经有了），把 .env 加进 .gitignore、提交 .env.example 说明要配哪些变量。

单元 21代码里全是魔法数字，改一个参数要翻 8 个文件

现象：「敌人快一点」这个需求改了半小时。原因：alien.rect.top += 1 这种数字散落在各处。修复：按 2.3 标准二抽到 settings.py，用有名字的常量替换；改完再搜一遍那个数字，确认没有漏网。

单元 21所有代码堆在一个文件里，两千行

现象：想加个功能要读 500 行才敢动手；pytest 一导入就把 pygame 窗口开起来了。原因：没拆文件（2.3 标准一）。修复：按「谁调用它」拆，先把纯逻辑挑出来——这一步顺带就解决了测试要开窗口的问题。
