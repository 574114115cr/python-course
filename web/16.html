二、核心知识点讲解

2.1 真实数据长什么样，去哪下载

前 15 个单元里，数据都是你自己写死的：scores = [92, 78, 65]——干净、整齐、随叫随到。从这一章开始，数据要从真实世界拿：

特点 玩具数据 真实数据
数量 三五条 几千上万行
质量 永远完整 有缺失、有异常
格式 你定的 别人定的，随时会变

类比：玩具数据像食堂里切好装盘的菜；真实数据像刚从菜地摘回来的菜——带着泥、有烂叶、大小不一。程序员的重要工作之一就是「洗菜」，本章就是教你洗菜。

本章处理两种最常见的真实数据格式：CSV（逗号分隔的表格，Excel 能直接打开）和 GeoJSON（带地理信息的 JSON，地震台网和地图服务的标准格式）。

教材数据去哪了。 第 16 章的代码会读这几个文件：

示例weather_data/sitka_weather_2021_simple.csv     # 锡特卡机场 2021 年气温
weather_data/death_valley_2021_simple.csv      # 死亡谷 2021 年气温（有缺失值）
eq_data/eq_data_1_day_m1.geojson               # USGS：一天内 M1 以上地震
eq_data/eq_data_30_day_m1.geojson              # USGS：30 天内 M1 以上地震

它们不在本仓库里（文件大，而且每年更新），要去教材配套资源站 https://ehmatthes.github.io/pcc_3e/ 打包下载，解压后把 chapter_16 里的 weather_data 和 eq_data 两个文件夹复制到你的项目目录。本讲义的所有示例都不依赖这些文件——先自己造小数据练手，拿到真数据后改个文件名就能用。

数据的真正来源。 气象数据来自美国 NOAA（国家海洋和大气管理局）的观测站网络；地震数据来自美国地质调查局（USGS），有实时 feed，可以自己下载最新数据：

示例USGS 地震数据 feed 列表页：
https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php

「过去一天、M1 以上」对应的实时数据：
https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/1.0_day.geojson

把第二个网址在浏览器里打开，看到的就是教材里 eq_data_1_day_m1.geojson 的「新鲜版」。教材数据是快照，你自己下载的永远是最新的——这就是「下载真实数据」的真正含义。

2.2 CSV：三件套读表头

教材的读取套路是「三件套」：Path.read_text() 读出全部文本 → splitlines() 切成行列表 → csv.reader() 逐行解析。真实 CSV 长这样（sitka 文件的前几行）：

示例"STATION","NAME","DATE","TAVG","TMAX","TMIN"
"USW00025333","SITKA AIRPORT, AK US","2021-01-01",,"44","40"
"USW00025333","SITKA AIRPORT, AK US","2021-01-02",,"44","35"

三个细节：每行一条记录、逗号分隔；字段带引号，但 csv.reader 会自动去掉；TAVG 那一列是空的（,,）——这就是后面要处理的缺失值。

Pythonfrom pathlib import Path
import csv

# 造一个小 CSV 代替教材数据（拿到真数据后换成 sitka_weather_2021_simple.csv）
path = Path("demo_weather.csv")
path.write_text(
    '"STATION","NAME","DATE","TAVG","TMAX","TMIN"\n'
    '"USW00025333","SITKA AIRPORT, AK US","2021-01-01",,"44","40"\n',
    encoding="utf-8")

lines = path.read_text(encoding="utf-8").splitlines()
reader = csv.reader(lines)
header_row = next(reader)      # 取出第一行（表头），reader 里剩下的就是数据

for index, column in enumerate(header_row):
    print(index, column)

# 正确姿势：先按列名找列号，再用变量取数据
column_index = {name: i for i, name in enumerate(header_row)}
print("DATE 在第", column_index["DATE"], "列")

为什么先取表头？ 表头告诉你每列是什么，但列的顺序不保证——今天 DATE 在第 2 列，明年 NOAA 调整格式可能就跑到第 3 列。所以教材反复强调：不要凭记忆写 row[2]，先用 enumerate 把列名和序号打出来，确认之后再写。 硬编码列号的程序，数据源一更新就会安静地取错列，或者干脆 IndexError。

2.3 datetime：把字符串变成日期 ★

这是本章最实用的新技能。CSV 里读出来的 "2021-07-01" 是字符串：没法做日期运算，matplotlib 也会把它当成普通文字，x 轴上 365 个标签挤成一团黑条。

datetime.strptime() 负责「解析」——把符合某个格式的字符串转成日期对象：

Pythonfrom datetime import datetime

first_date = datetime.strptime("2021-07-01", "%Y-%m-%d")
print(first_date)               # 2021-07-01 00:00:00

第二个参数是格式说明书。最常用的格式码：

格式码 含义 例子
%Y 四位年份 2021
%m 两位月份 07
%d 两位日期 01
%H 小时（24 小时制） 14
%M 分钟 30
%S 秒 05
%B 月份全称 July
%A 星期全称 Thursday

记忆口诀：p 是 parse（解析），字符串 → 日期对象；反过来 f 是 format（格式），日期对象 → 字符串：

Pythonfrom datetime import datetime

moment = datetime.strptime("2021-07-01 14:30", "%Y-%m-%d %H:%M")
print(moment.strftime("%Y年%m月%d日 %H:%M"))    # 2021年07月01日 14:30

这里难在哪？格式码必须和字符串严格对应。字符串里是连字符，格式码里也要有；字符串是 2021/07/01 而格式码写 %Y-%m-%d，就会抛 ValueError。卡住很正常——把字符串和格式码并排盯着看，一个字符一个字符对。

好消息是：matplotlib 认识日期对象。x 轴传日期对象进去，它会自动按月份、季度分布刻度，横轴立刻清爽——这就是「在图中添加日期」一节的全部秘密。

2.4 缺失值：真实数据的第一课

死亡谷的数据里有几天没测最高温，CSV 里对应字段是空的。int("") 会抛 ValueError，不处理程序直接崩。教材的处理模式值得逐行读懂（下面用 rows 模拟从 CSV 读出来的数据行）：

Pythonfrom datetime import datetime

rows = [
    ["USC00042319", "DEATH VALLEY, CA US", "2021-01-01", "71", "51"],
    ["USC00042319", "DEATH VALLEY, CA US", "2021-03-05", "", ""],   # 这天缺数据
]

dates, highs, lows = [], [], []
for row in rows:
    current_date = datetime.strptime(row[2], "%Y-%m-%d")
    try:
        high = int(row[3])
        low = int(row[4])
    except ValueError:
        print(f"Missing data for {current_date}")
    else:
        dates.append(current_date)
        highs.append(high)
        lows.append(low)

print(dates, highs, lows)

三个要点：

  1. try 只包住可能出错的两行转换——strptime 放在外面，日期格式是稳定的，真正的风险是空值。
  2. else 是灵魂：转换成功才把三个值分别 append。如果写在 try 里面，某天只有 TMAX 缺失时三个列表就可能错位——不等长，画图时直接报错。
  3. 警告要打印出来：print(f"Missing data for {current_date}") 让你知道「图上的缺口是数据缺失，不是代码 bug」。静默跳过的数据是不可信的。

类比：try/except 在这里是筛子——烂叶子（空值）漏出去，好菜进篮子。但筛子要留记录，否则你不知道漏掉了多少。

2.5 画温度图：plot + fill_between

数据洗干净了，画图只要几行（下面用内联小数据演示，真实项目里三个列表从 CSV 读出来）：

Pythonimport matplotlib.pyplot as plt
from datetime import datetime, timedelta

dates = [datetime(2021, 7, 1) + timedelta(days=i) for i in range(10)]
highs = [20, 21, 19, 22, 23, 21, 20, 19, 18, 20]
lows = [h - 7 for h in highs]

plt.style.use("seaborn-v0_8")       # 好看的内置样式（版本说明见下）
fig, ax = plt.subplots()
ax.plot(dates, highs, c="red", alpha=0.5)
ax.plot(dates, lows, c="blue", alpha=0.5)
ax.fill_between(dates, highs, lows, facecolor="blue", alpha=0.1)
fig.autofmt_xdate()                 # 日期标签自动倾斜，防止重叠
plt.savefig("演示温度图.png", dpi=120, bbox_inches="tight")
  • alpha 是透明度（0 全透明 ~ 1 全不透明）。两条线都半透明，重叠处颜色更深，信息不互相遮挡。
  • fill_between 把两条线之间的区域涂上颜色——温度区间带。一眼看出「这天的温差大不大」，比两根孤零零的线信息量大得多。
  • fig.autofmt_xdate() 让日期标签斜着排，365 天也不糊成一团。

绘图库的安装（本单元和下一单元都要用）：

终端命令# 安装绘图库（只需装一次）
pip install matplotlib plotly

版本说明（教材未涉及，补充）：plt.style.use("seaborn-v0_8") 的样式名带 -v0_8 后缀，是 matplotlib 0.13 之后的写法；老教程写 "seaborn"，新版会报 ValueError。样式只是皮肤，删掉这行完全不影响绘图。

教材里用 plt.show() 弹窗显示图形。本讲义的示例统一用 plt.savefig("文件名.png") 把图存成文件——服务器、远程环境、没有图形界面的地方也能跑，而且图能反复看、能贴进笔记。两者画出来的图完全一样。

2.6 GeoJSON：带地理位置的 JSON

JSON 你在单元 9 学过，GeoJSON 就是 JSON 的一个「行业规范」：专门表示地理要素。地震数据长这样（已删减）：

JSON{
  "type": "FeatureCollection",
  "metadata": {"title": "USGS Magnitude 1.0+ Earthquakes, Past Day"},
  "features": [
    {
      "type": "Feature",
      "properties": {"mag": 1.6, "place": "63km SE of Pondosa, CA"},
      "geometry": {"type": "Point", "coordinates": [-120.62, 41.13, 3.2]},
      "id": "nc733"
    }
  ]
}

结构拆解（这张图建议刻在脑子里）：

示例GeoJSON 文件
├── type: "FeatureCollection"        ← 这是个要素集合
├── metadata: {...}                  ← 数据是谁生成的、什么时候
└── features: [ ... ]                ← 重点！列表，每个元素是一次地震
    ├── [0]
    │   ├── properties: {...}        ← 震级 mag、地点 place 都在这
    │   └── geometry: {...}          ← 坐标 coordinates 在这
    │       └── coordinates: [经度, 纬度, 深度]
    └── [1] ...

取数据的路线和 JSON 一模一样——一层层字典取值：

Pythonimport json
from pathlib import Path

# 造一个 mini GeoJSON 代替教材数据
path = Path("demo_eq.geojson")
path.write_text(json.dumps({
    "type": "FeatureCollection",
    "features": [{"type": "Feature",
                  "properties": {"mag": 1.6},
                  "geometry": {"type": "Point",
                               "coordinates": [-120.62, 41.13, 3.2]}}],
}), encoding="utf-8")

all_eq_data = json.loads(path.read_text(encoding="utf-8"))
all_eq_dicts = all_eq_data["features"]           # 拿到地震列表

for eq_dict in all_eq_dicts:
    mag = eq_dict["properties"]["mag"]           # 震级
    lon = eq_dict["geometry"]["coordinates"][0]  # 经度
    lat = eq_dict["geometry"]["coordinates"][1]  # 纬度
    print(f"M {mag}  lon={lon}  lat={lat}")

★ 经纬度顺序是中国新手的高频错误，必须单独强调：

GeoJSON 的 coordinates 是 [经度, 纬度, 深度]——经度在前，纬度在后。这和「先说纬度」的日常习惯正好相反，也和 Plotly 函数参数 lat=..., lon=... 的书写顺序相反。类比：就像快递单上的「城市, 街道」——GeoJSON 要求先写城市（经度，东西方向），再写街道（纬度，南北方向），写反了包裹就送到地球另一边。coordinates[0] 是经度（北京约 116），coordinates[1] 是纬度（北京约 40）。

写反的后果最恶劣：不报错，只是静默地错。所有点都跑到镜像位置（比如中国跑到大西洋里去），图看着像那么回事，其实就是错的。每次写 coordinates 都默念一遍：先 lon 后 lat。

2.7 Plotly 画全球地震散点图

数据到手（三个列表：mags、lons、lats），画图是 plotly.express 的主场：

Pythonimport plotly.express as px

# 内联小数据演示（真实项目里换成从 GeoJSON 提取的三个列表）
lats, lons, mags = [19.3, 37.5], [-156.5, 142.8], [5.8, 6.1]
eq_titles = ["M 5.8 - Hawaii", "M 6.1 - Japan"]

fig = px.scatter_geo(
    lat=lats, lon=lons, size=mags, title="Global Earthquakes",
    color=mags,
    color_continuous_scale="Viridis",
    labels={"color": "Magnitude"},
    projection="natural earth",
    hover_name=eq_titles,
)
fig.write_html("全球地震.html")      # 保存成可交互网页

参数一个一个说：

参数 作用
lat / lon 每个点的位置
size 点的大小——传震级列表，大地震点就大
color 点的颜色映射——同样传震级
color_continuous_scale 渐变色方案，"Viridis" 是教材用的（还有 "Inferno"、"Plasma"、"Blues" 等）
projection 地图投影方式，"natural earth" 是常见的世界地图样式
hover_name 鼠标悬停时显示的标题列表
labels 图例的名字

fig.show() 会在浏览器里打开交互图；本讲义用 fig.write_html("xxx.html") 存成文件，双击打开效果一样，还能直接发给别人。

指定数据的另一种方式。 px.scatter_geo() 是「快捷函数」，一条龙服务；Plotly 也支持用 graph_objects 显式地指定数据，自己搭：

Pythonimport plotly.graph_objects as go

lons, lats, mags = [-156.5, 142.8], [19.3, 37.5], [5.8, 6.1]
eq_titles = ["M 5.8 - Hawaii", "M 6.1 - Japan"]

fig = go.Figure(
    data=go.Scattergeo(
        lon=lons, lat=lats, text=eq_titles,
        marker=dict(size=[5 * mag for mag in mags], color=mags),
    )
)
fig.update_geos(projection_type="natural earth")
fig.write_html("dict方式演示.html")

快捷函数帮你把常用配置打包好了；显式写法自由度更高（比如 marker 里能同时精细控制尺寸、颜色、描边）。入门阶段用 px 就够了，知道还有另一种方式，是为了以后看到别人的代码不陌生。

补充说明（教材未涉及）：如果运行 px.xxx() 报 NotImplementedError: Pandas installation is required，说明 plotly 没带上 pandas，pip install pandas 即可——plotly.express 内部用 pandas 处理数据。

示例 2：datetime 解析与格式化

Python# datetime_demo.py —— strptime / strftime 练习

from datetime import datetime, timedelta

# ===== 1. strptime：字符串 -> 日期对象（parse 解析）=====
samples = [
    ("2021-07-01", "%Y-%m-%d"),
    ("2021/07/01", "%Y/%m/%d"),
    ("2021-07-01 14:30:05", "%Y-%m-%d %H:%M:%S"),
    ("July 1, 2021", "%B %d, %Y"),
]

print("--- strptime 解析 ---")
for text, fmt in samples:
    date_obj = datetime.strptime(text, fmt)
    print(f"{text!r:24} + {fmt!r:22} -> {date_obj}")

# ===== 2. 格式码必须和字符串严格匹配，否则 ValueError =====
print("\n--- 格式不匹配会怎样 ---")
try:
    datetime.strptime("2021-07-01", "%Y/%m/%d")     # 字符串是 -，格式写 /
except ValueError as error:
    print("解析失败：", error)

# ===== 3. strftime：日期对象 -> 字符串（format 格式化）=====
first_date = datetime.strptime("2021-07-01", "%Y-%m-%d")
print("\n--- strftime 格式化 ---")
print(first_date.strftime("%Y年%m月%d日"))            # 2021年07月01日
print(first_date.strftime("%B"))                      # July（月份名）
print(first_date.strftime("%A"))                      # Thursday（星期名）

# ===== 4. 日期对象能做算术，字符串不能 =====
tomorrow = first_date + timedelta(days=30)
print(f"\n{first_date.date()} 往后 30 天是 {tomorrow.date()}")
print("字符串直接相加:", "2021-07-01" + "30")          # 2021-07-0130，没有意义

示例 6：不下载文件也能练 CSV——StringIO 造表 + 按年统计（csv_stringio.py）

2.2 节的「三件套」需要真文件，rw_visual 那类脚本更是非得有 weather_data/*.csv 才能跑。练手阶段不必等下载：io.StringIO 能把一段文本伪装成文件对象，csv.DictReader 照样能读。这个示例用 6 行假数据把「读表头 → 处理缺失值 → 按年统计 → 转成 JSON」整条链路走一遍——换成真文件时，只需把 StringIO 那行换成 open(...)。

Python# csv_stringio.py —— 不下载文件也能练：用 StringIO 造表 + 按年统计
import csv
import io
from datetime import datetime

CSV_TEXT = """STATION,NAME,DATE,TMAX,TMIN
USC00042319,DEATH VALLEY,2021-01-01,71,51
USC00042319,DEATH VALLEY,2021-07-11,128,91
USC00042319,DEATH VALLEY,2021-12-31,64,40
USC00042319,DEATH VALLEY,2022-06-17,,88
USC00042319,DEATH VALLEY,2022-07-09,127,90
USW00025333,SITKA,2022-07-05,64,52
"""

stream = io.StringIO(CSV_TEXT)          # 文件对象？StringIO 假装自己是文件
reader = csv.DictReader(stream)          # ★ 用表头当键，不用记列号
print("表头：", reader.fieldnames)
rows = list(reader)
print(f"数据行：{len(rows)} 条；第一行：{rows[0]}")

by_year = {}                             # 年份 -> {"tmax": 最高温, "when": 哪天}
missing = 0
for row in rows:
    when = datetime.strptime(row["DATE"], "%Y-%m-%d")
    try:
        high = int(row["TMAX"])
    except (TypeError, ValueError):
        missing += 1                     # 空字段 -> None，int(None) 抛 TypeError
        print(f"  跳过 {row['DATE']}：TMAX 缺失")
        continue
    best = by_year.setdefault(when.year, {"tmax": high, "when": when})
    if high > best["tmax"]:
        by_year[when.year] = {"tmax": high, "when": when}

print(f"\n=== 每年最高温（共 {len(by_year)} 年，跳过 {missing} 条缺数据）===")
for year in sorted(by_year):
    item = by_year[year]
    print(f"{year}：{item['tmax']}°F 出现在 {item['when']:%Y-%m-%d}")

print("\n=== 两个站点各有多少条 ===")
stations = {}
for row in rows:
    stations[row["NAME"]] = stations.get(row["NAME"], 0) + 1
for name, count in sorted(stations.items()):
    print(f"  {name:<14}{count} 条")

print("\n=== 换成 json 输出（plotly 那边要的就是这种结构）===")
import json

payload = [{"year": year, "tmax": item["tmax"],
            "date": item["when"].strftime("%Y-%m-%d")}
           for year, item in sorted(by_year.items())]
print(json.dumps(payload, ensure_ascii=False))

运行结果（实跑输出）：

示例表头： ['STATION', 'NAME', 'DATE', 'TMAX', 'TMIN']
数据行：6 条；第一行：{'STATION': 'USC00042319', 'NAME': 'DEATH VALLEY', 'DATE': '2021-01-01', 'TMAX': '71', 'TMIN': '51'}
  跳过 2022-06-17：TMAX 缺失

=== 每年最高温（共 2 年，跳过 1 条缺数据）===
2021：128°F 出现在 2021-07-11
2022：127°F 出现在 2022-07-09

=== 两个站点各有多少条 ===
  DEATH VALLEY  5 条
  SITKA         1 条

=== 换成 json 输出（plotly 那边要的就是这种结构）===
[{"year": 2021, "tmax": 128, "date": "2021-07-11"}, {"year": 2022, "tmax": 127, "date": "2022-07-09"}]

三条解读：

  1. DictReader 让「列号硬编码」这个坑彻底消失。2.2 节说别写 row[4]，DictReader 用表头当键，row["TMAX"] 永远不会因为列序调整而取错；代价是每行多一个 dict，4000 行的表也就几 MB，值得。空字段读出来是空字符串 ""（不是 None），int("") 抛的是 ValueError。
  2. by_year.setdefault(...) 与「先赋值再比」两行配合，才不漏第一年。少了 setdefault 那行，best["tmax"] 会 KeyError；少了后面那个 if，每年只会记住第一天。这类「累加式最大值」写错时不报错，只是结果偏向第一个样本——所以一定要像本示例一样把每年结果打印出来核对。
  3. 把 CSV 多加一列 TMIN 之后再加一列 TAVG 会怎样：统计逻辑一行都不用改，因为 DictReader 只按名字取；但如果换成 csv.reader + row[4]，加一列就让所有取值整体错位一列，页面照样出图，数字全错。这就是教材反复强调「先取表头」的原因。

Python# date_converter.py —— 多格式日期解析

from datetime import datetime

FORMATS = ["%Y-%m-%d", "%Y/%m/%d", "%Y年%m月%d日"]
WEEKDAYS = ["星期一", "星期二", "星期三", "星期四", "星期五", "星期六", "星期日"]

def parse_date(text):
    """依次尝试多种格式解析日期。

    成功返回 (True, 日期对象)，全部失败返回 (False, None)。
    """
    for fmt in FORMATS:
        try:
            return True, datetime.strptime(text, fmt)
        except ValueError:
            continue                     # 这种格式不行，换下一种
    return False, None

test_inputs = ["2021-07-01", "2021/07/01", "2021年7月1日", "07-01-2021", "乱七八糟"]

for text in test_inputs:
    ok, date_obj = parse_date(text)
    if ok:
        weekday = WEEKDAYS[date_obj.weekday()]      # weekday(): 周一=0
        pretty = f"{date_obj.year}年{date_obj.month:02d}月{date_obj.day:02d}日 {weekday}"
        print(f"{text!r:12} -> 解析成功: {date_obj.date()}, 格式化: {pretty}")
    else:
        print(f"{text!r:12} -> 解析失败（三种格式都不匹配）")

# 失败原因分析：
# "07-01-2021"：格式要求年份在前，它把 07 当年份、01 当月、2021 当日 -> 日越界
# "乱七八糟"：没有数字，三种格式全部 ValueError

六、常见错误清单（务必逐条自查）

错误 1：★ 把 coordinates[1] 当成经度（经纬度写反）

GeoJSON 的坐标是 [经度, 纬度, 深度]。写成 lat = coordinates[0]、lon = coordinates[1]，程序不报错，但所有点跑到镜像位置。自检方法：纬度绝对值不应超过 90。每次写完 coordinates，默念「先 lon 后 lat」。

错误 2：★ 硬编码列号 row[4]

数据源一更新（列顺序变了、多了几列），程序要么 IndexError，要么安静地取错列。正确做法：先 enumerate 打印表头，按列名建字典 {name: index}，再取数。

错误 3：strptime 格式码和字符串不匹配

"2021-07-01" 配 "%Y/%m/%d"、"2021/7/1" 配 "%Y-%m-%d"（少前导零也麻烦），都会抛 ValueError: time data ... does not match format。排查方法：把字符串和格式码并排写在纸上，一个字符一个字符对。

错误 4：把 append 写进 try 块

某天 TMAX 缺失时，int("") 抛异常，但异常前的 dates.append 已经执行，lows 也可能转换成功——三个列表错位，画图时报一个看不懂的错，或者更糟：画出一张安静的错图。记住：append 放 else，保证「要么三个都进，要么都不进」。

错误 5：plt.show() 在无图形界面的环境卡住

远程服务器、WSL、某些 IDE 里 plt.show() 会报错或让程序挂起。本讲义统一用 plt.savefig("图.png", dpi=150, bbox_inches="tight") 存文件，哪里都能跑。教材未涉及，补充说明。

错误 6：细节两件套——样式名和 CSV 参数

plt.style.use("seaborn") 在新版 matplotlib 会报 ValueError，要写 "seaborn-v0_8"（样式只是皮肤，删掉也行）；写 CSV 忘加 newline="" 会在 Windows 上多出空行，忘加 encoding="utf-8" 中文可能变乱码。

七、本单元验收自测

1. 简答题：读取 CSV 时，为什么教材不直接写 row[4] 取最高温，而要先用 enumerate 打印表头？

要点：真实数据的列顺序不保证。今天 DATE 在第 2 列，数据源一更新可能跑到第 3 列。硬编码列号的程序会安静地取错列或直接 IndexError。先用 enumerate 建立「列名 → 列号」的映射再取数，数据怎么变都不会错。这是处理外部数据的基本修养：永远不要信任你没验证过的数据结构。

2. 判断题：GeoJSON 的 coordinates 是 [纬度, 经度, 深度]。

要点：错误。是 [经度, 纬度, 深度]——经度在前。coordinates[0] 是 lon（东西向，±180 内），coordinates[1] 是 lat（南北向，±90 内）。这个错误不报错、只静默地错，是最危险的一类 bug。自检：纬度超过 90 就一定写反了。

3. 简答题：datetime.strptime("2021-07-01", "%Y-%m-%d") 和 .strftime("%Y年%m月%d日") 分别在做什么？格式码和字符串不匹配会怎样？

要点：strptime 是 parse（解析）：字符串 → 日期对象，第二个参数是「格式说明书」；不匹配抛 ValueError。strftime 是 format（格式化）：日期对象 → 字符串，格式码描述「想要什么样的输出」，一般不抛错，只会得到不符合预期的输出。记忆：p=parse 解析，f=format 格式化。
