二、核心知识点讲解

2.1 选型：静态图还是交互图

写下第一行 import 前先答：这张图给谁看？

场景 用什么 为什么
写进报告、论文，要能打印 matplotlib 存成 PNG，像素确定，到处能贴
发给同事，想拖动、悬停看数值 Plotly 存成 HTML，浏览器里能交互

类比：matplotlib 像印在纸上的图——定稿不变、能复印；Plotly 像挂墙的电子展板——观众能凑近看，但要通电和场地。

安装：

终端命令pip install matplotlib plotly

★ 无图形界面的环境怎么办。 服务器、WSL、某些 IDE 里没屏幕，plt.show() 会报 UserWarning: Matplotlib is currently using agg，或让程序挂住。本讲义示例统一用 fig.savefig("xx.png") 存文件。若连保存也要静默，在导入 pyplot 之前加 matplotlib.use("Agg")（教材未涉及，补充），写反会报错。

2.2 面向对象：fig, ax = plt.subplots() ★

教材先带你写「过程式」老写法：plt.plot(input_values, output_values)，所有东西都往全局的 plt 上挂。它能跑，但画三张图时标题互相覆盖、图互相顶掉，你得不停 plt.figure()、plt.subplot()。面向对象写法把「图」和「坐标轴」分成两个对象：

示例fig（图 / figure）——整张画布：多个子图、整体标题、存盘
 └── ax（坐标轴 / axes）——一块绘图区：画线、设标题、设刻度

类比：fig 是画板，ax 是画板上贴好的一张白纸。

Pythonimport matplotlib.pyplot as plt

fig, ax = plt.subplots()                  # 拿一块画板 + 一张纸
ax.plot([1, 2, 3], [1, 4, 9])             # 在纸上画
ax.set_title("第一个面向对象图")
fig.savefig("oo_第一张图.png", dpi=100, bbox_inches="tight")

中间的逗号叫解包：函数返回元组 (figure, axes)，一句话拆成两个变量。ax 是官方推荐的名字（axes 的缩写），全世界教程都在用。

2.3 折线图细节：线宽、标签、样式

参数 作用 例子
linewidth / lw 线条粗细（单位是「点」不是像素） lw=3
linestyle / ls 线型 "--" 虚线、":" 点线
color / c 颜色 c="red"、c="#1f77b4"
marker 数据点形状 marker="o"
alpha 透明度 0~1 alpha=0.5
label 图例用的名字 label="实际值"

内置样式一行换肤：先 print(plt.style.available) 看有哪些，再 plt.style.use("seaborn-v0_8")。

版本坑（教材未涉及，补充）：matplotlib 0.13 之后 seaborn 系列样式名都带版本后缀，要写 "seaborn-v0_8" 而不是 "seaborn"，否则抛 ValueError: style 'seaborn' is not in the list of available styles。而 "ggplot"、"bmh" 这些老名字仍然有效。样式只是皮肤，删掉不影响结果。

★ figsize 与 dpi：清晰度靠 dpi，物理尺寸靠 figsize（英寸）。想插一张不糊的图，两个一起加：subplots(figsize=(12, 8)) 配 savefig(..., dpi=200)。

2.4 散点图三件套：s=、c=、cmap=

折线图适合有先后顺序的数据，散点图适合两个量的关系。★ 三件套是三个独立通道：

示例散点图 = 点在哪（x, y）
       + 点多大（s=）      ← 第三个维度：数量级
       + 点什么色（c=）    ← 第四个维度：类别或数值
  • s=（size）控制面积，单位是「点」。教材里 s=x_values * 2 就是为了看得清。
  • c=（color）可以传颜色名字（分类），也可以传数值（必须配 cmap=）。
  • cmap=（color map）规定「数值怎么翻译成颜色」，最常用 plt.cm.Blues——值小则浅，值大则深。

「绘制一系列点」就是把两组数据画在同一张 ax 上（见示例 2），两种颜色叠着，一眼看出「谁增长得快」。

传颜色名字和传数值是两套机制：前者是「每点自己指定颜色」，后者是「让 matplotlib 按数值自动上色，并自动多一条颜色条」。初学最容易混的就是这个——c 里传数字却不给 cmap，所有点会变成同一种默认颜色，不报错，但你以为的渐变根本没出现。

2.5 ★ 校正绘图：给坐标轴留边距

这是新手最高频的坑，值得单独一节。默认坐标轴范围贴着数据：x 轴从最小值到最大值。但点本身有「直径」——s=100 的点不是没有面积的一个点，而画布边框会切掉越界部分，于是两端点被削掉一小块，看着像「数据缺了一头」。

解决办法是手动指定范围：ax.axis([0, 1100, 0, 1_100_000])，四个数顺序是 [xmin, xmax, ymin, ymax]。为什么写 1100 和 1 100 000 这种「多出来的数」？因为数据最大值正好是它们，再留一点余量，点才不被切。110 万写作 1_100_000（下划线只分组）。

示例没校正                  校正之后（四周加了余量）
┌──────────────┐      ┌──────────────┐
│◐   ○ ○ ○   ◑ │  →   │  ◐ ○ ○ ○ ◑  │
│ ◐ ○ ○ ○ ○ ◑  │      │  ○ ○ ○ ○ ○ ○  │
└──────────────┘      └──────────────┘
 ↑ 贴边的点被削掉了      ↑ 点完整，四周留白

ax.axis([...]) 这名字很怪——它既设范围又管外观。等价写法是 ax.set_xlim() + ax.set_ylim()，更直白。关键是要知道为什么要手动设范围；更稳的做法是用 max(数据) * 1.05 算余量，数据换了也不用改代码（见示例 3）。余量是算出来的，不是猜的：

Python# 余量交给函数算：换数据不用改代码
def axis_range(values, margin=0.05):
    """返回 [xmin, xmax, ymin, ymax]，四周各留 margin 比例的余量。"""
    low, high = min(values), max(values)
    pad = high * margin
    return [0, high + pad, 0, high + pad]


x_values = [1, 2, 3, 4, 5]
y_values = [1, 8, 27, 64, 125]
print("数据最大值：", max(y_values))
print("写死的范围：", [0, 1100, 0, 1_100_000], "（教材的例子，换数据就废）")
print("算出来的范围：", axis_range(y_values), "-> ax.axis(...) 直接用")
print("再换一组数据：", axis_range([10, 4400, 250]))
print("\n为什么要有余量：s=100 的点有直径，贴边的点会被画布切掉一半。")

这段的实跑输出：数据最大值 125 时范围是 [0, 131.25, 0, 131.25]；换成 [10, 4400, 250] 后自动变成 [0, 4620.0, 0, 4620.0]。你只改了数据，代码一个字没动。

定制刻度标记。 默认刻度由 matplotlib 自选，大数字上会变成 1.0e6 科学计数法，或标签挤成一团。set_xticks() 是「刻度放在这些位置」，set_xticklabels() 是「这些位置显示什么」（见示例 3）。

★ set_xticks 与 set_xticklabels 必须配套调用。 只调后者，标签会被硬贴在默认刻度上，位置不够就叠。

★ 自动保存绘图用 fig.savefig()，推荐写全两个参数：dpi=200 让线更细腻，bbox_inches="tight" 表示「按有内容区域裁剪」，不写就带大片白边。

2.6 随机游走：RandomWalk 类

随机游走是最简单的随机模型：一只小虫每次随机往一个方向走一步，走一千步得到一条弯曲路径。它是布朗运动、股票涨跌、扩散的数学原型。教材把它做成一个类，这个设计比代码更值得学——「一只虫」是一个对象，x、y 是属性，「走一步」是方法（类见示例 4）：

Pythonclass RandomWalk:
    def __init__(self, num_points=5000):
        self.num_points = num_points          # 属性：走多少步
        self.x_values = [0]                   # 属性：从原点出发
        self.y_values = [0]

    def fill_walk(self):
        while len(self.x_values) < self.num_points:
            x_step = random.choice([-1, 0, 1])
            y_step = random.choice([-1, 0, 1])
            if x_step == 0 and y_step == 0:
                continue                      # ★ 拒绝原地不动
            self.x_values.append(self.x_values[-1] + x_step)
            self.y_values.append(self.y_values[-1] + y_step)

★ 这里最容易错：为什么要「拒绝原地不动」？ 若允许 x 和 y 同时不变，这轮什么也没发生。四种组合里「不动」占 1/4，5000 步里约 1250 步原地踏步。这违反了随机游走「每一步都要真的移动」的定义。 正确写法是两个同时为 0 才重来——所以用 and，不是 or。

random.choice(seq) 是「从序列里随机挑一个」，兄弟还有 random.randint(a, b)（含两端）、random.random()（0~1）。 ★ random.seed(42) 是这一章最有工程价值的一行。 随机性是编程里的「double 难度 bug 源」：跑一遍正常、再跑一遍崩，而你复现不出来。写上种子后随机序列完全可复现，bug 能稳定复现、修好、再验证。调试随机程序第一件事就是加种子。

模拟多次随机游走就是循环创建多个对象（完整代码见示例 4），有三点值得说：alpha=0.1 让 500 条半透明路径叠在一起、经过次数多的区域自然变深（不透明会糊成一坨纯黑）；edgecolors="none" 是点太多时不要描边；c=[i] * len(...) 配 cmap=plt.cm.Blues 让**「第几次游走」变成深浅**（c 必须和点一样长）。

2.7 Plotly 掷骰子：Die 类

前面全是 matplotlib，从这里换成 Plotly，因为掷骰子的本质是「大量样本的分布」，Plotly 的 bar 一行出图还自带交互。选库看需求，不看时髦程度——要把这张图印进 PDF 的话，matplotlib 一样能画。

终端命令pip install plotly kaleido      # kaleido 只在导出 PNG/SVG 时需要

kaleido 是 Plotly 静态导出的引擎，教材存 HTML 用不到它；本讲义统一用 fig.write_html()。

Die 类的设计：骰子是「能被掷的对象」，该有的是——面数（属性）、记住每次结果（属性）、掷一次（方法）：

Pythonimport random

class Die:
    """一枚 n 面骰子。"""

    def __init__(self, num_sides=6):
        self.num_sides = num_sides
        self.results = []              # 存每一次掷出的点数

    def roll(self):
        result = random.randint(1, self.num_sides)   # 含两端
        self.results.append(result)

★ results.count(value) 是本节的关键一招。 想知道「1 点出现了多少次」，最笨是手写循环去数；list 自带 count()，一行返回出现次数（见示例 5）。统计完还要加 assert sum(frequencies) == len(die.results)：这不是装饰——分布类程序最容易出的 bug 是「某个类别被漏掉了」，而它不报错、只让你看到缺一列的图。

画分布图。 px.bar() 需要横纵两组数据；定制用 fig.update_layout()（改整体：标题、轴标题）和 fig.update_traces()（改柱子：颜色、描边）；还可以用 fig.add_hline() 画「理论平均线」，让读者一眼看出随机结果靠不靠谱。

★ 术语纠正：中文常把这种图叫「直方图」（histogram），但 px.bar() 画的是柱状图。真正的直方图（px.histogram）是把连续数值分箱——比如把身高分成 160~170、170~180 两堆。骰子点数是离散类别，所以用 bar。

同时掷两个骰子，建两个对象、掷同样多次后把结果相加（2 到 12 共 11 种），核心就一行列表推导：

Pythonimport random

random.seed(42)
rolls_1 = [random.randint(1, 6) for _ in range(1000)]   # 骰子 1 的 1000 次
rolls_2 = [random.randint(1, 6) for _ in range(1000)]   # 骰子 2 的 1000 次
sums = [a + b for a, b in zip(rolls_1, rolls_2)]       # zip 把两串配对
frequencies = [sums.count(v) for v in range(2, 13)]     # 2~12 共 11 种
print(dict(zip(range(2, 13), frequencies)))

zip(a, b) 把两条等长列表「拉链」起来，一次给你一对元素，for a, b in ... 再把这一对拆成两个名字。这个 zip + 解包 后面「两份数据逐行对照」都会用到，务必练熟。

同时掷两个面数不同的骰子，用 plotly.graph_objects 显式画两组柱子（见示例 5）。go.Figure() + add_trace() 比 px.bar() 啰嗦，但控制力强：能画多条配置的柱子、能命名、能设透明度。barmode="group" 是并排，"overlay" 是叠放（记得配 opacity）。

统计结论（比代码更重要）：每次掷骰子各点数等概率，所以单个骰子的分布是平的。两个骰子相加时，靠中间的点有更多组合方式凑出来（六面+六面凑 7 有 6 种组合，凑 2 只有 1 种），分布向中间隆起；面数越多分布越均匀（六面+二十面有 120 种组合，几乎平坦）。这就是「大数压倒小数」。

保存图形——两个库不一样：matplotlib 存静态图用 fig.savefig("x.png", bbox_inches="tight")；Plotly 存可交互网页用 fig.write_html("x.html")，需要静态图（且装了 kaleido）用 fig.write_image("x.png")。

import matplotlib.pyplot as plt

plt.style.use("seaborn-v0_8")

x_values = [1, 2, 3, 4, 5]
y_values = [1, 4, 9, 16, 25]

# ===== 1. 基础散点图：位置 = 两个列表 =====
fig, ax = plt.subplots()

# ===== 2. 三件套同时上场 =====
fig, ax = plt.subplots()
ax.scatter(x_values, y_values,
           s=[v * 30 for v in x_values],                # 点大小随 x 变化
           c=y_values,                                  # 颜色由 y 值决定

import random

import matplotlib.pyplot as plt


class RandomWalk:
    """模拟一只小虫的随机游走：每一步往四个方向之一移动一格。"""

    def __init__(self, num_points=5000):
        self.num_points = num_points       # 走多少步
        self.x_values = [0]                # 属性：位置列表，从原点出发
        self.y_values = [0]

    def step(self):
        """走一步，然后在列表末尾追加新位置。"""
        x_step = random.choice([-1, 0, 1])
        y_step = random.choice([-1, 0, 1])
        # ★ and 不是 or：只有"横竖都不动"才重来
        if x_step == 0 and y_step == 0:
            return False
        self.x_values.append(self.x_values[-1] + x_step)
        self.y_values.append(self.y_values[-1] + y_step)
        return True

    def fill_walk(self):
        """反复调用 step，直到攒够 num_points 个点。"""
        while len(self.x_values) < self.num_points:
            self.step()


plt.style.use("seaborn-v0_8")

示例 4 和 5 的重点都在 ax.plot() 上，容易让人以为「画图」才是难点。其实这张图对不对，全看 x_values / y_values 怎么来的。这个示例把画图那一步整个拿掉，只算数据：随机游走的坐标怎么一步步累加出来、掷骰子的结果怎么变成频次表。跑通它，你再回去看示例 4/5 的绘图代码，会发现那几十行只是「把两个列表交给 ax」。

Python# walk_and_dice.py —— 不画图，只算数据：坐标是怎么一步步走出来的
import random
from collections import Counter


def get_step():
    """一步的方向：x、y 各自随机取 -1 / 0 / 1。"""
    return random.choice([-1, 0, 1]), random.choice([-1, 0, 1])


class RandomWalk:
    """随机游走：x_values / y_values 两个列表就是全部数据。"""

    def __init__(self, num_points=5000):
        self.num_points = num_points
        self.x_values = [0]
        self.y_values = [0]

    def fill_walk(self):
        while len(self.x_values) < self.num_points:
            x_step, y_step = get_step()
            if x_step == 0 and y_step == 0:      # ★ and：两个都不动才重来
                continue
            self.x_values.append(self.x_values[-1] + x_step)
            self.y_values.append(self.y_values[-1] + y_step)


random.seed(42)                               # 固定种子，输出才可复现
walk = RandomWalk(500)
walk.fill_walk()
print(f"点数：{len(walk.x_values)}（num_points = 500）")
print("前十步坐标：", list(zip(walk.x_values[:10], walk.y_values[:10])))
print(f"终点：({walk.x_values[-1]}, {walk.y_values[-1]})")
print(f"x 的范围：{min(walk.x_values)} ~ {max(walk.x_values)}"
      f"；y 的范围：{min(walk.y_values)} ~ {max(walk.y_values)}")
stayed = sum(1 for a, b in zip(walk.x_values, walk.y_values)
             if (a, b) == (0, 0))
print(f"经过原点 {stayed} 次（概率模型不同，这个数会变）")

print("\n=== 同一份坐标，换个画法就是不同的图 ===")
print("折线 --> ax.plot(walk.x_values, walk.y_values)")
print("散点 --> ax.scatter(walk.x_values, walk.y_values, s=1)")
print("上色 --> c=range(len(walk.x_values)), cmap=plt.cm.Blues  # 越走越深")

print("\n=== 掷骰子：一堆结果怎么变成频次表 ===")
random.seed(7)
results = [random.randint(1, 6) for _ in range(600)]
counts = Counter(results)                    # 一行数完，等价于 results.count(v)
print("前 20 次结果：", results[:20])
print("频次表：", dict(sorted(counts.items())))
frequencies = [counts[v] for v in range(1, 7)]   # 按面数顺序取，缺的面补 0
print("按面数排列：", frequencies)
assert sum(frequencies) == len(results)      # ★ 分布类程序必加：总数必须对上
print(f"总数校验通过：sum(frequencies) = {len(results)}")
print(f"出现最多：{counts.most_common(1)[0]}；最少：{counts.most_common()[-1]}")
print(f"平均点数：{sum(results) / len(results):.3f}（理论 3.5）")

三条解读：

  1. append(self.x_values[-1] + x_step) 是整套随机游走的心脏：每一步都在上一步的位置上加位移，所以数据不是「一群随机数」，而是一条连续路径。写成 append(x_step) 你会得到一团散沙（每次从原点跳），图还是画得出来，但已经完全不是随机游走了。
  2. Counter 和 list.count() 的差别在复杂度：Counter 一趟遍历 O(n) 出全部频次；[results.count(v) for v in range(1, 7)] 要扫 6 趟。600 次掷骰子看不出差别，600 万次就是 6 倍时间——示例 5 用 count() 是为了跟教材对齐，量大时换 Counter。
  3. 把 num_points 改成 5000、掷骰子改成 6000 会怎样（同种子实跑）：游走终点从 (21, -18) 变成 (122, 59)，x 的范围从 -6 ~ 23 变成 -6 ~ 146；骰子六面的频次从 85 ~ 109 收窄到 953 ~ 1038，平均点数从 3.418 变成 3.473。样本越大，随机越像规律——位移按 √n 增长，频次越来越贴近 1000 这条理论线。

六、常见错误清单（务必逐条自查）

错误 1：★ 忘记校正绘图，点被边框切掉

数据范围正好等于坐标轴范围时，最边缘的点被裁掉一半，像「数据少了两头」。修法：ax.axis([0, x_max * 1.05, 0, y_max * 1.05])，四个数顺序是 [xmin, xmax, ymin, ymax]，写反会出现「图空白」。

错误 2：★ fill_walk() 里把 and 写成 or

写成 if x_step == 0 or y_step == 0: continue，等于要求「每一步必须同时改变 x 和 y」，图会退化成一条直线——不报错，只是图很怪。正确条件是两个都不动才重来，必须用 and。

错误 3：c= 传了数字却忘了 cmap=

所有点画成同一种默认蓝色，渐变根本没出现，却不报错。传数字必须配 cmap。

错误 4：set_xticklabels 不配 set_xticks

标签被硬贴在默认刻度上，数量一多就叠成团。位置和文字必须配套调用。

错误 5：样式名写老版本，报 ValueError: style 'seaborn' is not in available styles

matplotlib 0.13 之后 seaborn 系列加了版本后缀，写 "seaborn-v0_8" 而不是 "seaborn"；拿不准就先 print(plt.style.available) 看现装的。样式只是皮肤。

错误 6：matplotlib.use("Agg") 写在 import matplotlib.pyplot 之后

会报 RuntimeError: Cannot switch to Agg after importing pyplot，因为后端在导入 pyplot 时就定死了。顺序必须先 matplotlib.use、后 import pyplot。

错误 7：忘了 assert sum(frequencies) == len(results)

range(1, die.num_sides + 1) 少写 + 1，最后一个面的频次永远是 0，图上少一根柱子，程序一声不吭。凡「按类别统计」都该加这行断言。

七、本单元验收自测

1. 简答题：Matplotlib 和 Plotly 分别在什么场景下选？为什么不能「一个库走天下」？

要点：Matplotlib 适合静态图——要打印、贴进报告/论文，需要确定的像素。Plotly 适合可交互图——在浏览器里悬停看数值、缩放、开关图例。两者不是谁更高级，而是输出形态不同：前者输出「一张图」，后者输出「一个可以操作的小程序」。

2. 判断题：fig, ax = plt.subplots() 里 fig、ax 各代表什么？把 ax.axis([0, 1100, 0, 1_100_000]) 里四个数的顺序说对。

要点：fig 是 figure（整张画板），负责存盘与多子图排版；ax 是 axes（一张纸），负责画线、设标题、设刻度。逗号左边是解包：函数返回 (figure, axes) 元组被拆成两个变量。ax.axis([...]) 四个数依次是 [xmin, xmax, ymin, ymax]。写反不报错但图会莫名其妙。

3. 简答题：散点三件套 s=、c=、cmap= 各控制什么？c 传名字和传数字有何不同？

要点：s（size）控制点的面积；c（color）控制颜色；cmap 规定「数值 → 颜色」的翻译表。c 传颜色名字是逐点指定，不会有颜色条；c 传数值列表必须配 cmap=，此时自动上色并生成颜色条。传数字忘配 cmap 是最高频的错误——不报错，但点全同色。

要点：results.count(value) 是 list 的内置方法，返回该值出现了多少次——一行代替手写统计循环。断言确认「各类别频次之和 = 总投掷次数」，防止 range(1, die.num_sides + 1) 漏写 + 1 导致最后一个面频次恒为 0——这类 bug 不报错，只是图上少一根柱子。统计结论：单枚骰子各点等概率、分布是平的；两个骰子相加时靠中间的点有更多组合方式凑出来（凑 7 有 6 种组合，凑 2 只有 1 种），分布向中间隆起；面数越多分布越平坦——面数多 → 组合多 → 分布均匀。
