单元导入

元编程听起来玄，其实只回答一个问题：当 obj.x 被写出时，Python 到底做了什么？ 答案是一条固定的查找链：数据描述符 → 实例字典 → 非数据描述符 → 类属性 → __getattr__。

理解这条链，你就能看懂 ORM 的字段、Django 的 models.CharField、pytest 的 fixture、dataclass 的 field()，也能在「加一个通用机制」和「写一堆重复代码」之间做出正确选择。

学完本单元，你应该能：

  • 用 __getattr__ 处理运行时才知道的属性，用 property 做受控访问；
  • 写出数据描述符与非数据描述符，解释它们与实例字典的优先级；
  • 用 __init_subclass__、类装饰器注册子类，读懂简单元类；
  • 判断什么时候不该用元类，改用更简单的机制。

本单元对应原书第 22–24 章。四节课覆盖主干机制；__prepare__、元类冲突、描述符与 __slots__ 的交互等细节，需要回读对应小节。

第 45 课 · 动态属性：getattr、setattr 与 property

讲解

__getattr__ 只在常规查找失败后调用，是兜底，不是拦截：

Pythonclass Config:
    def __init__(self, data):
        self._data = data

    def __getattr__(self, name):
        try:
            return self._data[name]
        except KeyError:
            raise AttributeError(name) from None

cfg = Config({"host": "localhost"})
print(cfg.host)       # localhost
print(cfg.port)       # AttributeError: port

注意 __init__ 里访问 self._data 不能触发 __getattr__ 递归：_data 已存在时不会进来，若不存在会无限递归。防御写法是在 __getattr__ 开头判断 name.startswith("_") 并直接抛异常。

__getattribute__ 拦截所有属性访问，风险高，除非写代理否则不要动。property 是更安全的受控访问：

Pythonclass Account:
    def __init__(self, balance):
        self._balance = balance

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("negative balance")
        self._balance = value

延伸：property 的三个角色与特性工厂

Pythonclass Temp:
    def __init__(self, c):
        self._c = c

    @property
    def c(self):
        return self._c

    @c.setter
    def c(self, v):
        if v < -273.15:
            raise ValueError("below absolute zero")
        self._c = v

    @c.deleter
    def c(self):
        del self._c

三者共享同一个名字，后定义的两个用 @名字.setter / @名字.deleter。只定义 getter 就是只读；只定义 setter 而没有 getter 会得到一个写不进也读不出的怪东西，别这么写。

特性工厂用闭包批量生成校验属性：

Pythondef positive(name):
    def get(self):
        return getattr(self, "_" + name)
    def set(self, v):
        if v <= 0:
            raise ValueError(f"{name} must be positive")
        setattr(self, "_" + name, v)
    return property(get, set)

class Order:
    qty = positive("qty")

代价是 IDE 跳转和类型检查变弱，字段少时手写更清楚。字段多、校验规则一致时才值得上工厂。

关键点

  • __getattr__ 只在找不到时调用，已存在的属性不会进来。
  • __getattribute__ 每次访问都调用，容易死循环，慎用。
  • property 是数据描述符，优先级高于实例字典，所以能真正拦住赋值。
  • __getattr__ 里抛 AttributeError，否则 hasattr() 会误判。

动手

  1. 实现 Config，验证存在的键、缺失的键、下划线键三种情况。
  2. 用 property 实现带校验的 balance，测试赋负数时抛异常。
  3. 写一个 __getattr__ 版本，故意不抛 AttributeError 而返回 None，观察 hasattr 的结果。

验收清单

  • 能说清 __getattr__ 与 __getattribute__ 的区别
  • 会用 property 实现受控读写
  • 知道 __getattr__ 必须抛 AttributeError 的原因

第 46 课 · 描述符：把属性访问变成可复用逻辑

讲解

描述符是实现了 __get__、__set__、__delete__ 中至少一个的类。它挂在类上，控制实例的属性访问。

Pythonclass Positive:
    def __set_name__(self, owner, name):
        self.name = "_" + name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.name)

    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError("must be positive")
        setattr(obj, self.name, value)

class Order:
    qty = Positive()
    price = Positive()

查找优先级（简化）：

  1. 类型上的数据描述符（有 __set__ 或 __delete__）
  2. 实例 __dict__
  3. 类型上的非数据描述符（只有 __get__）
  4. 类属性
  5. __getattr__

非数据描述符适合做惰性属性，因为第一次计算后写进实例字典，后续直接命中字典：

Pythonclass Lazy:
    def __init__(self, fn):
        self.fn = fn
        self.name = fn.__name__

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        value = self.fn(obj)
        setattr(obj, self.name, value)
        return value

class Report:
    @Lazy
    def total(self):
        print("computing")
        return 42

延伸：函数就是非数据描述符

函数只实现 __get__（没有 __set__），属于非数据描述符，被存在类上；实例访问时 __get__ 返回绑定方法。这解释了两件事：

Pythonclass C:
    def m(self): return "method"

c = C()
print(c.m())                 # method
c.m = lambda: "instance"
print(c.m())                 # instance ← 实例字典盖住了方法
  1. 为什么实例属性可以「盖住」方法（非数据描述符优先级低于实例字典）。
  2. 为什么 property 盖不住（它是数据描述符，优先级最高）。

完整优先级：数据描述符 > 实例字典 > 非数据描述符 > 类属性。这条规则是所有「属性拦截」方案的地基：想拦住赋值就必须实现 __set__（或 __delete__）。

__set_name__（3.6+）在类创建时被调用，描述符靠它知道自己叫 name，不用再手动传名字：

Pythonclass Field:
    def __set_name__(self, owner, name):
        self.name = name

关键点

  • property 本身就是数据描述符，所以它能覆盖实例字典。
  • 数据描述符优先于实例字典，非数据描述符不优先。
  • __set_name__ 在类创建时调用，用来拿到属性名，避免手写字符串。
  • 描述符是类属性，每个实例共享同一个描述符对象，状态要存在实例上。

动手

  1. 实现 Positive，给 Order 的两个字段加校验，测试非法值。
  2. 实现 Lazy，验证第二次访问不再打印 computing。
  3. 把 Lazy 改成数据描述符（加 __set__），观察惰性缓存是否失效，并解释原因。

验收清单

  • 能背出属性查找的五步优先级
  • 能区分数据描述符与非数据描述符
  • 会用 __set_name__ 避免硬编码属性名

第 47 课 · 类元编程：__init_subclass__、类装饰器与元类

讲解

注册子类最轻的方式是 __init_subclass__：

Pythonclass Plugin:
    registry = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin.registry[cls.__name__] = cls

class JsonPlugin(Plugin):
    pass

print(Plugin.registry)     # {'JsonPlugin': <class ...>}

类装饰器同样能改类，但更灵活、更显式：

Pythondef add_repr(cls):
    def __repr__(self):
        fields = ", ".join(f"{k}={v!r}" for k, v in vars(self).items())
        return f"{cls.__name__}({fields})"
    cls.__repr__ = __repr__
    return cls

@add_repr
class User:
    def __init__(self, name):
        self.name = name

元类在类创建时介入，能改命名空间、强制结构：

Pythonclass Meta(type):
    def __new__(mcls, name, bases, ns):
        if name != "Base" and "save" not in ns:
            raise TypeError(f"{name} must define save()")
        return super().__new__(mcls, name, bases, ns)

class Base(metaclass=Meta):
    pass

class User(Base):
    def save(self):
        ...

__prepare__ 可以替换类命名空间（比如返回一个记录赋值顺序的 dict）。

延伸：type 是类工厂，prepare 换命名空间

type(name, bases, ns) 三参数形式就是类工厂，class 语句本质是它的语法糖：

Pythondef make(name, **attrs):
    return type(name, (), attrs)

P = make("P", x=1)
print(P.x, type(P))      # 1 <class 'type'>

元类里三个钩子的分工：

  • __prepare__(mcls, name, bases)：决定类体写入哪个命名空间，默认普通 dict。返回 OrderedDict 或自定义映射就能记录定义顺序（早期 dataclass 这么干过），甚至做「禁止重复字段名」的检查。
  • __new__(mcls, name, bases, ns)：真正造类，改类结构（加方法、收集字段）在这里做。
  • __init__(cls, name, bases, ns)：类造好后的收尾，一般只做注册。

顺序是 __prepare__ → 执行类体 → __new__ → __init__。想「在类体执行时就拦截名字」只能用 __prepare__ 返回自定义映射，__new__ 已经太晚了。

关键点

  • __init_subclass__ 足够解决 90% 的「注册/校验子类」需求，优先用它。
  • 类装饰器改的是已创建的类，元类改的是创建过程。
  • 一个类只能有一个元类，冲突会直接报 TypeError。
  • 元类是实现细节，不要把它暴露成公开 API，否则使用者会被绑死。

动手

  1. 用 __init_subclass__ 实现插件注册表，注册 3 个插件并打印。
  2. 用类装饰器给类自动加 __repr__，验证输出格式。
  3. 写一个元类，要求所有子类必须定义 save()，并测试缺少方法时的报错。

验收清单

  • 能用 __init_subclass__ 完成子类注册
  • 知道类装饰器与元类的介入时机差异
  • 能读懂一个 15 行以内的元类并说明它改了什么

第 48 课 · 综合验收：读懂框架的 200 行

讲解

拿一个你常用的库，按下面顺序读：

  1. 找入口：__init__.py 导出了什么，公开 API 是哪几个名字。
  2. 找类创建钩子：搜 metaclass=、__init_subclass__、__set_name__。
  3. 找属性访问钩子：搜 __getattr__、__getattribute__、__get__。
  4. 找注册表：搜全局 dict / list，看谁往里写、谁从里读。
  5. 画一张图：用户写一行代码 → 触发了哪条链 → 最终落到哪个函数。

以 ORM 为例：models.CharField() 返回一个描述符；模型类创建时元类收集所有字段；实例访问 user.name 时描述符从数据库行里取值。三件事分别对应本单元的三节课。

把钩子和本课程对照起来看：

钩子 触发时机 典型库 对应课节
__get__ / __set__ 访问/赋值实例属性 Django Field、SQLAlchemy Column 第 46 课
__set_name__ 类创建完成时 dataclasses.field、ORM 字段 第 46 课
__getattr__ 常规查找失败后 懒加载代理、配置对象 第 45 课
__init_subclass__ 子类定义完成时 插件注册、校验基类 第 47 课
元类 类创建过程中 Django ModelBase、pydantic ModelMetaclass 第 47 课

把这三节课拼起来，就是一个能跑的最小 ORM：

Pythonclass Field:
    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, owner=None):
        if obj is None:
            return self
        return obj._data.get(self.name)

    def __set__(self, obj, value):
        obj._data[self.name] = value


class ModelMeta(type):
    def __new__(mcls, name, bases, ns):
        cls = super().__new__(mcls, name, bases, ns)
        fields = {}
        for base in bases:                       # 继承父类字段
            fields.update(getattr(base, "_fields", {}))
        fields.update({k: v for k, v in ns.items() if isinstance(v, Field)})
        cls._fields = fields
        return cls


class Model(metaclass=ModelMeta):
    def __init__(self, **kwargs):
        self._data = {}
        for k, v in kwargs.items():
            setattr(self, k, v)

    def __repr__(self):
        return f"{type(self).__name__}({self._data!r})"


class User(Model):
    name = Field()
    age = Field()


u = User(name="Ann", age=30)
print(u)              # User({'name': 'Ann', 'age': 30})
print(User._fields)   # {'name': <Field ...>, 'age': <Field ...>}

这段代码不到 40 行，但已经具备 ORM 的三个核心：字段描述符负责读写、元类负责收集字段、模型基类负责初始化。真实框架多出来的是 SQL 生成、关系映射、迁移，而不是另一套元编程。

延伸：四类钩子的检索法

拿到陌生框架，按四个关键词搜源码，基本能画出扩展点地图：

关键词 机制 典型用途
__get__ 描述符 字段 / 属性拦截、惰性加载、ORM 列
__set_name__ 类创建回调 字段注册、知道自己叫什么
__init_subclass__ 子类定义回调 插件注册、自动加功能
metaclass= 元类 整类改造、接口约束 
Pythonclass Plugin:
    registry = {}
    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        Plugin.registry[cls.__name__] = cls

class JsonPlugin(Plugin):
    pass

print(Plugin.registry)      # {'JsonPlugin': <class 'JsonPlugin'>}

__init_subclass__ 是「不需要元类就能在子类定义时拿到钩子」的正规做法，1980 年代的元类需求里有一大半它能替代。判断该不该上元类：只需要「子类定义时做一件事」就用 __init_subclass__；需要改类的创建过程本身（换命名空间、改 __call__）才用元类。

读框架的顺序：先找钩子 → 再顺着钩子看调用链 → 最后才读工具函数。看不懂就先写 20 行最小复现，把框架剥到只剩钩子。

关键点

  • 先看公开 API，再看实现，不要一头扎进工具函数。
  • 钩子比流程重要：找到钩子，就找到了框架的扩展点。
  • 画调用链比读注释有效，尤其是元编程代码。
  • 看不懂时先写最小复现，把框架剥到 20 行。

动手

  1. 选一个库（Django ORM、SQLAlchemy、pydantic、pytest 任选），定位至少两个钩子。
  2. 写一页笔记：钩子名、触发时机、解决的问题、对应的最小复现。
  3. 给上面的迷你 ORM 补三件事：字段类型校验、to_dict()、按 id 从字典里取一条记录。

验收清单

  • 能在真实代码里定位描述符、元类/__init_subclass__、__getattr__ 三类钩子
  • 能画出一条从用户 API 到内部实现的调用链
  • 能判断某个机制「该不该用元编程实现」，并给出更简单的替代方案
  • 迷你 ORM 能跑通 User(name="Ann")，并解释每个字段的读写走了哪个方法

综合案例：迷你校验框架：把 if 校验收进描述符

两个模型、五条规则，先写成一堆 if，再看它怎么随字段增长失控，最后用描述符 + 子类注册收掉。

重构前（每个模型各写一遍校验）

字段校验写在 __init__ 里，字段名重复出现三次（签名、检查、赋值）；新增一个模型就得复制一遍规则；拼错字段名不会有任何提示。

Pythonclass ValidationError(ValueError):
    pass


class User:
    def __init__(self, name, age, email=None):
        if not name:
            raise ValidationError("name is required")
        if not isinstance(age, int) or age < 0:
            raise ValidationError("age must be a non-negative int")
        if email is not None and "@" not in email:
            raise ValidationError("email looks invalid")
        self.name, self.age, self.email = name, age, email

    def to_dict(self):
        return {"name": self.name, "age": self.age, "email": self.email}


class Article:
    def __init__(self, title, views, email=None):
        if not title:
            raise ValidationError("title is required")
        if not isinstance(views, int) or views < 0:
            raise ValidationError("views must be a non-negative int")
        self.title, self.views, self.email = title, views, email

    def to_dict(self):
        return {"title": self.title, "views": self.views, "email": self.email}


print(User("Ann", 30).to_dict())
print(Article("Post", 3).to_dict())

for bad in [lambda: User("", 1), lambda: User("A", -1), lambda: User("A", 1, "nope")]:
    try:
        bad()
    except ValidationError as e:
        print("rejected:", e)

u = User("Ann", 30)
u.name = ""                       # 绕过校验直接改
print("改成空名也成功:", u.to_dict())

重构后（描述符声明规则 + 子类自动注册）

字段是 Field 的类属性，规则写在字段上；Model.__init_subclass__ 自动把子类登记进注册表；__init__(**data) 遍历字段统一赋值，顺带拒绝未知字段。

Pythonclass ValidationError(ValueError):
    pass


class Field:
    def __init__(self, *, required=True, min_value=None, contains=None):
        self.required = required
        self.min_value = min_value
        self.contains = contains

    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, owner=None):
        if obj is None:
            return self
        return obj.__dict__.get(self.name)

    def __set__(self, obj, value):
        empty = value is None or (isinstance(value, str) and not value.strip())
        if empty:
            if self.required:
                raise ValidationError(f"{self.name} is required")
            obj.__dict__[self.name] = value
            return
        if self.min_value is not None and value < self.min_value:
            raise ValidationError(f"{self.name} must be >= {self.min_value}")
        if self.contains is not None and self.contains not in value:
            raise ValidationError(f"{self.name} must contain {self.contains!r}")
        obj.__dict__[self.name] = value


class Model:
    registry = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Model.registry[cls.__name__] = cls

    def __init__(self, **data):
        for name in type(self).fields():
            setattr(self, name, data.pop(name, None))
        if data:
            raise ValidationError(f"unknown fields: {sorted(data)}")

    @classmethod
    def fields(cls):
        found = {}
        for klass in reversed(cls.__mro__):
            for key, value in vars(klass).items():
                if isinstance(value, Field):
                    found[key] = value
        return found

    def to_dict(self):
        return {name: getattr(self, name) for name in type(self).fields()}


class User(Model):
    name = Field()
    age = Field(min_value=0)
    email = Field(required=False, contains="@")


class Article(Model):
    title = Field()
    views = Field(min_value=0)


print(sorted(Model.registry))                  # ['Article', 'User']
print(User(name="Ann", age=30).to_dict())
print(Article(title="Post", views=3).to_dict())

for kwargs in [{"name": "", "age": 1},
               {"name": "A", "age": -1},
               {"name": "A", "age": 1, "email": "nope"},
               {"name": "A", "age": 1, "nick": "x"}]:
    try:
        User(**kwargs)
    except ValidationError as e:
        print("rejected:", e)

u = User(name="Ann", age=30)
try:
    u.name = ""
except ValidationError as e:
    print("赋空值也被拦:", e)          # 数据描述符优先级高于实例字典

差异说明

问题 重构前 重构后 收益 代价
规则位置 写在 __init__ 里 写在字段声明上 规则一眼可见，可复用 需要理解描述符协议
新增模型 复制一段校验 继承 Model，声明字段 不重复、不漏校验 子类只能多字段，不能改协议
绕过校验 u.name = "" 直接改 __set__ 拦截 任何赋值路径都受控 数据描述符优先级会挡住实例字典
字段名 三处重复，拼错才发现 __set_name__ 自动取 不会写错名字 描述符实例不能跨类共享
未知字段 静默忽略 抛 ValidationError 拼错立刻暴露 需要 **data 的调用约定
继承 不存在 fields() 走 MRO 合并 父类字段自动带上 MRO 里同名字段要定覆盖规则
性能 直接赋值 每次赋值过一次 __set__ 换来确定性 高频热路径有开销

再往前一步

给 Field 加 default、converter（如 int）和 choices，校验就从「单字段」升级到「模型级」跨字段规则（start <= end）；再把 to_dict 换成 to_row() / from_row()，这套东西就是 ORM 的雏形。注意 pydantic v2 的核心已改成 Rust 实现——纯 Python 描述符版更容易读懂，但性能差一个数量级。
