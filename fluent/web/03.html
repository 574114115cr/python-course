单元导入

写业务代码时，大量类只是为了「装几个字段」：Point(x, y)、User(id, name, email)。手写 __init__、__repr__、__eq__ 既啰嗦又容易漏。Python 提供了三级工具：namedtuple（轻）、typing.NamedTuple（带类型）、@dataclass（可扩展）。

另一半是对象语义：变量不是盒子，而是贴在对象上的标签；赋值不复制对象，函数传参传的是引用；is 比较身份，== 比较值；浅拷贝只复制第一层。这些规则决定了你的代码会不会出现「改了 A，B 也变了」。

学完本单元，你应该能：

  • 在 namedtuple / NamedTuple / dataclass 之间按需选型；
  • 用 field(default_factory=...)、__post_init__、frozen 处理默认值、校验与不可变；
  • 用「引用图」解释赋值、传参、浅拷贝、深拷贝的差别；
  • 一眼认出可变默认参数与共享引用的 bug。

第 9 课 · 数据类三件套：namedtuple、NamedTuple、dataclass

讲解

collections.namedtuple 是最轻的方案：不可变、可迭代、支持按名访问，本质上是 tuple 的子类。

Pythonfrom collections import namedtuple

Point = namedtuple("Point", "x y")
p = Point(3, 4)
print(p.x, p[0], p)          # 3 3 Point(x=3, y=4)
print(p._replace(x=10))      # Point(x=10, y=4)

typing.NamedTuple 给它加上类型注解，写法更现代：

Pythonfrom typing import NamedTuple

class Point(NamedTuple):
    x: float
    y: float
    label: str = ""

@dataclass 则是一个「代码生成器」：根据字段声明生成 __init__、__repr__、__eq__，并且可变、可继承、可加方法。

Pythonfrom dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float
    label: str = ""

    def dist(self) -> float:
        return (self.x ** 2 + self.y ** 2) ** 0.5

选型口诀：只读的小记录 → namedtuple / NamedTuple；需要修改、需要方法、需要默认值工厂 → dataclass。三者都自动生成 __repr__ 和 __eq__，都不自动生成 __hash__（dataclass 在 frozen=True 时才生成）。

延伸：namedtuple 的三个自省工具

Pythonfrom collections import namedtuple
P = namedtuple("P", "x y")
p = P(1, 2)
print(P._fields)          # ('x', 'y')
print(p._asdict())        # {'x': 1, 'y': 2}（3.8+ 是普通 dict）
print(P._make([3, 4]))    # P(x=3, y=4)
print(p._replace(x=9))    # P(x=9, y=2)，返回新实例

_asdict() 在 3.8 之前返回 OrderedDict，现在返回普通 dict，顺序仍然是字段顺序。_replace 是浅拷贝出新实例，适合做不可变更新；_make 用来把从 CSV/数据库读到的行快速变成对象，比 P(*row) 更能表达意图。_fields 的典型用途是写通用的序列化函数，不用每加一个字段就改代码。

关键点

  • namedtuple 不可变，改字段要用 _replace() 生成新对象。
  • NamedTuple 的字段默认值必须放在最后，和函数参数规则一致。
  • dataclass 的 eq=True 默认开启，会比较所有字段；不想参与比较的字段用 field(compare=False)。
  • dataclass 不是「免费」的：字段多、创建频繁时，生成的 __eq__ 和 __repr__ 有成本，热路径要评估。

动手

  1. 用三种方式各定义一次 Point(x, y)，打印 repr 与相等判断结果。
  2. 给 dataclass 版加 dist() 方法，验证 namedtuple 版无法添加实例方法。
  3. 用 dataclasses.fields(Point) 打印字段名与类型，观察默认值。

验收清单

  • 能说出三种数据类工具各自的不可变性与扩展能力
  • 知道 dataclass 默认生成哪些方法、不生成哪些方法
  • 能在「只读记录」和「可变业务对象」之间做出选择并说明理由

第 10 课 · dataclass 进阶：默认值、校验、冻结与模式匹配

讲解

dataclass 最常踩的坑是可变默认值。直接写 tags: list = [] 会抛 ValueError，因为所有实例会共享同一个列表。正确写法是工厂：

Pythonfrom dataclasses import dataclass, field

@dataclass
class Article:
    title: str
    tags: list[str] = field(default_factory=list)
    views: int = field(default=0, compare=False)   # 不参与相等比较

需要在初始化后做校验或派生字段，用 __post_init__：

Python@dataclass
class Range:
    lo: int
    hi: int

    def __post_init__(self):
        if self.lo > self.hi:
            raise ValueError(f"lo({self.lo}) > hi({self.hi})")

frozen=True 让实例不可变，同时生成 __hash__，可以直接放进 set 或做 dict 的键：

Python@dataclass(frozen=True)
class Point:
    x: int
    y: int

print(hash(Point(1, 2)))

slots=True（3.10+）让 dataclass 只保留字段槽位，省内存、访问更快，但不能再动态加属性。模式匹配可以直接解构 dataclass：

Pythonmatch Point(0, 0):
    case Point(x=0, y=0):
        print("origin")
    case Point(x=0, y=y):
        print("on y-axis:", y)

延伸：数据类的代码异味

@dataclass 让「只有字段没有行为」的类写起来很省，但字段一多就是信号：3 个字段还行，8 个以上通常说明这个概念该拆。三条判断标准：

  • 字段是否总是一起出现、一起用？成组出现就抽小类（Address、Money），别让一个类装两套概念。
  • 有没有一半字段只服务于某一个方法？那些字段属于另一个类，只是暂时寄住在这里。
  • 是不是到处在写 obj.kind == "a" 的 if 分支？那缺的是行为，不是字段，该换多态或枚举分派。

原书把这种现象叫 code smell，不是说 dataclass 不好，而是提醒别用它替代设计。判断方法很简单：给这个类加一个方法时，你需要读几个字段？超过 3 个就该拆了。

关键点

  • 默认值工厂每个实例调用一次，field(default_factory=list) 不会共享列表。
  • frozen=True 是浅冻结：字段本身不可重新赋值，但字段指向的 list 仍可修改。
  • __post_init__ 在 __init__ 末尾调用，此时所有字段都已赋值，适合校验和派生。
  • slots=True 与 frozen=True 可以同时用，但继承时会受限制，别在会扩展的基类上开 slots。

动手

  1. 定义 Article，两个实例各 append 一个 tag，验证互不影响。
  2. 定义 Range，构造 Range(5, 1) 观察异常信息。
  3. 用 frozen=True 的 Point 做 dict 的键，再用模式匹配写一个 describe(point) 函数，覆盖原点、x 轴、y 轴、普通点四种情况。

验收清单

  • 能解释为什么 dataclass 不允许 tags: list = []
  • 会用 __post_init__ 做参数校验，并知道它在何时执行
  • 知道 frozen 只冻结字段绑定，不冻结字段指向的可变对象

第 11 课 · 变量不是盒子：引用、别名与拷贝

讲解

把变量想成盒子，是绝大多数引用 bug 的源头。正确的模型是：对象在堆上，变量是贴在对象上的标签。赋值只是贴新标签，不复制对象。

Pythona = [1, 2, 3]
b = a                 # 同一个对象的两个标签
b.append(4)
print(a)              # [1, 2, 3, 4]

print(a is b)         # True：身份相同
print(a == [1, 2, 3, 4])   # True：值相同

is 比较 id()，== 调用 __eq__。判断 None 用 is None，因为 None 是单例；判断数值、字符串内容用 ==。

浅拷贝只复制最外层容器，内部元素仍是共享引用：

Pythonimport copy

grid = [[1, 2], [3, 4]]
shallow = copy.copy(grid)      # 或 grid[:] / list(grid)
shallow[0][0] = 99
print(grid)                    # [[99, 2], [3, 4]]  ← 内层共享

deep = copy.deepcopy(grid)     # 递归复制，互不影响

延伸：浅拷贝返回自身，参数是引用

copy.copy() 对不可变对象常常直接返回自身，因为没必要复制：

Pythonimport copy
t = (1, 2, 3)
print(copy.copy(t) is t)          # True
l = [[1], [2]]
c = copy.copy(l)
print(c is l, c[0] is l[0])       # False True，内层仍共享

函数参数也是引用：在函数里 x += [1] 会改到调用方的 list，x = x + [1] 只是本地重绑定，外面看不到。要不要防御性复制，取决于这个参数是不是「你的所有物」——如果是调用方传进来、还要继续用的对象，就地修改必须写进文档，否则就是隐形副作用。

关键点

  • 赋值永不复制，b = a 只是多一个引用。
  • 浅拷贝复制容器，不复制元素；嵌套结构要用 deepcopy。
  • 不可变对象也可能共享：小整数、短字符串会被驻留（interning），所以 a is b 偶尔为 True，但不要依赖。
  • 函数传参是「对象引用传递」：在函数里改可变参数会影响调用方，重新绑定形参则不会。

动手

  1. 预测下面代码的输出，再运行验证：
Pythondef f(xs):
    xs.append(1)
    xs = [9]
    return xs

data = []
print(f(data), data)
  1. 用 id() 打印 a、b = a、copy.copy(a) 三个对象的身份，标出哪些相同。
  2. 构造三层嵌套列表，分别用浅拷贝和深拷贝修改最内层，比较原数据。

验收清单

  • 能用「标签—对象」模型解释一次别名 bug
  • 能说清 is 与 == 的区别，并知道 None 要用 is
  • 能预测浅拷贝后修改嵌套元素对原对象的影响

第 12 课 · 可变性、默认参数与对象生命周期

讲解

可变默认参数是最经典的坑：默认值在函数定义时求值一次，之后所有调用共享。

Pythondef add(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add(1))    # [1]
print(add(2))    # [1, 2]  ← 不是 [2]

正确写法：

Pythondef add(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket

同理，类属性如果是可变对象，会被所有实例共享：

Pythonclass Team:
    members = []          # 不要这样写

    def add(self, name):
        self.members.append(name)

del 删除的是名字绑定，不是对象本身；对象只有在引用计数归零（或被循环 GC 回收）时才释放：

Pythonimport weakref

class Node:
    pass

n = Node()
r = weakref.ref(n)     # 弱引用：不增加引用计数
print(r() is n)        # True
del n
print(r())             # None，对象已被回收

延伸：del 删的是名字，不是对象

Pythonimport sys
a = [1, 2, 3]
b = a
print(sys.getrefcount(a))   # 3：a、b、和 getrefcount 的临时参数
del a
print(b)                    # 对象还在，因为 b 还引用着它

CPython 靠引用计数立即回收，循环引用交给分代 GC（gc.collect() 可手动触发）。__del__ 不是可靠析构钩子：回收时机不确定，解释器退出时也不保证调用，拿它关文件、连数据库一定会漏。要确定性清理就用 with；对象没有上下文管理器，就 contextlib.closing 包一层。

关键点

  • 默认参数只求值一次，可变默认值必须用 None 哨兵。
  • del x 删的是名字，其他引用仍然有效；del lst[0] 才是删元素。
  • 循环引用靠分代 GC 回收，不是引用计数；大量创建对象时可用 gc.collect() 观测。
  • 弱引用适合做缓存：WeakValueDictionary 让缓存项在外部不再使用时自动消失。

动手

  1. 复现可变默认参数 bug，改写成 None 哨兵版本，并写一个测试证明两次调用互不影响。
  2. 用 weakref.WeakValueDictionary 实现一个「对象缓存」，删除外部引用后验证缓存自动清空。
  3. 用 sys.getrefcount() 观察一个对象在赋值、传参、删除时的引用计数变化（注意它本身会 +1）。

验收清单

  • 能解释默认参数为什么只求值一次
  • 知道 del 删除的是绑定而不是对象
  • 能说出弱引用适合解决什么问题，以及它不适合什么场景

综合案例：订单模型：可变数据类改不出来，换成值语义

订单要能打折，但打完折的订单不能影响原订单——先看看可变数据类会怎么坑人。

重构前（能跑但会互相污染）

@dataclass 默认可变，apply_discount 直接改 line.price。看起来「省了一次复制」，实际把历史订单也改了：

Pythonfrom dataclasses import dataclass, field


@dataclass
class Line:
    sku: str
    qty: int
    price: float


@dataclass
class Order:
    oid: str
    lines: list = field(default_factory=list)

    @property
    def total(self):
        return round(sum(l.qty * l.price for l in self.lines), 2)

    def apply_discount(self, rate):
        for l in self.lines:                 # 直接改，原订单跟着变
            l.price = round(l.price * (1 - rate), 2)
        return self


o = Order("A1", [Line("apple", 2, 3.5), Line("pear", 1, 4.0)])
print(o.total)                               # 11.0

o.apply_discount(0.1)
print(o.total)                               # 9.9

replay = Order("A1", o.lines)                # 想重建原单，拿到的是改过的行
print(replay.total)                          # 9.9，不是 11.0

bad = Line("pear", 0, 4.0)                   # 数量 0 也照收
print(bad.sku, bad.qty, bad.price)

重构后（不可变 + 构造时校验）

frozen=True 冻结赋值、slots=True 去掉实例字典、行用 tuple 保证「改不动」。改价不原地改，用 dataclasses.replace 生成新订单：

Pythonfrom dataclasses import dataclass, field, replace


class InvalidOrder(ValueError):
    pass


@dataclass(frozen=True, slots=True)
class Line:
    sku: str
    qty: int
    price: float

    def __post_init__(self):
        if self.qty <= 0:
            raise InvalidOrder(f"qty must be positive: {self.qty}")
        if self.price < 0:
            raise InvalidOrder(f"price must be >= 0: {self.price}")

    @property
    def amount(self):
        return round(self.qty * self.price, 2)

    def with_price(self, price):
        return replace(self, price=price)


@dataclass(frozen=True, slots=True)
class Order:
    oid: str
    lines: tuple = field(default_factory=tuple)

    def __post_init__(self):
        if not self.oid:
            raise InvalidOrder("oid is required")

    @property
    def total(self):
        return round(sum(l.amount for l in self.lines), 2)

    def with_discount(self, rate):
        if not 0 <= rate < 1:
            raise InvalidOrder(f"rate out of range: {rate}")
        new_lines = tuple(l.with_price(round(l.price * (1 - rate), 2))
                          for l in self.lines)
        return replace(self, lines=new_lines)


o = Order("A1", (Line("apple", 2, 3.5), Line("pear", 1, 4.0)))
d = o.with_discount(0.1)
print(o.total, d.total)              # 11.0 9.9，原单没被改
print(o.lines[0].price, d.lines[0].price)   # 3.5 3.15

try:
    Line("pear", 0, 4.0)
except InvalidOrder as e:
    print("rejected:", e)            # rejected: qty must be positive: 0

差异说明

问题 重构前 重构后 收益 代价
打折副作用 原地改 l.price，原订单被污染 replace 生成新订单 历史订单、撤销、回放都成立 每次打折多复制一层
容器类型 list，外部拿到就能改 tuple，改不了 frozen 才真的冻住 追加行要重建整个元组
非法数据 数量 0、负价都能构造 __post_init__ 直接抛 脏数据进不了系统 构造开销略增
错误类型 没有专用异常，调用方只能捕 ValueError InvalidOrder(ValueError) 可精确捕获，又能被通用处理兜住 多一个类
内存 每实例一个 __dict__ slots=True 省掉 大量订单时省内存 不能动态加属性
变价方式 直接赋值 with_price() 表达意图 调用点看得懂在做什么 方法变多

再往前一步

金额别用 float：0.1 + 0.2 != 0.3，累加几十行就会差几分钱。把 price 换成 Decimal（构造时传字符串），并在 amount 里做 quantize(Decimal("0.01"))。再进一步是按「分」存整数，展示时再除 100，这是支付系统的通行做法。
