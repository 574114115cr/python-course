单元 1–3

数据与对象：先把地基换成 Python 的

  • 特殊方法是语言协议的入口，不是语法糖
  • dict 的顺序与性能都由哈希表决定
  • 别名、可变性与 Unicode 是 bug 的高发区
单元 4–5

函数：从「能调用」到「能组合」

  • 函数是一等对象，可以传、可以返回、可以存
  • 类型提示是给工具看的文档，不是运行时检查
  • 闭包捕获的是变量，不是值
单元 6–8

类与协议：写出可组合的类型

  • 先有协议，再有继承；鸭子类型优先
  • ABC 负责「明确契约」，Protocol 负责「结构化匹配」
  • 运算符重载必须保持交换律与一致性
单元 9

控制流：惰性与上下文

  • 生成器把「计算」变成「按需产出」
  • yield from 是委派，不是简写
  • with 管理资源，match 解构数据
单元 10–11

并发与异步：先判断瓶颈

  • CPU 密集 → 进程；IO 密集 → 线程或协程
  • GIL 保护解释器状态，不等于线程安全
  • asyncio 的收益来自「等待时不占线程」
单元 12

元编程：把重复交给机制

  • __getattr__ 处理「运行时才知道的属性」
  • 描述符把「属性访问」变成可复用的逻辑
  • 元类只在类创建时介入，优先用 __init_subclass__
每节课的产出

不是笔记，是可运行的代码

  • 一段能跑的最小示例
  • 一次「错误写法 → 正确写法」的对照

代码标准

按团队代码的标准要求自己

  • 公开函数写全类型注解，mypy 无报错
  • 异常只捕获能处理的类型，不写裸 except
  • 复杂分支用数据驱动或模式匹配，不堆 if

常见卡点

大多数人会卡在这五处

  • 把特殊方法当普通方法直接调用
  • 以为 dict 有序就等于可以排序
  • 装饰器丢了 functools.wraps
  • 以为多线程能加速 CPU 密集任务
  • 描述符与 __getattr__ 的优先级搞混
