第 37 课 · 目标与要点

并发全景：GIL、线程、进程

能解释 GIL 的作用与边界，判断一个任务是 CPU 密集还是 IO 密集，并选出对应的并发模型。
  • GIL 不是 Python 语言规范，是 CPython 的实现；3.13 起提供实验性的 free-threaded 构建，但默认构建仍有 GIL。
  • GIL 不保证线程安全：x += 1 仍是「读—改—写」三步，可能被切换。
  • 进程有独立内存，通信要序列化（pickle），启动成本高。
  • 线程适合 IO，不是因为线程快，而是因为等待时不占 CPU。

def cpu_task(n):
    return sum(i * i for i in range(n))

t0 = time.perf_counter()
for _ in range(4):
    cpu_task(2_000_000)
print("serial", time.perf_counter() - t0)

第 38 课 · 目标与要点

线程与锁：竞态、队列与退出

能复现一次竞态，用 Lock 修复，用 Queue 做生产者—消费者，并让线程正确退出。
  • 锁要尽量短，持锁做 IO 等于把并发退化成串行。
  • 避免嵌套锁，需要多把锁时固定获取顺序，否则会死锁。
  • Queue 的 task_done() 与 join() 配对，忘了会让主线程永远等。
  • 线程不能强杀，用哨兵或 Event 通知退出，再 join()。
第 38 课 · 代码与实操

import threading

counter = 0

def worker():
    global counter
    for _ in range(100_000):
        counter += 1          # 可能被切换

ts = [threading.Thread(target=worker) for _ in range(4)]
[t.start() for t in ts]
[t.join() for t in ts]
print(counter)                # 通常小于 400000

第 39 课 · 目标与要点

执行器：ThreadPoolExecutor 与 ProcessPoolExecutor

能用两种执行器提交任务、收集结果、处理异常，并知道各自的启动成本与限制。
  • 线程池大小不是越大越好：IO 密集可以 2–4 倍 CPU 核数，CPU 密集取核数。
  • with 退出会等待所有任务结束；要提前取消用 shutdown(cancel_futures=True)。
  • 异常存到 Future 里，只有调用 result() 时才抛出。
  • 进程池启动慢，任务太短（毫秒级）时开销大于收益。

第 40 课 · 目标与要点

实战：并发下载与错误处理

能把一个串行下载脚本改造成并发版，处理超时、重试、限速与部分失败，并给出可观测的进度。
  • 超时必须显式设置，默认无超时会让线程永久挂起。
  • 重试要退避，固定间隔会在服务端故障时形成雪崩。
  • 并发度要有限制，无上限会耗尽文件描述符或被目标限流。
  • 进度输出要可关闭，日志环境里 \r 会污染输出。

import time
from concurrent.futures import ThreadPoolExecutor, as_completed
import urllib.request

def fetch(url, timeout=5, retries=2):
    for attempt in range(retries + 1):
        try:
            with urllib.request.urlopen(url, timeout=timeout) as r:
                return len(r.read())
        except Exception:
            if attempt == retries:
                raise
            time.sleep(0.5 * (attempt + 1))

def download_all(urls, workers=8):
    ok, failed = 0, []
    with ThreadPoolExecutor(max_workers=workers) as pool:
        futures = {pool.submit(fetch, u): u for u in urls}
