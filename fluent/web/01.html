单元导入

Python 的「地道的写法」不是背语法糖，而是让你的对象接入语言自己的协议。你写 len(x)、for i in x、x[1:3]、x + y、print(x)，解释器都在找同一组特殊方法。

本单元先把这套协议打通，再横向铺开内置序列：什么时候用 list、tuple、array、deque，推导式与生成器表达式各自的边界在哪里，切片和 += 有哪些反直觉行为。

学完本单元，你应该能：

  • 手写一个支持 len()、索引、切片、for、repr() 的类，并解释每一步是谁在调用；
  • 在 list / tuple / array / deque 之间做出有理由的选择，而不是默认用 list；
  • 一眼看出 [[]] * 3、t[2] += [...] 这类别名的坑。

第 1 课 · 特殊方法：让对象接入语言协议

讲解

特殊方法（dunder method）不是给你直接调的，而是给解释器调的。len(deck) 走的是 C 层的快速路径，最终调用 deck.__len__()；deck[0] 调用 __getitem__(0)；for card in deck 在没有 __iter__ 时会退化为「从 0 开始反复 __getitem__，直到 IndexError」。

Pythonimport collections

Card = collections.namedtuple("Card", ["rank", "suit"])


class FrenchDeck:
    ranks = [str(n) for n in range(2, 11)] + list("JQKA")
    suits = "spades diamonds clubs hearts".split()

    def __init__(self):
        self._cards = [Card(rank, suit)
                       for suit in self.suits
                       for rank in self.ranks]

    def __len__(self):
        return len(self._cards)

    def __getitem__(self, position):
        return self._cards[position]


deck = FrenchDeck()
print(len(deck))       # 52
print(deck[0])         # Card(rank='2', suit='spades')
print(deck[-1])        # Card(rank='A', suit='hearts')
print(deck[12::13])    # 每隔 13 张取一张，切片也自动生效

只实现 __len__ 和 __getitem__，这个类就白拿了 len()、下标、负索引、切片、for、random.choice()。这就是「数据模型」的杠杆效应。

延伸：特殊方法不是清单，是五组操作

背 80 多个特殊方法没有意义，按操作族分类就不会漏：

族 方法 什么时候被调
容器 __len__ __getitem__ __setitem__ __delitem__ __contains__ __iter__ __reversed__ __missing__ len()、obj[k]、k in obj、for
数值 __add__ __radd__ __iadd__ __mul__ __abs__ __round__ __int__ __float__ 运算符、round()、float()
比较与哈希 __eq__ __lt__ __hash__ __bool__ ==、排序、hash()、if obj
表示与转换 __repr__ __str__ __format__ __bytes__ repr()、print()、f-string、bytes()
生命周期 __init__ __new__ __del__ 构造、回收

三个容易记错的行为：

  • __reversed__ 不定义时，reversed() 会退化成「先 len() 再倒序取 __getitem__」；对象没有 __len__ 就直接 TypeError。
  • __contains__ 不定义时，in 退化为迭代比较，O(n)；给 FrenchDeck 加一个 __contains__ 就能把「这张牌在不在」变 O(1)。
  • __missing__ 只在 dict 子类里、且只由 d[k] 触发；d.get(k) 永远不会走它。想统一行为得同时重写 get。

关键点

  • 不要自己调 dunder：写 len(x)，不要写 x.__len__()。前者有 C 层优化，后者绕过了它。
  • __repr__ 是开发者视角，理想形式是 Vector2d(3, 4) 这种能重建对象的表达式；__str__ 面向用户。只定义 __repr__ 时，print() 会自动回退到它。
  • bool(x) 的回退链：先找 __bool__，没有就找 __len__，len(x) == 0 即为假。所以定义了 __len__ 的容器天然有真假值。
  • 算术运算符不会自动交换操作数：a + b 先试 a.__add__(b)，失败或返回 NotImplemented 再试 b.__radd__(a)。

动手

  1. 给 FrenchDeck 加 __repr__，打印成 FrenchDeck(52 cards)。
  2. 加一个 pick() 方法，随机返回一张牌，要求只写一行（提示：random.choice(self)）。
  3. 去掉 __len__，观察 len(deck) 的报错信息，再把 __len__ 加回来。
Pythonimport random

class FancyDeck(FrenchDeck):             # 接上面的 FrenchDeck
    def __repr__(self):
        return f"FrenchDeck({len(self)} cards)"

    def pick(self):
        return random.choice(self)

验收清单

  • 能不查资料说出 len / [] / for / print 各自触发的方法名
  • 解释为什么 len(deck) 比 deck.__len__() 更可取
  • 写出的类在 print() 时输出的是可读的对象表示，而不是 <__main__.X object at 0x...>

第 2 课 · 序列家族与推导式

讲解

内置序列按两层维度分类：

维度 类型 存什么
容器序列 list、tuple、collections.deque 存对象引用，可以放不同类型
扁平序列 str、bytes、bytearray、array.array、memoryview 存值本身，只能放字符/数字/字节，更省内存
可变 list、bytearray、array、deque 能原地改
不可变 tuple、str、bytes 改就生成新对象

推导式是「用表达式构造序列」，比 for + append 更快也更难读错：

Pythonsymbols = "$¢£¥€¤"
codes = [ord(s) for s in symbols if ord(s) > 127]
print(codes)                      # [162, 163, 165, 8364, 164]

# 等价写法，但 map/filter 需要 lambda，可读性通常更差
codes2 = list(filter(lambda c: c > 127, map(ord, symbols)))

生成器表达式把方括号换成圆括号，得到的是惰性迭代器，一次只产出一个元素，只能遍历一次：

Pythontotal = sum(ord(s) for s in symbols)      # 不需要先建列表
print(total)

colors = ["black", "white"]
sizes = ["S", "M", "L"]
tshirts = [(c, s) for c in colors for s in sizes]   # 笛卡尔积：6 种

延伸：memoryview：同一块内存的视图

lst[:] 一定复制，bytes 切片也复制，但 memoryview 的切片是视图：

Pythondata = bytearray(b"HTTP/1.1 200 OK")
mv = memoryview(data)
head = mv[:8]                 # 视图，不复制
print(head.tobytes())         # b'HTTP/1.1'
data[5] = ord("9")            # 改原对象
print(head.tobytes())         # b'HTTP/9.1'，视图跟着变
print(mv[0:4] == b"HTTP")     # True，可直接和 bytes 比较

NumPy 的切片同样是视图：arr[1:] 改的是原数组，这和 list 的复制语义相反，是从 list 迁到 NumPy 最常见的 bug。memoryview.cast("I") 还能把同一块内存按 4 字节整数重新解释，解析二进制协议头时省掉所有 unpack 拷贝。

关键点

  • 推导式只用来「建序列」，不要在里边 print 或改外部状态；副作用请用普通 for。
  • 生成器表达式省内存但有一次性：g = (x for x in data)，遍历一次就空了；需要重复用就存成 list。
  • 嵌套顺序 = 书写顺序：for c in colors for s in sizes 外层是 colors。写反了不会报错，只会得到错的结果。
  • array.array 存的是机器数值，比 list 省 2–8 倍内存（取决于元素类型），但只能放同一种数值类型。

动手

给定一份 20 个单词的列表，完成三件事，并记录每步耗时（用 time.perf_counter()）：

  1. 用列表推导式取出所有长度大于 5 的单词，转成大写；
  2. 用生成器表达式求这些单词的总长度；
  3. 用 array.array("d", ...) 存 100 万个浮点数，和 list 版本比较 sys.getsizeof()。

验收清单

  • 能举出一个「必须用生成器表达式而不能用列表推导式」的场景（内存受限 / 无限流 / 只需一次归约）
  • 能解释 [[]] * 3 与 [[] for _ in range(3)] 的区别
  • 知道 str 属于扁平序列，因此 str 的切片返回新字符串而不是视图

第 3 课 · 元组、拆包、切片与排序

讲解

元组有两个身份：不可变列表和没有字段名的记录。后者更常用——一行数据 ("Tokyo", 35.68, 139.69) 用元组，比 dict 轻，比自定义类省事。

Pythoncity = ("Tokyo", 35.68, 139.69)
name, lat, lon = city                     # 拆包
first, *rest = range(5)                   # first=0, rest=[1,2,3,4]
a, b = b, a                               # 交换，不需要临时变量

for rank, (name, score) in enumerate([("Ann", 90), ("Bob", 85)], start=1):
    print(rank, name, score)

切片是「读」的语法，切片赋值是「写」的语法：

Pythonlst = list(range(10))
print(lst[2:8:2])        # [2, 4, 6]
print(lst[::-1])         # 反转；会生成新列表
lst[2:5] = [20, 30]      # 长度可变：用 2 个元素替换 3 个
del lst[1:3]

排序有两套 API，区别不只是「原不原地」：

Pythonfruits = ["grape", "raspberry", "apple", "banana"]
print(sorted(fruits, key=len))        # 返回新列表
fruits.sort(key=str.lower)            # 原地排序，返回 None

list.sort() 返回 None 是刻意设计——防止你误以为拿到了新列表，同时提醒这是原地操作。Python 的排序是稳定的 Timsort，相同 key 的元素保持原相对顺序。

延伸：Ellipsis 与元组下标

...（Ellipsis）是合法的切片占位符，含义是「其余维度全取」。内置 list 只支持一维，写 lst[..., 0] 会 TypeError；但实现了 __getitem__ 的自定义类型可以自己解释它。NumPy 里 arr[..., 0]、arr[0, ..., :2] 是日常写法。

自己实现时，key 可能是单值也可能是元组，要把元组当结构拆：

Pythonclass Grid:
    def __init__(self, rows):
        self._rows = rows

    def __getitem__(self, key):
        if not isinstance(key, tuple):
            return self._rows[key]
        row, col = key
        if row is Ellipsis:
            return [r[col] for r in self._rows]
        return self._rows[row][col]

g = Grid([[1, 2], [3, 4]])
print(g[0, 1], g[..., 0])     # 2 [1, 3]

要点：Ellipsis 用 is 比较，不要用 ==；切片对象 slice(...) 也要单独放行。

关键点

  • 元组不可变 ≠ 内容不可变：元组里放 list，list 仍然能改。
  • s[a:b:c] 的 c 为负表示反向，s[::-1] 是最常用的反转写法，但它复制了一份数据。
  • 切片赋值不要求长度相等，这会让列表长度变化；步长不为 1 时则要求长度相等，否则报 ValueError。
  • 多维切片只对支持它的对象有效（如 NumPy 数组），内置 list 不支持 lst[1:2, 3:4]。

动手

有一份成绩单：

    {"name": "Ann", "score": 91, "city": "Tokyo"},

验收清单

  • 能解释 sorted(...) 与 list.sort(...) 的返回值差异
  • 会用 key=lambda r: (-r["score"], r["name"]) 实现多关键字排序
  • 知道 a, *rest = ... 中 rest 一定是 list

第 4 课 · 别名的坑与选型：list 不是万能的

讲解

先看三个经典陷阱，它们都源于「变量是引用，不是盒子」：

Python# 1) * 复制的是引用，不是内容
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)          # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]  ← 三行是同一个列表

# 2) 元组里的可变对象仍然能改；+= 先原地改，再赋值
t = (1, 2, [30, 40])
try:
    t[2] += [50, 60]
except TypeError as e:
    print("TypeError:", e)
print(t)             # (1, 2, [30, 40, 50, 60])  ← 报错了，但列表已经变了

# 3) 可变默认参数只创建一次
def append_to(item, bucket=[]):
    bucket.append(item)
    return bucket

print(append_to(1))  # [1]
print(append_to(2))  # [1, 2]  ← 不是 [2]

正确写法分别是：[[0] * 3 for _ in range(3)]、别对元组元素做增量赋值、默认值用 None 再在函数体里创建。

当 list 不合适时：

需求 选择 理由
存大量同类型数字 array.array 连续内存，省空间
频繁在两端增删 collections.deque 两端 O(1)，list 头部插入 O(n)
只读、不复制地看二进制 memoryview 零拷贝切片
频繁按序插入 bisect.insort 保持有序，插入 O(n) 但查找 O(log n)

延伸：+= 走哪条路，取决于有没有 iadd

x += y 先找 __iadd__；没有就退化成 x = x + y。list 有 __iadd__（等价 extend，原地改并返回 self），tuple 没有，所以 t += (4,) 必定新建对象，别名看不到变化：

Pythona = [1, 2]; b = a; a += [3]
print(a, b)          # [1, 2, 3] [1, 2, 3]，同一个对象

t = (1, 2); u = t; t += (3,)
print(t, u)          # (1, 2, 3) (1, 2)

*= 同理：lst *= 2 原地扩展，tup *= 2 新建。可变对象上还有第二个坑：lst *= 2 是同一对象自我复制，[[0]] * 3 则是三个引用指向同一个内层 list，改一个全变。

关键点

  • * 复制的是引用：[[0] * 3] * 3 三行共享同一个内层列表，写入就会三行联动。
  • += 先原地修改，再赋值：tuple 没有 __iadd__，所以 t[2] += [...] 改了列表却仍抛 TypeError。
  • 可变默认参数只求值一次：默认值用 None，在函数体里创建新对象。
  • list 不是万能：同类型数字用 array，两端增删用 deque，零拷贝读二进制用 memoryview。

动手

  1. 复现上面三个陷阱，把每个的输出写进注释，再改成正确写法。
  2. 用 deque(maxlen=5) 实现「最近 5 条日志」缓冲，连续 push 10 条，打印结果。
  3. 用 array.array("i", range(1_000_000)) 与 list 版本比较 sys.getsizeof()，记录倍数。

验收清单

  • 能解释 [[0] * 3] * 3 为什么会三行联动
  • 能说清 t[2] += [...] 为什么「既报错又修改成功」
  • 面对「尾部追加为主」和「头部插入为主」两种负载，能分别选 list 和 deque

综合案例：从「能跑」到「好用」的 Deck

同一个牌堆，先写只够演示的版本，再补成能进真实代码的版本。

重构前（能跑但粗糙）

只实现 __len__ 和 __getitem__。len、索引、切片都能用，但三个操作会立刻露馅：in 退化成逐个比较、reversed 依赖 C 层回退、random.shuffle 直接报错。

Pythonimport random


class Deck:
    ranks = [str(n) for n in range(2, 11)] + list("JQKA")
    suits = "spades diamonds clubs hearts".split()

    def __init__(self):
        self._cards = [(r, s) for s in self.suits for r in self.ranks]

    def __len__(self):
        return len(self._cards)

    def __getitem__(self, i):
        return self._cards[i]


deck = Deck()
print(len(deck))                       # 52
print(deck[0])                         # ('2', 'spades')
print(("A", "hearts") in deck)         # True，但走了 52 次比较
print(list(reversed(deck))[:2])        # 靠 len + getitem 倒着取

try:
    random.shuffle(deck)
except TypeError as e:
    print("shuffle 失败:", e)          # 没有 __setitem__，改不了元素

重构后（可直接用）

补上四个协议方法，外加一个「抽 n 张返回新牌堆」的业务方法。注意 __iter__ 返回的是迭代器而不是 self，否则牌堆会被用成一次性迭代器。

Pythonimport random


class Deck:
    ranks = [str(n) for n in range(2, 11)] + list("JQKA")
    suits = "spades diamonds clubs hearts".split()

    def __init__(self, cards=None):
        self._cards = list(cards) if cards is not None else [
            (r, s) for s in self.suits for r in self.ranks]

    def __len__(self):
        return len(self._cards)

    def __getitem__(self, i):
        return self._cards[i]

    def __contains__(self, card):
        return card in self._cards

    def __iter__(self):
        return iter(self._cards)

    def __reversed__(self):
        return reversed(self._cards)

    def __eq__(self, other):
        if not isinstance(other, Deck):
            return NotImplemented
        return self._cards == other._cards

    def pick(self, n=1):
        """抽走 n 张，返回新牌堆；原牌堆不变。"""
        picked = random.sample(self._cards, n)
        rest = [c for c in self._cards if c not in picked]
        return Deck(rest), Deck(picked)

    def shuffle(self):
        random.shuffle(self._cards)
        return self


deck = Deck()
print(len(deck), deck[0], ("A", "hearts") in deck)
print(list(reversed(deck))[:1])        # [('A', 'hearts')]

rest, hand = Deck().shuffle().pick(3)
print(len(rest), len(hand), len(rest) + len(hand))   # 49 3 52
print(Deck([("A", "hearts")]) == Deck([("A", "hearts")]))   # True

差异说明

问题 重构前 重构后 收益 代价
成员判断 没有 __contains__，in 逐个比较 显式实现 语义清楚，可换 O(1) 结构 多 4 行代码
反向遍历 靠 len + __getitem__ 的 C 层回退 实现 __reversed__ 不依赖对象可索引 必须先想清楚「反向」的语义
洗牌 没有 __setitem__，shuffle 直接抛错 提供 shuffle() 方法改内部列表 不暴露可变接口就能打乱 调用方不能对 Deck 下标赋值
相等判断 默认按身份比较，两个内容相同的牌堆不相等 __eq__ 逐张比较 可进集合、可断言 必须同时想 __hash__（可变对象不该有）
抽牌 只能自己 deck[i]，容易和洗牌混在一起 pick(n) 返回两个新牌堆 不可变风格，便于测试 每次复制列表，牌多时有开销
迭代器 若 __iter__ 返回 self，只能遍历一次 返回 iter(self._cards) 可重复遍历、可嵌套 无

再往前一步

把 _cards 换成 frozenset 索引 + tuple 顺序，__contains__ 就变成 O(1)；或者把 pick 改成返回生成器，让「抽牌」也能惰性消费。真要做牌类游戏，牌堆应该是不可变的值对象，所有操作返回新牌堆——这样撤销和回放都不用额外记录状态。
