继承：优劣与替代

原书这一章的写法，Python 为什么这样选、换别的要付什么代价。

子类化内置类型要和 C 实现打交道，多数时候组合更安全。

项 内容
选择 优先组合；必须复用时用 UserDict/UserList/混入类
主要替代 直接继承 dict/list，或深继承层次
替代为何落选 C 实现会绕过重写的方法；深继承导致 MRO 难推理
付出的代价 组合多一层转发；混入类的 MRO 需要理解

当时的约束

内置容器是 C 实现，性能好但很多操作不走 Python 层方法。用户想「加一点行为」时，最直觉的做法就是继承，然后发现拦截不到。

候选方案

继承内置类型、继承 collections.UserDict（纯 Python 实现）、组合 + 委托、混入类。选后三者。

为什么选它

UserDict 内部就是一个 data 字典，所有操作都走 Python 层，重写哪个方法都能生效；组合把「有」与「是」分开，父类变化不会震到子类。

代价与反例

dict 子类的 __missing__ 只管 d[k]，get 不走它；|=、update() 可能绕过 __setitem__；混入类写了 __init__ 会破坏协作式继承。

如果重来

默认组合；确需「是一种」时层级不超过两层；混入类只加方法、不写 __init__，需要参数就 **kwargs 转交 super()。
