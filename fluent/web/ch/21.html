异步编程

原书这一章的写法，Python 为什么这样选、换别的要付什么代价。

单线程协程处理 IO 并发：没有锁，也不需要锁，但整条调用链必须是异步的。

项 内容
选择 事件循环 + 协程 + await，在一个线程内并发调度
主要替代 线程池、回调式事件循环、多进程
替代为何落选 线程池每个任务都有栈与切换成本；回调把控制流拆碎；进程对连接级并发太重
付出的代价 一个阻塞调用卡住整个循环；库要同时维护同步/异步两套 API

当时的约束

C10K 问题：单机要同时维持上万个连接。一万个线程意味着上万份栈和持续的调度开销，而这些连接 99% 的时间在等数据。要么把等待的成本压到零，要么把并发的单位从「线程」换成「更轻的东西」。

候选方案

每连接一个绿色线程（gevent 路线，靠猴补丁让阻塞调用变成协作式让出）、回调式事件循环（Node 与 Twisted 路线）、语言级协程（从 yield from 到 async/await）。

为什么选它

async/await 让异步代码长得像同步代码：顺序读、try/except 照常、循环就是普通 for。没有线程切换就没有数据竞争，共享状态的加锁问题整类消失——这是它相对线程池最被低估的优势。事件循环本身只做一件事：在 IO 就绪时唤醒对应的协程，单次切换成本是纳秒级。

代价与反例

混进一个阻塞调用（time.sleep、同步读文件、同步 requests）整个循环停转，且症状是「莫名其妙全变慢」而不是报错，得靠 asyncio.to_thread 或 run_in_executor 兜底。asyncio.gather 默认一个任务失败就取消其余任务，想「都跑完再统一收异常」要显式 return_exceptions=True。3.11 起的 TaskGroup 是更安全的默认选择：它保证要么全部成功，要么取消并抛出 ExceptionGroup。

如果重来

保留 async/await，但会把 asyncio.to_thread 放到文档更显眼的位置，并在教程第一课就讲清「哪些调用会阻塞循环」——这是新手最容易踩、且最难自查的一类坑。
