序列构成的数组

原书这一章的写法，Python 为什么这样选、换别的要付什么代价。

list 是默认容器，不是通用最优解：内存看 array，两端操作用 deque。

项 内容
选择 list 用动态指针数组（连续内存 + 溢出时整体搬迁）
主要替代 链表、array.array、collections.deque
替代为何落选 链表随机访问 O(n) 且缓存不友好；array 只能同类型；deque 中段插入差
付出的代价 头部插入 O(n)；每个元素是指针，元素对象另有开销

当时的约束

绝大多数 Python 代码按索引访问、遍历、切片；同时要和 C 扩展共享连续内存。链表在这三件事上都不占优，CPython 干脆不提供。

候选方案

连续数组（list）、同类型紧凑数组（array）、双端队列（deque）、第三方 NumPy 数组。判断标准是「访问模式」而不是「元素多少」。

为什么选它

list 的「均摊 O(1) 追加 + O(1) 索引 + 切片复制」覆盖了 90% 的用法，而且连续内存对 CPU 缓存友好。array 省内存但每次取值都要装箱成 Python 对象；deque 两端 O(1)，中段插入 O(n)。

代价与反例

list.insert(0, x) 是 O(n)，循环里做就是 O(n²)——这是最常见的性能事故。每个元素存的是指针，所以 [0]*1000000 占的是 8 MB 指针 + 共享的小整数对象；换成 array('q') 只要 8 MB 且无对象开销。

如果重来

默认仍然 list，但会在「已知同类型数值」时先想 array，在「当队列用」时先想 deque，在「需要零拷贝切片」时想 memoryview。
