类型提示

原书这一章的写法，Python 为什么这样选、换别的要付什么代价。

注解是给检查器和读者看的，运行时不会因此多做一次检查。

项 内容
选择 可选注解 + 外部静态检查器（mypy/pyright），运行时不强制
主要替代 强制类型系统（Java）、运行时校验（pydantic）
替代为何落选 强制会破坏「鸭子类型」与快速原型；运行时校验有性能成本
付出的代价 注解可能撒谎；边界数据仍要运行时校验

当时的约束

Python 生态里有大量动态技巧：猴子补丁、getattr 代理、元类生成类。强制类型检查会把这些直接判死，而且老代码没法渐进迁移。

候选方案

PEP 484 的可选注解、typeguard 这类运行时检查、完全不做。最终选了「注解 + 外部检查器」，语言层只保证语法与 __annotations__。

为什么选它

它让「要不要检查」变成项目决策，而不是语言强制。库可以只加注解不给检查器，应用可以开 strict；渐进迁移的成本最低。

代价与反例

cast(int, "abc") 能骗过检查器；json.load() 返回 Any，你标的类型只是断言；除零、越界、None 从外部进来，检查器都看不见。

如果重来

仍然可选，但会在入口层（HTTP、配置、命令行）强制运行时校验，内部靠注解；并把 Any 当技术债，出现就要有理由。
