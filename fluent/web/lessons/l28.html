多重继承与混入类：什么时候不该继承

本节目标：能识别混入类的特征，判断一个场景该用继承还是组合，并重构一次滥用继承的代码。

讲解

混入类（mixin）是「只提供一组方法、不单独实例化」的类，通常不带状态、不做 __init__：

Pythonclass JsonMixin:
    def to_json(self):
        import json
        return json.dumps(self.__dict__, ensure_ascii=False)

class User(JsonMixin):
    def __init__(self, name):
        self.name = name

print(User("Ann").to_json())   # {"name": "Ann"}

判断标准：

判断项 倾向继承 倾向组合
子类真的是父类的一种？ ✅ 不是就别继承
需要复用父类的实现？ 可以用混入 委托通常更灵活
父类会独立变化？ 不适合 ✅
继承层级超过 2 层？ 重新设计 ✅

组合通常更灵活：

Pythonimport json

class JsonCodec:
    def encode(self, data):
        return json.dumps(data, ensure_ascii=False)

class User:
    def __init__(self, name):
        self.name = name
        self._json = JsonCodec()

    def to_json(self):
        return self._json.encode({"name": self.name})

延伸：混入类不要写 init

混入类（mixin）的职责是「加一小块能力」，不是「初始化状态」。三条铁律：

  1. 不写 __init__；确实需要时只接受 **kwargs 并原样转交 super().__init__(**kwargs)。
  2. 只依赖调用方已经有的方法或属性，不假设自己的初始化顺序。
  3. 一层混入别超过 3 个方法，超了说明它是基类，不是混入。
Pythonclass JsonMixin:
    def to_json(self):
        import json
        return json.dumps(self.__dict__, ensure_ascii=False, default=str)

class User(JsonMixin):
    def __init__(self, name):
        self.name = name

print(User("Ann").to_json())    # {"name": "Ann"}

MRO 是 C3 线性化，super() 不是「父类」而是「MRO 里的下一个」。所以混入里调 super() 会按 MRO 继续往下走，这也是混入能协作的基础；层级超过两层、开始需要记 MRO 顺序时，换组合更稳。

关键点

  • 混入类不写 __init__，也不假设 MRO 的位置。
  • 「is-a」不成立就不要继承，哪怕代码看起来能复用。
  • 继承是编译期最强的耦合，父类改一个方法可能影响所有子类。
  • 优先组合 + 协议：需要多态就实现同一组方法，不需要共享实现。

动手

  1. 找出你写过的一个继承层级，用上表逐条判断是否该改成组合。
  2. 用混入类给 3 个不相关的类加 to_json()，确认它们都不需要改 __init__。
  3. 把一段「继承 + 重写 5 个方法」的代码改成「组合 + 委托 2 个方法」，比较行数与可读性。

验收清单

  • 能说出混入类的三个特征
  • 能用「is-a / 复用实现 / 变化方向」判断继承是否合理
  • 完成过一次「继承 → 组合」的重构并说明收益
