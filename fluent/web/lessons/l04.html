别名的坑与选型：list 不是万能的

本节目标：能识别 `*` 复制、`+=` 原地修改、可变默认参数三类别名问题，并按数据规模选择 array / deque / memoryview。

讲解

先看三个经典陷阱，它们都源于「变量是引用，不是盒子」：

Python# 1) * 复制的是引用，不是内容
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)          # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]  ← 三行是同一个列表

# 2) 元组里的可变对象仍然能改；+= 先原地改，再赋值
t = (1, 2, [30, 40])
try:
    t[2] += [50, 60]
except TypeError as e:
    print("TypeError:", e)
print(t)             # (1, 2, [30, 40, 50, 60])  ← 报错了，但列表已经变了

# 3) 可变默认参数只创建一次
def append_to(item, bucket=[]):
    bucket.append(item)
    return bucket

print(append_to(1))  # [1]
print(append_to(2))  # [1, 2]  ← 不是 [2]

正确写法分别是：[[0] * 3 for _ in range(3)]、别对元组元素做增量赋值、默认值用 None 再在函数体里创建。

当 list 不合适时：

需求 选择 理由
存大量同类型数字 array.array 连续内存，省空间
频繁在两端增删 collections.deque 两端 O(1)，list 头部插入 O(n)
只读、不复制地看二进制 memoryview 零拷贝切片
频繁按序插入 bisect.insort 保持有序，插入 O(n) 但查找 O(log n)

延伸：+= 走哪条路，取决于有没有 iadd

x += y 先找 __iadd__；没有就退化成 x = x + y。list 有 __iadd__（等价 extend，原地改并返回 self），tuple 没有，所以 t += (4,) 必定新建对象，别名看不到变化：

Pythona = [1, 2]; b = a; a += [3]
print(a, b)          # [1, 2, 3] [1, 2, 3]，同一个对象

t = (1, 2); u = t; t += (3,)
print(t, u)          # (1, 2, 3) (1, 2)

*= 同理：lst *= 2 原地扩展，tup *= 2 新建。可变对象上还有第二个坑：lst *= 2 是同一对象自我复制，[[0]] * 3 则是三个引用指向同一个内层 list，改一个全变。

关键点

  • * 复制的是引用：[[0] * 3] * 3 三行共享同一个内层列表，写入就会三行联动。
  • += 先原地修改，再赋值：tuple 没有 __iadd__，所以 t[2] += [...] 改了列表却仍抛 TypeError。
  • 可变默认参数只求值一次：默认值用 None，在函数体里创建新对象。
  • list 不是万能：同类型数字用 array，两端增删用 deque，零拷贝读二进制用 memoryview。

动手

  1. 复现上面三个陷阱，把每个的输出写进注释，再改成正确写法。
  2. 用 deque(maxlen=5) 实现「最近 5 条日志」缓冲，连续 push 10 条，打印结果。
  3. 用 array.array("i", range(1_000_000)) 与 list 版本比较 sys.getsizeof()，记录倍数。

验收清单

  • 能解释 [[0] * 3] * 3 为什么会三行联动
  • 能说清 t[2] += [...] 为什么「既报错又修改成功」
  • 面对「尾部追加为主」和「头部插入为主」两种负载，能分别选 list 和 deque
