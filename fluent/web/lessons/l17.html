闭包：捕获的是变量，不是值

本节目标：能写出带状态的闭包，解释 LEGB 查找与 `nonlocal`，并识别循环中 lambda 的延迟绑定陷阱。

讲解

闭包 = 函数 + 它引用的外层变量（cell）。外层函数返回后，这些变量仍然活着：

Pythondef make_counter(start=0):
    n = start

    def counter(step=1):
        nonlocal n
        n += step
        return n

    return counter

c = make_counter(10)
print(c(), c(5))        # 11 16
print(c.__closure__[0].cell_contents)   # 16

n += step 会赋值，所以必须声明 nonlocal n；不声明的话 Python 认为 n 是局部变量，抛 UnboundLocalError。

闭包捕获的是变量本身，不是创建时的值。这导致循环里的函数全部看到最后一个值：

Pythonfuncs = [lambda: i for i in range(3)]
print([f() for f in funcs])      # [2, 2, 2]

funcs = [lambda i=i: i for i in range(3)]   # 用默认参数固化
print([f() for f in funcs])      # [0, 1, 2]

延伸：闭包变量存在 closure 里

闭包把外层变量存在函数对象的 __closure__ 中，每一项是一个 cell：

Pythondef counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc

c = counter()
c(); c()
print(c.__closure__[0].cell_contents)    # 2

nonlocal 只声明「最近一层」的外层变量：跨两层就要每层各写一次，或者干脆把状态放进 list/dict 里（改内容不算重新绑定，不需要 nonlocal）。只读外层变量不用声明，赋值才需要——忘了写会得到 UnboundLocalError，因为赋值让这个名字在整个函数里变成局部变量。

关键点

  • LEGB 顺序：Local → Enclosing → Global → Builtin；闭包变量在 Enclosing 层。
  • 只有「赋值」才需要 nonlocal；只读外层变量不需要声明。
  • 闭包持有引用，会延长对象生命周期；大量闭包 + 大对象要留意内存。
  • 延迟绑定是特性不是 bug：它让闭包能共享状态，但循环里要显式固化。

动手

  1. 写 make_accumulator()，连续调用累加，并打印 __closure__ 里的 cell 内容。
  2. 复现 [lambda: i for i in range(3)] 的陷阱，用两种方式修复（默认参数、functools.partial）。
  3. 写一个闭包版 rate_limiter(max_calls)，超过次数返回 False。

验收清单

  • 能解释闭包变量为什么在外层函数返回后仍然存在
  • 知道什么时候必须写 nonlocal
  • 能识别并修复循环中 lambda 的延迟绑定
