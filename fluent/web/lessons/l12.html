可变性、默认参数与对象生命周期

本节目标：能识别可变默认参数、类属性共享、`del` 的真实语义，并在需要时用 weakref 管理缓存。

讲解

可变默认参数是最经典的坑：默认值在函数定义时求值一次，之后所有调用共享。

Pythondef add(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add(1))    # [1]
print(add(2))    # [1, 2]  ← 不是 [2]

正确写法：

Pythondef add(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket

同理，类属性如果是可变对象，会被所有实例共享：

Pythonclass Team:
    members = []          # 不要这样写

    def add(self, name):
        self.members.append(name)

del 删除的是名字绑定，不是对象本身；对象只有在引用计数归零（或被循环 GC 回收）时才释放：

Pythonimport weakref

class Node:
    pass

n = Node()
r = weakref.ref(n)     # 弱引用：不增加引用计数
print(r() is n)        # True
del n
print(r())             # None，对象已被回收

延伸：del 删的是名字，不是对象

Pythonimport sys
a = [1, 2, 3]
b = a
print(sys.getrefcount(a))   # 3：a、b、和 getrefcount 的临时参数
del a
print(b)                    # 对象还在，因为 b 还引用着它

CPython 靠引用计数立即回收，循环引用交给分代 GC（gc.collect() 可手动触发）。__del__ 不是可靠析构钩子：回收时机不确定，解释器退出时也不保证调用，拿它关文件、连数据库一定会漏。要确定性清理就用 with；对象没有上下文管理器，就 contextlib.closing 包一层。

关键点

  • 默认参数只求值一次，可变默认值必须用 None 哨兵。
  • del x 删的是名字，其他引用仍然有效；del lst[0] 才是删元素。
  • 循环引用靠分代 GC 回收，不是引用计数；大量创建对象时可用 gc.collect() 观测。
  • 弱引用适合做缓存：WeakValueDictionary 让缓存项在外部不再使用时自动消失。

动手

  1. 复现可变默认参数 bug，改写成 None 哨兵版本，并写一个测试证明两次调用互不影响。
  2. 用 weakref.WeakValueDictionary 实现一个「对象缓存」，删除外部引用后验证缓存自动清空。
  3. 用 sys.getrefcount() 观察一个对象在赋值、传参、删除时的引用计数变化（注意它本身会 +1）。

验收清单

  • 能解释默认参数为什么只求值一次
  • 知道 del 删除的是绑定而不是对象
  • 能说出弱引用适合解决什么问题，以及它不适合什么场景
