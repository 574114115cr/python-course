上下文管理器与 with

本节目标：能实现 `__enter__`/`__exit__`，用 `@contextmanager` 简化写法，并用 `ExitStack` 动态管理多个资源。

讲解

with 保证退出时执行清理，即使中途抛异常：

Pythonclass Timer:
    def __enter__(self):
        import time
        self.t0 = time.perf_counter()
        return self

    def __exit__(self, exc_type, exc, tb):
        import time
        self.elapsed = time.perf_counter() - self.t0
        return False        # False 表示不吞异常

with Timer() as t:
    sum(range(1_000_000))
print(f"{t.elapsed:.4f}s")

__exit__ 返回 True 会吞掉异常，除非你明确要做「抑制错误」，否则一律返回 False 或不返回。

用 @contextmanager 写更短：

Pythonfrom contextlib import contextmanager

@contextmanager
def tag(name):
    print(f"<{name}>")
    try:
        yield
    finally:
        print(f"</{name}>")

with tag("p"):
    print("hello")

需要同时管理数量不定的资源时，用 ExitStack：

Pythonfrom contextlib import ExitStack

with ExitStack() as stack:
    files = [stack.enter_context(open(p, encoding="utf-8")) for p in paths]

延伸：ExitStack：数量不定的资源

ExitStack 管理数量不定的上下文，退出顺序是后进先出：

Pythonfrom contextlib import ExitStack

def first_bytes(paths):
    with ExitStack() as stack:
        files = [stack.enter_context(open(p)) for p in paths]
        return [f.read(1) for f in files]

stack.callback(fn, *args) 注册一个退出时调用的普通函数，适合没有上下文管理器的清理动作（关 socket、删临时目录）。stack.pop_all() 把清理责任转交出去，写装饰器或需要延后清理时用。

__exit__ 返回 True 会吞掉异常，这是最容易造成「异常静默消失」的写法，除刻意抑制（如 contextlib.suppress）外不要这么做。ExitStack 里的异常会依次传给每个 __exit__ 的 exc_type 参数，由它们各自决定是否抑制。

关键点

  • __exit__ 的三个参数是异常类型、异常对象、traceback；无异常时全是 None。
  • return True 会吞异常，这是很多「静默失败」的来源。
  • @contextmanager 的 yield 只能出现一次，且必须放在 try/finally 里保证清理。
  • 上下文管理器可以复用，但每次 with 都是一次新的进入/退出。

动手

  1. 实现 Timer，测量一段代码耗时，并验证异常时也能打印。
  2. 用 @contextmanager 实现「临时切换工作目录」，退出时切回。
  3. 用 ExitStack 同时打开 3 个文件，验证异常时全部关闭。

验收清单

  • 能写出 __enter__ / __exit__ 并解释返回值含义
  • 会用 @contextmanager 改写类版本
  • 知道 ExitStack 适合什么场景
