实战：并发下载与错误处理

本节目标：能把一个串行下载脚本改造成并发版，处理超时、重试、限速与部分失败，并给出可观测的进度。

讲解

需求：下载 50 个 URL，超时 5 秒，失败重试 2 次，输出成功/失败数量与耗时。

Pythonimport time
from concurrent.futures import ThreadPoolExecutor, as_completed
import urllib.request

def fetch(url, timeout=5, retries=2):
    for attempt in range(retries + 1):
        try:
            with urllib.request.urlopen(url, timeout=timeout) as r:
                return len(r.read())
        except Exception:
            if attempt == retries:
                raise
            time.sleep(0.5 * (attempt + 1))

def download_all(urls, workers=8):
    ok, failed = 0, []
    with ThreadPoolExecutor(max_workers=workers) as pool:
        futures = {pool.submit(fetch, u): u for u in urls}
        for i, fut in enumerate(as_completed(futures), 1):
            url = futures[fut]
            try:
                fut.result()
                ok += 1
            except Exception as e:
                failed.append((url, repr(e)))
            print(f"\r{i}/{len(urls)}", end="")
    return ok, failed

这个脚本的关键不是「用了线程池」，而是失败不会拖垮整体：单个 URL 抛异常只记录，不中断其他任务。

延伸：as_completed 与取消的边界

Pythonfrom concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(4) as ex:
    futs = {ex.submit(pow, i, 2): i for i in range(4)}
    for f in as_completed(futs):
        print(futs[f], f.result())

按完成先后产出，适合进度条和「先到先用」。future.cancel() 只对「还没开始执行」的任务生效，返回布尔值表示是否取消成功；已经在跑的线程取消不了——线程没有安全的中断点。所以「取消」在并发里通常意味着「设一个标志位，让任务自己检查后退出」，而不是强行掐断。

shutdown(cancel_futures=True)（3.9+）批量取消排队中的任务；with 退出时默认 wait=True，会等所有任务跑完，这点在服务优雅关闭时要注意。

关键点

  • 超时必须显式设置，默认无超时会让线程永久挂起。
  • 重试要退避，固定间隔会在服务端故障时形成雪崩。
  • 并发度要有限制，无上限会耗尽文件描述符或被目标限流。
  • 进度输出要可关闭，日志环境里 \r 会污染输出。

动手

  1. 把上面的脚本跑在 10 个真实 URL 上（含 1 个故意错误的），记录成功/失败。
  2. 去掉超时参数，观察一个不可达地址会挂多久。
  3. 给脚本加「最大并发 4」与「总耗时统计」，输出一张结果表。

验收清单

  • 能写出带超时、重试、部分失败处理的并发脚本
  • 知道并发度为什么必须限制
  • 能解释重试退避的作用
