单元导入

类型提示写到一定程度，一定会遇到三个问题：容器里装什么（泛型）、字典的键固定但类型不同（TypedDict）、同一个函数对不同输入返回不同类型（重载）。这一单元把它们补齐，并说明「型变」为什么会让 list[Dog] 不能当 list[Animal] 用。

运算符重载则是另一条线：让自定义类型支持 +、*、@、<，代码会更接近数学表达。但重载必须遵守约定——不改变运算符的语义、保持交换律、返回新对象，否则调用方会被坑。

学完本单元，你应该能：

  • 用 TypeVar / Generic / Protocol 写出通过 mypy 的泛型类；
  • 用 TypedDict 描述结构化字典，用 @overload 描述多签名函数；
  • 正确实现一元、算术、矩阵乘与反射运算符；
  • 用 total_ordering 补齐比较，并让 += 与 + 语义一致。

第 29 课 · 泛型：TypeVar、Generic 与型变

讲解

TypeVar 是类型变量，让「输入类型」与「输出类型」建立关系：

Pythonfrom typing import TypeVar

T = TypeVar("T")

def first(items: list[T]) -> T:
    return items[0]

first([1, 2]) 推出 int，first(["a"]) 推出 str。带约束时用 bound：

Pythonfrom typing import TypeVar
from collections.abc import Sized

S = TypeVar("S", bound=Sized)

def longest(a: S, b: S) -> S:
    return a if len(a) >= len(b) else b

泛型类：

Pythonfrom typing import Generic, TypeVar

T = TypeVar("T")

class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()

型变描述「子类型关系能否传递到容器」：

  • 不变（invariant）：list[Dog] 不是 list[Animal]，因为往里塞猫会破坏原列表。
  • 协变（covariant）：只读容器可以，Sequence[Dog] 是 Sequence[Animal]。
  • 逆变（contravariant）：只作为输入的 Callable 参数可以。

延伸：TypedDict 的可选键与重载的实现体

TypedDict 描述「带固定键名的 dict」，默认所有键必需；可选键有两种写法：

Pythonfrom typing import TypedDict, NotRequired, Required   # 3.11+

class Movie(TypedDict):
    title: str
    year: NotRequired[int]        # 3.11+；3.10 用 total=False 再补 Required

m: Movie = {"title": "Alien"}     # 合法，year 可省

3.10 及更早只有 total=False（全部可选），要用 Required[...] 逐个标回必需。TypedDict 只约束静态形状，运行时就是普通 dict，多余键不会报错。

关于重载：@overload 的多个签名只是给检查器看的，最后一个实现体的参数必须能接受所有重载的组合（通常用联合类型或 *args, **kwargs），返回类型也要能覆盖。写错实现体签名时检查器会明确报「实现与重载不兼容」，这是最常踩的坑。

关键点

  • list 是不变的，Sequence 是协变的；只读场景优先注解为 Sequence。
  • TypeVar 只在同一次调用内保持类型一致，不是全局绑定。
  • 能用 Protocol 就别造基类，泛型 + 协议能覆盖大多数约束。
  • 别给 TypeVar 加无意义的 bound=object，等于没约束。

动手

  1. 写 pair(a: T, b: T) -> tuple[T, T]，用 mypy 验证混合类型会报错。
  2. 实现 Stack[T]，分别 push 三个 int，验证 pop() 的返回类型被推断为 int。
  3. 用 Sequence 与 list 各写一版 first，比较 mypy 对 list[Dog] 的接受度。

验收清单

  • 能写出带 bound 的 TypeVar 并解释约束作用
  • 能解释 list[Dog] 为什么不能传给 list[Animal]
  • 知道只读场景该用 Sequence 而不是 list

第 30 课 · TypedDict、重载与运行时读取注解

讲解

TypedDict 适合「本质是 dict，但键固定」的数据，比如 API 响应：

Pythonfrom typing import TypedDict

class Movie(TypedDict):
    title: str
    year: int
    rating: float

m: Movie = {"title": "Alien", "year": 1979, "rating": 8.5}

total=False 让所有键可选；Required / NotRequired 可以逐键控制。

重载用于「同一个函数，不同输入返回不同类型」：

Pythonfrom typing import overload

@overload
def parse(x: str) -> int: ...
@overload
def parse(x: bytes) -> str: ...
def parse(x):
    if isinstance(x, str):
        return int(x)
    return x.decode()

实现体的签名不对外暴露，调用方只看重载签名；但 mypy 会检查实现体与重载是否兼容。@overload 只在静态检查时生效。

运行时读取注解用 typing.get_type_hints（会解析字符串注解与前向引用）：

Pythonfrom typing import get_type_hints

def f(x: "int", y: list["str"]) -> None:
    ...

print(get_type_hints(f))
# {'x': <class 'int'>, 'y': list[str], 'return': NoneType}

延伸：型变只影响静态检查

Pythonfrom typing import TypeVar, Generic

T_co = TypeVar("T_co", covariant=True)      # 只读产出，协变
T_contra = TypeVar("T_contra", contravariant=True)   # 只消费，逆变

class Producer(Generic[T_co]):
    def get(self) -> T_co: ...

class Consumer(Generic[T_contra]):
    def put(self, x: T_contra) -> None: ...

规则的直觉：只往外给的容器可以协变（Producer[Dog] 是 Producer[Animal]），只往里收的可以逆变，既读又写的必须不变（list 就是不变，所以 list[Dog] 不能当 list[Animal] 用）。这些声明只在静态检查时生效，运行时 TypeVar 不产生任何行为差异，也不能据此做 isinstance 判断。

关键点

  • TypedDict 不做运行时校验，它只是给检查器看的形状。
  • 重载签名必须与实现兼容，否则 mypy 报 overload 错误。
  • __annotations__ 可能是字符串（from __future__ import annotations），要用 get_type_hints 求值。
  • 运行时读注解可以驱动校验、序列化、依赖注入，但要注意循环导入。

动手

  1. 用 TypedDict 描述一个 API 响应，写一个函数返回该类型，并让 mypy 检查。
  2. 用 @overload 实现 double(x)：int 返回 int，str 返回重复字符串。
  3. 写一个 validate(obj)，用 get_type_hints 读取 dataclass 字段类型并做简单校验。

验收清单

  • 能用 TypedDict 替代「键名靠猜」的 dict
  • 能写出两个重载签名 + 一个实现体
  • 会用 get_type_hints 处理字符串注解
教材对照第 15 章 §15.6–15.8本节自足，无需回查原书

第 31 课 · 运算符重载：一元、算术与 @

讲解

运算符对应特殊方法：

表达式 方法 反射版本
-v __neg__ —
v + w __add__ __radd__
v * 3 __mul__ __rmul__
v @ m __matmul__ __rmatmul__ 
Pythonclass Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(self.x + other.x, self.y + other.y)

    def __mul__(self, scalar):
        if not isinstance(scalar, (int, float)):
            return NotImplemented
        return Vector(self.x * scalar, self.y * scalar)

    __rmul__ = __mul__

    def __neg__(self):
        return Vector(-self.x, -self.y)

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

当 a + b 里 a.__add__ 返回 NotImplemented，Python 会尝试 b.__radd__(a)。这是 3 * v 能工作的原因。直接抛 TypeError 会阻止反射回退。

延伸：+ 和 @ 都必须返回新对象

中缀运算符的两个约定：__add__ 返回新对象，不修改操作数；__matmul__ 同理。@ 的优先级和 * 相同，比 + 高，所以 a @ b + c 是 (a @ b) + c——但别依赖读者记得，加括号。

Pythonclass Vec:
    def __init__(self, x, y): self.x, self.y = x, y
    def __add__(self, o):
        return Vec(self.x + o.x, self.y + o.y)      # 新对象
    def __matmul__(self, o):
        return self.x * o.x + self.y * o.y          # 点积，标量
    def __repr__(self):
        return f"Vec({self.x}, {self.y})"

print(Vec(1, 2) + Vec(3, 4))        # Vec(4, 6)
print(Vec(1, 2) @ Vec(3, 4))        # 11

返回 NotImplemented（不是 raise）才能让 Python 尝试对方的反射方法 __radd__。类型不匹配时返回 NotImplemented，是「我不认识这个类型」的标准回答。

关键点

  • 返回 NotImplemented，不要抛异常，让解释器有机会尝试另一侧。
  • @ 是矩阵乘法，NumPy 用得多；自己实现时要明确维度规则。
  • + 不应修改操作数，返回新对象；原地修改交给 +=。
  • 运算符语义要符合直觉：+ 表示合并/相加，不要拿来表示「删除」。

动手

  1. 实现 Vector 的 +、*、-，验证 3 * v 与 v * 3 都可用。
  2. 故意让 __add__ 抛 TypeError，观察 1 + v 的报错变化，再改回 NotImplemented。
  3. 用 @ 实现 2×2 矩阵乘向量，写 3 条断言。

验收清单

  • 知道反射运算符在什么时机被调用
  • 能解释返回 NotImplemented 与抛 TypeError 的差异
  • 实现的算术运算符不修改操作数
教材对照第 16 章 §16.2–16.6本节自足，无需回查原书

第 32 课 · 比较、增量赋值与一致性

讲解

只需要定义 __eq__ 和一个顺序方法，total_ordering 会补齐其余：

Pythonfrom functools import total_ordering

@total_ordering
class Version:
    def __init__(self, text):
        self.parts = tuple(int(x) for x in text.split("."))

    def __eq__(self, other):
        if not isinstance(other, Version):
            return NotImplemented
        return self.parts == other.parts

    def __lt__(self, other):
        if not isinstance(other, Version):
            return NotImplemented
        return self.parts < other.parts

增量赋值 += 优先调用 __iadd__；没有则退化为 a = a + b。可变类型应实现 __iadd__ 并返回 self：

Pythonclass Bag:
    def __init__(self, items=()):
        self.items = list(items)

    def __iadd__(self, other):
        self.items.extend(other)
        return self

一致性检查清单：

  • a == b 为真时，hash(a) == hash(b) 必须为真；
  • a < b 与 b > a 必须一致；
  • a == a 必须为真（除非对象是 NaN 这类特例）；
  • 排序结果不能依赖调用顺序（稳定排序另说）。

延伸：iadd 返回 self 才算原地

c += d 的语义是「重新绑定 c」，但你可以在 __iadd__ 里选择原地改再返回 self，也可以新建对象返回。前者调用方看到的别名会一起变，后者不会：

Pythonclass Score:
    def __init__(self, v): self.v = v
    def __iadd__(self, n):
        self.v += n
        return self                 # 原地：别名同步可见
    def __repr__(self): return f"Score({self.v})"

a = Score(1); b = a; a += 2
print(a, b)                         # Score(3) Score(3)

如果 __iadd__ 忘了 return，a += 2 会把 a 绑成 None，这是最隐蔽的 bug 之一。可变对象（list、set、numpy 数组）通常原地，不可变对象（tuple、str、int）必然新建——判断标准就是「这个类型能不能改内容」。

关键点

  • total_ordering 要求 __eq__ 与 __lt__ 同时存在，否则报错。
  • __iadd__ 必须返回 self，返回 None 会让 a 变成 None。
  • 浮点 NaN 破坏自反性，涉及 NaN 的比较要单独处理。
  • 比较运算符不要做副作用操作，调用方默认它是纯函数。

动手

  1. 用 total_ordering 实现 Version("1.2.3") 的比较，验证 <=、>、>= 全部可用。
  2. 实现 Bag.__iadd__，验证 b += [1, 2] 后 b 仍是原对象（用 id 检查）。
  3. 写一个测试，检查相等、哈希、排序三者在 10 组数据上是否自洽。

验收清单

  • 能用 total_ordering 补齐四个比较运算符
  • 知道 __iadd__ 的返回值要求
  • 能列出相等/哈希/排序一致性的至少三条规则

综合案例：栈：从「裸列表」到带类型参数的容器

内部用 list 实现栈，先写成最顺手的样子，再看它怎么被外部改坏、怎么在空栈上崩。

重构前（内部状态全暴露）

items 是公开属性，外部可以直接 append、clear，绕过后进先出；空栈 pop() 抛 IndexError，调用方得自己 try；没有类型信息，push("a") 进 list[int] 也没人管。

Pythonclass Stack:
    def __init__(self):
        self.items = []

    def push(self, item):
        self.items.append(item)

    def pop(self):
        return self.items.pop()

    def size(self):
        return len(self.items)


s = Stack()
s.push(1)
s.push(2)
print(s.pop(), s.size())        # 2 1

try:
    Stack().pop()
except IndexError as e:
    print("空栈:", e)           # pop from empty list

print(len(s.items))             # 1：绕过 API 直接看内部
s.items.append(99)              # 绕过 push 插队
s.items.clear()                 # 直接清空，size 归零但没人知道
print(s.size())                 # 0

s.push("字符串也能进来")          # 没有类型约束
print(s.items)

重构后（封装 + 泛型 + 空栈语义）

内部列表改成 _items，对外只暴露方法；pop / peek 在空栈时返回 None（明确写进返回类型），并补 __len__、__iter__、__bool__ 让它像内置容器。

Pythonfrom typing import Generic, Iterator, Optional, TypeVar

T = TypeVar("T")


class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> Optional[T]:
        return self._items.pop() if self._items else None

    def peek(self) -> Optional[T]:
        return self._items[-1] if self._items else None

    def __len__(self) -> int:
        return len(self._items)

    def __bool__(self) -> bool:
        return bool(self._items)

    def __iter__(self) -> Iterator[T]:
        return iter(self._items)

    def __repr__(self) -> str:
        return f"Stack({self._items!r})"


s: Stack[int] = Stack()
s.push(1)
s.push(2)
print(s.pop(), s.peek(), len(s), bool(s), list(s))   # 2 1 1 True [1]
print(s.pop(), s.pop())                              # 1 None
print(bool(Stack()), list(Stack()))                  # False []

# 内部状态不再暴露：下面这行会直接 AttributeError
try:
    s.items
except AttributeError as e:
    print("封装生效:", e)

差异说明

问题 重构前 重构后 收益 代价
内部状态 items 公开，可随意改 _items 私有 不变量（后进先出）守得住 调试时要看私有属性
空栈 pop() 抛 IndexError 返回 None，类型写明 调用方不用 try 无法区分「空」和「存了 None」
长度 size() 自定义方法 __len__ len(s)、bool(s) 自动可用 需要额外实现 __bool__ 才不依赖 __len__
类型 无约束 Generic[T] + Optional[T] 静态检查能拦 push("a") 运行时仍是 Any，不会校验
迭代 只能 s.items __iter__ for、list()、解包都能用 返回迭代器后不再受栈操作影响
打印 默认对象地址 __repr__ 显示内容 日志可读 元素多时打印很长

再往前一步

区分「空」与「存了 None」需要一个哨兵对象（_MISSING = object()），或者干脆让 pop 在空栈抛自定义的 EmptyStack——库代码通常后者更安全，脚本代码前者更省事。再进一步：加 maxsize 做成有界栈（满时拒绝），或改用 collections.deque 让 popleft 也 O(1)（当队列用）。

单元验收

  • 泛型：写出 Stack[T] 与 first(Sequence[T])，mypy 通过
  • 结构类型：用 TypedDict + overload 描述一个真实 API 的输入输出
  • 运算符：Vector 支持 +、*、@、-，且 3 * v 可用
  • 一致性：相等、哈希、排序、+= 四项在一组测试里全部自洽
