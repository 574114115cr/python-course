序列协议：只写五个方法，白拿一整套序列行为

一个可以整段复制运行的完整程序 + 逐段讲解 + 真实输出。 先跑一遍，再对着输出读讲解，最后做文末的三处改动。

原书第 12 章用一个 FrenchDeck 和一个继承 MutableSequence 的类说明：实现序列的最小集合是五个方法，其余全部自动获得。这一篇把「白拿的」逐个点名验一遍。

程序

Pythonfrom collections.abc import MutableSequence


class Playlist(MutableSequence):
    """只实现 __getitem__ / __setitem__ / __delitem__ / __len__ / insert，其余靠基类。"""

    def __init__(self, items=()):
        self._items = list(items)

    def __getitem__(self, i):
        if isinstance(i, slice):
            return Playlist(self._items[i])       # 切片返回同类型，而不是 list
        return self._items[i]

    def __setitem__(self, i, value):
        self._items[i] = value

    def __delitem__(self, i):
        del self._items[i]

    def __len__(self):
        return len(self._items)

    def insert(self, i, value):
        self._items.insert(i, value)

    def __repr__(self):
        return f"Playlist({self._items})"


p = Playlist(["A", "B", "C"])
print("初始    ", p)

# ① 继承来的方法：append / extend / pop / remove / clear / reverse / count / index
p.append("D")
p.extend(["E", "F"])
print("append+ ", p)
print("pop     ", p.pop(), "| 剩", len(p), "首", p[0])
p.remove("B")
print("remove  ", p)
print("count   ", p.count("C"), "| index", p.index("C"))
p.reverse()
print("reverse ", p)

# ② 切片返回同类型：切片后还能继续用 Playlist 的方法
sub = p[0:2]
print("slice   ", sub, "| 是 Playlist？", isinstance(sub, Playlist))

# ③ 协议带来的：in / 迭代 / reversed / 排序视图
print("in      ", "C" in p, "| iter", list(p))
print("reversed", list(reversed(p)))

# ④ 鸭子类型：只要实现了协议，不继承也能当序列用
class Range3:
    def __len__(self):
        return 3

    def __getitem__(self, i):
        if i >= 3:
            raise IndexError(i)
        return (10, 20, 30)[i]


r = Range3()
print("鸭子    ", list(r), "| len", len(r), "| in", 20 in r)

# ⑤ 哪些是自己写的、哪些是白拿的
import collections.abc as abc
written = ["__init__", "__getitem__", "__setitem__", "__delitem__", "__len__",
           "insert", "__repr__"]
inherited = sorted({n for n in dir(Playlist) if not n.startswith("_")} - {"insert"})
print("自己写的", len(written), "个：", ", ".join(written))
print("白拿的  ", len(inherited), "个：", ", ".join(inherited))
print("继承链  ", [c.__name__ for c in Playlist.__mro__][:4])
print("抽象方法", sorted(Playlist.__abstractmethods__) or "无（都实现了）")

逐段走读

  1. 可变序列的最小集合是 5 个方法。 MutableSequence 要求 __getitem__、__setitem__、__delitem__、__len__、insert——其中 insert 是 append/extend/pop/remove/clear/+= 的基石，因为这几个方法在基类里都是用 insert 和 __delitem__ 实现的。只读序列（Sequence）更省：只要 __getitem__ 和 __len__。

  2. 切片必须返回同类型。 p[0:2] 返回 Playlist 而不是 list，这样切片结果还能用 append、还能再切片。原书把这条列为「序列的契约」之一：__getitem__ 收到 slice 时，返回值的类型应该和 self 一致（内置 list 也遵守，只是返回的仍是 list）。

  3. in、迭代、reversed 全是白拿的。 它们由 __getitem__ + __len__ 推导：in 靠逐个索引比较（除非你写 __contains__），迭代从 0 开始取到 IndexError（除非你写 __iter__），reversed 靠 __len__ 和 __getitem__ 倒着走（除非你写 __reversed__）。写不写优化版取决于热路径。

  4. 鸭子类型不要求继承。 Range3 只实现了 __len__ 与 __getitem__，list()、len()、in 全都能用。Python 的协议是「结构」而不是「名义」——但这也意味着 isinstance(r, Sequence) 为 False（没有注册），需要 Sequence.register(Range3) 或继承才认。

  5. 白拿的方法可能很慢。 基类的 __contains__ 是线性扫描后调用 __eq__；index() 也是线性；__iadd__ 会逐个 insert。数据量大时应该自己实现 __contains__（比如用内部 set 做索引）——「白拿」不等于「够用」。

  6. __abstractmethods__ 是检查继承是否完整的工具。 输出里显示「无（都实现了）」，说明五个必需方法都在。少写一个，实例化时会抛 TypeError: Can't instantiate abstract class，报错直接点名缺哪个方法。最后两行把「自己写的」和「白拿的」列了出来——白拿的那一串正是继承 MutableSequence 换来的收益。

跑通之后改三处

  • 删掉 insert：实例化 Playlist() 立刻抛 TypeError，报错里点名 insert。
  • 把切片的 Playlist(self._items[i]) 改成 self._items[i]：sub 变成普通 list，sub.append 虽然还能用，但类型契约断了。
  • 给 Range3 负下标：现在 r[-1] 会走 (10,20,30)[-1]，输出 30，但 r[-5] 会抛 IndexError——补齐负索引是自定义序列最容易漏的一条。
