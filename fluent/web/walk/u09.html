迭代器、生成器与控制流：从手写类到 yield from

一个可以整段复制运行的完整程序 + 逐段讲解 + 真实输出。 先跑一遍，再对着输出读讲解，最后做文末的三处改动。

原书第 17 章的主线：迭代器协议只有 __iter__ + __next__，但生成器把它变成了两行代码。这一篇用同一条需求（把嵌套结构拍平）走完四种写法，再比较它们的行为差异。

程序

Pythonimport itertools


# ① 手写迭代器：把协议显式写出来
class Countdown:
    def __init__(self, start):
        self.n = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1


print("迭代器  ", list(Countdown(3)), "| 一次性？", list(Countdown(3)) == [3, 2, 1])


# ② 生成器函数：同样的语义，三行
def countdown(start):
    while start > 0:
        yield start
        start -= 1


print("生成器  ", list(countdown(3)))

# ③ yield from：把嵌套列表拍平，递归交给 Python 自己的栈
def flatten(items):
    for x in items:
        if isinstance(x, list):
            yield from flatten(x)
        else:
            yield x


nested = [1, [2, [3, 4]], [[5]], 6]
print("flatten ", list(flatten(nested)))

# ④ 生成器是惰性的：消费多少算多少
def noisy():
    for i in range(5):
        print(f"  产出 {i}")
        yield i


print("惰性    ", next(noisy()), "（只产出一个就停了）")

# ⑤ 生成器也能当协程用：send 把值送进去，yield 把值送出来
def running_avg():
    total, count, avg = 0, 0, None
    while True:
        x = yield avg
        if x is None:
            break
        total += x
        count += 1
        avg = round(total / count, 2)


avg = running_avg()
next(avg)                     # 预激活：先跑到第一个 yield
print("协程    ", [avg.send(v) for v in (10, 20, 30)])

# ⑥ itertools：组合、切片、分组，都是惰性的
print("chain   ", list(itertools.chain("ab", "cd")))
print("islice  ", list(itertools.islice(itertools.count(10, 5), 4)))
print("groupby ", [(k, len(list(g))) for k, g in
                   itertools.groupby("aaabbc")])

# ⑦ for-else 与 break：循环没被打断时才走 else
def find_first_even(xs):
    for x in xs:
        if x % 2 == 0:
            return f"找到 {x}"
    else:
        return "没有偶数"


print("for-else", find_first_even([1, 3, 5]), "|", find_first_even([1, 3, 4]))

逐段走读

  1. 迭代器协议的两个方法各有分工。 __iter__ 返回迭代器本身（所以迭代器可以反复放进 for），__next__ 每次给一个值、耗尽时抛 StopIteration。for 循环本质就是反复调 __next__ 并捕获 StopIteration——这也是为什么 for 里手动 raise StopIteration 会被转成 RuntimeError（PEP 479，生成器里尤其常见）。

  2. 生成器函数「先定义、不执行」。 调用 countdown(3) 只是创建生成器对象，函数体一行都没跑；第一次 next() 才开始执行到第一个 yield。这个「懒启动」是后面所有特性的基础。

  3. yield from 一次性委托。 它等价于 for x in sub: yield x，但额外把 send/throw/close 转发给子生成器，还能拿到子生成器的 return 值。递归拍平用它是标准写法；写成手写循环也能跑，但少了异常与返回值的透传。

  4. 惰性是可见的。 第四段里 noisy() 只被取了一个值，打印只有一次「产出 0」。如果把生成器换成列表推导，五条会立刻全部打印——这就是内存与响应速度的差别。

  5. send 之前必须预激活。 刚创建的生成器停在函数开头，还没执行到 yield，此时 send 会抛 TypeError: can't send non-None value to a just-started generator。所以要先 next(avg) 一次。running_avg 用 yield avg 同时做「接收」和「输出」，这是协程的原型，也是 asyncio 的前身。

  6. itertools 全是惰性的。 chain 拼接、islice 截断（可以截无限序列）、groupby 分组（只合并相邻的相同键，所以分组前通常要 sorted）。三者都不会一次性把数据读进内存。

  7. for-else 里的 else 是「没被 break 打断」。 这里用 return 提前结束，所以 else 在找得到时不会执行。很多人把它当成「循环正常结束」的语法糖，实际上它的语义是「没有 break」。

跑通之后改三处

  • 把 flatten 的 yield from flatten(x) 改成 yield flatten(x)：输出里会出现 <generator object>，因为嵌套生成器没有被展开。
  • 去掉 next(avg) 直接 send：立刻抛 TypeError，验证「预激活」这一步不能省。
  • 把 itertools.groupby("aaabbc") 换成 groupby("abab")：输出会变成 4 组，因为 groupby 只合并相邻的相同键。
