asyncio：一个事件循环里同时等十件事

一个可以整段复制运行的完整程序 + 逐段讲解 + 真实输出。 先跑一遍，再对着输出读讲解，最后做文末的三处改动。

原书第 21 章讲异步编程。这一篇不碰网络，只用 asyncio.sleep 把「并发等待」这件事看清楚：任务、gather、信号量、超时、队列，五件套全部跑一遍。

程序

Pythonimport asyncio


async def fetch(i, delay):
    await asyncio.sleep(delay)          # 这里会把控制权交还事件循环
    return i


async def main():
    # ① 串行 vs 并发：同样的等待时间，总耗时差一个数量级
    t0 = asyncio.get_running_loop().time()
    for i in range(5):
        await fetch(i, 0.02)
    serial = asyncio.get_running_loop().time() - t0

    t0 = asyncio.get_running_loop().time()
    results = await asyncio.gather(*(fetch(i, 0.02) for i in range(5)))
    concurrent = asyncio.get_running_loop().time() - t0
    print("串行    ", round(serial * 1000), "ms | 并发", round(concurrent * 1000),
          "ms | 快一倍以上？", concurrent < serial * 0.5)
    print("结果    ", results)

    # ② create_task：任务在后台跑，await 时才收结果
    task = asyncio.create_task(fetch(99, 0.01))
    print("任务状态", task.done())
    print("任务结果", await task, "| 完成？", task.done())

    # ③ 信号量：限制同时进行的数量
    sem = asyncio.Semaphore(2)
    state = {"running": 0, "peak": 0}

    async def limited(i):
        async with sem:
            state["running"] += 1
            state["peak"] = max(state["peak"], state["running"])
            await asyncio.sleep(0.01)
            state["running"] -= 1
            return i

    order = await asyncio.gather(*(limited(i) for i in range(6)))
    print("信号量  ", order, "| 峰值并发", state["peak"])

    # ④ 超时：等不到就抛 TimeoutError，而不是把整个循环卡死
    try:
        await asyncio.wait_for(fetch(1, 0.3), timeout=0.05)
    except TimeoutError:
        print("超时    ", "TimeoutError（0.05s 内没等到）")

    # ⑤ 队列：生产者-消费者，天然的背压
    q = asyncio.Queue(maxsize=2)

    async def producer():
        for i in range(5):
            await q.put(i)
        await q.put(None)               # 结束信号

    async def consumer():
        got = []
        while True:
            item = await q.get()
            if item is None:
                return got
            got.append(item)

    got = await asyncio.gather(producer(), consumer())
    print("队列    ", got[1])

    # ⑥ 取消：任务可以被取消，CancelledError 会从等待点抛出
    slow = asyncio.create_task(fetch(7, 5))
    await asyncio.sleep(0.01)
    slow.cancel()
    try:
        await slow
    except asyncio.CancelledError:
        print("取消    ", "CancelledError | 已取消？", slow.cancelled())


asyncio.run(main())

逐段走读

  1. await 是「让出控制权」，不是「开线程」。 第一段里串行五次 20ms 等待要 100ms，gather 并发只要 20ms 左右——因为 asyncio.sleep 只是把当前协程挂起，事件循环转去跑别的协程。全程只有一个线程，没有任何并行计算。

  2. create_task 才真正「排进调度」。 直接写 await fetch(...) 会立刻等到结束；create_task 把协程包装成任务放进循环，后面的代码可以继续跑。要看任务是否完成用 done()，要拿结果用 await——注意未取结果的异常会以「Task exception was never retrieved」告警露出来。

  3. gather 不取消兄弟任务。 其中任何一个抛异常，gather 默认会把异常往上抛，但其他任务仍在后台跑。要「一个失败全取消」，用 asyncio.TaskGroup（3.11+），或者自己管理任务列表。

  4. 信号量是并发上限，不是限速器。 Semaphore(2) 保证最多两个协程同时进入临界区，第③段的「峰值并发 2」就是证据。它的典型用途是控制对下游的并发请求数，避免把对方打挂；要控制速率（每秒 N 个）得用令牌桶。

  5. 超时要加在等待点上。 wait_for 到期会取消被等待的协程并抛 TimeoutError。不加超时的异步代码最危险的地方在于：对端不响应时，整个任务会安静地挂着，日志里什么都没有。

  6. Queue 自带背压。 maxsize=2 时，生产者 put 到第 3 个就会挂起，直到消费者取走——这正是「慢消费者不要拖垮内存」的机制。结束信号用 None 是常见约定（也可以用哨兵对象）。

  7. 取消是协作式的。 cancel() 只是打个标记，真正的 CancelledError 在下一个 await 点抛出；如果协程正在跑一段没有 await 的密集计算，取消不会立刻生效。清理逻辑要放在 finally 里，否则取消会跳过 except 之后的收尾。

跑通之后改三处

  • 把 gather 换成 for i in range(5): await fetch(...)：耗时回到 100ms 左右，验证「并发」来自调度而不是魔法。
  • 把 Semaphore(2) 改成 Semaphore(1)：峰值并发变成 1，总耗时接近翻倍。
  • 把 wait_for 的 timeout=0.05 改成 1：不再抛超时，观察异常分支完全不触发。
