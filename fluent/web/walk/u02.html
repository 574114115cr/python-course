字典与文本：让 dict 学会「找不到时怎么办」

一个可以整段复制运行的完整程序 + 逐段讲解 + 真实输出。 先跑一遍，再对着输出读讲解，最后做文末的三处改动。

原书第 3 章的重心不是 dict 的 API，而是两个扩展点：__missing__ 决定查不到时做什么，__set_name__ 之外的规范化决定「看起来一样」是不是真的一样。

程序

Pythonimport unicodedata
from collections import Counter, defaultdict


class Config(dict):
    """带默认值的配置字典：查不到时按 key 的结构自动生成。"""

    def __missing__(self, key):
        if key.endswith("_list"):
            value = []
        elif key.endswith("_count"):
            value = 0
        else:
            raise KeyError(f"配置项不存在：{key}")
        self[key] = value          # 记住这次推断，下次直接命中
        return value


cfg = Config(host="localhost")
cfg["retries_count"] += 1
cfg["hosts_list"].append("10.0.0.1")
print("Config  ", dict(cfg))
try:
    cfg["nope"]
except KeyError as e:
    print("KeyError", e)

# ② 用 defaultdict 做分组：比 setdefault 少一次字典查找
rows = [("a", 1), ("b", 2), ("a", 3), ("c", 4), ("b", 5)]
grouped = defaultdict(list)
for k, v in rows:
    grouped[k].append(v)
print("grouped ", dict(grouped))

# ③ Counter：计数、取前 N、集合运算
words = "the quick brown fox jumps over the lazy dog the fox".split()
c = Counter(words)
print("Counter ", c.most_common(3))
print("集合运算", dict(Counter("banana") - Counter("band")))

# ④ 文本：看起来一样的字符串，可能不相等
a = "café"                                  # 预组合：é 是一个码位
b = unicodedata.normalize("NFD", a)         # 分解：e + 组合重音
print("码位数  ", len(a), len(b), "| 相等？", a == b, "| 规范化后？",
      unicodedata.normalize("NFC", b) == a)

# ⑤ 大小写折叠：casefold 比 lower 更彻底
print("lower   ", "Straße".lower(), "| casefold", "Straße".casefold())
name = "Straße"
print("查表    ", {name.casefold(): "德国街道"}[
    unicodedata.normalize("NFC", "STRASSE").casefold()])

逐段走读

  1. __missing__ 只在 __getitem__ 查不到时触发。 cfg["retries_count"] += 1 会先走 __missing__ 拿到 0，再加 1 写回——一次调用同时完成「推断默认值」和「写回」。注意 get()、in、[] 赋值的路径都不触发它，__missing__ 只在 d[key] 读不到时被调用。

  2. __missing__ 写回是策略选择。 这里 self[key] = value 让第二次访问直接命中；defaultdict 也是这么做的。如果不想污染原字典，就别写回——但那样每次访问都要重新构造。

  3. defaultdict(list) 与 setdefault(k, []) 的区别。 后者每次调用都会先构造一个空 list（哪怕 key 已存在），前者只在缺失时调用 list()。数据量大时这是实打实的开销差异。

  4. Counter 减法只保留正数。 Counter("banana") - Counter("band") 里 b 扣成 0、d 扣成 -1，两者都被丢掉，只剩 {'a': 2, 'n': 1}；要保留负数计数请用 subtract()。

  5. len(a) != len(b) 但两者肉眼一样。 预组合的 café 是 4 个码位，分解形式是 5 个（e + 组合重音）。所以「比较用户输入」前必须先 unicodedata.normalize("NFC", s)，否则同一个名字会有两种写法，登录、去重、建索引全都会出错。

  6. casefold() 是 lower() 的加强版。 ß 的 lower() 仍是 ß，casefold() 会变成 ss。做大小写无关的比较和键，一律用 casefold()；lower() 只在需要保留原字符形状时用。

跑通之后改三处

  • 把 __missing__ 里的 self[key] = value 删掉：cfg["retries_count"] += 1 仍然能算，但下次再访问又是 0——观察「写回」带来的差别。
  • 把 casefold() 换成 lower()：Straße 与 STRASSE 的查表立刻 KeyError。
  • 把 Counter("banana") - Counter("band") 换成 .subtract()：结果里会出现负数计数。
