单元导入

闭包是「函数记住定义环境」的能力，装饰器是「在不改函数体的前提下加行为」的语法。两者合起来，支撑了缓存、重试、权限校验、路由注册、日志埋点——几乎所有框架的入口都长这样。

本单元还会用一等函数重写两个经典设计模式。目的不是背模式，而是看清一件事：很多模式在 Python 里只需要一个函数或一个字典，不需要一整套类层级。

学完本单元，你应该能：

  • 画出闭包的 cell 结构，解释 nonlocal 为什么必要；
  • 徒手写出带参数、保留元数据、能处理异常的装饰器；
  • 正确使用 lru_cache、singledispatch、cached_property；
  • 用函数字典替代策略模式，用可调用对象替代命令模式。

第 17 课 · 闭包：捕获的是变量，不是值

讲解

闭包 = 函数 + 它引用的外层变量（cell）。外层函数返回后，这些变量仍然活着：

Pythondef make_counter(start=0):
    n = start

    def counter(step=1):
        nonlocal n
        n += step
        return n

    return counter

c = make_counter(10)
print(c(), c(5))        # 11 16
print(c.__closure__[0].cell_contents)   # 16

n += step 会赋值，所以必须声明 nonlocal n；不声明的话 Python 认为 n 是局部变量，抛 UnboundLocalError。

闭包捕获的是变量本身，不是创建时的值。这导致循环里的函数全部看到最后一个值：

Pythonfuncs = [lambda: i for i in range(3)]
print([f() for f in funcs])      # [2, 2, 2]

funcs = [lambda i=i: i for i in range(3)]   # 用默认参数固化
print([f() for f in funcs])      # [0, 1, 2]

延伸：闭包变量存在 closure 里

闭包把外层变量存在函数对象的 __closure__ 中，每一项是一个 cell：

Pythondef counter():
    n = 0
    def inc():
        nonlocal n
        n += 1
        return n
    return inc

c = counter()
c(); c()
print(c.__closure__[0].cell_contents)    # 2

nonlocal 只声明「最近一层」的外层变量：跨两层就要每层各写一次，或者干脆把状态放进 list/dict 里（改内容不算重新绑定，不需要 nonlocal）。只读外层变量不用声明，赋值才需要——忘了写会得到 UnboundLocalError，因为赋值让这个名字在整个函数里变成局部变量。

关键点

  • LEGB 顺序：Local → Enclosing → Global → Builtin；闭包变量在 Enclosing 层。
  • 只有「赋值」才需要 nonlocal；只读外层变量不需要声明。
  • 闭包持有引用，会延长对象生命周期；大量闭包 + 大对象要留意内存。
  • 延迟绑定是特性不是 bug：它让闭包能共享状态，但循环里要显式固化。

动手

  1. 写 make_accumulator()，连续调用累加，并打印 __closure__ 里的 cell 内容。
  2. 复现 [lambda: i for i in range(3)] 的陷阱，用两种方式修复（默认参数、functools.partial）。
  3. 写一个闭包版 rate_limiter(max_calls)，超过次数返回 False。

验收清单

  • 能解释闭包变量为什么在外层函数返回后仍然存在
  • 知道什么时候必须写 nonlocal
  • 能识别并修复循环中 lambda 的延迟绑定

第 18 课 · 装饰器：从注册到参数化

讲解

@deco 只是语法糖：

Python@deco
def f(): ...

# 等价于
def f(): ...
f = deco(f)

最小装饰器：

Pythonimport functools

def logged(fn):
    @functools.wraps(fn)          # 保留 __name__ / __doc__ / __wrapped__
    def wrapper(*args, **kwargs):
        print("call", fn.__name__, args, kwargs)
        return fn(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    return a + b

print(add(1, 2), add.__name__)    # 3 add

functools.wraps 不是可选项：没有它，被装饰函数的 __name__ 会变成 wrapper，FastAPI、click、pytest 这类靠签名和名字工作的框架会直接失效。

带参数的装饰器是「三层函数」：

Pythondef retry(times=3, exceptions=(Exception,)):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for i in range(times):
                try:
                    return fn(*args, **kwargs)
                except exceptions:
                    if i == times - 1:
                        raise
        return wrapper
    return deco

@retry(times=2)
def fetch():
    raise TimeoutError("boom")

注册型装饰器不需要包装函数，直接把函数存进注册表：

PythonHANDLERS = {}

def route(path):
    def deco(fn):
        HANDLERS[path] = fn
        return fn                # 原样返回，不包装
    return deco

@route("/ping")
def ping():
    return "pong"

延伸：用类写参数化装饰器，wraps 做了什么

三层嵌套（工厂 → 装饰器 → wrapper）可以用类压平，参数放 __init__、被装饰函数交给 __call__：

Pythonimport functools

class retry:
    def __init__(self, times=3):
        self.times = times
    def __call__(self, fn):
        @functools.wraps(fn)
        def wrapper(*a, **kw):
            for i in range(self.times):
                try:
                    return fn(*a, **kw)
                except Exception:
                    if i == self.times - 1:
                        raise
        return wrapper

functools.wraps 复制 __name__、__doc__、__module__、__dict__，并写入 __wrapped__ 指向原函数；inspect.signature 会顺着 __wrapped__ 拿到真实签名。所以漏写 wraps 的典型症状是：文档变 wrapper、路由注册参数丢失、框架读不到注解。用类实现的代价是实例不能被当函数直接调用两次以上的配置场景复用，看需求选。

关键点

  • 装饰器在导入时执行，不是调用时；不要在装饰器里做耗时操作。
  • 一定要 functools.wraps，否则签名、文档、名字全丢。
  • 多个装饰器从下往上包裹：@a @b def f 等价于 f = a(b(f))。
  • 注册型装饰器直接返回原函数，包装型才返回 wrapper；混用会导致重复注册或行为叠加。

动手

  1. 写 @timer，打印函数耗时，要求保留 __name__ 与 __doc__。
  2. 写 @retry(times=3, exceptions=(TimeoutError,))，用一个随机失败的函数验证。
  3. 写 @route(path) 注册 3 个处理函数，打印注册表并调用。

验收清单

  • 能手写带参数的装饰器，并解释三层函数各自的职责
  • 知道不加 functools.wraps 会造成什么具体故障
  • 能区分「包装型」与「注册型」装饰器

第 19 课 · 标准库装饰器：缓存、分派与惰性属性

讲解

functools.lru_cache 按参数缓存返回值，适合纯函数：

Pythonfrom functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

参数必须可哈希；maxsize=None 表示不淘汰，长期运行的服务要设上限，否则内存会涨。需要按对象身份缓存时用 functools.cache（3.9+，等价于 lru_cache(maxsize=None)）。

按类型分派用 singledispatch，避免一长串 isinstance：

Pythonfrom functools import singledispatch

@singledispatch
def render(x):
    raise TypeError(f"unsupported: {type(x)!r}")

@render.register
def _(x: int) -> str:
    return f"<b>{x}</b>"

@render.register
def _(x: list) -> str:
    return "<ul>" + "".join(f"<li>{i}</li>" for i in x) + "</ul>"

cached_property 把开销大的属性算一次后存进实例 __dict__，之后直接读：

Pythonfrom functools import cached_property

class Report:
    def __init__(self, rows):
        self.rows = rows

    @cached_property
    def total(self):
        print("computing...")
        return sum(self.rows)

延伸：lru_cache 的键与 singledispatch 的注册

Pythonfrom functools import lru_cache, singledispatch

@lru_cache(maxsize=128, typed=True)
def f(x): return x

f(1); f(1.0)
print(f.cache_info())      # misses=2，typed 区分 1 与 1.0

@singledispatch
def show(x): return "other"

@show.register
def _(x: int): return "int"

@show.register(str)
def _(x): return "str"

print(show(1), show("a"), show(1.5))    # int str other

maxsize=None 等价于 cache，无上限。参数必须可哈希，list 直接 TypeError。带副作用、依赖时间或外部状态的函数不能缓存；把 lru_cache 挂在实例方法上还会把 self 当键，导致实例不被回收——要么用类级别的缓存，要么自己管字典。

关键点

  • lru_cache 的键是参数的哈希，传 list/dict 会直接报错。
  • 缓存不会自动失效：数据变了要手动 cache_clear()，或改用带版本号的键。
  • singledispatch 只看第一个参数的类型，多参数分派要自己组合。
  • cached_property 需要实例有 __dict__，用 __slots__ 的类不支持。

动手

  1. 用 lru_cache 优化一个递归函数，比较加缓存前后的调用次数。
  2. 用 singledispatch 实现 to_json，支持 int、str、list、dict 四种类型。
  3. 用 cached_property 缓存一次数据库聚合结果，并手动实现一个 invalidate()。

验收清单

  • 知道 lru_cache 对参数的要求与内存风险
  • 能用 singledispatch 替代 5 个以上分支的 isinstance 链
  • 能解释 cached_property 与 property 的区别

第 20 课 · 用一等函数重构策略与命令模式

讲解

经典策略模式会定义 Strategy 基类和多个子类。在 Python 里，策略就是一个函数：

Pythondef bulk_price(qty, unit):
    return qty * unit * 0.9

def normal_price(qty, unit):
    return qty * unit

PRICING = {"bulk": bulk_price, "normal": normal_price}

def checkout(mode, qty, unit):
    try:
        rule = PRICING[mode]
    except KeyError:
        raise ValueError(f"unknown mode: {mode}") from None
    return rule(qty, unit)

ch.10 的电商示例还展示了用装饰器注册策略，把「新增一种折扣」变成「加一个函数 + 一个装饰器」，而不是改 if/elif。

命令模式适合「把操作变成对象」，因为对象能保存参数、能排队、能撤销：

Pythonclass Command:
    def __init__(self, text):
        self.text = text

    def execute(self):
        raise NotImplementedError

    def undo(self):
        raise NotImplementedError

class Append(Command):
    def __init__(self, doc, text):
        super().__init__(text)
        self.doc = doc

    def execute(self):
        self.doc.append(self.text)

    def undo(self):
        self.doc.pop()

延伸：撤销栈保存命令，不保存快照

命令模式把「一次操作」变成对象，好处是可排队、可记录、可撤销。用可调用对象实现最省：

Pythonclass Add:
    def __init__(self, x): self.x = x
    def __call__(self, acc): return acc + self.x
    def undo(self, acc): return acc - self.x

cmds = [Add(3), Add(5)]
acc = 0
for c in cmds: acc = c(acc)
print(acc)                              # 8
for c in reversed(cmds): acc = c.undo(acc)
print(acc)                              # 0

要点是成本差异：保存命令只占一条记录的字节，保存整份状态快照可能是几 MB。只有不可逆的操作（发邮件、扣库存、调第三方）才需要补偿动作或快照。设计时先问「这个操作能不能算逆运算」，能就别存快照。

关键点

  • 函数字典的键要是可控枚举，不要用用户输入直接查表。
  • 策略函数要签名一致，否则调用方还得判断；可以用 Protocol 约束（第 7 单元）。
  • 命令对象的价值在「可存储、可撤销、可组合」，不需要这些能力就别上类。
  • 模式是手段不是目标：Python 里能用函数、字典、functools 解决的，不要硬套类层级。

动手

  1. 把一段 6 个分支的 if mode == ... 计费代码改成函数字典，并加一个未知模式的明确异常。
  2. 用装饰器实现策略注册：@pricing("bulk") 自动写入 PRICING。
  3. 实现 Append / Undo 两个命令，用一个栈支持连续撤销。

验收清单

  • 能把策略分支重构为函数字典，并保持异常信息清晰
  • 能说出命令模式相比直接调函数的三个额外能力
  • 能判断一个场景「不需要设计模式」，并说明理由

综合案例：计时、重试、注册：三个装饰器把样板代码收掉

一个抓取任务：要计时、失败要重试、函数要能被插件表找到。先手写，再抽成装饰器。

重构前（每个调用点复制一遍）

计时用 time.time() 前后夹，重试用 for + try，注册靠手工往字典里塞。三处调用就有三份几乎一样的代码，改一处忘两处。

Pythonimport time

REGISTRY = {}


def fetch(name, fail_times=2):
    """模拟不稳定接口：前 fail_times 次失败。"""
    state = {"n": 0}

    def call():
        state["n"] += 1
        if state["n"] <= fail_times:
            raise OSError("transient")
        return f"{name}:ok"

    start = time.perf_counter()
    result = None
    for i in range(3):
        try:
            result = call()
            break
        except OSError:
            if i == 2:
                raise
    print(f"fetch {name} took {time.perf_counter() - start:.4f}s")
    return result


def summarize(text):
    state = {"n": 0}

    def call():
        state["n"] += 1
        if state["n"] <= 1:
            raise ValueError("flaky")
        return text.upper()

    start = time.perf_counter()
    out = None
    for i in range(3):
        try:
            out = call()
            break
        except ValueError:
            if i == 2:
                raise
    print(f"summarize took {time.perf_counter() - start:.4f}s")
    return out


REGISTRY["fetch"] = fetch
REGISTRY["summarize"] = summarize

print(fetch("a"))
print(summarize("hi"))
print(sorted(REGISTRY))

重构后（三个装饰器，各管一件事）

timed 用 finally 保证异常也记录耗时；retry 只重试指定异常并最后一次必须抛出；register 只登记、不包装，所以名字和签名都是原样。

Pythonimport functools
import time

REGISTRY = {}


def timed(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            print(f"{fn.__name__} took {time.perf_counter() - start:.4f}s")
    return wrapper


def retry(times=3, exc=Exception, backoff=0.0):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for i in range(times):
                try:
                    return fn(*args, **kwargs)
                except exc:
                    if i == times - 1:
                        raise
                    if backoff:
                        time.sleep(backoff * (2 ** i))
        return wrapper
    return deco


def register(name=None):
    def deco(fn):
        REGISTRY[name or fn.__name__] = fn
        return fn                  # 只登记，不包装
    return deco


_calls = {"n": 0}


@register("fetch")
@timed
@retry(times=3, exc=OSError)
def fetch(name):
    _calls["n"] += 1
    if _calls["n"] <= 2:
        raise OSError("transient")
    return f"{name}:ok"


@register("summarize")
@timed
@retry(times=2, exc=ValueError)
def summarize(text):
    return text.upper()


print(fetch("a"))          # fetch took 0.0000s / a:ok
print(summarize("hi"))     # summarize took 0.0000s / HI
print(sorted(REGISTRY))
print(fetch.__name__)      # fetch，wraps 保住了名字

差异说明

问题 重构前 重构后 收益 代价
计时 每个函数前后各写一遍 @timed 一行 不会漏、不会忘 finally 多一层函数调用
重试 for + try 复制 @retry(times=3, exc=OSError) 只捕指定异常，参数可调 重试策略藏在装饰器里，读代码要跳一次
失败语义 三处各自写 if i == 2: raise 统一在装饰器里抛最后一次 不会静默返回 None 无
注册 手工 REGISTRY[...] = f @register("fetch") 定义即注册，顺序无依赖 隐式副作用，导入即执行
元信息 名字、文档全丢（若包装过） functools.wraps 全保留 日志、路由、调试都正常 无
叠放顺序 不存在这个概念 register 最外层、retry 最内层 重试只影响一次业务调用 顺序写反会重复计时或重复注册

再往前一步

给 retry 加「只对幂等操作重试」的说明与 jitter（随机抖动），避免大量客户端同时重试打爆对方；把 REGISTRY 换成 __init_subclass__ 自动登记（单元 12 会做），注册就从「装饰函数」升级为「定义类即注册」。注意装饰器栈顺序：@register 放最外面，注册到的才是最终可调用对象。
