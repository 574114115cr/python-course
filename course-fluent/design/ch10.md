@@ch10|设计模式
> 很多 GoF 模式在 Python 里被语言特性吸收了，不需要照搬类图。

| 项 | 内容 |
|---|---|
| 选择 | 用语言特性替代模式：函数替代策略/命令，模块替代单例，`__getattr__` 替代代理 |
| 主要替代 | 严格照搬 Java 式类层次（策略接口、命令基类、单例类） |
| 替代为何落选 | 多出来的类没有带来约束力，只带来缩进 |
| 付出的代价 | 「模式名」不再出现在代码里，新人可能认不出意图 |

## 当时的约束

GoF 成书于 C++/Java 时代，很多模式是为了绕开「函数不是对象」「没有闭包」「不能动态加方法」这些限制。Python 没有这些限制。

## 候选方案

一是照搬类图，二是用函数/模块/协议重新表达，三是用装饰器或元类做框架级实现。选第二条：能用一个函数解决的，不写三个类。

## 为什么选它

因为 Python 的「策略」就是可调用对象，「命令」就是带 `__call__` 的实例，「单例」就是模块，「观察者」就是回调列表。少一层抽象，测试和调试都更直接。

## 代价与反例

代码里看不到 `Strategy` 这种名字，意图要靠命名表达（`pricing_rule`、`on_event`）。反过来，硬套模式会得到 `AbstractStrategyFactoryImpl` 这类空壳。

## 如果重来

先问「语言有没有现成机制」，没有再上模式；用模式时在注释里写清它对应哪个问题，而不是只写模式名。
