@@ch04|文本与字节序列
> `str` 是码位序列，`bytes` 是字节序列，两者之间只能显式转换。

| 项 | 内容 |
|---|---|
| 选择 | Python 3 把文本与字节彻底分开，`str` 不带编码 |
| 主要替代 | Python 2 的 `unicode`/`str` 双类型 + 隐式 ASCII 转换 |
| 替代为何落选 | 隐式转换在非 ASCII 上静默出错，错误点常常离原因很远 |
| 付出的代价 | 每次 IO 都要指定编码；老代码迁移成本高 |

## 当时的约束

Python 2 里 `str` 是字节，`unicode` 是文本，混用时按 ASCII 隐式解码。只要数据里出现一个中文，就会在某个不相关的位置抛 `UnicodeDecodeError`。

## 候选方案

继续隐式转换、只保留字节、彻底分离。选彻底分离：`str` 永远是无编码的码位序列，`bytes` 永远是字节，边界处必须 `encode`/`decode`。

## 为什么选它

因为错误被推到了边界：读文件、收 socket、解析协议时就要决定编码，而不是在业务逻辑深处炸。这也让「文本」这个概念第一次在语言层面干净了。

## 代价与反例

每个文件、每个网络请求都要想编码；`open()` 的默认编码跟平台走（3.15 起统一 UTF-8）。文件名还有第三套编码（`os.fsencode` 的 `surrogateescape`），不是 UTF-8。

## 如果重来

仍然分离，但会把「打开文件必须显式 `encoding=`」写进代码审查清单，并默认用 `errors="strict"` 暴露问题而不是 `ignore`。
