# 单元 3 综合案例 · 订单模型：可变数据类改不出来，换成值语义

> 订单要能打折，但打完折的订单不能影响原订单——先看看可变数据类会怎么坑人。

### 重构前（能跑但会互相污染）

`@dataclass` 默认可变，`apply_discount` 直接改 `line.price`。看起来「省了一次复制」，实际把历史订单也改了：

```python
from dataclasses import dataclass, field


@dataclass
class Line:
    sku: str
    qty: int
    price: float


@dataclass
class Order:
    oid: str
    lines: list = field(default_factory=list)

    @property
    def total(self):
        return round(sum(l.qty * l.price for l in self.lines), 2)

    def apply_discount(self, rate):
        for l in self.lines:                 # 直接改，原订单跟着变
            l.price = round(l.price * (1 - rate), 2)
        return self


o = Order("A1", [Line("apple", 2, 3.5), Line("pear", 1, 4.0)])
print(o.total)                               # 11.0

o.apply_discount(0.1)
print(o.total)                               # 9.9

replay = Order("A1", o.lines)                # 想重建原单，拿到的是改过的行
print(replay.total)                          # 9.9，不是 11.0

bad = Line("pear", 0, 4.0)                   # 数量 0 也照收
print(bad.sku, bad.qty, bad.price)
```

### 重构后（不可变 + 构造时校验）

`frozen=True` 冻结赋值、`slots=True` 去掉实例字典、行用 `tuple` 保证「改不动」。改价不原地改，用 `dataclasses.replace` 生成新订单：

```python
from dataclasses import dataclass, field, replace


class InvalidOrder(ValueError):
    pass


@dataclass(frozen=True, slots=True)
class Line:
    sku: str
    qty: int
    price: float

    def __post_init__(self):
        if self.qty <= 0:
            raise InvalidOrder(f"qty must be positive: {self.qty}")
        if self.price < 0:
            raise InvalidOrder(f"price must be >= 0: {self.price}")

    @property
    def amount(self):
        return round(self.qty * self.price, 2)

    def with_price(self, price):
        return replace(self, price=price)


@dataclass(frozen=True, slots=True)
class Order:
    oid: str
    lines: tuple = field(default_factory=tuple)

    def __post_init__(self):
        if not self.oid:
            raise InvalidOrder("oid is required")

    @property
    def total(self):
        return round(sum(l.amount for l in self.lines), 2)

    def with_discount(self, rate):
        if not 0 <= rate < 1:
            raise InvalidOrder(f"rate out of range: {rate}")
        new_lines = tuple(l.with_price(round(l.price * (1 - rate), 2))
                          for l in self.lines)
        return replace(self, lines=new_lines)


o = Order("A1", (Line("apple", 2, 3.5), Line("pear", 1, 4.0)))
d = o.with_discount(0.1)
print(o.total, d.total)              # 11.0 9.9，原单没被改
print(o.lines[0].price, d.lines[0].price)   # 3.5 3.15

try:
    Line("pear", 0, 4.0)
except InvalidOrder as e:
    print("rejected:", e)            # rejected: qty must be positive: 0
```

### 差异说明

| 问题 | 重构前 | 重构后 | 收益 | 代价 |
|---|---|---|---|---|
| 打折副作用 | 原地改 `l.price`，原订单被污染 | `replace` 生成新订单 | 历史订单、撤销、回放都成立 | 每次打折多复制一层 |
| 容器类型 | `list`，外部拿到就能改 | `tuple`，改不了 | `frozen` 才真的冻住 | 追加行要重建整个元组 |
| 非法数据 | 数量 0、负价都能构造 | `__post_init__` 直接抛 | 脏数据进不了系统 | 构造开销略增 |
| 错误类型 | 没有专用异常，调用方只能捕 `ValueError` | `InvalidOrder(ValueError)` | 可精确捕获，又能被通用处理兜住 | 多一个类 |
| 内存 | 每实例一个 `__dict__` | `slots=True` 省掉 | 大量订单时省内存 | 不能动态加属性 |
| 变价方式 | 直接赋值 | `with_price()` 表达意图 | 调用点看得懂在做什么 | 方法变多 |

### 再往前一步

金额别用 `float`：`0.1 + 0.2 != 0.3`，累加几十行就会差几分钱。把 `price` 换成 `Decimal`（构造时传字符串），并在 `amount` 里做 `quantize(Decimal("0.01"))`。再进一步是按「分」存整数，展示时再除 100，这是支付系统的通行做法。
