# 单元 4 综合案例 · 文本清洗流水线：三个 if 改不出来的组合

> 清洗 → 替换 → 截断，今天三步，明天五步，顺序还要能换。先写死，再抽成流水线。

### 重构前（能跑但只能这样跑）

三步写在一个函数里，用三个布尔开关控制。想加一步就得改函数签名，想换顺序只能改函数体，别处想复用其中一步也拿不到。

```python
CONFIG = {"strip": True, "punct": True, "limit": 16}


def clean(text, cfg=CONFIG):
    if cfg["strip"]:
        text = " ".join(text.split())
    if cfg["punct"]:
        text = text.replace("，", ",").replace("。", ".")
    if cfg["limit"] and len(text) > cfg["limit"]:
        text = text[:cfg["limit"] - 1] + "…"
    return text


print(clean("  hello   世界，Python 很好看 。  "))
print(clean("a，b", {"strip": False, "punct": False, "limit": 0}))
print(clean("a，b", {"strip": True, "punct": True, "limit": 0}))

# 想「先截断再统一标点」？没有开关能做到，只能再写一个函数。
def clean_reversed(text):
    text = " ".join(text.split())
    if len(text) > 16:
        text = text[:15] + "…"
    return text.replace("，", ",").replace("。", ".")
```

### 重构后（步骤即函数，顺序即列表）

每个步骤是 `str -> str` 的可调用对象，`pipeline()` 把它们串起来。带参数的步骤用闭包生成，顺序由列表决定——想换顺序就换列表。

```python
from typing import Callable, Iterable

Step = Callable[[str], str]


def strip_ws(s: str) -> str:
    return " ".join(s.split())


def collapse_punct(s: str) -> str:
    return s.replace("，", ",").replace("。", ".")


def clip(n: int) -> Step:
    if n <= 1:
        raise ValueError(f"n must be > 1: {n}")

    def step(s: str) -> str:
        return s if len(s) <= n else s[:n - 1] + "…"

    return step


def pipeline(steps: Iterable[Step]) -> Step:
    steps = tuple(steps)             # 固化：传生成器时只消费一次

    def run(s: str) -> str:
        for f in steps:
            s = f(s)
        return s

    return run


TEXT = "  hello   世界，Python 很好看 。  "

normal = pipeline([strip_ws, collapse_punct, clip(16)])
short = pipeline([strip_ws, clip(8), collapse_punct])

print(normal(TEXT))     # hello 世界,Python…
print(short(TEXT))      # hello 世…
print(pipeline([strip_ws])(TEXT))   # 只清空白，其余不动

# 步骤可单独复用，也可运行时拼装
extra = [strip_ws, clip(12)]
print(pipeline(extra + [collapse_punct])(TEXT))
```

### 差异说明

| 问题 | 重构前 | 重构后 | 收益 | 代价 |
|---|---|---|---|---|
| 增加步骤 | 改 `clean` 签名和函数体 | 往列表里加一个函数 | 开闭原则，不动老代码 | 步骤多了要有个地方登记 |
| 调整顺序 | 只能复制函数再改 | 换列表顺序 | 用配置表达意图 | 顺序错不会报错，只会结果错 |
| 复用单步 | 做不到，都藏在 `if` 里 | 每个 `str -> str` 都是公开函数 | 可单独测试、可组合 | 命名空间多几个函数 |
| 带参步骤 | 全局 `CONFIG` | 闭包 `clip(16)` | 每个实例无状态，可并存 | 闭包不好 pickle |
| 校验 | 没有 | `clip` 拒绝 `n <= 1` | 早失败 | 多几行 |
| 类型 | 无 | `Step` 别名 + 注解 | IDE 能提示、mypy 能查 | 需要维护别名 |
| 性能 | 一个函数内联，最快 | 每步一次函数调用 | 步骤多时开销可见 | 极热路径要重新内联 |

### 再往前一步

把 `Step` 升级成 `Callable[[str], str | None]`，`None` 表示「丢弃这条」，流水线就变成过滤器；再加一个 `tap(fn)` 步骤做无侵入打点（只观察不改值），排查时插进去、上线前摘掉。真做文本 ETL 时，每个步骤应该自带 `name` 和 `describe()`，这样失败时能报出「第 3 步 punct 失败」而不是一个光秃秃的异常。
