# 单元 8 综合案例 · 栈：从「裸列表」到带类型参数的容器

> 内部用 list 实现栈，先写成最顺手的样子，再看它怎么被外部改坏、怎么在空栈上崩。

### 重构前（内部状态全暴露）

`items` 是公开属性，外部可以直接 `append`、`clear`，绕过后进先出；空栈 `pop()` 抛 `IndexError`，调用方得自己 try；没有类型信息，`push("a")` 进 `list[int]` 也没人管。

```python
class Stack:
    def __init__(self):
        self.items = []

    def push(self, item):
        self.items.append(item)

    def pop(self):
        return self.items.pop()

    def size(self):
        return len(self.items)


s = Stack()
s.push(1)
s.push(2)
print(s.pop(), s.size())        # 2 1

try:
    Stack().pop()
except IndexError as e:
    print("空栈:", e)           # pop from empty list

print(len(s.items))             # 1：绕过 API 直接看内部
s.items.append(99)              # 绕过 push 插队
s.items.clear()                 # 直接清空，size 归零但没人知道
print(s.size())                 # 0

s.push("字符串也能进来")          # 没有类型约束
print(s.items)
```

### 重构后（封装 + 泛型 + 空栈语义）

内部列表改成 `_items`，对外只暴露方法；`pop` / `peek` 在空栈时返回 `None`（明确写进返回类型），并补 `__len__`、`__iter__`、`__bool__` 让它像内置容器。

```python
from typing import Generic, Iterator, Optional, TypeVar

T = TypeVar("T")


class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> Optional[T]:
        return self._items.pop() if self._items else None

    def peek(self) -> Optional[T]:
        return self._items[-1] if self._items else None

    def __len__(self) -> int:
        return len(self._items)

    def __bool__(self) -> bool:
        return bool(self._items)

    def __iter__(self) -> Iterator[T]:
        return iter(self._items)

    def __repr__(self) -> str:
        return f"Stack({self._items!r})"


s: Stack[int] = Stack()
s.push(1)
s.push(2)
print(s.pop(), s.peek(), len(s), bool(s), list(s))   # 2 1 1 True [1]
print(s.pop(), s.pop())                              # 1 None
print(bool(Stack()), list(Stack()))                  # False []

# 内部状态不再暴露：下面这行会直接 AttributeError
try:
    s.items
except AttributeError as e:
    print("封装生效:", e)
```

### 差异说明

| 问题 | 重构前 | 重构后 | 收益 | 代价 |
|---|---|---|---|---|
| 内部状态 | `items` 公开，可随意改 | `_items` 私有 | 不变量（后进先出）守得住 | 调试时要看私有属性 |
| 空栈 | `pop()` 抛 `IndexError` | 返回 `None`，类型写明 | 调用方不用 try | 无法区分「空」和「存了 None」 |
| 长度 | `size()` 自定义方法 | `__len__` | `len(s)`、`bool(s)` 自动可用 | 需要额外实现 `__bool__` 才不依赖 `__len__` |
| 类型 | 无约束 | `Generic[T]` + `Optional[T]` | 静态检查能拦 `push("a")` | 运行时仍是 `Any`，不会校验 |
| 迭代 | 只能 `s.items` | `__iter__` | `for`、`list()`、解包都能用 | 返回迭代器后不再受栈操作影响 |
| 打印 | 默认对象地址 | `__repr__` 显示内容 | 日志可读 | 元素多时打印很长 |

### 再往前一步

区分「空」与「存了 `None`」需要一个哨兵对象（`_MISSING = object()`），或者干脆让 `pop` 在空栈抛自定义的 `EmptyStack`——库代码通常后者更安全，脚本代码前者更省事。再进一步：加 `maxsize` 做成有界栈（满时拒绝），或改用 `collections.deque` 让 `popleft` 也 O(1)（当队列用）。
