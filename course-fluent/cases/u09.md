# 单元 9 综合案例 · CSV 流水线：一次性读进内存，还是逐行流过去

> 读一个「可能很大」的 CSV，过滤 + 改名 + 只取前几条。先写成列表版，再改成生成器管道。

### 重构前（全部读进内存再处理）

`splitlines()` 建一个列表，解析再用列表推导建第二个，过滤建第三个。文件 10 MB 时能看到内存翻三倍；文件比内存大时直接跑不动。收尾统计也只能等全部处理完。

```python
RAW = """id,name,score
1,ann,88
2,bob,95
3,cid,72
4,dee,59
5,eve,91
"""


def load(text):
    lines = text.strip().splitlines()
    header = lines[0].split(",")
    rows = []
    for line in lines[1:]:
        rows.append(dict(zip(header, line.split(","))))
    return rows


rows = load(RAW)
good = [r for r in rows if int(r["score"]) >= 60]
renamed = [{"id": int(r["id"]), "name": r["name"].title(), "score": int(r["score"])}
           for r in good]

print(len(rows), len(good), len(renamed))       # 5 4 4
for r in renamed[:2]:
    print(r)
print("avg", round(sum(r["score"] for r in renamed) / len(renamed), 1))   # avg 86.5
```

### 重构后（生成器管道 + 惰性截断）

每一段都是生成器：`rows` 逐行读、`scored` 逐条过滤、`stat` 边转发边累计。`islice` 只取前 2 条，后面的行根本不会被解析。

```python
import csv
import io
from itertools import islice

RAW = """id,name,score
1,ann,88
2,bob,95
3,cid,72
4,dee,59
5,eve,91
"""


def rows(text):
    yield from csv.DictReader(io.StringIO(text))


def scored(it, low=60):
    for r in it:
        score = int(r["score"])
        if score >= low:
            yield {"id": int(r["id"]), "name": r["name"].title(), "score": score}


def stat(it):
    n = 0
    total = 0
    try:
        for r in it:
            n += 1
            total += r["score"]
            yield r
    finally:
        # 无论是正常结束还是被 islice 提前关闭，都会执行
        print("count", n, "avg", round(total / n, 1) if n else 0)


pipe = stat(scored(rows(RAW)))
print(type(pipe).__name__)                 # generator，还没有读任何一行
for r in islice(pipe, 2):
    print(r)
pipe.close()          # 显式关闭：finally 立刻执行
# count 2 avg 91.5（只统计被消费的 2 条）

print("--- 全量 ---")
for r in stat(scored(rows(RAW))):
    pass                                    # count 4 avg 86.5
```

### 差异说明

| 问题 | 重构前 | 重构后 | 收益 | 代价 |
|---|---|---|---|---|
| 内存 | 列表 ×3，随文件线性增长 | 常数级（只留当前行） | 大文件、管道、网络流都能处理 | 只能遍历一次 |
| 首次输出 | 全部处理完才有结果 | 第一行立刻可用 | 可做进度、可提前停止 | 逻辑分散在多个生成器里 |
| 截断 | 先全部处理再切前 2 条 | `islice` 之后的行不解析 | 省掉 90% 的工作 | 要显式 `close()`，否则 `finally` 等到 GC 才跑 |
| 统计 | 最后统一算 | `finally` 里收尾 | 提前关闭也能拿到部分统计 | 统计范围是「被消费的部分」 |
| 解析 | 手写 `split(",")` | `csv.DictReader` | 引号、逗号、换行都正确 | 比 `split` 慢一点 |
| 错误定位 | 列表推导里一处异常，难知第几行 | 逐行处理，可带行号 | 报错能定位 | 需要在生成器里加计数器 |

### 再往前一步

给 `rows` 加行号与异常包装（`raise ValueError(f"line {i}: ...") from e`），让脏数据能定位；把 `stat` 换成独立聚合器，避免「边转发边打印」这种副作用。真跑大数据时，`csv.reader` 比 `DictReader` 快 30% 左右（少了建 dict），需要时用列下标访问。
