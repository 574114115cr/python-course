# 单元 7 综合案例 · 存储后端：用 if/else 分派，还是用接口收口

> 业务代码要能换存储：今天内存、明天文件。先写 if/else，再换成抽象基类。

### 重构前（一个类装两种后端）

`Store.kind` 决定走哪个分支，读写都要 `if` 一次。加第三种后端（Redis）时，每个方法都要再改一遍；调用方还得知道 `kind`。

```python
import json
import io


class Store:
    def __init__(self, kind="mem", stream=None):
        self.kind = kind
        self.data = {}
        self.stream = stream or io.StringIO()

    def put(self, key, value):
        if self.kind == "mem":
            self.data[key] = value
        elif self.kind == "file":
            self.data[key] = value
            self.stream.seek(0)
            self.stream.truncate()
            json.dump(self.data, self.stream, ensure_ascii=False)
        else:
            raise ValueError(f"unknown kind: {self.kind}")

    def get(self, key):
        if self.kind in ("mem", "file"):
            return self.data.get(key)
        raise ValueError(f"unknown kind: {self.kind}")


mem = Store("mem")
mem.put("u1", {"name": "Ann"})
print(mem.get("u1"))

f = Store("file")
f.put("u1", {"name": "Bob"})
print(f.get("u1"), f.stream.getvalue())

try:
    Store("redis").put("u1", {})
except ValueError as e:
    print("失败:", e)
```

### 重构后（ABC 定接口，两个实现各自负责）

`Storage` 只声明「必须有什么」，两个实现各自处理序列化。业务函数 `save_user` 只依赖抽象，连 `kind` 都不用知道。

```python
import io
import json
from abc import ABC, abstractmethod
from typing import Optional


class Storage(ABC):
    @abstractmethod
    def get(self, key: str) -> Optional[dict]:
        ...

    @abstractmethod
    def put(self, key: str, value: dict) -> None:
        ...


class MemoryStorage(Storage):
    def __init__(self):
        self._data = {}

    def get(self, key):
        return self._data.get(key)

    def put(self, key, value):
        self._data[key] = dict(value)


class StreamStorage(Storage):
    """把整表序列化到任意可写流，测试里用 StringIO，生产里换真文件。"""

    def __init__(self, stream=None):
        self._data = {}
        self._stream = stream or io.StringIO()

    def get(self, key):
        return self._data.get(key)

    def put(self, key, value):
        self._data[key] = dict(value)
        self._stream.seek(0)
        self._stream.truncate()
        json.dump(self._data, self._stream, ensure_ascii=False)
        return None

    def dump(self):
        return self._stream.getvalue()


def save_user(store: Storage, uid: str, name: str) -> dict:
    store.put(uid, {"name": name})
    found = store.get(uid)
    assert found is not None, "刚写进去的读不到"
    return found


mem = MemoryStorage()
print(save_user(mem, "u1", "Ann"))          # {'name': 'Ann'}

stream = io.StringIO()
disk = StreamStorage(stream)
print(save_user(disk, "u2", "Bob"))         # {'name': 'Bob'}
print(disk.dump())                          # {"u2": {"name": "Bob"}}

# 抽象类在实例化阶段就拦住「没实现完」的后端
try:
    class Half(Storage):
        def get(self, key):
            return None

    Half()
except TypeError as e:
    print("拒绝实例化:", str(e)[:60])
```

### 差异说明

| 问题 | 重构前 | 重构后 | 收益 | 代价 |
|---|---|---|---|---|
| 新增后端 | 每个方法加 `elif` | 新增一个 `Storage` 子类 | 不改老代码 | 多一个类 |
| 未实现完整 | 运行时才报 `unknown kind` | 实例化时 `TypeError` | 错误提前到启动 | 每加方法都要给实现 |
| 调用方耦合 | 要知道 `kind` 字符串 | 只依赖 `Storage` | 可替换、可 mock | 需要传对象而不是字符串 |
| 序列化 | 混在 `put` 的 `if` 里 | `StreamStorage` 自己负责 | 关注点分离 | 每个后端重复一点逻辑 |
| 存储位置 | 硬编码写流 | 构造时注入流 | 测试用 `StringIO`，生产换文件 | 生命周期要调用方管 |
| 未知后端 | 静默降级或运行时报错 | 类型系统挡住 | 早失败 | 需要类型检查器配合 |

### 再往前一步

把 `Storage` 换成 `Protocol`（只要求方法签名）：第三方类不用继承你的基类也能被接受，适合「接口是别人定的」场景；代价是实例化时不再有检查。再进一步加 `delete`、`keys()`、`__contains__`，并把「整表序列化」换成「追加日志 + 定期压缩」，避免每次写都重写全文件。
