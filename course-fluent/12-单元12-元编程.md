# 单元 12 · 元编程：动态属性、描述符与元类

> 教材第 22–24 章 ｜ 4 节课 × 90 分钟 ｜ 建议 2–4 周

## 单元导入

元编程听起来玄，其实只回答一个问题：**当 `obj.x` 被写出时，Python 到底做了什么？** 答案是一条固定的查找链：数据描述符 → 实例字典 → 非数据描述符 → 类属性 → `__getattr__`。

理解这条链，你就能看懂 ORM 的字段、Django 的 `models.CharField`、pytest 的 fixture、dataclass 的 `field()`，也能在「加一个通用机制」和「写一堆重复代码」之间做出正确选择。

学完本单元，你应该能：

- 用 `__getattr__` 处理运行时才知道的属性，用 `property` 做受控访问；
- 写出数据描述符与非数据描述符，解释它们与实例字典的优先级；
- 用 `__init_subclass__`、类装饰器注册子类，读懂简单元类；
- 判断什么时候**不该**用元类，改用更简单的机制。

> 本单元对应原书第 22–24 章。四节课覆盖主干机制；`__prepare__`、元类冲突、描述符与 `__slots__` 的交互等细节，需要回读对应小节。

## 第 45 课 · 动态属性：getattr、setattr 与 property

> 本节目标：能写出 `__getattr__` 兜底、`property` 受控属性，并说清 `__getattr__` 与 `__getattribute__` 的调用时机。

### 讲解

`__getattr__` 只在**常规查找失败后**调用，是兜底，不是拦截：

```python
class Config:
    def __init__(self, data):
        self._data = data

    def __getattr__(self, name):
        try:
            return self._data[name]
        except KeyError:
            raise AttributeError(name) from None

cfg = Config({"host": "localhost"})
print(cfg.host)       # localhost
print(cfg.port)       # AttributeError: port
```

注意 `__init__` 里访问 `self._data` 不能触发 `__getattr__` 递归：`_data` 已存在时不会进来，若不存在会无限递归。防御写法是在 `__getattr__` 开头判断 `name.startswith("_")` 并直接抛异常。

`__getattribute__` 拦截**所有**属性访问，风险高，除非写代理否则不要动。`property` 是更安全的受控访问：

```python
class Account:
    def __init__(self, balance):
        self._balance = balance

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("negative balance")
        self._balance = value
```

### 延伸：property 的三个角色与特性工厂

```python
class Temp:
    def __init__(self, c):
        self._c = c

    @property
    def c(self):
        return self._c

    @c.setter
    def c(self, v):
        if v < -273.15:
            raise ValueError("below absolute zero")
        self._c = v

    @c.deleter
    def c(self):
        del self._c
```

三者共享同一个名字，后定义的两个用 `@名字.setter` / `@名字.deleter`。只定义 getter 就是只读；只定义 setter 而没有 getter 会得到一个写不进也读不出的怪东西，别这么写。

特性工厂用闭包批量生成校验属性：

```python
def positive(name):
    def get(self):
        return getattr(self, "_" + name)
    def set(self, v):
        if v <= 0:
            raise ValueError(f"{name} must be positive")
        setattr(self, "_" + name, v)
    return property(get, set)

class Order:
    qty = positive("qty")
```

代价是 IDE 跳转和类型检查变弱，字段少时手写更清楚。字段多、校验规则一致时才值得上工厂。

### 关键点

- **`__getattr__` 只在找不到时调用**，已存在的属性不会进来。
- **`__getattribute__` 每次访问都调用**，容易死循环，慎用。
- **`property` 是数据描述符**，优先级高于实例字典，所以能真正拦住赋值。
- **`__getattr__` 里抛 `AttributeError`**，否则 `hasattr()` 会误判。

## 第 46 课 · 描述符：把属性访问变成可复用逻辑

> 本节目标：能写出数据描述符与非数据描述符，解释属性查找优先级，并用描述符实现一个「惰性属性」。

### 讲解

描述符是实现了 `__get__`、`__set__`、`__delete__` 中至少一个的类。它挂在**类**上，控制**实例**的属性访问。

```python
class Positive:
    def __set_name__(self, owner, name):
        self.name = "_" + name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.name)

    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError("must be positive")
        setattr(obj, self.name, value)

class Order:
    qty = Positive()
    price = Positive()
```

查找优先级（简化）：

1. 类型上的**数据描述符**（有 `__set__` 或 `__delete__`）
2. 实例 `__dict__`
3. 类型上的**非数据描述符**（只有 `__get__`）
4. 类属性
5. `__getattr__`

非数据描述符适合做惰性属性，因为第一次计算后写进实例字典，后续直接命中字典：

```python
class Lazy:
    def __init__(self, fn):
        self.fn = fn
        self.name = fn.__name__

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        value = self.fn(obj)
        setattr(obj, self.name, value)
        return value

class Report:
    @Lazy
    def total(self):
        print("computing")
        return 42
```

### 延伸：函数就是非数据描述符

函数只实现 `__get__`（没有 `__set__`），属于**非数据描述符**，被存在类上；实例访问时 `__get__` 返回绑定方法。这解释了两件事：

```python
class C:
    def m(self): return "method"

c = C()
print(c.m())                 # method
c.m = lambda: "instance"
print(c.m())                 # instance ← 实例字典盖住了方法
```

1. 为什么实例属性可以「盖住」方法（非数据描述符优先级低于实例字典）。
2. 为什么 `property` 盖不住（它是**数据**描述符，优先级最高）。

完整优先级：**数据描述符 > 实例字典 > 非数据描述符 > 类属性**。这条规则是所有「属性拦截」方案的地基：想拦住赋值就必须实现 `__set__`（或 `__delete__`）。

`__set_name__`（3.6+）在类创建时被调用，描述符靠它知道自己叫 `name`，不用再手动传名字：

```python
class Field:
    def __set_name__(self, owner, name):
        self.name = name
```

### 关键点

- **`property` 本身就是数据描述符**，所以它能覆盖实例字典。
- **数据描述符优先于实例字典**，非数据描述符不优先。
- **`__set_name__` 在类创建时调用**，用来拿到属性名，避免手写字符串。
- **描述符是类属性**，每个实例共享同一个描述符对象，状态要存在实例上。

### 动手

## 第 47 课 · 类元编程：__init_subclass__、类装饰器与元类

> 本节目标：能注册子类、校验类定义，读懂一个简单元类，并判断何时用 `__init_subclass__` 替代元类。

### 讲解

注册子类最轻的方式是 `__init_subclass__`：

```python
class Plugin:
    registry = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin.registry[cls.__name__] = cls

class JsonPlugin(Plugin):
    pass

print(Plugin.registry)     # {'JsonPlugin': <class ...>}
```

类装饰器同样能改类，但更灵活、更显式：

```python
def add_repr(cls):
    def __repr__(self):
        fields = ", ".join(f"{k}={v!r}" for k, v in vars(self).items())
        return f"{cls.__name__}({fields})"
    cls.__repr__ = __repr__
    return cls

@add_repr
class User:
    def __init__(self, name):
        self.name = name
```

元类在**类创建时**介入，能改命名空间、强制结构：

```python
class Meta(type):
    def __new__(mcls, name, bases, ns):
        if name != "Base" and "save" not in ns:
            raise TypeError(f"{name} must define save()")
        return super().__new__(mcls, name, bases, ns)

class Base(metaclass=Meta):
    pass

class User(Base):
    def save(self):
        ...
```

`__prepare__` 可以替换类命名空间（比如返回一个记录赋值顺序的 dict）。

### 延伸：type 是类工厂，__prepare__ 换命名空间

`type(name, bases, ns)` 三参数形式就是类工厂，`class` 语句本质是它的语法糖：

```python
def make(name, **attrs):
    return type(name, (), attrs)

P = make("P", x=1)
print(P.x, type(P))      # 1 <class 'type'>
```

元类里三个钩子的分工：

- `__prepare__(mcls, name, bases)`：决定类体写入哪个命名空间，默认普通 dict。返回 `OrderedDict` 或自定义映射就能记录定义顺序（早期 dataclass 这么干过），甚至做「禁止重复字段名」的检查。
- `__new__(mcls, name, bases, ns)`：真正造类，改类结构（加方法、收集字段）在这里做。
- `__init__(cls, name, bases, ns)`：类造好后的收尾，一般只做注册。

顺序是 `__prepare__` → 执行类体 → `__new__` → `__init__`。想「在类体执行时就拦截名字」只能用 `__prepare__` 返回自定义映射，`__new__` 已经太晚了。

### 关键点

- **`__init_subclass__` 足够解决 90% 的「注册/校验子类」需求**，优先用它。
- **类装饰器改的是已创建的类**，元类改的是创建过程。
- **一个类只能有一个元类**，冲突会直接报 `TypeError`。
- **元类是实现细节**，不要把它暴露成公开 API，否则使用者会被绑死。

## 第 48 课 · 综合验收：读懂框架的 200 行

> 本节目标：能在一个真实框架的核心模块里定位「描述符 / 元类 / `__getattr__`」三种机制，并说清它们各自解决了什么问题。

### 讲解

拿一个你常用的库，按下面顺序读：

1. **找入口**：`__init__.py` 导出了什么，公开 API 是哪几个名字。
2. **找类创建钩子**：搜 `metaclass=`、`__init_subclass__`、`__set_name__`。
3. **找属性访问钩子**：搜 `__getattr__`、`__getattribute__`、`__get__`。
4. **找注册表**：搜全局 dict / list，看谁往里写、谁从里读。
5. **画一张图**：用户写一行代码 → 触发了哪条链 → 最终落到哪个函数。

以 ORM 为例：`models.CharField()` 返回一个描述符；模型类创建时元类收集所有字段；实例访问 `user.name` 时描述符从数据库行里取值。三件事分别对应本单元的三节课。

把钩子和本课程对照起来看：

| 钩子 | 触发时机 | 典型库 | 对应课节 |
|---|---|---|---|
| `__get__` / `__set__` | 访问/赋值实例属性 | Django `Field`、SQLAlchemy `Column` | 第 46 课 |
| `__set_name__` | 类创建完成时 | `dataclasses.field`、ORM 字段 | 第 46 课 |
| `__getattr__` | 常规查找失败后 | 懒加载代理、配置对象 | 第 45 课 |
| `__init_subclass__` | 子类定义完成时 | 插件注册、校验基类 | 第 47 课 |
| 元类 | 类创建过程中 | Django `ModelBase`、pydantic `ModelMetaclass` | 第 47 课 |

把这三节课拼起来，就是一个能跑的最小 ORM：

```python
class Field:
    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, owner=None):
        if obj is None:
            return self
        return obj._data.get(self.name)

    def __set__(self, obj, value):
        obj._data[self.name] = value


class ModelMeta(type):
    def __new__(mcls, name, bases, ns):
        cls = super().__new__(mcls, name, bases, ns)
        fields = {}
        for base in bases:                       # 继承父类字段
            fields.update(getattr(base, "_fields", {}))
        fields.update({k: v for k, v in ns.items() if isinstance(v, Field)})
        cls._fields = fields
        return cls


class Model(metaclass=ModelMeta):
    def __init__(self, **kwargs):
        self._data = {}
        for k, v in kwargs.items():
            setattr(self, k, v)

    def __repr__(self):
        return f"{type(self).__name__}({self._data!r})"


class User(Model):
    name = Field()
    age = Field()


u = User(name="Ann", age=30)
print(u)              # User({'name': 'Ann', 'age': 30})
print(User._fields)   # {'name': <Field ...>, 'age': <Field ...>}
```

这段代码不到 40 行，但已经具备 ORM 的三个核心：字段描述符负责读写、元类负责收集字段、模型基类负责初始化。真实框架多出来的是 SQL 生成、关系映射、迁移，而不是另一套元编程。

### 延伸：四类钩子的检索法

拿到陌生框架，按四个关键词搜源码，基本能画出扩展点地图：

| 关键词 | 机制 | 典型用途 |
|---|---|---|
| `__get__` | 描述符 | 字段 / 属性拦截、惰性加载、ORM 列 |
| `__set_name__` | 类创建回调 | 字段注册、知道自己叫什么 |
| `__init_subclass__` | 子类定义回调 | 插件注册、自动加功能 |
| `metaclass=` | 元类 | 整类改造、接口约束 |

```python
class Plugin:
    registry = {}
    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        Plugin.registry[cls.__name__] = cls

class JsonPlugin(Plugin):
    pass

print(Plugin.registry)      # {'JsonPlugin': <class 'JsonPlugin'>}
```

`__init_subclass__` 是「不需要元类就能在子类定义时拿到钩子」的正规做法，1980 年代的元类需求里有一大半它能替代。判断该不该上元类：只需要「子类定义时做一件事」就用 `__init_subclass__`；需要改类的创建过程本身（换命名空间、改 `__call__`）才用元类。

读框架的顺序：先找钩子 → 再顺着钩子看调用链 → 最后才读工具函数。看不懂就先写 20 行最小复现，把框架剥到只剩钩子。

### 关键点

- **先看公开 API，再看实现**，不要一头扎进工具函数。
- **钩子比流程重要**：找到钩子，就找到了框架的扩展点。
- **画调用链**比读注释有效，尤其是元编程代码。
- **看不懂时先写最小复现**，把框架剥到 20 行。
