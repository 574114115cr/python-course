@@u04|一等函数：把函数当数据，拼一条处理管线
> 原书第 7 章的主线是「函数是一等对象」：能赋值、能当参数、能返回、能存进表。这一篇用一条文本处理管线把这四件事全部用上，顺带把类型提示写进去。

## 程序

```python
import functools
import operator
from typing import Callable, Iterable, Iterator

Pipeline = Callable[[str], str]


# ① 函数就是值：三个小函数存进列表和字典
def strip(s: str) -> str:
    return s.strip()


def squeeze(s: str) -> str:
    return " ".join(s.split())


def lower(s: str) -> str:
    return s.casefold()


def compose(*fns: Pipeline) -> Pipeline:
    """从右到左组合：compose(f, g)(x) == f(g(x))。"""
    return functools.reduce(lambda f, g: lambda x: f(g(x)), fns, lambda x: x)


clean = compose(lower, squeeze, strip)          # 右→左：先 strip，再 squeeze，最后 lower
raw = "   Hello   WORLD  \t"
print("compose ", repr(clean(raw)))

# ② 高阶函数：把函数当参数传
def apply_all(s: str, fns: Iterable[Pipeline]) -> str:
    for f in fns:
        s = f(s)
    return s


print("从左    ", repr(apply_all(raw, [strip, squeeze, lower])))

# ③ 用 operator / itemgetter 代替 lambda：更快也更可读
rows = [
    {"name": "键盘", "price": 299, "stock": 12},
    {"name": "鼠标", "price": 89, "stock": 0},
    {"name": "显示器", "price": 1299, "stock": 3},
]
by_name = sorted(rows, key=operator.itemgetter("name"))
in_stock = list(filter(lambda r: r["stock"] > 0, rows))
prices = list(map(operator.itemgetter("price"), rows))
print("排序    ", [r["name"] for r in by_name])
print("filter  ", [r["name"] for r in in_stock])
print("map     ", prices, "| 总和", functools.reduce(operator.add, prices))

# ④ partial：固定前几个参数，得到新的可调用对象
def fmt(tpl: str, *, name: str, price: int) -> str:
    return tpl.format(name=name, price=price)


cheap = functools.partial(fmt, "<{name}> ¥{price}")
print("partial ", cheap(name="鼠标", price=89))

# ⑤ 函数返回函数：闭包记住外层变量
def make_tagger(prefix: str) -> Callable[[str], str]:
    return lambda s: f"{prefix}{s}"


tag = make_tagger("SKU-")
print("返回函数", tag("A1"), tag("B2"))

# ⑥ 可调用对象与函数在调用语法上等价
class Doubler:
    def __call__(self, n: int) -> int:
        return n * 2


print("callable", list(map(Doubler(), [1, 2, 3])), "| 可调用？", callable(Doubler()))

# ⑦ 迭代器协议：生成器让管线可以惰性处理
def take(n: int, it: Iterable[str]) -> Iterator[str]:
    for i, x in enumerate(it):
        if i >= n:
            return
        yield x


gen = (x.strip() for x in [" a ", " b ", " c ", " d "])
print("惰性    ", list(take(2, gen)))
```

## 逐段走读

1. **`compose` 的方向要先说清楚。** `compose(a, b, c)(x)` 等价于 `a(b(c(x)))`——最右边的先执行。所以 `compose(lower, squeeze, strip)` 的阅读顺序和书写顺序相反，这正是很多人写组合函数时踩的坑；如果想让代码从左往右读，就用第二段的 `apply_all`。

2. **`functools.reduce` 的初始值不能忘。** `reduce(f, fns, lambda x: x)` 里的第三个参数是起始值（恒等函数）。不给初始值时，空序列会抛 `TypeError`，而且首元素会被当成累加器，语义容易错。

3. **`operator.itemgetter("name")` 与 `lambda r: r["name"]` 的区别在速度，不在功能。** `itemgetter` 是 C 实现，`sorted` 内部大量调用 key 时省下的时间很可观（实测页里 `itemgetter` 比 lambda 快约 13%）。同理 `operator.add` 比 `lambda a, b: a + b` 快。

4. **`partial` 是「预填参数」，不是「新建函数」。** 它返回的对象保存了原函数和已填的参数，调用时把剩余参数接上。好处是签名清晰、可序列化；坏处是 `__name__` 之类的元信息会丢，调试时要留意。

5. **闭包记住的是变量，不是值。** `make_tagger("SKU-")` 返回的 lambda 引用外层的 `prefix`，每次调用 `make_tagger` 都会生成一个独立的作用域，所以两个 tagger 互不干扰；如果在外层循环里创建闭包并延迟调用，就会踩到「都引用同一个变量」的经典坑。

6. **`callable()` 只看有没有 `__call__`。** 类和函数都是可调用对象，所以 `map(Doubler(), ...)` 和 `map(doubler, ...)` 写法一致。这也是为什么「策略模式」在 Python 里常常不需要类——一个函数就够了。

7. **生成器让管线惰性。** `take(2, gen)` 只消费前两项，后面的字符串根本没被 `strip`。这一点和列表推导的本质区别在于：前者是「按需生产」，后者是「先全算完」。数据大或源无限时，这是唯一可行的写法。

## 运行输出

```text
compose  'hello world'
从左     'hello world'
排序     ['显示器', '键盘', '鼠标']
filter   ['键盘', '显示器']
map      [299, 89, 1299] | 总和 1687
partial  <鼠标> ¥89
返回函数 SKU-A1 SKU-B2
callable [2, 4, 6] | 可调用？ True
惰性     ['a', 'b']
```

## 跑通之后改三处

- 把 `compose(lower, squeeze, strip)` 改成 `compose(strip, squeeze, lower)`：输出会变成小写但保留首尾空格——顺序错的典型表现。
- 把 `operator.itemgetter("price")` 换成 `lambda r: r["price"]`：结果一样，用实测页的脚本量一下差距。
- 把 `take` 里的 `yield` 改成 `return`：函数立刻不再是生成器，`list(take(2, gen))` 会抛 `TypeError`（`NoneType` 不可迭代）。
