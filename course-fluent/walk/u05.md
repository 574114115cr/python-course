@@u05|闭包与装饰器：把「重试、计时、缓存」写成可叠加的壳
> 原书第 9 章的核心不是 `@` 语法，而是「装饰器 = 接受函数、返回函数的高阶函数」这一句话。这一篇手写三个：计时、重试、缓存，然后叠在一起。

## 程序

```python
import functools
import time


# ① 最朴素的装饰器：不传参，包一层，用 wraps 保住元信息
def clock(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        result = fn(*args, **kwargs)
        return result, round((time.perf_counter() - t0) * 1000, 3)
    return wrapper


# ② 带参数的装饰器：外面再套一层，返回真正的装饰器
def retry(times=3, on=(ValueError,)):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            last = None
            for i in range(1, times + 1):
                try:
                    return fn(*args, **kwargs), i
                except on as e:                 # 只重试指定异常
                    last = e
            raise last
        return wrapper
    return deco


# ③ 缓存装饰器：手写一份，看清楚 lru_cache 到底省了什么
def memo(fn):
    cache = {}

    @functools.wraps(fn)
    def wrapper(n):
        if n not in cache:
            cache[n] = fn(n)
        return cache[n], len(cache)            # 顺便把缓存大小暴露出来
    return wrapper


@clock
def slow_double(x):
    time.sleep(0.01)
    return x * 2


@retry(times=3)
def flaky(attempts):
    """前两次抛错，第三次成功。"""
    flaky.state = getattr(flaky, "state", 0) + 1
    if flaky.state < attempts:
        raise ValueError(f"第 {flaky.state} 次失败")
    return "ok"


@memo
def fib(n):
    return n if n < 2 else fib(n - 1)[0] + fib(n - 2)[0]


print("clock   ", slow_double(21))
print("retry   ", flaky(3))
fib(10)
print("memo    ", fib(20)[0], "| 缓存条目", fib(20)[1])
print("wraps   ", slow_double.__name__, "|", flaky.__doc__)
```

## 逐段走读

1. **装饰器只做两件事：接受一个函数、返回一个函数。** `@clock` 等价于 `slow_double = clock(slow_double)`。理解这一句之后，「带参数的装饰器」就只是「先调用一次拿到装饰器，再应用到函数上」——也就是 `retry(times=3)` 先返回 `deco`，再由 `deco` 去包装 `flaky`。

2. **`functools.wraps` 不是装饰性代码。** 它会复制 `__name__`、`__doc__`、`__module__`、`__wrapped__`，让被包的函数在日志、`help()`、调试器和类型检查里仍然像原来那个。最后一行输出就是在验证：名字还是 `slow_double`，文档还是原来那句。

3. **`*args, **kwargs` 是包装器的通用壳。** 不写死参数列表，任何函数都能被包；代价是签名信息丢失（`inspect.signature` 需要靠 `__wrapped__` 还原），所以给库写装饰器时最好用 `functools.wraps` 并考虑 `ParamSpec`。

4. **带参数的装饰器多一层，作用是「配置」。** `retry(times=3, on=(ValueError,))` 把「重试几次」「重试哪些异常」变成参数；只捕获指定异常很关键——把所有异常都重试，会把 `KeyboardInterrupt` 和编程错误一起吞掉。

5. **缓存装饰器靠闭包里的 `cache` 字典。** 每次调用 `memo(fn)` 都会生成一个新的 `cache`，所以不同的 `@memo` 函数互不共享。标准库的 `lru_cache` 额外做了：按容量淘汰、按参数类型区分（`1` 与 `1.0` 的 key 相同但类型不同）、线程安全。

6. **递归 + 缓存是「自顶向下」的加速。** `fib` 不带缓存是指数级，带上缓存是线性——注意递归里调用的是装饰后的 `fib`，所以每一层都会查缓存，这正是它能从 2^n 掉到 n 的原因（实测页 u5 有对比数字）。

7. **装饰顺序有语义。** 如果写 `@clock` 在 `@retry` 外层，计时会把三次重试的时间一起算进去；反过来只算每次尝试。叠加装饰器时，从下往上应用、从上往下生效，这一点和数学里的函数复合一致。

## 运行输出

```text
clock    (42, 10.172)
retry    ('ok', 3)
memo     6765 | 缓存条目 21
wraps    slow_double | 前两次抛错，第三次成功。
```

## 跑通之后改三处

- 把 `@functools.wraps(fn)` 从 `clock` 里删掉：`slow_double.__name__` 变成 `wrapper`，最后一行立刻暴露。
- 把 `retry` 的 `on=(ValueError,)` 改成 `on=(Exception,)`：行为不变，但试着让它捕获 `KeyError` 之外的东西，体会「范围越宽越危险」。
- 把 `@memo` 放到 `@clock` 外层：输出的缓存条目数不变，但计时会把「命中缓存」的极短耗时也记进去。
